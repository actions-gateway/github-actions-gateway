# EgressProxy envtests wait on a NetworkPolicy no longer applied last

**Top of queue per [flakes-first rule](../development/maintaining-backlog.md#flake-fixes-go-first).**

`TestV2_EgressProxy_UnmanagedAutoscalingLifecycle` failed on PR #2243's GMC integration job ([job 125576339170](https://github.com/actions-gateway/github-actions-gateway/actions/runs/41532563090/job/125576339170)) at `v2_egressproxy_test.go:551` with `deployments.apps "byo-proxy" not found`, on a branch that changes nothing the test exercises.

The cause is a regression in the test's premise rather than an old flake.
Three tests in `cmd/gmc/internal/controller/integration/v2_egressproxy_test.go` wait for the proxy NetworkPolicy, calling it "the last child applied in a reconcile pass", then `Get` the children they assume came before it.
#2238 (Q1264) moved `applyNetworkPolicy` ahead of `applyDeployment` in `EgressProxyReconciler.reconcileResources`, so the NetworkPolicy is now the *first* child applied, and a `Get` of the Deployment, Service, HPA or PDB can land before that child's apply.
The failing test is the one whose next read is the Deployment; the other two, `TestV2_EgressProxy_ReconcilesOwnedProxyPool` and `TestV2_EgressProxy_ProvisionsMetricsMTLS`, read the same way and can fail the same way.

The fix waits on the PDB instead, the last child the reconciler always applies (the FQDN policy, ServiceMonitor and proxy shares after it are conditional).
The v2 ActionsGateway test's "AGC Deployment is the last child applied" premise still holds: `actionsgateway_v2_controller.go` applies it after both NetworkPolicies.
