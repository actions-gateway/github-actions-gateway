# Line-numbered citations in `docs/plan/make.md` land on unrelated code

Measured 2026-08-21 over `docs/plan/`: 21 citations carry a `path:N` line anchor into a repo file, and 14 have a target that changed after the citing plan doc last did.
All 14 are in [make.md](../plan/make.md), whose items are ✅ Done, so nothing re-bases them.
Four checked by hand were all stale, and all four land on unrelated content: `cmd/agc/Makefile:7` is cited as `all: generate build test` and is now a `LOCALBIN` assignment (the target sits at line 25), `cmd/gmc/Makefile:16` likewise (line 39), `Makefile:31` is cited for a `-C cmd/agc` flag and is now `KIND_CLUSTER`, and `Makefile:118` is cited as the `setup-envtest` build and is now a comment about tool pins.
Q830's class: a citation into live data rots unless the doc names its movement.
The rot is by implementation here, which is the sharpest form of it.
`make.md` §2.3 proposed deleting a `go install ...@release-0.23` from `cmd/gmc/Makefile:63‑64`; that landed, so the line the citation names is now the `test-integration` target and the code it describes exists nowhere in the file.
Nothing gates it: `no-plan-refs-check` asserts the opposite direction, that code does not cite plan docs.
A durable fix cites the target or symbol by name and drops the anchor, since a ✅ Done plan is a historical record that no one maintains; repointing the 14 buys one correct render and rots on the next edit to the cited file.
PR #1677 shifts one of them by a further line, which is how it surfaced.
