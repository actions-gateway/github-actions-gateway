# Refresh the scale-set demand gauge while the set advertises no capacity

`actions_gateway_scaleset_jobs_available` (Q720) reads GitHub's queued-but-unassigned count off the statistics that ride on session responses and queue messages.
An empty poll answers 202 and carries none, so a set advertising `0` capacity takes no reading at all: GitHub assigns nothing, no message is delivered, and the assignment check that would refresh it is gated on `len(l.deferred) != 0`, which a job blocked before assignment never enters.
Measured 2026-08-24 against the stub with capacity 0 and five jobs queued: one write, at session open, holding `0` for the whole run.
That is the state the gauge exists to explain — the AGC withholding while work stacks up — so today it reads a stale zero exactly when an operator needs the number, and no alert can be built on it.
The fix is a paced statistics reading on the empty-poll path, but it is not free: `RefreshSession` is a GitHub call per interval per scale set, on every idle set rather than only a backed-up one, and §3.5's rate-limit budget is what decides the pacing.
Settle that before coding; the honest interim is the caveat now carried in the metric's `Help` string and its [operator row](../operations/observability-metrics.md#scale-set-acquisition-tier-q264).
