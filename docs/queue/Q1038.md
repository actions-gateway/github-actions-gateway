# `mirror-timing`'s first live run lands on a release candidate's gate

The probe ships unexercised against a real mirror, and the step that runs it can fail an e2e job.

**Why it shipped that way.** [Q1020](https://github.com/actions-gateway/github-actions-gateway/pull/1796) was held in draft to wait for a dogfood window, on the premise that the 1.7.0 candidate run would take the reading.
It cannot: a candidate runs the tree at its tag target, and the probe is not in that tree until it merges.
Measured 2026-08-29 at the rc.2 target `49b35a41a`: `e2e-mirror-hits.sh` and `e2e-mirror-validate.sh` are present, `scripts/e2e/mirror-timing.sh` and `scripts/dogfood/e2e-mirror-clients.sh` are not, and `e2e-reusable.yml` carries no line invoking either.
Both rc.1 and rc.2 passed their Kata e2e leg without exercising them.
Maintainer's call, 2026-08-29: merge anyway and take the reading on the next candidate.

**What the next watcher needs to know.** The step's comment says it reports and never fails on what the numbers said, and that is true of the verdict, and `SEPARATED` and `OVERLAPPING` both exit 0.
Two other paths do not.
`main()` returns 1 when no layer digest resolves, which is the mirror being unreachable or serving something else.
`separation_verdict()` returns 1 when either arm is empty, deliberately, so a reading that was not taken can never read as a refuted channel.
The step carries no `continue-on-error`, so either one reddens the e2e job.

On the next candidate, **a `mirror-timing` failure is a fault in the probe or in the mirror wiring, not in the released surface**.
Read the step's output before treating it as a release blocker.

**Done when** one live run has produced a verdict line, and this row records which one it was.
If that first run refuses rather than reading, fix the refusal's cause; if the step proves noisy against a healthy mirror, `continue-on-error: true` is the fallback, at the cost of the signal the empty-arm return exists to give.
