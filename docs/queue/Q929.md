# The lint gate returns two verdicts on one tree

Measured 2026-08-18: `c99129aa` passed `lint` in run 32145897225 and failed in 32172968731, `nolintlint` calling two staticcheck directives unused in only one. #1639 deleted the directives; the flake outlives them.

**Do not retire this as "the defect has no way to express itself": that read was wrong.** Re-counted 2026-08-24 and independently again 2026-08-27: 117 first-party directive sites, 104 naming `gosec` and 5 `staticcheck`.
The original count matched the literal `nolint:staticcheck` and so missed the five `//nolint:revive,staticcheck` dot-imports under `cmd/gmc/test/utils/`.
Any query counting this surface has to span the comma form before its zero means anything.

## The unused check cannot see why a linter went quiet

Two reproductions on 2026-08-27, each silencing a linter by a route that is neither a config exclusion nor disabling it, so neither restates cause #1 below.

- **gosec, with `.golangci.yml` byte-identical to `main`.** Renaming `ConditionCredentialUnavailable` at `api/apiconditions/conditions.go:40` so G101's identifier pattern stops matching, with the directive itself untouched, takes the `api` module from `0 issues` to a `nolintlint` red naming that directive for linter "gosec".
  Restoring the name returns `0 issues`.
- **staticcheck, with no exclusion rule involved.** Adding `-ST1001` to `linters.settings.staticcheck.checks`, which leaves the linter enabled and every other check running, reds all five surviving comma-form directives.
  Removing it returns `0 issues`.

The source says why the route cannot matter.
`nolint_filter.go` keeps `matchedIssueFromLinter map[string]bool` keyed on `issue.FromLinter`, and answers an `//nolint:X` with that map's lookup for `X`.
There is no per-linter branch, and no input describing *why* an issue is absent, so nothing downstream can tell a nondeterministic silence from a configured one.
Both reproductions above are deterministic, so they measure the linter half; the step this row turns on, that a *nondeterministic* silence lands the same way, rests on that source read.
The whole 117-site surface is therefore exposed, and the gosec half is a measurement rather than an inference.
**The row is not retired.**

## Refuted leads

- **The `restore-keys` fallback.** Both runs logged `Cache hit for: golangci-lint-Linux-c9fb5326…`, the primary key rather than the prefix fallback, and the same `Cache Size: ~8 MB (8856940 B)`.
  One cache archive in, two verdicts out.
- **A different runner.** Both `lint` jobs ran GitHub-hosted `ubuntu-latest` on Go 1.26.6 in the same workspace path, despite `runs-on` being an expression here and the failing run being a dispatch.
- **Issue-count truncation ahead of the filter.** `MaxSameIssues` and `MaxFromLinter` are registered after `NewNolintFilter` in `pkg/lint/runner.go` (2.12.2), so no cap can make a directive read unused.
  Q1003 covers what the caps do instead.
- **Cause #1 firing in one run and not the other.** At `c99129aa` the exclusion rule's path was `proxytrust_test\.go`, the name the file carried before #1137 renamed it, so the rule matched nothing and the two directives were the sole suppression.
  Q923 repointed it afterwards.
  The incident is a linter silence with no exclusion in play.
