# The lint gate returns two verdicts on one tree

Measured 2026-08-18: `c99129aa` passed `lint` in run 32145897225 and failed in 32172968731, `nolintlint` calling two staticcheck directives unused in only one.
Same Go, cache key and scope. #1639 deleted the directives; the flake outlives them.

**Do not retire this as "the defect has no way to express itself": that read was wrong.** Re-measured 2026-08-24: 117 first-party directive sites, 104 naming `gosec` and 5 `staticcheck`.
The earlier count matched the literal `nolint:staticcheck` and so missed the five `//nolint:revive,staticcheck` dot-imports under `cmd/gmc/test/utils/`.
Those five are what keep the staticcheck surface alive, and they are a plain count.

The `gosec` half is a measurement plus one inference, and the join matters.
Measured: silencing `G101` at `api/apiconditions/conditions.go:40` takes that package from `0 issues` to a `nolintlint` red naming the directive, and removing the exclusion takes it back.
That silence was induced by a config exclusion, which is cause #1 and not this row's.
Inferred: that the *nondeterministic* silence lands the same way, which rests on `nolintlint`'s unused check being linter-agnostic rather than on a reproduction.
Whether the CI silence is staticcheck-specific is therefore still open, and it is the question that could still retire this row.
