# The lint gate returns two verdicts on one tree

**Event:** a `nolintlint` `directive … is unused` red on `main` or in the merge queue that a rerun clears, or any `//nolint:staticcheck` reported unused where the deprecated call it covers is still in the tree.

Measured 2026-08-18: `c99129aa` passed `lint` in run 32145897225 and failed in 32172968731, `nolintlint` calling the two `//nolint:staticcheck` directives on lines 171 and 182 of `trustpool_test.go` at that commit unused in only one, both on `x509.CertPool.Subjects`, which is deprecated.
PR #1639 deleted the directives; the flake outlives them, because a `nolintlint` red is about the linter's silence and every one of the 117 first-party directive sites is exposed to a silence of its linter ([mechanism and the known causes](../development/testing.md#a-directive-is-unused-red-is-about-the-linters-silence-not-the-directive)).

## The cause is upstream, and the pin lacked the fix

golangci-lint [#3228](https://github.com/golangci/golangci-lint/issues/3228), which the maintainer named as the root cause of [#6224](https://github.com/golangci/golangci-lint/issues/6224), a durable CI cache leaking deprecated uses past SA1019, and fixed in [#6649](https://github.com/golangci/golangci-lint/pull/6649), released in v2.13.0 on 2026-08-19.
A package restored from the analyzer cache re-exported only the facts about its own objects, so a package analyzed from source lost every fact about an object it reaches through that cached package's export data but which a third package owns.
SA1019 runs on staticcheck's `IsDeprecated` fact, so the deprecated call went unreported and the directive beside it read as unused.
`tools/go.mod` pinned v2.12.2, which predates the fix by 48 commits.

**Measured 2026-09-07, both arms.** A scratch package under `cmd/agc` that takes a `*x509.CertPool` back from `transport.BuildTrustPool` without importing `crypto/x509`, linted with a fresh `GOLANGCI_LINT_CACHE`:

- **2.12.2:** cold run `0 issues`; append one comment line and run warm: `directive //nolint:staticcheck … is unused for linter "staticcheck"` on `pool.Subjects()`; a third run without an edit repeats it.
- **2.13.2:** the same three runs all `0 issues`.
  2.13.2 rebuilds a restored package's inherited facts in memory (`inheritFactsFromDeps`, `pkg/goanalysis/runner_action_cache.go`, reworked from #6649 by [#6762](https://github.com/golangci/golangci-lint/pull/6762)).

The mitigation is the bump to v2.13.2.
CI's analyzer-cache key hashes `tools/go.sum`, so the bump also retires every archive the old linter wrote.

## What the reproduction does not reach

The incident's own site imports `crypto/x509` directly, and the recipe above on that site, with the two directives restored and the file's SA1019 exclusion removed, stays at `0 issues` on 2.12.2 across cold and warm runs.
So the class is measured and the incident's route through it is not: whatever put a direct import's fact out of reach in run 32172968731 and not in 32145897225 is not reproduced here, and the two job logs differ only in trigger (`workflow_dispatch` against `push`) and Azure region once timestamps, temp paths and credential UUIDs are normalised.
The one wall-clock input the analyzer cache reads is its trim (`trimLimit` 5 days on entry mtime, run at most daily at `Close`), and a trim deletes entries, which sends a package back to source analysis rather than silencing it; no mechanism is asserted for the direct edge.
Upstream's own reproduction was "not simple" and the fix rests on the fact-and-cache diagnosis rather than on a minimal case, so a sighting after the bump is evidence about a second cause, not this one.

## Refuted before the cause was found

- **The `restore-keys` fallback.** Both runs logged `Cache hit for: golangci-lint-Linux-c9fb5326…`, the primary key, and the same `Cache Size: ~8 MB (8856940 B)`.
- **A different runner.** Both `lint` jobs ran GitHub-hosted `ubuntu-latest` on Go 1.26.6 in the same workspace path.
- **Issue-count truncation ahead of the filter.** `MaxSameIssues` and `MaxFromLinter` are registered after `NewNolintFilter` in `pkg/lint/runner.go`; the caps are lifted now (Q1003).
- **The exclusion rule firing in one run and not the other.** At `c99129aa` the rule's path was `proxytrust_test\.go`, the pre-#1137 name, so it matched nothing in either run; Q923 repointed it.
- **Silence at rest.** Six local full sweeps on 2026-08-24, three cold and three warm, all `0 issues`; the warm runs never edited a file between passes, which is the step the recipe above needs.

Soak counts from the bump's merge.
Read against the [infra floor](../development/maintaining-backlog.md#retiring-a-flake-watch-row): a recurrence costs a rerun.
