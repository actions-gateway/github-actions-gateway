# check-artifact-unchanged.sh has no lane scope, so a skip never clears

[release.md § When to cut](../operations/release.md#when-to-cut) discharges a path-skipped required gate by proving the released surface has not moved since a commit that ran that gate in full.
The proof is `check-artifact-unchanged.sh`, which diffs the whole released surface and knows nothing about which lane covers which paths, so *any* released-surface change fails it even when the skipped lane could never have covered the changed file.
The step therefore cannot be discharged on a release whose tip carries an unrelated code change, which is most of them.

**Measured 2026-09-12** cutting `v1.8.0-rc.1` at `c99137ea6`.
`check-gates-green.sh origin/main` reported 0 gates not green and `e2e-calico` path-skipped.
`check-artifact-unchanged.sh 96ca227f1 origin/main` (that lane's last full run) exited 1 naming one file, `cmd/agc/internal/provisioner/admission.go`, whose diff in that window is **comment-only**: eight lines of prose inside an existing block comment, no statement changed.
Two independent reasons the skip was safe, neither of which the script can see:

- `cmd/agc/**` appears nowhere in `e2e-calico.yml`'s `push` path filter, which lists `cmd/gmc/**`, `cmd/proxy/**`, `Dockerfile`, `charts/actions-gateway/templates/**`, `deploy/registry-mirror/**`, `scripts/e2e/**`, `scripts/fetch/**`, `scripts/lib/**`, `Makefile` and the two workflow files.
  The lane is scoped to what can regress NetworkPolicy enforcement, and AGC capacity admission is not that, so no `cmd/agc` change has ever triggered it.
- The change cannot alter behaviour at all.

Worked around by dispatching the lane manually ([run 34733367705](https://github.com/actions-gateway/github-actions-gateway/actions/runs/34733367705), `e2e-calico / e2e` green on the tag target), which is the honest move but costs a full e2e matrix to re-prove something the path filter already asserts.

The fix is to make the comparison lane-aware: intersect the released-surface diff with the skipped lane's own path filter, and report unchanged when the intersection is empty.
The filter is already machine-readable and already asserted against the `push` list by `scripts/ci/check-path-filters.sh`, so the lane's path set can be read rather than restated.
That keeps the check conservative where it matters and stops it failing on files the lane would never run for.

**Do not fix this by ignoring comment-only diffs.** That is the narrower reading of this measurement and it is the wrong generalisation: a comment-only change happened to be what tripped it here, but a *behavioural* change to `cmd/agc` would trip it identically and would be equally outside the Calico lane's scope.
Lane scope is the defect; the comment is a coincidence of this instance.

Sibling of [Q1058](Q1058.md), found in the same pre-flight: both are release scripts whose answer silently stopped matching the repo they read.
This one fails loudly rather than returning a false zero, which is why it costs a workaround rather than a wrong release.
