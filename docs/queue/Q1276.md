# Alert when a scale-set listener cannot open its session

A `ScaleSet` RunnerSet whose listener cannot open its message session raises no alert, while `ActionsGatewayNoActiveSessions` gives a classic set that page.
Q1275 covered half of it: `ActionsGatewayMessagePollFailing` fires when an open session's long polls keep failing, and `ActionsGatewayScaleSetProvisioningStalled` fires when assigned jobs go unprovisioned.
Neither sees a session that never opens, because no poll error is counted and nothing is assigned.
Q968 is a different mechanism, an AGC shutdown leaking the session that locks its successor out.
That is one cause of a session never opening, while this row is about raising an alert for any cause.

Read on `main` at `abb6fcd7f`, 2026-11-02, two paths reach that state:

- `Listener.Start` failing in `ensureScaleSet` or `createSession`.
  `ensureScaleSetListener`'s caller in `cmd/agc/internal/controller/runnerset_scaleset.go` sets `Ready=False` with reason `NoActiveSessions`, records a `ScaleSetListenerStartFailed` Event, zeroes `status.activeSessions`, and returns the error to the work queue.
- A session that answers 404 inside the poll loop, whose re-create also fails.
  `handlePollError` in `cmd/agc/internal/scalesetlistener/listener.go` backs off and polls the dead session again, and the 404 is a heal path that counts nothing.

A rejected credential on either path still reaches `ActionsGatewayTokenRefreshErrors` or `Degraded=True`.
A non-credential failure reaches only `controller_runtime_reconcile_errors_total`.
The work queue's exponential backoff probably drops that rate under `ActionsGatewayReconcileErrors`' 0.033/s once the failure persists, but nobody has measured whether it does.

The reviewer of Q1275 named two fixes, neither measured: a per-set gauge for an open session with a rule on it at 0, or leaving the gap documented.
The gauge needs a writer on both paths above, the reconcile's status write and the in-loop re-create.
It also needs a row in the acquisition-tier ledger that `make metric-tiers-check` holds to the source.

Two decisions ride with this row.
Q264 removes `ActionsGatewayNoActiveSessions`, so decide then whether `ActionsGatewayMessagePollFailing` (shipped `warning`) should become the page in its place.
And its threshold sums over every set in a namespace, so "most of one listener's polls failing" holds only for a namespace with one set.
