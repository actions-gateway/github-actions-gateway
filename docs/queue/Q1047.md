# Fold the gate-lists driver's second set merge onto the shared Go core

Phase 3 of [merge-drivers-go.md](../plan/merge-drivers-go.md), and the reason the plan covers four drivers rather than three.

[`git-merge-gate-lists.sh`](../../scripts/ci/git-merge-gate-lists.sh) never called `merge-keyed-records.awk`.
Its `merge_entries` is a second three-way set merge with its own tie-breaking (survivors keep base order, then ours-only additions, then theirs-only) because a Makefile list entry is a bare word rather than a Markdown record.
That is the same algorithm the shared core now owns, reached by a different key reader.

The rest of the driver is genuinely its own: lifting each managed variable's backslash-continued assignment out behind a `#__GATE_LIST_SLOT_<VAR>__` sentinel so the Makefile merges as ordinary text, and rendering the block back with ours' operator, indent and line width, appending when only additions arrived, re-rendering the whole block only when a removal forces it, because a full re-render churns every wrapped line of a 30-line list and buries the real change.

Keep the round-trip check: the rendered block is re-read and its entry set must equal the set that went in, or the merge falls back.
That check is the one thing standing between a render bug and a silently dropped test suite, which is the failure `gate-lists-check` exists to catch.

`MANAGED_VARS` must stay reconciled against the assignments in `mk/gate-lists.mk` in both directions, which `scripts/ci/git-merge-gate-lists-test.sh` asserts today via `--managed-vars`; whatever replaces that flag has to keep both directions.
