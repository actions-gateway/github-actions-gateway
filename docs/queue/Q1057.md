# A discarded Go queuestore is cited as a live second implementation

Three files under `scripts/docs/` tell a reader that the magnitude-head rank
algebra is implemented twice and that both implementations run the shared
vectors. The fixture says "Both suites run these vectors"
(`scripts/docs/rank-vectors.tsv:4`) and its runner says the Go side "runs the
same file from its own side" (`scripts/docs/rank-vectors-test.sh:8`).
`queue.py` asserts it three more times, once in the `rank` subcommand's
`--help`, which prints it to whoever runs it: `scripts/docs/queue.py:20`,
`scripts/docs/queue.py:77` and `scripts/docs/queue.py:1007`.

No such package exists here. Measured 2026-09-04 at `9681038e` immediately
after `git fetch`: no path on `origin/main` is named `queuestore` across 15104
paths, against controls of 12 `go.mod` paths and 346 files matching `rank`, so
the empty answer is a finding rather than a broken read. The five content hits
are the three files above plus this repo's own migration plan, which records
the Go package as unlanded and whose branch
[Q889](../plan/q889-backlog-item-store.md) closed.

So these vectors run against a second copy of one implementation rather than a
second implementation. The repair states that outcome rather than deleting the
framing, because what makes the fixture worth keeping does not depend on a
second consumer: every expected key is derived from the scheme's rules rather
than from a run of the implementation under test.

It is not three comment edits, because two of the three files are vendored.
`scripts/ci/check-vendored-skills.sh --report` reports `rank-vectors.tsv`
unmodified and `queue.py` forked. Editing the fixture in place forfeits the
clean overwrite that
[skills.md](../development/skills.md#vendored-from-the-skills-repo) records,
and upstream has already rewritten that header, so it wants re-vendoring rather
than a local edit. The three `queue.py` sites were fixed upstream too, and
reaching them means the re-vendor [Q956](Q956.md) already owns.

`rank-vectors-test.sh` is the file this repo can fix outright, and it carries a
second finding. It was adopted from upstream in `bbc2578f5` beside the
registered files, holds no row in `scripts/ci/vendored-skills.tsv`, and is
therefore invisible to `make vendored-skills-check`: the unregistered fifth
file [skills.md](../development/skills.md#vendored-from-the-skills-repo) warns
nothing derives. That adoption also dropped the "not live yet" qualifier
upstream carried at the time, so this copy asserts the cross-check flatly where
upstream hedged it.

[Q955](Q955.md) owns whether anything asks if the vendored files have moved
upstream. This row is a second measured instance of the drift that row cannot
see, filed beside [Q956](Q956.md) rather than folded into it because two of its
three files sit outside that row's scope.
