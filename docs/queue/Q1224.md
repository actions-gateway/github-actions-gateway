# Retire the cache-runner patch once actions/runner takes an override

**Event:** a GitHub maintainer replies to the override proposal in [community discussion #211436](https://github.com/orgs/community/discussions/211436), or an `actions/runner` release honours an operator-set `ACTIONS_RESULTS_URL` on its own.

The `cache-runner` image binary-patches `Runner.Worker.dll`, renaming the UTF-16LE `ACTIONS_RESULTS_URL` literal to `ACTIONS_RESULTS_GAG` so actions inherit the pod's value ([Q215](Q215.md)).
It is the only way a v2 scale-set worker can reach an in-cluster cache, because the runner overwrites the variable from the job message, and the build check stops a runner bump from shipping it silently unpatched.
It is still a modified Microsoft binary in a security-relevant image, so it should not outlive the need.

On a maintainer reply, the work is upstream first: an Architectural Decision Record (ADR) and then a PR in the shape the maintainer picks, which `actions/runner`'s `docs/contribute.md` asks for before code.
Not before: [actions/runner#3411](https://github.com/actions/runner/pull/3411) and [#3906](https://github.com/actions/runner/pull/3906) proposed the same override as unsolicited PRs and both closed with no maintainer reply.

Once a runner release carries the override: switch `cache-runner` to set it instead of patching, drop the `RUN perl` step and its literal check from the `Dockerfile`, and re-run the Q215 spike's save, restore and sibling-scope checks on the stock image.
