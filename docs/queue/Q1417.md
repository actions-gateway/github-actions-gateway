# The release ladder's revived marker loses its escapes through awk -v

`check-release-ladder.sh` passes `REVIVED_MARKER='(is|are) back\.\*\*'` to awk with `-v`, and `-v` processes escape sequences, so the backslashes are gone before the regex is built.
The marker awk sees is `(is|are) back.**`, which matches any line containing "is back" or "are back", not only the bold `is back.**` closer.

Measured 2026-11-26 on macOS awk version 20200816: `awk -v marker='(is|are) back\.\*\*'` prints the marker as `(is|are) back.**` and matches the line "it is back now", with no warning.
CI's awk does the same and warns: plan-hygiene's log on main, run 45928941237 (2026-11-27), prints ``awk: warning: escape sequence `\.' treated as plain `.'`` and the same for `\*`.
That wording is gawk's; which awk binary the runner uses was not checked.
The same script already says so for its other patterns (the comment above its bracket-expression regexes: BSD awk drops the backslash while parsing the string).

Nothing misreads today: `docs/plan/release-ladder.md` has one line with either phrase, line 119, and it is the revived paragraph.
A second line saying something "is back" would be read as revived too, adding its Q-IDs before the first colon to the revived set.

The fix is to write the marker the way the script's other patterns are written, with bracket expressions (`back[.][*][*]`), or to double the backslashes: `-v marker='(is|are) back\\.\\*\\*'` reaches awk as `back\.\*\*` and stops matching "it is back now", measured on the same macOS awk.
A test case should hold a plain "is back" line outside the paragraph.
This is separate from [Q1145](Q1145.md), which is a fixture builder in the same checker's test.
