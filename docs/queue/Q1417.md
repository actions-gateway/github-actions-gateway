# The release ladder's revived marker loses its escapes under gawk

`check-release-ladder.sh` passes `REVIVED_MARKER='(is|are) back\.\*\*'` to awk with `-v`, and `-v` processes escape sequences.
CI's awk drops the backslashes: plan-hygiene's log on main, run 45928941237 (2026-11-27), prints ``awk: warning: escape sequence `\.' treated as plain `.'`` and the same for `\*`.
So on CI the marker is `(is|are) back.**`, which matches any line containing "is back" or "are back", while macOS's awk (version 20200816) keeps the escapes, prints no warning, and matches only the bold `is back.**` closer.

Nothing misreads today: `docs/plan/release-ladder.md` has one line with either phrase, line 119, and both patterns match it.
A second line saying something "is back" would be read as the revived paragraph on CI only, adding its Q-IDs before the first colon to the revived set, and a local run would disagree with CI.

The fix is to pass the pattern through `ENVIRON` or with doubled backslashes, so both awks see `back\.\*\*`, with a test case holding a plain "is back" line outside the paragraph.
This is separate from [Q1145](Q1145.md), which is a fixture builder in the same checker's test.
