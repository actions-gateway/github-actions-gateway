# Milestone: P2P at the node, pull-through cache in-guest

Validate the composed stack: node-level P2P for pod images, in-guest mirror for job pulls.
Nothing node-layer is built.

[The plan](../plan/q540-node-layer-p2p.md) graded both candidates on kind against what a pod with no egress policy can do at a node address, and recommends Spegel: its worst case is read access to cached images, where Dragonfly's node client exposes unauthenticated task control.
A Kata worker under the GMC's workload policy reaches no node address on dogfood ([Q539 plan §8.1](../plan/q539-dragonfly-mirror-backend.md#81-measured-the-worker-policy-holds-and-nothing-else-does)).

Next is dogfood, gated on three readings the plan lists as unmeasured: whether GKE's containerd reads `certs.d` per pull, what Spegel displaces on a GKE node running `kata-deploy`, and whether `resolveTags: false` costs a digest-pinned worker image anything.
Ship with the plan's ingress policy and `resolveTags: false`; the cross-node hostPort path stays open to pods outside a GAG tenant.
