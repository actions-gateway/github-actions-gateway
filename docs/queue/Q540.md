# Milestone: Dragonfly at the node, pull-through cache in-guest

Validate the composed stack: node-level P2P for pod images, in-guest mirror for job pulls.
Nothing node-layer is built.

[The plan](../plan/q540-node-layer-p2p.md) graded Dragonfly's node client and Spegel on kind, and chose Dragonfly: it pre-heats nodes ahead of a burst, which pays most for GPU CI's large images, and it is already deployed as the mirrors' back end (Q539).
Against this item's goal, running untrusted pull-request checks on Kata workers, the node client is off the worker's path: a Kata worker under the GMC's workload policy reaches no node address on dogfood ([Q539 plan §8.1](../plan/q539-dragonfly-mirror-backend.md#81-measured-the-worker-policy-holds-and-nothing-else-does)).

Next is dogfood, gated on three readings the plan lists as unmeasured: whether GKE's containerd reads `certs.d` per pull (so dfinit's containerd restart can stay off), what dfinit displaces on a GKE node running `kata-deploy`, and whether the node clients can share Q539's scheduler.
The milestone's own security reading is the worker's reachable set unchanged with the real node client installed, under Kata.
