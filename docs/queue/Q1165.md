# render-overflow-check times out loading a page from its own local server

**Event:** the `render-overflow` job fails on `main` after three attempts on one page, or prints the checker's `failed (attempt N of 3: …), retrying on a fresh page` warning on most runs. → top of Queue, escalated.

Sighted once on `main`, on the `push main` run of `1ced9359b` (#2047, run 37403964143, 2026-10-06), which left `main`'s tip red on `doc-links`.
The merge-group run of the same tree passed six minutes earlier.
Playwright's navigation to `http://127.0.0.1:35949/operations/velero-backup-restore/` timed out waiting for `load` while measuring the `site` scope, and the `site-dev` scope then measured 424 pages with no finding, so nothing about the page's layout failed.

**Not an off-host subresource.** Measured 2026-10-09 against a local `make docs-build`, with every off-host request in the checker's browser context routed to a handler that never answers: that page still reached `load` in 0.4 seconds.
Its only off-host requests are the two `api.github.com` repository-stats XHRs, which do not delay `load`, and its favicon links to `actions-gateway.com` were never requested.
So blocking off-host traffic would not have prevented this sighting, and the cause sits on the runner side, unidentified.
The same probe found one page that *does* wait on an off-host host, which is [Q1168](Q1168.md)'s, not this row's.

**Retrying on the same page did not recover.** The first mitigation retried `page.goto` timeouts on the one page the checker reuses for every path.
In merge-group run 38083333704 (2026-10-10) it timed out twice on `/plan/q710-overlong-paragraphs/`, about halfway through the `site-dev` sweep, and the third attempt failed `net::ERR_ABORTED`, which that retry did not catch.
That page is ordinary: 65 KB, 141st largest of 431.

**Not renderer growth across the sweep, on a Mac.** Measured 2026-10-10 over a local `site-dev` sweep using Chromium's own counters: the shared page's renderer sits at about 4.2 GB RSS throughout, and recycling the page every 25 paths still reaches about 3.5 GB within 24 paths, then holds flat.
So memory does not accumulate across the sweep, and recycling pages on a schedule would not cap it.
The runner's memory during a failure has not been read.

Mitigation: the checker retries loading and measuring a path up to three times at Playwright's 30-second default, on a fresh page each time and for any Playwright error, rather than raising the timeout.
Each retry prints a `::warning::` annotation, so a page that keeps failing stays visible instead of silently slowing the job.
