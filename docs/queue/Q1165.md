# render-overflow-check times out loading a page from its own local server

**Event:** the `render-overflow` job fails on `main` with `Page.goto: Timeout 30000ms exceeded` after three attempts on one page, or prints the checker's `did not finish loading (attempt N of 3), retrying` warning on most runs. → top of Queue, escalated.

Sighted once, on the `push main` run of `1ced9359b` (#2047, run 37403964143, 2026-10-06), which left `main`'s tip red on `doc-links`.
The merge-group run of the same tree passed six minutes earlier.
Playwright's navigation to `http://127.0.0.1:35949/operations/velero-backup-restore/` timed out waiting for `load` while measuring the `site` scope, and the `site-dev` scope then measured 424 pages with no finding, so nothing about the page's layout failed.

**Not an off-host subresource.** Measured 2026-10-09 against a local `make docs-build`, with every off-host request in the checker's browser context routed to a handler that never answers: that page still reached `load` in 0.4 seconds.
Its only off-host requests are the two `api.github.com` repository-stats XHRs, which do not delay `load`, and its favicon links to `actions-gateway.com` were never requested.
So blocking off-host traffic would not have prevented this sighting, and the cause sits on the runner side, unidentified.
The same probe found one page that *does* wait on an off-host host, which is [Q1168](Q1168.md)'s, not this row's.

Mitigation: the checker retries a timed-out navigation up to three times at Playwright's 30-second default rather than raising the timeout, and announces each retry with a `::warning::` annotation, so a page that keeps stalling stays visible instead of silently slowing the job.
