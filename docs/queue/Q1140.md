# Pre-pull hit predicate trusts the cache layer, not the files it needs

A restored cache entry whose contents no longer match what the script expects takes the miss branch silently, so the only symptom is a cold run that looks like a first run.
Two of the three pre-pulled manifests sat in that state for three months and nothing reported either.

## The class, and why the two fixes do not close it

`actions/cache` reports a hit for the key; the script then checks whether `images.tar` and `images.txt` are both present and, finding them absent, re-fetches.
That degradation is correct behaviour and it is also unobservable: a run that never warms reads exactly like a run whose key legitimately moved.

Q1125 fixed cert-manager's entry and [Q1138](Q1138.md) fixes metrics-server's, both by bumping a key generation.
Those retire the two known instances.
Neither stops a third entry skewing the same way the next time a tar is renamed without a key bump, which is precisely how both of these arose -- [#319](https://github.com/actions-gateway/github-actions-gateway/pull/319) renamed the tar for all three manifests at once and bumped no key.

## What a guard would be, and why this is not yet a task

The shape raised in review was a self-guarding predicate: have the script assert the restored entry carries what it needs, and fail or re-fetch loudly rather than degrade quietly.
`REQUIRE_MANIFEST` was the name floated for it.

Unmeasured on both sides, and that is the whole reason this is a row rather than a diff.
Nobody has established what the guard should do on a skew -- fail the run, warn and re-fetch, or emit an annotation -- and the answers differ in cost: failing turns a silent slow run into a red one, which is right for a defect nobody notices and wrong for a transient CDN miss the retry would have absorbed.
Nor is it known whether a third manifest can skew now that the tar names are uniform.

## Notes

Declined during independent review of the cert-manager PR rather than folded into it, on the grounds that widening a finished diff for an unmeasured guard is worse than filing it.
The author left the predicate alone and the reviewer flagged it once as the only finding in that review with no row behind it.
This row is that filing decision, taken at the groom.

**Settles:** whether a third manifest can still skew is readable off the tree -- compare the tar and index names each of the three pre-pull paths writes against the names the hit predicate checks.
If they are uniform the class is already closed by construction and this row is a delete, which is the cheapest outcome and the one to check first.
