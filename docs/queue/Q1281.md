# spec.tracing needs an operator-named collector peer and a CA path

An `ActionsGateway` with `spec.tracing` set delivers no spans on a CNI that enforces NetworkPolicy until an operator adds a policy by hand, and a proxied tenant must also spell the endpoint as the full `.svc.cluster.local` name.
Q1278 documented that in [Reaching the collector](../operations/observability-logging.md#reaching-the-collector) rather than changing it, because opening the path widens a default-deny egress policy, which needs sign-off under the secure-by-default principle.

**Karl made two separate decisions on 2026-11-03, and each gates `v2.0.0`.**

1. **"Karl gates v2.0.0 on a peer field".** An operator-named `spec.tracing` peer, which the GMC turns into an AGC-only egress rule.
   The GMC does not open the path by deriving a peer from the endpoint's host, so egress stays closed until an operator names one, and a tenant with `spec.tracing` unset keeps the policy it has today.
2. **"Karl gates v2.0.0 on a CA path"**, asked in a later prompt after the plaintext finding below.
   A CA reference alongside the peer field, so a proxied tenant can use TLS at 2.0 and the plaintext gap closes before the tag.

Measured on 2026-11-03 against 5c46c1b with a real `otel/opentelemetry-collector:0.120.0` over plaintext gRPC, on a two-node kind cluster with Calico and one job per setup:

| Tenant | `endpoint` host | Operator policy, AGC to collector | Root spans received | AGC log |
|---|---|---|---|---|
| Proxied | `otel-collector.observability:4317` | No | 0 | `traces export: ... reading server HTTP response: unexpected EOF` |
| Proxied | `otel-collector.observability.svc:4317` | No | 0 | same |
| Proxied | `otel-collector.observability.svc.cluster.local:4317` | No | 0 | `traces export: ... DeadlineExceeded` |
| Proxied | `otel-collector.observability.svc.cluster.local:4317` | Yes | 1 | no new line |
| Proxied | `otel-collector.observability:4317` | Yes | 0 | `unexpected EOF` |
| Direct | `otel-collector.observability:4317` | No | 0 | `DeadlineExceeded` |
| Direct | `otel-collector.observability:4317` | Yes | 1 | no new line |
| Direct | `otel-collector.observability.svc.cluster.local:4317` | Yes | 4, from one enqueued job after the AGC restarted | none |

Each provisioning attempt opens a root span, so replays after that restart may be the extra three; that was not checked.
Every row is plaintext.
The AGC's `traces export:` line at `info` is the only signal: the shutdown flush returns nil, and no metric or status condition reports a failed export.
The measurement was a throwaway Ginkgo spec and is not committed, so nothing in CI covers delivery on a real cluster; an in-process test does cover `tracing.Init` to an OTLP server.

The precedent is the Vault signer.
`signer.vault.networkPolicy` has the operator name a peer, and `vaultEgressRule` turns it into a scoped AGC-only egress rule, so a `spec.tracing` peer could reuse `egressPeerTo`, whose comment already names telemetry as a future consumer.
That covers the direct dial and leaves the proxied short-name case to the docs, or to validating the endpoint's host against `NO_PROXY` at admission.

The plaintext finding: `spec.tracing` has no CA field and `configureTrustPool` patches only `http.DefaultTransport`, so the gRPC exporter verifies against the AGC image's public roots, which cannot validate a `.svc.cluster.local` name.
A proxied tenant must use that name, so its export can only be plaintext.
Measured in-process on 2026-11-03: `https://` to a self-signed server gives 0 spans and `x509: certificate signed by unknown authority`, and delivers once `OTEL_EXPORTER_OTLP_TRACES_CERTIFICATE` names the CA, an SDK variable `spec.tracing` cannot set and that has no volume mounted behind it.
The SDK reads that file once, when the exporter is built, and on a read failure logs the error and falls back to the system roots (`WithCertPool`, read and not run), so rotation and a missing file both need an answer.
The precedent for the reference is `githubCABundleRef`, a ConfigMap the GMC mounts and reports as `CABundleNotFound` or `CABundleInvalid`.
Q536 built that in #1137 at 29 files and +1347/-216 outside docs, which is why this row is `L` with the peer field and the e2e beside it, though the size is an estimate rather than a measurement.
Read how `signer.vault` handles its own CA, and `api-review.md` on whose fact the CA is, before choosing the shape.
The doc examples stay `http://` with `insecure: true` until this ships, and move to TLS in the same change.

Done when both fields ship, an e2e spec on the Calico lane proves a tenant's spans reach a collector and that a worker pod still cannot, and a real run shows a proxied tenant exporting over TLS to a collector with a private CA.

Neither decision covers the proxied short-name case or the two gaps below, so they do not gate `v2.0.0` unless one blocks that Done when.
`spec.tracing.endpoint` has no admission check, so a bare IP is admitted and silently exports to `127.0.0.1:4317`, and routing the export through an `EgressProxy` with `destinationFQDNs` is unmeasured, including what it costs in worker egress.
