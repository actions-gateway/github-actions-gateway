# spec.tracing leaves the AGC no egress path to its collector

An `ActionsGateway` with `spec.tracing` set delivers no spans on a CNI that enforces NetworkPolicy until an operator adds a policy by hand, and a proxied tenant must also spell the endpoint as the full `.svc.cluster.local` name.
Q1278 documented that in [Reaching the collector](../operations/observability-logging.md#reaching-the-collector) rather than changing it, because opening the path widens a default-deny egress policy, which needs sign-off under the secure-by-default principle.
The question for the maintainer is whether the GMC should open it, and whether that gates `v2.0.0`.

Measured on 2026-11-03 against 5c46c1b with a real `otel/opentelemetry-collector:0.120.0` over plaintext gRPC, on a two-node kind cluster with Calico and one job per setup:

| Tenant | `endpoint` host | Operator policy, AGC to collector | Root spans received | AGC log |
|---|---|---|---|---|
| Proxied | `otel-collector.observability:4317` | No | 0 | `traces export: ... reading server HTTP response: unexpected EOF` |
| Proxied | `otel-collector.observability.svc:4317` | No | 0 | same |
| Proxied | `otel-collector.observability.svc.cluster.local:4317` | No | 0 | `traces export: ... DeadlineExceeded` |
| Proxied | `otel-collector.observability.svc.cluster.local:4317` | Yes | 1 | no new line |
| Proxied | `otel-collector.observability:4317` | Yes | 0 | `unexpected EOF` |
| Direct | `otel-collector.observability:4317` | No | 0 | `DeadlineExceeded` |
| Direct | `otel-collector.observability:4317` | Yes | 1 | no new line |
| Direct | `otel-collector.observability.svc.cluster.local:4317` | Yes | 4, from one enqueued job after the AGC restarted, the extras not explained | none |

The AGC's `traces export:` line at `info` is the only signal: the shutdown flush returns nil, and no metric or status condition reports a failed export.
The measurement was a throwaway Ginkgo spec and is not committed, so nothing in CI covers delivery on a real cluster; an in-process test does cover `tracing.Init` to an OTLP server.

There is a precedent to follow if the answer is yes.
`signer.vault.networkPolicy` has the operator name a peer, and `vaultEgressRule` turns it into a scoped AGC-only egress rule, so a `spec.tracing` peer could reuse `egressPeerTo`, whose comment already names telemetry as a future consumer.
That covers the direct dial and leaves the proxied short-name case to the docs, or to validating the endpoint's host against `NO_PROXY` at admission.
Done when that decision is recorded, and if the rule ships, an e2e spec on the Calico lane proves a default tenant's spans reach a collector and that a worker pod still cannot.

Two smaller gaps sit beside it: `spec.tracing.endpoint` has no admission check, so a bare IP is admitted and silently exports to `127.0.0.1:4317`, and routing the export through an `EgressProxy` with `destinationFQDNs` is unmeasured, including what it costs in worker egress.
