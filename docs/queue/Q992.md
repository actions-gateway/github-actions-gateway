# `cover-check` replays a stale pass over the uncacheable package

`go-test.sh` runs a second `-count=1` pass over the `UNCACHED` list that [`check-test-cache-inputs.py`](../../scripts/go/check-test-cache-inputs.py) owns, so `make test` and `make test-race` cannot replay a stale result for `cmd/probe/compat`, its sole entry.
[`coverage.sh`](../../scripts/go/coverage.sh) has no equivalent: `-count=1` appears nowhere in it, and its `firstparty_nonworkspace_modules` loop addresses modules outside `go.work`, which is a different problem.
`make check` runs `cover-check` rather than `go-test.sh`, so the primary local gate is the one path Q936's stale-cache mode is still live on.

Measured 2026-08-25 through `make cover-check` itself.
On a clean tree it exits 0 with `probe/compat` running fresh; run again, it exits 0 with that package `(cached)`.
Add Q936's own violation, `_ "net/http/httptest"` in `cmd/proxy`'s `package main`, and it still exits 0: `proxy` re-runs fresh at 34.968s while `probe/compat` replays `(cached)`, so the guard test never executes.
That same package with `-count=1` on that same tree exits 1, naming the import.

CI is not exposed: `unit-test` runs `make test-race` beside the `coverage` job under an identical `if:` condition, so the forced pass runs there whenever `cover-check` does.
The cost is a local green followed by a red CI cycle, which is the shape [`unit-test.yml`](../../.github/workflows/unit-test.yml)'s own step comment describes.

Give `run_coverage` the same forced pass, sourced from `check-test-cache-inputs.sh --uncached-packages` so the two lists cannot drift; the uninstrumented loop already in that function is the shape to copy.
It costs one cold run of that package, measured at 3.8s, 12.5s and 35.4s across three clean-tree runs here, because the test shells out to `go list` per workspace module and so tracks build-cache warmth rather than a fixed duration.
A regression test for this has to change compiled output to bust the cache: measured here, a comment-only edit and an unused package-level var both replay `(cached)`, while adding a test function re-runs the package at 28.302s.

Distinct from [Q989](Q989.md), which moves the tolerance denominator on an unchanged tree: a stale cache replays a stale PASS and cannot produce that row's spurious FAIL.
Across the three `cover-check` runs above, spanning 49 to 58 cached packages, `./cmd/proxy` measured 79.3% every time at tolerance 0.8621pp, so nothing measured here connects the two.
That figure is this tree's measurement and coincidentally equals the recorded floor; Q989 measures the same module at 78.7% on its own base, so the two differ by tree rather than disagreeing.
[Q953](Q953.md) owns the neighbouring gap in the detector that builds the list, and fixing either leaves the other.
