# Gate new comments for provenance; move the existing ones to docs

[code-comments.md](../development/code-comments.md) limits a comment to what a later reader of the file needs, and nothing enforces it: the rule is prose in a doc and a skill, and the existing source contradicts it at every turn, so a session matching its surroundings reproduces what the page forbids.

Measured 2026-11-27 at `036f6ccc9` over tracked first-party source: Go implementation files hold 0.50 comment lines per code line and shell 0.65; 550 Go and 320 shell comment blocks run 10 lines or more; comments cite a backlog ID 5,139 times and 4,915 of those name a row no longer in this directory.

Two pieces, separable:

**A diff-scoped gate on added comment lines.** It fails an added comment line that carries a backlog ID or PR number outside `TODO(QNNN):`, a date, or a change-narration word ("previously", "no longer"), and an added implementation comment block over a length cap.
Diff-scoped so it ratchets without a baseline file; the existing comments stay legal until touched.
Open before building: whether a cap on block length can tell a doc comment from an implementation comment in Bash and YAML, where nothing marks the difference, and what the exemption for Custom Resource Definition field godoc and chart `values.yaml` keys on.
The counts above came from plain regular expressions over comment lines, which is enough to count and not enough to gate: a gate needs a false-positive suite in both directions.

**Burning down what exists.** The dead backlog IDs are the mechanical half: an ID cited outside a `TODO` with no row here can be dropped where the sentence stands without it.
The long blocks are not mechanical, because most hold real design rationale that has no other copy.
Each needs its content moved to `docs/design/` before the comment shrinks, starting with the longest: `Admit` in `cmd/agc/internal/provisioner/admission.go` (98 lines) and the script headers over 70 lines under `scripts/`.
A sweep per package, in its own PR, keeps each reviewable.
