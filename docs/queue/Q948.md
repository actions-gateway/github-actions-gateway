# Nothing asserts a path filter covers the inputs its gated jobs read

Every assertion runs pattern → repo: the registry is complete, workspace filters cover `go.work`, patterns pin live paths, duplicated lists agree, globstars expand.
None runs the reverse, so an input a gated job reads and no pattern matches is invisible — the gate then goes green by skipping, which the file's own header calls the most expensive false negative.
Two instances so far, both found by hand: Q881 (a tree, `docs/plan/*.md` against a filter naming two files in it) and [Q947](Q947.md) (two scripts a job runs).
The tree case needs a hand-kept script → tree map, so the design decision is how to keep that map from going stale the way the lists it guards do.
