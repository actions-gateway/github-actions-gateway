# Rescue a Dependabot PR that is behind main, not only a conflicted one

`eligible()` skips any PR whose mergeable state is not `CONFLICTING`, on the reasoning its own comment states: "A branch merely behind main is mergeable and needs no help."
That held while every required gate read only the branch's own tree.
It stopped holding once a required gate started reading state that moves on its own.

## Measured 2026-09-16

[#1878](https://github.com/actions-gateway/github-actions-gateway/pull/1878) and [#1880](https://github.com/actions-gateway/github-actions-gateway/pull/1880), both based 2026-09-10 and both `MERGEABLE`, fail `release-pins` and `doc-links-gate`.
Neither PR changes a single file under `docs/`, `README.md`, or `CONTRIBUTING.md` — they touch `THIRD-PARTY-NOTICES`, four `go.mod`/`go.sum` pairs, and `vendor/`.
`release-pins-check` fails because it compares the install/upgrade pins against the newest stable tag, and v1.8.0 was tagged 2026-09-14, after the branch base; `main` is green on the same gate.

So the gate's verdict is a function of wall-clock time, not of the branch.
Nothing heals it: Dependabot disowned both branches when the `chore(deps): sync …` commit landed, and this script skips them for being mergeable.
They sit red until a human intervenes, which is the exact failure mode Q427 created this script to end.

## The fix

Add a second eligibility arm: a Dependabot `go_modules` PR whose tip is not Dependabot's, that is behind `origin/main` and whose checks are failing, is as stranded as a conflicting one.
Prefer "behind **and** red" over "behind" alone, so a behind-but-green PR is still left to the merge queue rather than force-pushed for no reason.

The replay path itself needs no change — it already resets to current `main` and re-applies the bumps, which is exactly what a stale base wants.
Reuse the `MAX_PRS` cap so a day of accumulated staleness cannot fan out.

## Notes

The sibling gap in the same bot chain is the generated-output drift a k8s bump leaves behind; that one is fixed by `make deps-sync`.
This row is only about *which* PRs the rescue considers.
