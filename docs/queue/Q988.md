# Read the worker runner version from the registry, not the container

Q792 ships the version as a self-report: the wrapper writes it, the tenant owns the image and the filesystem, and workflow steps run in that container afterwards, so the last write to the termination log wins.
Nothing inside the container can carry a verdict: the termination log, a shared `emptyDir`, and `bin/Runner.Listener.deps.json` itself are all tenant-writable, an init container cannot see the runner image, and a `shareProcessNamespace` sidecar reading `/proc/<pid>/root` reads the same live rootfs.
The only unforgeable source is the image in the registry, read by the AGC before the container runs, which also covers the digest-only references Q715 reports `Unknown` for and needs no pod.
Two variants, and they are *not* the same trust level: the config blob's `org.opencontainers.image.version` label is one GET and immutable once pinned by digest, but it is authored by whoever built the image, so for a tenant's custom image it is a durable self-report rather than an attestation; only extracting the layer holding `deps.json` reads what the runner will actually execute.
Whether `actions-runner` sets such a label is unverified.
Sized `L` because the repo has no registry client at all (no `go-containerregistry`, `crane` or `remote.Image` anywhere), so this needs a client, registry auth (plausibly per-tenant), digest-keyed caching, and unreachable-registry handling.
Blocks making `RunnerVersionTooOld` verdict-bearing for a custom image; until then `Unknown` stays `Unknown` by design.
