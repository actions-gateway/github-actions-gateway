# Script suites share one fixture path and delete each other's

Measured 2026-08-25 over the 97 members of `SCRIPTS_TESTS`: 38 put their fixtures at a fixed path under `$REPO_ROOT/tmp/`, and 37 of those both `rm -rf` it at startup and register `trap 'rm -rf ...' EXIT`.
(99 files match `scripts/*/*-test.sh`; `go-test.sh` is the heavy-build runner and `claude-usage-test.sh` is its own gate, so neither is in the fan-out.)
Two runs that overlap therefore destroy each other's fixtures, and the trap fires on a kill as well as on a clean exit, so a killed run can delete a live one's.
Observed once: a `make check` went red on `check-script-docs-test` with four assertions failing `cd: .../clean: No such file or directory` after a separate `make scripts-test` in the same worktree was killed; the same tree passed on a re-run alone.

**Why this is not [Q822](Q822.md)'s mechanism, and the reason is not worktree isolation.** The fan-out is *intra*-worktree, 97 suites in one `$REPO_ROOT` sharing one `tmp/`, so `$REPO_ROOT` scoping says nothing about the case that matters.
What rules it out is that no two suites share a name: 42 distinct fixture names across the 43 suites that touch `tmp/`, none used twice, and nothing that `rm -rf`s the `tmp/` root.
So two suites in one run cannot collide today, and this must not be read as closing Q822.

**That invariant is conventional rather than structural, which is why it wants a gate and not a note.** It holds because 43 authors happened to pick distinct names, and the first reuse turns the fan-out into a reproducible cause of suite failure, which is exactly the causal link Q822 records as missing.
The incident above is that mechanism one step removed, across runs rather than within one.

`mktemp` is the fix and it needs no new pattern: 46 suites already use it, and the guard that makes agents prefer fixed paths in ad-hoc commands never inspects inside a committed script.
Source-readable throughout, so this is fixable without reproducing a race.
