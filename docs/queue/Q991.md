# Test suites share a fixed fixture path and delete each other's

Counted from source 2026-08-25 over the 99 `*-test.sh` files: 41 assign a repo-rooted `tmp/` path, 38 of those carry a `$$`, `$RANDOM` or `$BASHPID` uniquifier, and **3 carry none**.
Those 3 both `rm -rf` the path at startup and register `trap '... rm -rf ...' EXIT`.
(48 suites call `mktemp` somewhere; the two counts overlap, so neither partitions the set on its own.)
All three are under `scripts/docs/`: `check-script-docs-test.sh`, `check-comparison-stamps-test.sh`, `check-page-density-test.sh`.
The trap fires on a kill as well as on a clean exit, so a killed run can delete a live one's.
Observed once: a `make check` went red on `check-script-docs-test` with four assertions failing `cd: .../clean: No such file or directory` after a separate `make scripts-test` in the same worktree was killed; the same tree passed on a re-run alone.
**Assert any recount still contains that suite.** The first census here returned 37 sites and excluded `check-script-docs-test.sh` itself, because skipping files that mention `mktemp` looked like hygiene and dropped the one site with direct evidence behind it.

**Recounted 2026-09-09 (Q1078): 7 carry none, over a population of 121 `*-test.sh` files of which 49 assign a repo-rooted `tmp/` path.** The original three are all still in the set, which is the reconciliation the rule above asks for.
The four that joined them are `scripts/ci/check-script-modes-test.sh`, `scripts/docs/check-rung-order-test.sh`, `scripts/dogfood/gmc-test.sh` and `scripts/manifest/check-registry-mirror-render-test.sh`, so the class is no longer confined to `scripts/docs/`.
All 7 both `rm -rf` the path at startup and register the same EXIT trap, so the fix below applies unchanged and only its blast radius grew.
Nothing catches the drift: the convention lives in prose, so each new suite copies whichever neighbour its author read.

**Observed a second time 2026-09-09 (Q1078), taking two suites in one run.** `check-script-docs-test` failed four assertions on `open scripts/README.md: no such file or directory`, and `check-script-modes-test` failed one on `cd: .../tmp/check-script-modes-test/empty: No such file or directory`.
Same precondition as the first sighting: an earlier `make check` in that worktree had been killed mid-`scripts-test` (SIGTERM, exit 143).
Both passed when run serially minutes later against the same tree, and a third `make check` was green.
The second suite is one of the four the recount added, so a prediction made off the first census would have missed it.
The host was at load average 82 to 108 on 18 cores for the red runs and 40 for the green one, which is a confound the sighting cannot separate out.

**The fix is the repo's own convention, not `mktemp`.** 38 suites already keep the path under `tmp/` and append `.$$`, which is a per-PID directory and a one-token change (the convention dates to `c619c431c`, 2026-08-11).
That keeps what [CLAUDE.md](../../CLAUDE.md)'s temp-file rule asks for and `mktemp` in host `/tmp` gives up: the fixture persists and stays citable in a PR.
`scripts/docs/check-script-docs-test.sh:22` records the fixed path as deliberate, so whatever lands must keep the fixture inside the tree.

**Not [Q822](Q822.md)'s mechanism.** Its suites are the Go `provisioner` and `controller` ones under 8 workers, a different failure entirely.
Two suites in one run cannot collide here either, since the names are distinct; what bites is one worktree running the suites twice.
But that is conventional rather than structural, and the first name reused turns the fan-out into a reproducible cause of suite failure, which is the causal link Q822 records as missing.
