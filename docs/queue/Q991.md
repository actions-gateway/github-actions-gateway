# Script suites share one fixture path and delete each other's

Measured 2026-08-25 over the 99 suites under `scripts/*/`: 38 put their fixtures at a fixed path under `$REPO_ROOT/tmp/`, and 37 of those both `rm -rf` it at startup and register `trap 'rm -rf ...' EXIT`.
Two runs that overlap therefore destroy each other's fixtures, and the trap fires on a kill as well as on a clean exit, so a killed run can delete a live one's.
Observed once: a `make check` went red on `check-script-docs-test` with four assertions failing `cd: .../clean: No such file or directory` after a separate `make scripts-test` in the same worktree was killed; the same tree passed on a re-run alone.

**The collision domain is one worktree, not the machine.** The path is under `$REPO_ROOT`, so sibling sessions in their own worktrees never collide, and a CI runner is fresh and runs once.
This is therefore not the mechanism behind [Q822](Q822.md)'s 8-worker observation, and it should not be read as closing it.
What it does reach is a single worktree running the suites twice at once, which is ordinary when a gate is backgrounded.

`mktemp` is the fix and it needs no new pattern: 46 of the 99 suites already use it, and the guard that makes agents prefer fixed paths in ad-hoc commands never inspects inside a committed script.
Source-readable throughout, so this is fixable without reproducing a race.
