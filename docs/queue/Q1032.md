# maintaining-backlog quotes a flake trigger 8 of 10 rows do not use

[maintaining-backlog.md:528](../development/maintaining-backlog.md#flake-fixes-go-first) says a flake-watch row's trigger "is always" `**Event:** recurs on main after the fix`, quoting `main` bare.

Measured 2026-08-29 over the ten `flake` + `status: deferred` rows, read per file rather than from a merged grep: backticked `` `main` `` in 8 ([Q1007](Q1007.md), [Q300](Q300.md), [Q549](Q549.md), [Q747](Q747.md), [Q823](Q823.md), [Q891](Q891.md), [Q968](Q968.md), [Q999](Q999.md)), bare `main` in 1 ([Q912](Q912.md)), and no `main` at all in 1 ([Q797](Q797.md), which delegates its trigger to Q1007).
The escalation clause the same sentence describes is written into 2 of the 10 ([Q747](Q747.md), [Q912](Q912.md)).

So the doc's "always" is false twice over, and the one row matching it literally is the outlier.
Nothing gates the wording, so a reviewer who reads the doc and a worker who reads the store disagree about what a correct row looks like; that already cost one review round on [#1793](https://github.com/actions-gateway/github-actions-gateway/pull/1793).

Two ways to settle it and they differ in cost, so this is a decision rather than a fix.
Either relax the doc to describe the mechanic and stop quoting a literal string, which leaves the 8 alone; or keep a literal and normalise the store, which needs the linter to enforce it or it drifts again.
Prefer the first: the trigger's *meaning* is what the revive mechanic turns on, and the rows already express it consistently.

Separate from [Q924](Q924.md), which is the same doc's flake section and a different defect: stale tool references (a deleted `lint-backlog.sh`, a `BACKLOG_ALLOW_FLAKE_DELETE` override no code reads).
Neither fix closes the other, but whoever takes one should read the other.
