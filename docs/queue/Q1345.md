# Pin a tenant's controllers and workers to separate pools in the samples

**The placement policy samples co-schedule a tenant's AGC and egress proxy with its workers.** Both `kyverno/restrict-gag-placement.yaml` and `gatekeeper/restrict-gag-placement.yaml` stamp one `nodeSelector` onto every pod in a tenant namespace, read from the namespace's `actions-gateway.com/node-pool` label.
Read from source at `b55697e25`: the Kyverno rule matches all pods in a labelled namespace, and its description says it pins "worker, egress-proxy, and AGC pods" to the one pool.
A worker that escapes onto one of those nodes can then read the AGC's GitHub App private key, which is the co-location [security-operations.md § Keep GAG's control plane off worker nodes](../operations/security-operations.md#keep-gags-control-plane-off-worker-nodes) tells operators to avoid.
That section, and a caution in `admission-policies.md`, now say not to apply the samples as written; the samples themselves are unchanged.

The fix is two pins rather than one, keyed on what each pod is.
The proxy pins to the tenant's egress pool, because its node decides the tenant's egress IP.
Workers pin to a worker pool, keyed on the controller-stamped `actions-gateway/component: workload` label.
In the default proxied mode a worker's GitHub traffic leaves through the proxy, so its own node does not decide the IP.
Direct-egress mode (no `proxyRef`) is the case to design for: there the worker's node does pick the IP, so the tenant pool has to carry workers, and the AGC needs somewhere else to run.
Whether the AGC's own GitHub traffic is proxied in every mode is unverified for this row; `migration-from-arc.md` says it is in proxied mode.

The toleration half is a validation that is sound where the pin was not: deny any non-worker pod in a GAG namespace that tolerates the worker pool's taint key, or carries a keyless `Exists`.
A toleration matches a taint by a fixed rule, so a finite deny list covers it, unlike a `nodeAffinity` allowlist.

**Done when** both samples pin the proxy and the workers to separate pools, deny the worker-pool toleration on non-worker pods, handle direct-egress mode or say why not, and `admission-policies.md` drops its caution for a description of the new shape.
