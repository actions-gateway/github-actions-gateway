# workflow-acting-steps-test cannot fail: it counts in a subshell

The suite prints `FAIL`, prints `all workflow acting-step tests passed`, and exits 0.

Measured 2026-09-21 on branch `claude/frosty-gauss-483196`, which differs from `main` in this file by one registry line.
I changed `check-covers-main` to expect rc 7 from a delegate that exits 0, ran the suite, and got the `FAIL check-covers-main want rc=7 got rc=0` line, the all-passed banner, and exit status 0.
The mutation was reverted; `git diff` against the branch head is empty.

**The mechanism.** `run_check`, `run_report` and `run_mike` are each called as `dir="$(run_… )"`. A command substitution is a subshell, so the `fails=$((fails + 1))` that `fail()` performs inside one increments a copy the parent never sees.
`fail()`'s own output goes to stderr and is not captured, which is why the line still appears and reads like a real failure report.
The function then hits `|| return 0`, `$dir` comes back empty, the `if [[ -n "$dir" ]]` block is skipped, and the rest of that case's assertions never run either.
Nothing counts the cases, so a case that vanished this way leaves no trace in the exit status.

Every case whose first assertion is the `expect_rc` inside one of those three helpers is affected.
The cases that call `expect_rc` at top level are not, and do count.

**The fix is written and measured**, in [`workflow-publish-steps-test.sh`](../../scripts/ci/workflow-publish-steps-test.sh), which had the same defect because it was built on this suite's shape.
A file-backed ledger: `fail()` and `pass()` append a line to `$WORK/failures` and `$WORK/reports`, and a `count_fails` reads the count back before it decides anything, because an append from a subshell does reach the parent.
That suite also gained two controls this one still lacks, and both belong here as part of the same change: a report count, so a case that vanished fails rather than shrinking the log, and a `registry-complete` line keyed on the registry's own findings rather than the global count, so a red run can still tell "the registry assertion passed" from "it never reported".
