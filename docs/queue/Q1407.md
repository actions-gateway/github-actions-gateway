# Read the kernel log beside the counters, as a reporter option

Blocked on [Q1406](Q1406.md), whose wait must end on the counters' five reasons alone.

PR 9b of Q1403's design: the witness half of the kernel-log option, whose reader half is built and off by default behind the chart's `kernelLog.enabled`.
The agent's report carries the reader's lines as numbers (a pod, a container, the level of the limit, a time) and the controller reads none of them, so until this lands the option runs a uid-0 `SYSLOG` container whose readings nothing uses.
What is left is the controller's two-witness table, the four `Log` reasons with their condition and Event words, their words in the failed job's record, and an e2e kill the counters miss, such as one made while the agent is absent, that reads a `Log` reason.
A `Log` reason replaces nothing but `Unknown`, where it disagrees with the counters theirs stands, and nothing in the AGC acts on one.
Its e2e lane is a run of `make e2e-oomreporter`, which installs the option already.

The kind lane runs the reader; on GKE, reading 10 is left for the release candidate's dogfood validation.
The duplicate search flags Q1403, which is the tool this is an option of.
