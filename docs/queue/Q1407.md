# Read the kernel log beside the counters, as a reporter option

Blocked on [Q1403](Q1403.md)'s PRs 5 and 6: the e2e lane it extends and the record it adds words to.

PR 9 of Q1403's design, off by default behind the reporter chart's own value: a second container at uid 0 with `CAP_SYSLOG` and nothing else, which reads the kernel's out-of-memory lines by `syslog(2)`.
It names some kills the counters leave `Unknown`, and loses lines the counters do not: the kernel prints ten in five seconds for a whole node (read, `oom_kill.c`, v6.12).
A line can be falsified, so its reasons have names of their own, the AGC never acts on one, and where it disagrees with the counters their reason stands.

The `syslog(2)` route is read from source and not run; reading 10 proves it, in CI's kind lane first and then on GKE.
It rides 2.1 where it is ready and does not gate it, which is why it is a row of its own.
The duplicate search flags Q1403, which is the tool this is an option of.
