# Skip known-futile re-runs on the existing disruption arms

The disruption arms (eviction, preemption, deletion, abandoned, vanished) spend a slot of `maxEvictionRetries` on any re-run they fire, and nothing in the re-run path checks whether a newer commit superseded the run, whether the run is at GitHub's 50-re-run cap (added 2026-04-10), or whether it is past the 30-day re-run window (read from `cmd/agc/internal/provisioner`, 2026-10-10).
Only a `cancelled` conclusion is checked, and only on the deletion arm (Q811).
A futile re-run costs a node, queue time and a budget slot, and ends in an Event saying a manual re-run is needed when nothing would help.
Add those checks before a slot is spent, skip with a reason label on a counter, and event the reason and its fix.
This needs no new retry class and no ledger, and helps today, independently of Q555 and Q1182: the abandoned arm keeps its exemption from the `run_cancelled` check, which Q1182 later replaces with a per-attempt record of GAG's own force-cancel ([design](../plan/q555-automatic-recovery-design.md#the-futility-checks-r18-in-order)); it is it is R18 of [the draft](../plan/q555-flaky-job-retry.md#known-futile-retries) applied to the arms that already exist.
Q1177 covers the futile storage-limit eviction separately.
