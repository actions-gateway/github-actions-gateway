# Round-trip the conversion webhook on real objects (GA soak criterion 3)

[v2-ga.md](../plan/v2-ga.md) Phase 1 criterion 3 requires the conversion webhook to have round-tripped every served version under real objects, including ones created before the `v2beta1` graduation, and no such reading exists.

The envtest fixtures cover the hop mechanically; what the criterion asks for is objects that lived on the dogfood cluster across the graduation, read back through each served version and compared field for field.
Q1104's `verify_conversion` step in `scripts/dogfood/setup.sh` is not that reading and does not close this: it reads the three tenant objects back at the deprecated served version on every bootstrap, which proves the webhook answers over TLS but compares no field and touches no pre-graduation object.
**The `v1alpha1` object this row nominated cannot serve, and the reason is mechanical.** An earlier reading here named `deploy/dogfood-migrate`'s `v1alpha1` `ActionsGateway` as "the pre-graduation object the criterion names, so the reading is available without manufacturing one".
Measured 2026-09-12: that object is `actions-gateway.github.com/v1alpha1`, and the v2 kinds are `actions-gateway.com` — two CRDs in two API groups (`actionsgateways.actions-gateway.github.com` serving `v1alpha1`, `actionsgateways.actions-gateway.com` serving `v2alpha1` and `v2beta1`).
A conversion webhook converts versions *within* one CRD and cannot cross groups, so no round-trip of that object through this webhook exists to take; reaching v2 from v1 is `gag-migrate`, a migration.
What criterion 3 can mean is the two **served** versions of the v2 CRD compared field for field, and an object predating the graduation is a `v2alpha1` object in that same group, not a v1 one.

**Wired 2026-09-12** as the `soak` phase of `scripts/dogfood/validate-release.sh`, which reads the standing tenant's `ActionsGateway` at both served versions and compares the specs, reporting a difference as the reading rather than failing the candidate.
Storage is `v2beta1`, so the `v2alpha1` read forces a conversion over TLS.
What remains for this row is a window that actually runs it, and a verdict recorded in the plan's Phase 1 table.
Rides in [release-1.8.md](../plan/release-1.8.md) rather than gating it, for the reason [Q1059](Q1059.md) gives.
