# The test-cache-input gate cannot see a subprocess's reads

Go's testlog records the `open`/`stat` calls the test process itself makes, so a test that shells out reads whatever the subprocess reads and keys on none of it.
Neither detector in the gate can reach that: one sweeps path literals, the other the test's own root derivation, and both read only the test's source.
The spelling is irrelevant, because the escaping read is not in the test at all.

Measured 2026-08-21 while closing Q936: five cached-tier tests call `exec.Command`.
Four (`cmd/worker/worker_test.go` and the three under `devtools/release/semverfloor/`) set `cmd.Dir` to a `t.TempDir()` they populate themselves, so they depend on nothing outside their own run and cache correctly.
The fifth, `cmd/probe/compat`, is in `UNCACHED` and forced to `-count=1`, but for its `os.Getwd` walk rather than for the `go list` subprocesses that actually read the tree.

**The hole went live the same day.** Q958's `TestGettingStarted_Executable` is the sixth, and the first to shell out against the repo rather than a temp dir: it execs `scripts/docs/doc-blocks.sh`, which sources `scripts/lib/common.sh` and reads the tree from the repo root.
It caches correctly only because the test also `os.ReadFile`s both, by hand, through `testdata/` symlinks.
That is the workaround this row exists to replace, and it is one an author has to know to write: nothing failed when it was absent, which is the whole defect.
A detector would flag `exec.Command` in a cached-tier test unless `cmd.Dir` is a temp dir the test created, which is a dataflow question a lexical sweep answers badly.
The hand-read workaround is not a discriminator either: it is indistinguishable from an ordinary fixture read.
Separate from Q936, whose shape detector does not see a subprocess at all: fixing that one does not close this.
