# A check-candidate-covers-main-test case exits 2 under load

**Event:** one failure inside `make check`, on a branch that touches no `scripts/release/` file, passing on an immediate rerun of the suite alone.

On 2026-10-27 at about 21:00 PDT, `make check` failed `scripts-test` on one case: `FAIL the same window's Actions bump moves nothing that ships (got exit 2)`, 10 passed and 1 failed.
The same suite passed inside a `make check` over a tree differing only by one new `docs/queue/` file about ten minutes earlier, and passed 11 of 11 when run alone a minute later.
Load average was 82 on 18 cores at the failure and 33 at the rerun.

Exit 2 is the subject's "could not measure" status, not a finding.
**Why it could not measure is unknown, because the case discards the subject's output**: `scripts/release/check-candidate-covers-main-test.sh:194:	(cd "$INCIDENT" && "$SUBJECT" 0d9a40cbc >/dev/null 2>&1) || neg_rc=$?`, where the positive case beside it keeps `inc_out` and prints it on failure.
So the first step is to print the subject's output on this case's failure as the positive case does, which is what turns the next occurrence into a diagnosis.

The mechanism is unverified; load is a correlation from one sighting, not a cause.

**Reach.** Every `make check` and every CI run of `scripts-test`: a red gate on PRs that did not touch release tooling.

**Diagnostic shipped, cause still unknown.** The case now keeps the subject's output and prints it on failure, as the positive case beside it does, so the next occurrence names which of the subject's exit-2 paths fired (a non-commit ref, no prerelease tag matching the outstanding release, or the delegate's `surface check failed (exit N)`).
Reproduction was tried on 2026-11-01 and did not produce the failure: the suite passed 5 of 5 (one alone at load average 65, then four concurrent copies at load average up to 113 on 18 cores), each run taking several minutes because the incident cases derive the real released surface with `go build` and `go list`.
That is evidence a load level alone does not trigger it, not a cause; the mechanism stays unverified.
The case still requires exit 0, because accepting exit 2 would turn "could not measure" into a pass.

A flake fix is unproven until it stops recurring, so this parks in flake watch rather than closing.
