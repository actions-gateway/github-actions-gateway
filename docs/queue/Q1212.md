# Dogfood tenant objects are written at actions-gateway.com/v2

1.10 makes `v2` the storage version (Q1086) and the onboarding docs move new tenants to `v2`, but the dogfood cluster's own tenant objects are still authored at `v2beta1`.
The cluster stores them as `v2` after the storage sweep either way; the manifests should say what the project now recommends, so the project runs what it tells new tenants to run.

Measured 2026-10-26 with `git grep -n 'actions-gateway\.com/v2beta1'`, the writers are the main tenant in `scripts/dogfood/setup.sh` (`ActionsGateway`, `RunnerTemplate`, `RunnerSet`), the on-demand e2e tenant in `deploy/dogfood-e2e/base/resources.yaml` with the `RunnerSet` patch targets in its `dind` and `kata` overlays, and the tests and READMEs that assert or describe them.
Every field they author exists on the `api/v2` types.

Out of scope: probes that name `v2beta1` on purpose, such as `validate-release.sh`'s Q1059 reading of every `v2beta1` kind, the conversion-webhook probe in `setup.sh`, and `deploy/dogfood-migrate`, which is the `v1alpha1` migration story.
