# `queue.py` cannot cite a path under a dot-directory such as `.github/`

`scripts/docs/queue.py:498`'s citation regex opens with `\b`, and a leading `.` is not a word character, so the boundary never holds before it.
A citation of `.github/workflows/security-scan.yml` with a line number is captured as `github/workflows/...`, which resolves from neither base.
The row then draws a note it can silence only by dropping the line number.
Measured 2026-08-18 against the shipped pattern; a path under `.claude/` loses its dot the same way.
No row cites such a path today, which is why nothing has caught it, and a `ci` row citing a workflow line is the likeliest one to.
Fix is `(?<![\w./-])` in place of `\b`; assert both directions, since a pattern that stops matching fails as silently as one that matches everything.
