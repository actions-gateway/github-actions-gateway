# Mirror battery fetches a digest manifest and a blob, not only a tag

`scripts/dogfood/e2e-mirror-validate.sh` proves each mirror instance by fetching one manifest by tag, and a tag lookup takes the Dragonfly seed peer's direct path, never its P2P rule.
So the battery cannot see a failure on the P2P path, and the release gate's Dragonfly leg reports green on it while the e2e run it dispatches then fails.

Measured on `v1.9.0-rc.2` (gate run 37273426462, 2026-10-05): the battery passed every instance, including `mirror-gcr-io`, and the e2e run's `docker-mirror-pull` failed because gcr.io answered the P2P path's manifest-by-digest fetch with 404 ([Q539 plan §7.1](../plan/q539-dragonfly-mirror-backend.md#71-the-first-dogfood-run-gcrio-manifests-on-the-p2p-path)).
The same blind spot leaves the gate's `dragonfly_p2p_reading` reading probe traffic that holds no blob, so it reported "no request took the P2P rule; 27 went direct" on that run.

The fix: for each instance, also resolve the tag's platform manifest by digest and fetch its smallest layer blob, check the blob's sha256 against its digest, and grade both like the existing checks.
Then the P2P reading has a blob to count, and a back end that breaks digest fetches fails the gate's battery a full e2e run earlier.
