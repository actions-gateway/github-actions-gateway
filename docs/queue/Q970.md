# `run-parallel-test` asserts a one-second ceiling on an instant command

[`run-parallel-test.sh:184`](../../scripts/ci/run-parallel-test.sh) asserts `^\[run-parallel\] +[01]s +quick$` against a command that is literally `true`, so the assertion holds only while spawn plus the fan-out's own measurement overhead stays under a second.
The generator is permanent and not specific to any one machine: any loaded host trips it, a CI runner under a busy queue included, and the failure then reads as a defect in `run-parallel.sh` rather than in the bound.
Measured 2026-08-24 with ~18 sessions live: it failed inside `make check` alongside `claude-go-throttle-hook-test` (throttle probe killed) and `queue-test`, and all three passed on individual rerun with no code change.
Local only so far; `scripts-test` was green in CI on the same tree, so this has not been observed on a runner.
The neighbouring `want_order` at line 189 rests on the same timing and is a second latent instance.
Also a contention datum for [Q822](Q822.md), whose cause is still unproven, but the assertion is a defect on its own terms and one fix does not close both.
