# `run-parallel-test` asserts a one-second ceiling on an instant command

[`scripts/ci/run-parallel-test.sh:184`](../../scripts/ci/run-parallel-test.sh) asserts `^\[run-parallel\] +[01]s +quick$`, and line 180 sets the fan-out up as `rp "quick:true" "slow:sleep 2"`, so the command under that bound is literally `true`. [`run-parallel.sh`](../../scripts/ci/run-parallel.sh) captures `started="$(date +%s)"` inside the child subshell (line 82) and writes `$(( $(date +%s) - started ))` (line 100), so the bounded span covers a `date` fork, the `bash -c` fork/exec, the `awk` fork/exec, pipeline teardown and a second `date`, integer-floored at both ends.
The assertion therefore encodes that four forks never take a second.
**Its intent is that the label appears in the timing block at all** — the test's own name is `a fast command is reported too` — so the seconds are incidental and the whole replacement is `^\[run-parallel\] +[0-9]+s +quick$`, not a larger ceiling.
`want_order` at line 189 is a second latent instance and needs a **different** fix in kind: an ordering claim cannot rest on a command with no duration floor, so it needs a real duration on both sides or the claim has to go.
Measured 2026-08-24 with ~18 sessions live: it failed inside `make check` beside `claude-go-throttle-hook-test` (throttle probe killed) and `queue-test`, all three passing on individual rerun with no code change.
**Not observed on a runner, and no docs-only PR can show otherwise:** `make scripts-test` runs in [unit-test.yml](../../.github/workflows/unit-test.yml)'s path-gated `shellcheck` job, which skips on a docs-only diff, so the runner evidence is the push-to-main runs (32836906076, `ubuntu-latest`, success) rather than any PR's green.
