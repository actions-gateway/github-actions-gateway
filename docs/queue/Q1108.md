# A drain whose claim loses the race still needs a manual re-run

A drained scale-set worker whose pod is gone before the recovery claim lands is reported and abandoned: `actions_gateway_eviction_recovery_evidence_lost_total{cause="deletion"}` increments, an `EvictionRecoveryEvidenceLost` Warning Event lands on the `RunnerSet`, and the run needs a manual re-run.
This closes that.

**It gates 1.8 by the maintainer's decision on 2026-09-13**, so that the release can claim drains are recovered rather than mostly recovered.
The class is not a 1.8 regression: it has shipped reported since `v1.5.0` (#1441, Q809), and 1.8's [Q1029](../plan/q549-scaleset-rerun-flake.md#mode-c-closed-2026-09-07-recovery-runs-off-the-worker-pod-watch) closes its invisible sibling, where a swallowed window produced no claim, no metric, no Event and no log line.
What is left is the visible half.

## What is measured

**Detection already works; the claim is what fails.** On the three `e2e-calico` failures Q809 attributed on 2026-08-12, `disruptionAwaitingRecovery` returned `cause: deletion` every time.
Two lost the pod before the patch (`pods "ssrec-drain-probe-1" not found`), one took a `Conflict` from the kubelet publishing the terminal phase.
The delete was issued at about 02:07:40 and the pod was unreadable by 02:07:42, well inside its 30-second grace period, because the runner traps `TERM` and exits at once.

**The pod is doing two jobs and only one has to survive the delete.** It is the evidence, which the AGC has already read off its informer by then, and it is the substrate the at-most-once claim is written on ([AnnotationEvictionHandledAt](../../cmd/agc/internal/provisioner/eviction_scaleset.go)).
The design's stated objection to acting on the cached copy is that two AGC replicas would each spend a slot of one run's retry budget.
That is an objection to acting with no claim, not to acting on a cached pod, so it dissolves if the claim lives somewhere that outlives the pod.

**The durable substrate already exists and already serves this purpose.** [Q844](../../cmd/agc/internal/provisioner/orphaned_scaleset.go)'s own contract is headed *What replaces the pod as the record*: the listener persists the run identity of every job whose worker it built into the per-RunnerSet guard ConfigMap it already writes ([Q606](../../cmd/agc/internal/controller/scaleset_guards.go)), owner-ref'd to the `RunnerSet` so the garbage collector reaps it, read uncached through the APIReader.
The AGC's permission contract already grants `configmaps: get, create, update` ([the fragment](../../charts/actions-gateway/files/agc-tenant-role-rules.yaml)).
So storage, lifecycle and RBAC are all settled before this row starts.

**Q844 excludes this class deliberately, on a premise that does not hold for it.** Its verdict is taken once per process and scoped to the AGC having been *absent* across the window, because "an entry this process created is covered by the live pod-watch recovery, so re-examining one can only produce a false positive".
`EvictionRecoveryEvidenceLost` is precisely the case where live pod-watch recovery ran and lost.
Those entries are assumed covered and are not.

## The open design question, which is this row's real work

**Unverified: the shape of the fix.** The obvious move is that a `NotFound` claim marks its existing `InFlight` entry *disruption observed, claim lost* instead of only emitting the Event, and recovery acts on the ledger, with at-most-once moving to the ConfigMap's own optimistic lock.

That breaks an invariant `orphaned_scaleset.go` states outright: "The owning reconciler reads the ConfigMap; it never writes it, so the listener's poll goroutine stays the single writer."
Making the reconciler a writer turns a single-writer object into a contended one, and the contention is per-`RunnerSet` rather than per-pod, so it is narrower than the pod annotation it replaces but wider than what is there now.

**Settle that before writing the fix, and weigh at least these:**

1. **Reconciler writes the same ConfigMap**, arbitrated by resourceVersion, with the retry-on-conflict shape Q809 already worked out for the pod claim.
   Cheapest in objects, and it is the invariant that has to give.
2. **A second ConfigMap owned by the reconciler**, leaving the listener's single-writer object alone.
   Costs an object per `RunnerSet` and a second read, and keeps two ledgers that can disagree.
3. **Move the whole ledger behind one writer** that both paths post to.
   Largest change; removes the question rather than answering it.
4. **A finalizer on the worker pod** closes the race outright and is rejected here unless someone argues it back: `kubectl drain` would then block on the AGC being alive, which is when a node gets drained, and [appendix-h](../design/appendix-h-v2-api-decomposition.md) already warns that finalizers are a common cause of stuck-`Terminating` resources.

A tenant can write in its own namespace, so whatever holds the claim is tenant-reachable.
That is already true of the pod annotation, and the exposure is a suppressed re-run rather than a forged one; say so explicitly in the design rather than leaving it implied.

## Done when

A drained scale-set worker whose pod is gone before the claim lands is recovered rather than reported, `eviction_recovery_evidence_lost_total{cause="deletion"}` has a reason to stay at zero, and the recovery is still at-most-once across replicas and restarts.
Verified by deleting the mechanism: the assertion that names the recovery must go red when the ledger write is removed, and an at-most-once assertion must go red when the arbitration is removed.
The e2e that owns this shape is `E2E_AGC_ScaleSetDrainedWorkerClaimAndRerunLandUnderChartRBAC` ([Q549](Q549.md)), whose re-staging on a lost claim exists only because the loss was unrecoverable.
