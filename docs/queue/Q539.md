# Validate the Dragonfly mirror back end on dogfood

Dragonfly fails the mirror contract as the endpoint workers reach: dfdaemon's proxy is an open forward proxy that forwards pushes, so it sits behind the five Distribution mirrors instead ([plan §2, §4](../plan/q539-dragonfly-mirror-backend.md)).
That back end is built and measured on kind: `E2E_MIRROR_BACKEND=dragonfly scripts/dogfood/e2e-start.sh`.
What remains is Phase 3, a booked dogfood session: the Q408 §3.7 battery, one Kata e2e run with its in-job negatives unchanged, blob `GET`s taking the P2P path in the seed peer's log, and a worker timing out on the seed proxy port.
The release gate is to take that reading on every candidate ([Q1160](Q1160.md)), and its first run discharges Phase 3.
Artifacts and cache saves stay out of scope, [per content class](../plan/caching-and-worker-storage.md).
