# An AGC shutdown can leak a scale-set session and lock its successor out

**Event:** `TestV2_RunnerSet_ScaleSet_RestartReclaimsWorkerOrphanedWhileDown` or `TestStopListeners_ThenEnsure_DoesNotLeaveASessionBehind` fails on `main`.

Filed as a flake in `RestartReclaimsWorkerOrphanedWhileDown`; the flake was the symptom and the defect is in shutdown.
The reconciler keeps serving queued reconciles while the manager drains, and no listener start path checked whether the drain had run.
A reconcile landing after it started a fresh listener and opened a session the drain would have deleted had it still been running, so the process exited holding one.
A scale set admits a single session and GitHub keeps it until its owner deletes it, so the successor AGC could never open its own: an operator-visible rollout stall, and the property [Q222](../design/appendix-h-v2-api-decomposition.md) exists to hold.

Measured 2026-08-27, `make test-integration` over the full `cmd/agc` suite, 1 red in 4 runs on one unchanged tree: the failure at 31.81 s against the 30 s `require.Eventually`, preceded by 16 consecutive `scaleset: session already exists (HTTP 409)` at the 2 s `scaleSetSessionRetry` cadence, all in the failing test's own namespace `v2-rs-ss-restart`.
The row's original guess that a neighbouring `v2-rs-ss-lifetime` session was interfering was wrong: that test owns a private `scalesettest` server and starts one manager it never restarts.
Both readings the row offered are refuted rather than unproven, because the stub expires no session: once one is held, no `Eventually` budget could ever have covered it.

Root cause proven deterministically in 0.09 s with no load, as a three-step sequence whose middle step is the control: start a listener (session present), drain (session gone, which is what makes the third step mean anything), then start again and find a session present that nothing will delete.

Mitigation: the drain is one-way.
`stopListeners` sets a `stopped` flag before draining and every start path refuses once it is set.
The census is four start paths across five sites, derived from the tree rather than recalled: the scale-set listener, both `getOrCreateMultiplexer` bodies, and the two restart branches.
An earlier revision of this fix claimed three and guarded four of the five, missing the classic RunnerSet `getOrCreateMultiplexer`; that function creates *and* starts, and `Reconcile` reaches it before the restart branch's own check, so the classic tier's guard covered only the restart case.
Only the scale-set path is measured.
The other four are fixed by symmetry, which is an argument rather than a measurement, and the classic tier is deprecated (ScaleSet is the default as of Q264 P5), so wiring broker scaffolding into a unit test to pin it is cost against a shrinking surface.
