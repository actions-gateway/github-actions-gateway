# `baseRefName` is the merge target, not what a stacked PR sits on

Nothing records how to ask what a stacked branch is based on, and the two `gh pr view` fields that look like the answer are not.

**Measured 2026-08-29** on [#1795](https://github.com/actions-gateway/github-actions-gateway/pull/1795), a PR stacked on #1794:

```
baseRefName  main         <- the merge target
baseRefOid   ef29e336f    <- origin/main's head, NOT the parent branch's
#1794 tip    42a94729c    <- what it actually sits on
```

A reviewer read `baseRefName: main` and reported the branch as rebased off #1794 onto main.
It was still stacked: `git merge-base --is-ancestor claude/hungry-mahavira-d19a81 b0eb56b69` returns 0, and `origin/main..b0eb56b69` carried all nine commits including the parent's.

**The natural repair does not work, which is why this is worth writing down rather than leaving to care.** Widening the read to `baseRefOid` returns a second description of the merge target, and it returns a plausible SHA, so the mistake survives the correction.
No `gh pr view` field answers what a branch sits on; only ancestry does, and `git merge-base --is-ancestor <parent-branch> <head>` is the whole check.

**Same shape as [Q1028](Q1028.md), and the two together sharpen it.** That row has the CI instance: a correct instrument aimed at a narrower question than the claim built on it.
What both instances add is *when* the substitution bites — each field equals the right answer except in the one case that makes anyone ask.
`baseRefName` equals what a branch sits on for every unstacked PR and diverges exactly when there is a stack; a workflow-level run conclusion equals job reality except when a path-gated job skips.
So a long history of the shortcut being right is not weak evidence, it is none: the shortcut is only ever exercised where it holds.
That is why a field read correctly a hundred times is not distrusted on the hundred-and-first, and it is the part neither instance states on its own.

Fixes are separable, which is why this is not folded into Q1028: that row replaces a CI recipe, this one records an ancestry check for stacked work, and neither closes the other.
Deliverable: the ancestry check in [parallel-dispatch.md](../development/parallel-dispatch.md), beside the rebase guidance, with the measurement above as the reason.
