# `ScaleSetWorkerEviction_DoesNotRecover` reruns via the orphan scan

**Event:** `TestAGC_Drain_ScaleSetWorkerEviction_DoesNotRecover` fails on `main` with a re-run, or any AGC logs `worker pod for an unconcluded job was gone when this AGC started` for a pod its own listener provisioned in the same process.

`TestAGC_Drain_ScaleSetWorkerEviction_DoesNotRecover` asserts that a scale-set worker evicted before any terminal phase is not re-run, and it failed with a re-run under `cause=vanished`: the AGC logged the orphan-scan warning for a pod its own listener had provisioned seconds earlier, in a process that never restarted.

**Sighted 2026-09-07**, on one tree, at a host load average of 75 to 120 on 18 cores: 3 failures in 5 runs on the branch that found it and 1 pass in 1 run on the base it was cut from, none of which touched the orphan scan.
The failing runs finish in 3 to 4.5 s because the `assert.Never` fires the moment the re-run lands.
It is load-dependent: 5 passes in 5 runs at a load average of about 5 on the same tree, which is why the fix was measured against the mechanism instead.

**Mechanism, measured directly.** `RecoverOrphanedScaleSetWorkers` took its once-per-process verdict when it first saw a **non-empty** in-flight set, not on the set's first reconcile: the caller returned early on an empty `state.InFlight` before the provisioner's `orphanScans.claim`.
The listener adds the in-flight entry on a successful provision, so the reconcile the pod's Create event enqueues can read the ConfigMap before the entry lands and consume nothing.
The spec then evicts the pod the instant it appears, envtest removes it at once, and the next reconcile is the first to see a non-empty set: the entry's pod is gone, so the scan reads it as a worker lost while the AGC was absent.
That is the false positive the file's own comment says the once-per-process rule exists to prevent ("an entry this process created is covered by the live pod-watch recovery, so re-examining one can only produce a false positive"), reached because the claim was keyed on the reading rather than on the process.

**Mitigated** by claiming the verdict on the first reconcile that reads the set at all, empty or not.
That dating is the one the design already documents — the reconcile runs ahead of this process's listener, so an empty reading is the answer "nothing was inherited" rather than a reading still to take — and the read that could not be taken still returns without claiming, so a failed ConfigMap read leaves the question open.
The spec's own race is kept as the tripwire rather than widened: the product defect is a live AGC re-running a job that never ran, and the fake accepts the `rerun-failed-jobs` a real GitHub would refuse.

Soak clock runs from the fix; blast radius is the AGC envtest suite, which runs on every PR touching `cmd/agc`.
