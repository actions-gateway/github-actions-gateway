# Registry read: the http bearer-realm failure is undocumented

`WorkerImageVersionUnknown`'s resolution names three of the ten failures `client.go` can return on the authentication path, and the other seven fall to the catch-all sentence about a registry that is out of reach or cannot be authenticated to.
That is correct advice for six of them.
The seventh is `registry <host>: bearer realm "<url>" is not https`, raised where a registry answers a `401` with a Bearer challenge whose realm is `http` (`fetchToken` refuses it, since the login would ride on that exchange in the clear).
Re-tagging cannot fix it and the registry is reachable, so the catch-all points the operator at the wrong remedy.

An internal or air-gapped mirror is exactly where an http realm shows up, which is also the audience Q1066's operator docs are written for, so the gap is not in an exotic corner.
Closing it is a clause in the same paragraph naming the message and saying the fix is on the registry: serve the token realm over TLS.

Whether any registry in use here actually emits an http realm is unmeasured; the code path is read from `cmd/agc/internal/runnerimage/client.go`.
