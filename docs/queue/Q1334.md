# Warn at admission when a gateway's GitHub host is not allowlisted

**An FQDN-mode EgressProxy leaves a referrer's GitHub Enterprise Server (GHES) host out of its policy until the platform allowlists it, and the tenant learns that only from a condition on the EgressProxy.** The reconciler sets `GitHubEgressIncomplete=True` with reason `GitHubHostNotAllowlisted`, but `kubectl apply` of the gateway or the RunnerSet returns clean.
An admission warning on the ActionsGateway and RunnerSet webhooks would say so at apply time: the bound pool is in an FQDN mode, the gateway's host is neither public GitHub nor covered by the platform egress allowlist, and a platform admin has to add it.

It is a warning and not a rejection for two reasons.
The allowlist's ConfigMap half and the proxy binding both change after admission, so the reconciler is the enforcement point whatever admission says.
A rejection is also a stricter admission rule, which needs a major, where a warning can ship in any minor.

The two webhooks hold no reference to `EgressDestinationAllowlist`, so the change includes wiring it into both validators.
How often a tenant applies a GHES gateway before the platform allowlists its host is unmeasured, and no report of the confusion exists, which is why this row is unscheduled.

**Done when** applying a gateway or RunnerSet that binds an FQDN-mode pool with an uncovered host returns a warning naming the host and the fix, an unchanged stored object is warned the same way and never refused, and `troubleshooting.md` quotes the warning.
