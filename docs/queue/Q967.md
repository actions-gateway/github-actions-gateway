# `golangci-lint` `run.timeout` cannot fire under the job budget above it

Measured 2026-08-24: `.golangci.yml` sets `run.timeout: 10m` as "a canary for a genuinely wedged analysis", and `unit-test.yml`'s `lint` job sets `timeout-minutes: 10` for the whole job.
The job also does checkout, `setup-go`, a cache restore, the linter build and seven `make` steps after `make lint`, so the job budget is always spent first and the canary never fires on CI.
What a wedged analysis produces there is a killed job with no linter diagnostic.

Same class as [Q823](Q823.md): an inner wall-clock budget chosen without reference to the outer one.
Either raise the job or lower `run.timeout` so the inner limit is reachable; the comment explaining the 5m-to-10m raise stays true either way.
