# endpoint-parity startup: the inherited-pipe mechanism is not this one

The trigger fired 2026-08-24 under `make check` on an unrelated branch, so this row is ready with evidence rather than deferred waiting for it.
Both instances went red in one run: `endpoint-parity-check` at the top level of the fan-out, and `check-endpoint-parity-test` inside `scripts-test`.
The top-level one reported `fakegithub was still running after 30s and never accepted on http://127.0.0.1:56220`.

Two findings, neither resting on what the fake did or did not write.
The recurrence is **after** the pipe-to-file change this row credits: `cmd.Stdout = logFile` landed 2026-08-18 in #1627 and the row was filed from that PR's retro, so the child's fds have been a private `*os.File` throughout, and an inherited-pipe write is not this occurrence's mechanism.
And the top-level gate is not under `scripts-test`, so the 85-suite nested fan-out this row blames was not in play for it either.
What is left is contention past the 30s bound: 45 gates and 90 suites concurrent on one host.
A second worker hit the same failure independently in the same window on a different port (55916 against 56220), with concurrent envtest also running on that host, which is a confound worth recording because it makes starvation more plausible and is unrecoverable once a session ends.

The failure also printed `(the fake wrote nothing, so it had not reached its first log line)`, and that clause **cannot** carry its own conclusion — a blocked write and a write that never happened look identical from outside.
That wording is `childLog`'s, in `devtools/e2e/endpointparity/probe.go`, so every future reader of this failure inherits the same over-claim; correcting it to state the observation rather than the inference is the cheapest part of this row.
Raising `readyTimeout` again is a bound rather than a fix; establish whether the child is scheduled at all before it binds.
The suite instance reported only `expected rc=0, got rc=2` because its shipped-tree case drops the checker's stderr, which is why only one of the two yielded any diagnosis.
