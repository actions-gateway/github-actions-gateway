# A patch line's e2e leg dispatches from main, not the candidate

`dispatch_e2e_run` defaults `E2E_DISPATCH_REF` to `main` (validate-release.sh:472), so the e2e matrix leg runs `main`'s copy of `e2e-test.yml` and its test code against the candidate's GAG runners.
For a minor cut from `main`'s head those are near enough the same tree.
For a patch cut off an older tag they are not, and Q879 made validating a patch line compulsory, so the case now happens by design rather than never.

Decide what a patch line should dispatch, and whether the default should be the candidate's ref rather than `main`.
The same tension is already documented at release.md's "A release line carries its own validation harness": the gate runs the scripts in your checkout against the artifacts of the tag, deliberately, so pinning the dispatch to the candidate is not obviously right either.
It may be that `main` is correct and only the runbook needs to say so.

Unmeasured: nobody has run the gate on a patch line.
The mechanism above is read off the source, not observed, and no patch release has ever been cut here (all seven stable tags are `.0`).
Surfaced by the review of #1788.
