# Worker egress admits most of Azure in 14 regions, not only GitHub

Every worker egress backend admits Azure endpoints GitHub does not operate, now recorded as an accepted residual in [05-security.md](../design/05-security.md#worker-exfiltration-to-azure-hosted-endpoints-inside-githubs-published-ranges) from public data, unprobed from a cluster.

Measured on 2026-11-12 from GitHub's `/meta` and Microsoft's `ServiceTags_Public_20261109.json`, IPv4 only ([the plan](../plan/q1253-azure-egress-residual.md#what-public-data-settles)): the `actions` key the GMC admits on 443 is 28.6 million addresses, all inside Azure's `AzureCloud` tag, and covers at least 97.5% of the address space of 14 regions.
Two of Microsoft's open-dataset storage accounts resolve into admitted East US ranges, so the row's original question (does a storage account nobody at GitHub owns land in the admitted set) is answered yes by resolution, and the residual is wider than storage.
The FQDN backends' `*.blob.core.windows.net` admits every account by name.

Blocked on the dogfood cluster, which is production: the remaining measurement is the plan's probe, a one-job workflow on a spike branch run against the e2e tenant's Kata pool, which needs no Azure account ([the probe](../plan/q1253-azure-egress-residual.md#the-probe)).

Done is that probe's result recorded in the plan and in 05-security.md, plus a decision on narrowing.
The FQDN backends can be narrowed from source to the 140 `productionresultssa<N>` names `/meta` publishes under `domains.actions`, at the cost of job failures whenever GitHub adds an account before the GMC's next refresh; direct mode and the CIDR-mode proxy cannot be narrowed by address without the same churn ([the options](../plan/q1253-azure-egress-residual.md#can-the-admitted-set-be-narrowed)).
Changing the default is a security-posture call, so the narrowing becomes its own row once chosen.
Found by Q215's Kata run, whose step 3 assumed blob storage was unreachable ([the Kata run](../plan/q215-worker-cache.md#the-kata-run-2026-11-01)).
