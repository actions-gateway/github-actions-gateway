# `test-integration` runs the whole module; CI runs one package

Both module Makefiles pass `./...` to [go-test-integration.sh](../../scripts/go/go-test-integration.sh), while [integration-test.yml](../../.github/workflows/integration-test.yml) and the wrapper's own default pass `./internal/controller/integration/...`.
Nothing is lost in CI: `go:build integration` files exist only in the integration package, so the extra packages are the module's unit tests re-run under `-race`, which `make test` already covers.
The cost is local.
Measured 2026-08-21 on `make -C cmd/gmc test-integration RUN=TestGMC_ApplyHelpers_NoSteadyStateChurn`: 13 packages reported an elapsed, 12 of them `[no tests to run]`, for 36.3s on top of the 21.5s the one selected test cost, plus every one of their `-race` compiles.
Which way to settle it needs the intent: narrow the Makefiles to the wrapper's default so local and CI agree, or keep the wider set deliberately and say why in [testing.md](../development/testing.md#the-envtest-suite-budget).
