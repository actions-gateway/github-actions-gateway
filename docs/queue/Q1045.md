# Two rows on one defect go unmatched when their titles barely overlap

Q922, Q924 and Q987 all described one defect, docs naming the deleted `lint-backlog.sh` as live.
Q922 and Q924 stood together for twelve days (filed 2026-08-18, closed 2026-08-30) and all three for five (Q987 filed 2026-08-25), which is how two sessions picked different rows and both fixes reached review before either noticed the other.

The half that cost the collision is fixed: rule 13 in `check-queue-rules.py` now fails an item a branch files when the matcher flags a candidate the row names nowhere.
This row is the half it does not reach.

Replayed 2026-08-30 with `find-duplicate-rows.sh --store` against the store as it stood when each was filed, passing each row's own `target:`:

- Filing Q922 with Q924 present surfaced [Q830](Q830.md) at 0.43, a false positive, and never showed Q924.
  `bare()` strips the anchor, so the two **do** share a target, and the relaxed same-target path is built for exactly this pair.
  It needs `TARGET_MIN_SHARED=2` shared content words and `TARGET_MIN_SCORE=0.25`.
  The titles share **one**, `backlog`, since `lint-backlog.sh` and `maintaining-backlog.md` both tokenize through it, which scores 1/7 = 0.143.
  So the word floor is not what blocks the pair: lowering it to 1 changes nothing, and the score floor has to come down to 0.10 before the pair surfaces, measured by moving each in turn.
- Filing Q987 surfaced Q922 at 0.50, so that pair was always within reach and only the advisory's silence let it through.

The two describe one defect at different altitudes, the class and one file's instance of it, which is the shape a title-only matcher cannot resolve.

Same-target-alone is not the answer, and this is measured rather than assumed.
Over the store at 6ee9e7848, before this row was retargeted: 184 of 192 items carry a target and 121 targets are distinct, so advising on target alone yields 219 pairs, 120 of them from the 16 items pointing at `testing.md`.
The tree matters because retargeting this one row moves two of those figures, to 122 distinct and 215 pairs, which is why the reading names where it was taken.
A filer targeting a popular doc would meet fifteen candidates every time and learn to skip the block.

What is unmeasured: the item **body** is the one signal nothing reads today, and these two rows do share body vocabulary where their titles do not.
Whether that holds across the store, and at what noise, wants an `--audit` variant before anyone changes a threshold.

Overlaps [Q693](Q693.md), the same blind spot reached from the other side, and the pair is worth reporting because the matcher's verdict on it has swung across every value while neither row changed what it is about.
Scored against the store at `2eec06d51`, varying only this row's own title and target:

| This row's title | target `maintaining-backlog.md` | target `find-duplicate-rows.sh` |
|---|---|---|
| `Two rows on one defect: a missed match and an ignored advisory` | not flagged | not flagged |

Only one of the eight combinations reaches Q693 at the score floor, and the title that does was carried for a matter of hours.
The target is the stronger variable: retargeting alone removes the pair under every title, so a row that moves to where its work lands stops being comparable to its own neighbours.
This row has done exactly that, and the prose citation above is the only durable link between the two, which is the argument for rule 13 reading bodies rather than trusting a score.
Rule 13 did not raise that pair because it scores only the items a branch *adds*, and this row was edited rather than filed; an item edited into a near-duplicate is invisible to it, which is a second residue worth knowing about.
