# Audience pill links go to the site root on pages outside operations/

`docs/javascripts/extra.js` links each audience pill to `../?persona=<tag>`, a path relative to the page, which reaches the operations index only from a page one level under `operations/`.
On [reference/README.md](../reference/README.md) the same href resolves to the site root, which has no persona chips, so clicking "Platform engineer" lands on the landing page unfiltered.
Measured 2026-09-29 on a local `make docs-build` of the dev scope: the pills on `/reference/` carry `href="../?persona=Platform%20engineer"`.

On the hosted site every other page carrying a single-line `> **Audience:**` blockquote sits under `operations/`, so `reference/` is the one live instance there.
**The offline export (`make docs-export`) breaks it on every page.** `mkdocs-offline.yml` enables Material's `offline` plugin, which turns directory URLs off, so a page is `operations/install.html` and `../?persona=` resolves to the export root rather than to `operations/index.html`.
`hooks/offline_links.py` repoints raw-HTML directory links at their `.html` file, but this href is built by JavaScript after load and never reaches it.
Found in review of the PR that filed this row: the export was built and its hrefs resolved with `urljoin`, and no browser rendered them, because `file://` pages render here without JavaScript.
`docs/design/github-protocol-dependencies.md` carries an audience line too, but it is a two-line blockquote, and the pill regex (`^Audience:\s*(.+)$`, no multiline flag) matches only a one-line one, so it stays a blockquote and makes no link.

The fix is to build the href from the site root rather than from the page, for instance from the `base` field of the `__config` JSON that MkDocs Material writes into every page (`"base": ".."` on `/reference/`), so the link is right wherever the page lives and in both publication scopes.
`base` alone still fails the export: it resolves to the `operations/` directory, which `file://` does not map to `index.html`, so with directory URLs off the href also needs an explicit `index.html`.
That second half is a proposal nobody has measured, so drive it in the export before shipping it.

**Done when** an audience pill on any published page, and on any page of the offline export, opens the operations index filtered to that persona.
