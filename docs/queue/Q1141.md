# Audience pill links go to the site root on pages outside operations/

`docs/javascripts/extra.js` links each audience pill to `../?persona=<tag>`, a path relative to the page, which reaches the operations index only from a page one level under `operations/`.
On [reference/README.md](../reference/README.md) the same href resolves to the site root, which has no persona chips, so clicking "Platform engineer" lands on the landing page unfiltered.
Measured 2026-09-29 on a local `make docs-build` of the dev scope: the pills on `/reference/` carry `href="../?persona=Platform%20engineer"`.

Every other page carrying a single-line `> **Audience:**` blockquote today sits under `operations/`, so `reference/` is the one live instance.
`docs/design/github-protocol-dependencies.md` carries an audience line too, but it is a two-line blockquote, and the pill regex (`^Audience:\s*(.+)$`, no multiline flag) matches only a one-line one, so it stays a blockquote and makes no link.

The fix is to build the href from the site root rather than from the page, for instance from the `base` field of the `__config` JSON that MkDocs Material writes into every page (`"base": ".."` on `/reference/`), so the link is right wherever the page lives and in both publication scopes.

**Done when** an audience pill on any published page opens the operations index filtered to that persona.
