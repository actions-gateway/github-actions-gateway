# The `v2.0.0` cut

Everything else under `v2.0.0` has landed but the tag: the coupled removals (Q273, Q264, Q1167), the storage advance (Q1086), Q1330's default refusal of fork pull request jobs, which breaks fork CI and so needed a major, and the operator docs and migration guide, which describe the surface `v2.0.0` ships with no served version it removes.

**What is left** is the release itself, run from `docs/operations/release.md`: the release candidate, its dogfood validation, and the tag.

**What the candidate has to confirm.** [upgrade.md](../operations/upgrade.md#action-required-at-v200-apply-the-crds-with-the-upgrade-because-the-agcs-watch-depends-on-them) states the upgrade and rollback order from a run on kind against `test/fakegithub` with workers held `Pending`, on 2026-11-06.
So a job running through the gap, and the same walk against github.com, are unmeasured until the candidate reaches dogfood.
`scripts/dogfood/setup.sh` applies the CRDs and then the chart, so a candidate's run crosses the gap and can give both readings; neither `release.md` nor the release-candidate skill has a step for taking them, so this row is what binds them.
A chart-first rollback was not measured either, and no candidate run measures it, so `upgrade.md` says so and it stays unmeasured.

**A candidate on or after about 2026-11-25 needs a newer e2e runner image first** ([Q1307](Q1307.md)): `scripts/dogfood/e2e-runner/Dockerfile` builds `dogfood-e2e-runner:2.338.1-2` on `dogfood-runner:2.338.1`, so its self-hosted e2e jobs should stop being queued then, which is read from the Dockerfile, not run.

**The label outlives the candidate on purpose.** The release-candidate skill's gating-row check lists this row until the tag closes it, so it is the one hit that check should return.

**Done when** the candidate's run has been read for a job running through the gap and for the walk against github.com, `upgrade.md` says what came back, and the tag is cut.
