# Confirm an RC gate run uploads a renderable soak-readings artifact

**Event:** the next `validate-candidate.yml` gate run on a release-candidate tag completes, green or red.

`validate-release.sh` appends each soak reading to `RELEASE_READINGS_FILE`, and `scripts/dogfood/soak-readings.sh` renders that stream as the rows of [v2-ga.md's readings table](../plan/v2-ga.md#soak-readings).
`validate-candidate.yml` points that file at `${{ runner.temp }}/soak-readings.jsonl` and uploads it as the `soak-readings-<attempt>` artifact under `if: always()`, so a CI gate run keeps its readings rather than leaving them only in the job log.

**What is measured and what is not.** Locally: an explicitly set `RELEASE_READINGS_FILE` wins over the derived default (`scripts/dogfood/lib/progress.sh:47`), and `soak-readings.sh --file` renders a record written that way.
`gh run download -n <name> -D <dir>` extracts a single-file artifact flat into `<dir>`, measured on gh 2.101.0.
No gate run on a real runner has produced the artifact, because that needs a release-candidate tag and a billable dogfood window, which no pull request can supply.

**The check.** On that run, follow step 6 of [the legs the gate runs](../operations/release.md#the-legs-the-gate-runs): `gh run download <run-id> -n soak-readings-<attempt> -D tmp/readings`, then `scripts/dogfood/soak-readings.sh --file tmp/readings/soak-readings.jsonl`.
A missing artifact or an empty render means the env or the upload is not wired the way the workflow reads, and the readings from that window are in its job log only.

**Done when** that run's `soak-readings-<attempt>` artifact renders as table rows with `soak-readings.sh --file`.
