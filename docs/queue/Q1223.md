# The CI release gate never uploads its soak readings

`validate-release.sh` appends one JSON record per soak reading to `tmp/soak-readings.jsonl`, and `scripts/dogfood/soak-readings.sh` renders that stream as the rows of [v2-ga.md's readings table](../plan/v2-ga.md#soak-readings), so that, in the script's own header, nothing there is transcribed by hand.
Since the gate moved into `validate-candidate.yml`, that stream is written on a hosted runner and dropped with it.

**Measured 2026-10-27.** `.github/workflows/validate-candidate.yml:128:        uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2` is the workflow's only upload, and its `path` is `${{ runner.temp }}/gate-evidence.txt`; nothing names the readings file or sets `RELEASE_READINGS_FILE`.
The readings survive only as prose in the job log.
Closing Q1048 needed the census verdicts from run 40407403332 (`v1.10.0-rc.2`), and they were read out of `gh run view --log` and typed into the table by hand, which is the transcription the renderer was written to remove.

**What it needs.** Point `RELEASE_READINGS_FILE` into `runner.temp` for the gate step and upload it beside the evidence under `if: always()`, so a red leg still keeps the readings taken before it.
Then the table's rows can again be `soak-readings.sh --file <downloaded artifact>` output.

Not a duplicate of Q1162 or Q1189, which `make queue-id` offered: both are about what the CI gate runs, and this is about what it keeps.

**Done when** a `validate-candidate.yml` run uploads a readings artifact that `soak-readings.sh --file` renders.
