# render-overflow-check fails when Playwright's browser target crashes

The `render-overflow` job failed in run 38081758922 (job 114300061125, head `07befb885`, 2026-10-10) and passed when that job was re-run with no code change.
It measured `site` at widths 320 and 1440 clean (63 pages, 126 measurements, 0 findings), began on `site-dev`, and about three minutes later raised from `measure`:

```text
playwright._impl._errors.Error: Page.set_viewport_size: Target crashed
```

So no page produced a finding; the browser tab died under the checker.
That head changed only Go and a few doc paragraphs, none of them layout.

This is a different symptom from Q1165, a navigation timeout, and the retry proposed for Q1165 does not reach it: as drafted it catches Playwright's `TimeoutError` from `page.goto` only.
The cause of the crash is unmeasured.
A crashed Chromium renderer on a hosted runner is usually memory pressure, and `site-dev` publishes the backlog, which is the largest scope the checker loads; that is a hypothesis, not a reading.

**A likely fix**: when a measurement raises `Target crashed`, open a fresh page (or browser context) and retry that path a bounded number of times, reporting a crash that persists as a failure that names the path.
First check the failed run's runner for memory, and whether one path crashes repeatedly, since a page that reliably kills the renderer is a finding rather than a flake.

**Reach.** Any run of the `render-overflow` job: a red that a re-run clears.
One occurrence observed; the rate is unmeasured.
