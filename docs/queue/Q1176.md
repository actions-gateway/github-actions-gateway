# render-overflow-check fails when Playwright's browser target crashes

**Event:** the `render-overflow` job fails on `main` with `Target crashed` after three attempts on one path, or fails because opening the fresh page itself raises (a whole-browser crash rather than one renderer's). → top of Queue, escalated.

The `render-overflow` job failed in run 38081758922 (job 114300061125, head `07befb885`, 2026-10-10) and passed when that job was re-run with no code change.
It measured `site` at widths 320 and 1440 clean (63 pages, 126 measurements, 0 findings), began on `site-dev`, and about three minutes later raised from `measure`:

```text
playwright._impl._errors.Error: Page.set_viewport_size: Target crashed
```

So no page produced a finding; the browser tab died under the checker.
That head changed only Go and a few doc paragraphs, none of them layout.

**Mitigated by [Q1165](Q1165.md)'s retry**, which owns the mechanism: since #2054 the checker retries each path's load, resize and measure up to three times, on a fresh page, for any Playwright error.
Measured 2026-10-10 on macOS against `11b992181`'s checker and its pinned Playwright: a probe drove the checker's own `retry()` on a local page, crashed the renderer with Chrome DevTools Protocol `Page.crash` after `goto`, then called `set_viewport_size`.
It raised `Page.set_viewport_size: Target crashed` (the CI message, word for word), printed the retry warning, and measured the path on attempt 2, in 10 of 10 rounds.
A Linux hosted runner was not tried.

**What the retry does not reach.** Opening the fresh page sits outside the retried call, so a crash of the whole browser, rather than one tab's renderer, still fails the job, and so does a path that crashes all three fresh pages.
The second would be a finding rather than a flake: a page that reliably kills the renderer.

The cause of the crash is unmeasured.
A crashed Chromium renderer on a hosted runner is usually memory pressure, and `site-dev` publishes the backlog, the largest scope the checker loads; that is a hypothesis, not a reading.
Q1165 measured no renderer growth across a local `site-dev` sweep on a Mac, and the runner's memory during a failure has not been read.

Soak counts `render-overflow` runs on `main` from #2054's merge, 2026-10-10.
One occurrence observed; the rate is unmeasured.
