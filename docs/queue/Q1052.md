# A PR whose workflows await approval blocks silently and forever

A withheld `action_required` run is indistinguishable from a PR nobody has pushed to, and it holds every PR that needs the fix.

## What selects them: the head commit's author

**Measured 2026-09-04 06:25 PDT.** A Dependabot PR's runs are withheld exactly when its **head commit is authored by `github-actions[bot]`**: that is, when one of this repo's own workflows has force-pushed to the branch with the default `GITHUB_TOKEN`.
Neither the ecosystem nor the fork origin selects anything:

| head commit author | n | run attempt | hold before start |
|---|---|---|---|
| `github-actions[bot]` | 10 | `2` on every one | 1m35s to 4d01h03m, median 6h35m |
| `dependabot[bot]` | 8 | `1` on every one | 0s on every one |

A clean 18/18 split over the last 40 Dependabot PRs, plus [#1821](https://github.com/actions-gateway/github-actions-gateway/pull/1821) and [#1823](https://github.com/actions-gateway/github-actions-gateway/pull/1823) held at attempt 1 right now.

```bash
# Withheld: head authored by github-actions[bot]
# run 33508119136, head 1851d3637e1ce1b0ad5489eea17b1430f35ab548  (#1821)
#   action_required, attempt=1, created == started == 2026-09-01T12:31:05Z
#   all 16 runs on that head read action_required
# run 33777861089, head 14c803185e0537835d22f555eabd70761f7b8444  (#1823)
#   action_required, attempt=1, created == started == 2026-09-03T16:18:46Z

# Ran normally: head authored by dependabot[bot]
# run 33508008216, head 87323a15a85031a8350d8095865b986a7123043d  (#1822, go_modules)
# run 33508277737, head 2608f62c05129085269e77f2051c075ea3878543  (#1824, github_actions)
```

**The ecosystem hypothesis is refuted outright.** #1822 is `go_modules` and ran; #1824 is `github_actions` and ran.
`go_modules` only *correlates* with the withholding because `dependabot-go-sync.yml` and `dependabot-rebase-stale.yml` rewrite Go-module branches and nothing else, so those are the only branches that ever acquire a `github-actions[bot]` head.

**The fork hypothesis is refuted directly.** Every head repository reads `actions-gateway/github-actions-gateway` with `fork: false`, and every run's event is `pull_request`, not `pull_request_target`.
The repository setting `actions/permissions/fork-pr-contributor-approval` reads `{"approval_policy": "first_time_contributors"}`, which is the only approval knob the API exposes on this repo.
But these branches are not forks, so **whether that setting is what withholds them is unverified**.
Confirming it means changing a repository setting and re-measuring, which needs admin access and is a live mutation; nothing short of that separates it from an unexposed rule keyed on the actor.

## Why it is invisible

`statusCheckRollup` is empty, so every instrument that reads a PR's checks reports *no checks* rather than *checks withheld*, which is the same answer it gives for a branch pushed seconds ago.
`mergeStateStatus` reads `BLOCKED`, which is also what a PR with a failing required check reads.
So the state has no signature of its own at either level, and the PR ages out of view.

**The durable fingerprint is `run_attempt`, not the conclusion.** Approving a withheld run overwrites `action_required` with the real result, so the evidence of the hold is erased from the conclusion and survives only as `run_attempt >= 2` with `run_started_at` well after `created_at`.
That is why a scan for `action_required` finds only PRs that are stuck *right now*, and why the ten historical cases above had to be recovered from the timing instead.

## The repo documents the opposite mechanism, in eight places

Eight assertions across the tree say GitHub **creates no runs** on a `GITHUB_TOKEN` push, and prescribe close + reopen as the remedy.
Both halves are wrong: 16 runs were created on #1821's head, and 9 of the 10 released PRs have exactly one unit-test run and **zero** `reopened` timeline events, so they were released in place rather than by close + reopen.
That is a separate defect with a separate fix and it is filed as Q1053, which cites this row for the measurement.
**Q1052 owns it**.

It belongs here because it is why nobody looked: the docs told every maintainer and every session that an empty check list was the expected, benign outcome of a sync.

## What it cost

[#1825](https://github.com/actions-gateway/github-actions-gateway/pull/1825) **merged 2026-09-03T16:16:25Z**, so its `CVE-2026-84304` episode is history and not a live cost.
It remains the worked example: run 33607824908 sat withheld from `2026-09-02T08:16:17Z` to `2026-09-03T15:51:29Z`, a span of 31h35m, while a HIGH severity CVE stayed live on `main`'s dependencies and two unrelated dispatch-batch PRs were hard-blocked on `trivy (agc, 1)`, `trivy (gmc, 1)` and `security-scan-gate`.

Two sessions independently diagnosed the CVE, and both searched the open PRs for `trivy` and `CVE`, the symptom's vocabulary, which a dependency bump's title carries neither of.
Only searching the package the scanner named reached #1825.

The live cost today is #1821 (withheld since 2026-09-01) and #1823 (since 2026-09-03).

## Done when

An open PR whose runs are all withheld cannot age silently.

**The mechanism is a maintainer's call and is deliberately still not chosen**, because the two arms differ in preference and in access rather than in evidence:

- **Remove the approval requirement for this actor.** Closes the row outright with nothing to detect.
  Needs repository-admin access, and rests on the unverified attribution above: if `first_time_contributors` is not what withholds these, there is no knob here to turn.
  On a public repository, relaxing it also weakens the approval gate for genuine fork PRs, which is a security-property regression and needs sign-off under the secure-by-default rule.
- **Detect and name such PRs** via a scheduled check or a `make doctor` probe.
  Nothing today inspects withheld-run state on open PRs: `make doctor` checks local tooling only, `pr-mergeability-watch.py` reads one PR and no checks, and `dependabot-rebase-stale.sh` selects on conflict state.
  **The durability finding above is this arm's shaping constraint, not a detail of it.** Approval overwrites `action_required`, so a probe keyed on that conclusion can only ever see what is withheld at the instant it runs, and is blind by construction to every case already released.
  A probe that must also account for history has to key on `run_attempt >= 2` with `run_started_at` well after `created_at`, which is a different query against different fields, and it is the only query that can measure how often this happens.
  Detection does not stop the withholding either, so every affected PR still needs a manual release.

A third arm the original row did not consider: **stop creating the condition**, or have the pushing workflow release its own runs via `POST /actions/runs/{run_id}/approve` with `actions: write`.
Whether a `GITHUB_TOKEN` may approve a run it caused is **unverified** and is the first thing to measure if this arm is taken.

**A probe built for the second arm names both directions**: a head authored by `github-actions[bot]` with `action_required` runs must go red, and #1822 and #1824, which are `dependabot[bot]` heads at attempt 1, must stay green.
Selectivity is the open question: the condition held on 10 of 40 recent Dependabot PRs but on only 2 at any given moment, so a probe that reports every historical case will fire constantly and be ignored.

Found by the dispatch run of 2026-09-03, which lost two of its eight PRs to it.
