# GMC pod templates revert foreign annotations and labels each reconcile

Every GMC-managed Deployment loses any pod-template annotation or label the GMC did not write, on the next reconcile.
`assignManagedPodTemplate` does `*live = desired` and carries over only `kubectl.kubernetes.io/restartedAt` (Q552); both `assignManagedDeploymentSpec` and `assignHPATargetDeploymentSpec` route through it, so this covers the AGC Deployment and both proxy pools.
An operator who adds a mesh opt-in (`sidecar.istio.io/inject`), a workload-identity pod label, or lets Stakater Reloader stamp its annotation sees it reverted, and the rollout it triggered is rolled back.
Read from source 2026-10-27 at `e1e2dd9a2`, not exercised against a cluster.

Q552 chose a single tolerated key on purpose: its comment says arbitrary hand-edited annotations should still revert and "a key the builders stop setting cannot linger forever".
The second half is a real constraint here, which is why this is not the plain merge Q1215 used for metadata labels.
The builders set pod-template keys conditionally: `actions-gateway.com/attribution-ca` only while attribution has ports (`egressproxy_attribution.go:295:if dep.Spec.Template.Annotations == nil {`), and `actions-gateway/github-app-secret` only when a credential Secret name is set (`shared_agc_deployment.go:250:var podAnnotations map[string]string`).
Under a plain merge, turning either off leaves the stale key on every pod.

**Done when** the GMC tracks the pod-template annotation and label keys it wrote on the previous apply (for example a metadata annotation on the Deployment listing them), removes a tracked key the builders no longer set, writes every key they do set, and leaves every other key alone.
Unit tests seed a foreign template annotation and a foreign template label and assert both survive; a second test turns a conditional key off and asserts it is removed.
Each must go red against today's `assignManagedPodTemplate`.
`docs/design/02-architecture.md` and the Q552 comment in `deployment_restart_annotation.go` are updated to the new rule, and the operator-facing docs say a hand-added template key now persists.
Metadata annotations need nothing: no apply closure writes them, and the one the GMC owns (`annAttributionHeld`) is set and deleted per key.
