# `gag-migrate` no longer needs to pin `acquisitionProtocol: Classic`

It writes Classic onto every set it emits, whose stated reason — keeping multi-label matching — Q726 removed.
Now conservative rather than necessary, but flipping it changes a migrating tenant's protocol silently, so it is a decision, not a cleanup.

**Ask:** whether `gag-migrate` may stop writing `acquisitionProtocol: Classic`.
Flipping it changes the acquisition protocol of every set a tenant migrates, silently and without their asking, on a tool whose whole promise is a faithful translation of what they already run.
The technical reason for the pin is gone (Q726), so nothing here is a measurement: what is left is whether a migration tool is allowed to improve on its input.

The question now has an end date: `gag-migrate` emits `v2alpha1` objects (`cmd/gmc/internal/migrate/migrate.go:1:// Package migrate implements the one-shot v1alpha1 → v2alpha1 fan-out the M5`), and `v2.0.0` removes both `v2alpha1` and classic acquisition ([v2-ga.md](../plan/v2-ga.md#phase-3--the-storage-advance-and-the-coupled-removals)).
Every set it writes as Classic changes protocol at that upgrade whatever is decided here, so the answer governs only the 1.x window between a migration and the `v2.0.0` upgrade.
