# The slow-command patterns match a mention, and miss a real spelling

`slow.commands` holds seven patterns and only the two `scripts/dogfood/*.sh` ones carry a command anchor.
The five `make`/`go test` patterns are matched with `re.search` against the whole raw command string, so any text naming a tier matches.
Measured 2026-09-16 by driving foreground-guard 0.7.0: a foreground `git grep -n 'make e2e' docs/` is denied as a slow command needing a 1800000 ms timeout, and so is this session's own Bash call whose only offence was carrying a tier name inside a test matrix.

This is the class `CLAUDE.md` already names under *Adding a pattern to a hook registry*: these hooks search the whole raw string, so a pattern naming a command also matches a `git show` or a commit message quoting it.
The cost is a deny whose remediation does not apply, on a command that was never slow, and a session that learns to reach for `FOREGROUND_GUARD_OVERRIDE` by reflex.

There is a second defect in the same seven patterns, pointing the other way.
They want exactly one space, and `(-C [^ ]+ )?` cannot absorb a second, so spellings bash runs identically match nothing at all: `make  test-race` with two spaces, a tab separator, an escaped newline, `make -C  cmd/agc test-integration`, and `go  test -race ./...`.
Measured 2026-09-16 with a `printf` positive control confirming all four spellings invoke the command identically, exit 0.
That is a slow tier running with no timeout warning, which is the direction the registry exists to catch.

Fix: anchor each of the five to command position, in the shape the two dogfood patterns already use, tolerate runs of whitespace where the patterns currently hardcode one space, and assert both directions in `scripts/agent/foreground-guard-patterns-test.sh`: a pattern that stops matching fails as silently as one that matches everything.
`scripts/agent/record-launch-guard.py` reads this same registry and now handles both halves on its own side, by lexing the command, collapsing whitespace runs and matching at command position; its suite carries seven mention-only negatives and five whitespace-spelling denies that this row's fix should make redundant there.
The two copies deliberately disagree until then, which is itself a reason to close this rather than leave it.

Notes: the registry is shared, so a change here moves foreground-guard's matching for every session in the repo, which is why the launch-record guard fixed its own side rather than this file.
Check the plugin's negatives still pass before and after; a regex that over-anchors silently stops catching the real slow tier, which is the expensive direction.
