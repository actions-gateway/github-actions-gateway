# unit-test skips a PR that edits only files its tests read by symlink

A pull request that changes only `deploy/templates/` does not run `TestTemplateLibrary_PodShape`, the test that checks each shipped runner template is admitted, so the required `unit-test-gate` reports green without it.
[#2436](https://github.com/actions-gateway/github-actions-gateway/pull/2436) is the specimen: it edited `deploy/templates/privileged-dind/template.yaml`, and on its head `7198d17` the `unit-test`, `coverage` and `lint` jobs read `skipped`.

The cause is the `code:` list in `unit-test.yml`.
`.github/workflows/unit-test.yml:478:if: needs.changes.outputs.code == 'true' || github.event_name == 'push'` gates the job, and `.github/workflows/unit-test.yml:141:- 'deploy/templates/**'` sits under `scripts`, not under `code`.
The test reads the tree through `cmd/gmc/internal/webhook/v2/testdata/templates`, a committed symlink.
No other tier covers it: `integration-test` runs on the PR, but its `cmd/gmc` leg tests `./internal/controller/integration/...` only.

**The merge group skips it too.** Read from the workflow on 2026-11-26, not observed in a run: the job's `if:` names `push` and `workflow_dispatch` and no `merge_group`, so a queue candidate is decided by the same `code:` list.
The `push` run on `main` does run the job whatever the filter says, so for a template the first verdict comes after the merge.

**Other trees look uncovered the same way.** Listed on 2026-11-26 from the committed `testdata/` symlinks whose target no `code:` pattern matches and which an untagged `_test.go` names; each test was matched by name and none was run against an edit:

| Link target | Test naming it |
|---|---|
| `deploy/templates` | `cmd/gmc/internal/webhook/v2/runnertemplate_podshape_test.go` |
| `charts/actions-gateway/files` | `cmd/agc/internal/controller/rbac_chart_drift_test.go` |
| `charts/actions-gateway/templates` | `cmd/gmc/internal/controller/admission_policy_coverage_test.go` |
| `testdata/crypto_fixture.json` (repo root) | `broker/crypto_test.go` |
| `docs/development/broker-compatibility.md` | `cmd/probe/compat/compat_test.go` |

The last is under `docs/**`, which the `push` trigger's `paths-ignore` also drops, so a change to that file alone runs the test nowhere.

- Add the missing targets to `code:`, as `charts/oom-reporter/templates/**` and `Dockerfile` already are for the same reason.
- Settle `broker-compatibility.md` separately if charging its edits a Go run is not wanted.

[Q948](Q948.md) is the wider gap and not a duplicate: it is the missing check that any filter covers what its jobs read, and adding these patterns does not build it.
The symlinks are a machine-readable list of Go test inputs, which may answer part of the map Q948 says it needs.
