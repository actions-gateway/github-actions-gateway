# Nothing schedules the mirror client census in a dogfood window

The reading Q1026 was written to take before its own narrowing has still never been taken, and no checklist asks for it.

**Measured 2026-09-03.** No workflow invokes `scripts/dogfood/e2e-mirror-clients.sh` and no runbook step asks for it.
Outside its own unit test and the `mk/gate-lists.mk` entry that runs that test, every mention of it in the tree is prose: `scripts/README.md`, `deploy/registry-mirror/README.md`, and backlog rows.
Its three siblings are all scheduled: `docs/operations/kata-dind-workloads.md` names `e2e-mirror-validate.sh`, `e2e-mirror-hits.sh` and `mirror-timing.sh` as window checks, and the census is the one omission.

**What it would have said.** The script resolves every address that reached a mirror to a pod or a node and reports whether each carries `actions-gateway/component=workload`, the label the shared topology's ingress peer now ANDs into its `from` element.
That is a prediction of who the narrowing cuts off, and it is valid under the isolated topology the dogfood cluster actually runs, because it is a census of clients rather than a grading of a policy.
It is also the reading that reaches a Kata worker's real source address on GKE Dataplane V2, which no kind lane can stand in for: `E2E_Mirror_SharedTenantsNP` ([`cmd/gmc/test/e2e/mirror_np_test.go`](../../cmd/gmc/test/e2e/mirror_np_test.go)) grades the peer expression on a Calico kind cluster with a curl pod, and names this census as its residual.

**Why it is small and not urgent.** Every client in this repository is a container of an AGC-provisioned worker pod, and `pod.go` sets the label unconditionally, so the source read says the census should pass.
That is precisely why it is worth taking rather than assuming: the script's own header says a source read has checked the clients somebody thought of.
The cost of never taking it is borne by an adopter running the shared topology, once per adoption, against a failure that is total for the client it misses.

**What it needs.** A line in `kata-dind-workloads.md`'s window checklist beside its three siblings, and a step in the Kata leg's sequence that runs it while the workers are still up: the script exits 2 rather than passing when an address no longer resolves, so it cannot be run after `e2e-stop.sh`.
**Q1038 answered its half on 2026-09-12 and the answer is `e2e-reusable.yml`.** `mirror-timing.sh` runs there as a step (`e2e-reusable.yml:718`), and the `v1.8.0-rc.1` validation window gave it its first live run against a real mirror: `4 references through mirror-docker-io…, one cold fetch and one warm fetch each`, verdict `SEPARATED  every hit (<=46ms) was faster than every miss (>=147ms)`, without failing the e2e job.
So the placement question this row was holding open is settled by demonstration rather than by argument, and the census should take the same route.
Q1038 is closed; this row inherits the caution it carried, that an exit 2 is a reading that was not taken and not a finding.

**The same window did not take this reading**, which is the row's own point restated by events: nothing invokes `scripts/dogfood/e2e-mirror-clients.sh`, so the candidate's window came and went without it, and teardown scaled the mirror deployments to zero, taking the access logs the census reads with the pods.
A reading now is impossible until another window opens.

**Done when** one window has produced a verdict from the script and this row records which one.
