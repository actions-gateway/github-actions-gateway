# Bump CA_VERSION to v1.37 once cluster-autoscaler publishes it

Blocked on a `v1.37.*` tag in `registry.k8s.io/autoscaling/cluster-autoscaler`.

Kind v0.33.0 (PR #2140) moves the live-autoscaler drift harness onto Kubernetes v1.37.0, since the harness runs kind's default node image, and `CA_VERSION` stays at v1.36.1.
[testing.md](../development/testing.md#its-cadence-the-version-bump-not-a-clock) says the CA minor must follow the kind bump in the same PR, because a new CA minor is where an event-vocabulary reword lands; that could not happen here, as `registry.k8s.io/autoscaling/cluster-autoscaler` held no v1.37 tag on 2026-10-27 (newest v1.36.1).

Nothing else will prompt the move.
The kind bump was the trigger, and [`updatecli.d/cluster-autoscaler.yaml`](../../updatecli.d/cluster-autoscaler.yaml) moves only the patch within the pinned minor, so v1.37.0 publishing opens no PR.
The skew does not fail the gate either: the drift job on #2140 ran v1.36.1 against a v1.37.0 node and passed all three `TestLiveClusterAutoscaler_*` tests (run 40329218360), so the docs' "fails on version skew" signal does not fire for a one-minor skew.

Once it lands, set `CA_VERSION` to it, which runs the drift gate against the new minor, and correct the testing.md sentence that says the gate fails on skew.
