# Retype the controllers onto v2, move the hub, drop v2alpha1 and v2beta1

Blocked until 1.10 tags: a version still named in a CRD's `storedVersions` cannot leave its `spec.versions`, so nothing here can drop a served version until the storage migration has run on every cluster that upgrades.
Q1086 shipped that migration for 1.10 as `gag-migrate storage-version`.

The `actions-gateway.com` half of Phase 3, which no row owned until the 2.0 scope was reviewed on 2026-10-09.
[Q273](Q273.md) removes the `actions-gateway.github.com` group (`v1alpha1`) and [Q264](Q264.md) the classic acquisition machinery, and neither reaches the `v2` group's own versions.
Three things, measured 2026-10-09 off `main`:

- **The controllers are typed on `v2alpha1`.** 43 non-test Go files import `api/v2alpha1` (180 with tests), 24 of them under `cmd/gmc/internal` and 15 under `cmd/agc/internal`, the reconcilers included.
  Removing the version removes the types they compile against, so they move onto `api/v2` first.
- **The conversion hub is `v2beta1`.** `api/v2beta1/conversion.go` carries the five `Hub()` methods, and [v2-ga.md](../plan/v2-ga.md#the-hub-stays-at-v2beta1) kept it there on purpose for 1.9.
  Dropping `v2beta1` means `v2` becomes the hub and the conversion code is rewritten around it, or deleted once `v2` is the only served version.
- **Every kind still serves three versions.** Each CRD in `charts/actions-gateway-crds-v2/` lists `v2alpha1`, `v2beta1` and `v2`, and the `v2.0.0` CRDs list `v2` alone.

Ships in the `v2.0.0` bundle beside Q273 and Q264, after the 1.10 tag, since `main`'s next tag once a served version is gone is `v2.0.0`.
Sized `L` on the file count; how the retype splits into PRs is the first thing to decide when it is picked up.
