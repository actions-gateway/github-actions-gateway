# Drop v2alpha1, v2beta1 and the conversion hub after the v2 retype

This is the last of three PRs, after Q1262 and Q1263 retyped the GMC and the AGC, and it deletes `api/v2alpha1` and `api/v2beta1`, which compile only once nothing outside them imports either.
In the AGC that is `integration/conversion_webhook_test.go`, `v2alpha1_crd_test.go` and the suite's scheme registration, which Q1263 left for this PR.
[q1167-v2-retype-split.md](../plan/q1167-v2-retype-split.md) is the split and the import-graph evidence that each step leaves `main` building.

The PR deletes both packages, `api/v2/conversion.go`, the conversion webhook (`cmd/gmc/internal/webhook/v2beta1/`) and its readers, and the `conversion:` stanza of every CRD in `charts/actions-gateway-crds-v2/`, which then serve `v2` alone.
It also retypes the GMC's classic-reading trio, `scalesetscope.go`, `webhook/v2/runnerset_read.go` and `agentidentity.go`, which Q1262 left on `v2alpha1` because Q264 had not landed, and drops the test helpers that store each fixture at both versions for them ([what Q1262 left](../plan/q1167-v2-retype-split.md#what-q1262-left-on-the-older-versions)).
Until then the GMC's cache holds two informers for `ActionsGateway` and `RunnerSet`: `evalScaleSetNameCollisions` lists them at `v2alpha1` through the reconciler's cached client while the controllers watch `v2`, so every listed object also passes through the conversion webhook.
That was read from controller-runtime's GVK-keyed informer map and not measured; retyping `scalesetscope` removes it.
The hub is deleted rather than moved to `v2`: with one served version there is nothing to convert ([why](../plan/q1167-v2-retype-split.md#the-hub-delete-the-conversion-dont-move-it)).
`gag-migrate storage-version` survives `v2.0.0` and reads `EgressProxy` at `v2beta1` against a 1.10 cluster on purpose, so `cmd/gmc/internal/migrate/storageversion.go` swaps its import of the deleted package for the version string and the two alias values held locally rather than retyping.
It also has to run against a `v2`-only cluster, which today it cannot: it lists `EgressProxy` at `v2beta1` before its "already `[v2]`" short-circuit, and the candidate gate's default `storage` leg runs the candidate's own sweep after applying its CRDs ([item 6](../plan/q1167-v2-retype-split.md#what-compiles-and-still-breaks)); skip the alias check when every kind stores `[v2]`, or read a no-match as no aliases, and test it against a `v2`-only CRD set.
`RunnerSet`'s godoc in `api/v2` explains declaring its selectable field on two of three versions, which stops applying once `v2` is the only one.
`TestV2_RunnerSet_GatewayRefSelectableField` lives in `v2alpha1_crd_test.go`, which this PR deletes, so move it first: it pins the selectable field the AGC's watch needs.
`scripts/go/check-v2-api-sync.sh`, its Makefile target and its `unit-test.yml` step go with the packages, since a stale exemption entry fails it.

Seven things the build does not catch are this PR's ([list](../plan/q1167-v2-retype-split.md#what-compiles-and-still-breaks)), and three are silent:

- `charts/actions-gateway/templates/tenant-resource-guard.yaml` matches `runnersets` at `v2alpha1` alone and stops confining the GMC's writes once that version is not served; `make webhook-versions-check` reads only the controller-gen webhook manifest, so this PR retargets the rule and widens the gate to the chart's admission policies.
- `cmd/gmc/internal/controller/crd_schema.go` checks fields at `v2beta1` and `v2alpha1` by name at GMC startup and has to move to `v2`.
- Objects a `v1.10.0` AGC created keep an owner reference naming `actions-gateway.com/v2alpha1`, which `v2.0.0` no longer serves ([item 7](../plan/q1167-v2-retype-split.md#what-compiles-and-still-breaks)).
  Worker pods are short-lived, but three ConfigMaps per `RunnerSet` are not: the scale-set guard, the recovery claims and the failure ledger take the reference at create, and later writes change only `Data`.
  Measure what the garbage collector does on a real controller-manager, since envtest runs none, and fix what the measurement finds.

`make chart-released-upgrade-check` is expected to pass, because a fresh 1.10 install stores at `v2` only, but the e2e lanes that run it are merge-group-only: take `make e2e` before enqueueing.
Draft PR #2084 (Q1066) edits all three `v2` API packages; whichever lands second rebases.

The `storedVersions` precondition the 1.10 tag was waiting on is met: `v1.10.0` tagged 2026-10-27 with `gag-migrate storage-version` (Q1086).
