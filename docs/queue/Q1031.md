# go-throttle's probe is killed under host load, denying a -race rewrite

`claude-go-throttle-hook-test` fails its `safety: -race not throttled by rewrite` case when the machine is loaded, and the hook it exercises denies the command rather than throttling it.

**Measured 2026-08-29 00:45 PDT**, in `make check` on a branch touching no file under `scripts/agent/`: the suite failed, took 163 s (the slowest of the 115), and the hook returned a deny whose own reason names the cause: `throttle probe failed after 5.805s: scripts/agent/local-throttle.sh prefix: signal: killed`.
The host was at load average 40.82 over 18 cores.
Re-run alone six minutes later on the same tree: exit 0.

So the mechanism is not in doubt and does not need re-deriving: `local-throttle.sh prefix` has its own timeout, the probe exceeds it when the box is oversubscribed, and `gothrottle` is correct to fail closed, since an unthrottled `-race` can freeze the GUI, which is the incident the throttle exists for (Q92, long closed and so no longer a row).
What is wrong is that the closed failure lands on a *test* that asserts the rewrite, so a loaded machine reddens `make check` for a branch that changed nothing near it.

Two candidate fixes, neither measured:

- Give the probe a longer or load-aware budget, so it answers under the load this repository's own gate generates.
  `make check` runs 115 suites through `run-parallel.sh`, so the gate is itself a source of the load that breaks it.
- Or stub the probe in the test.
  The case asserts the *rewrite*, not that a live probe answers, so a test that depends on probe timing is measuring the host as well as the hook, which is the shape [testing.md § A test's environment assumptions must be probed](../development/testing.md#a-tests-environment-assumptions-must-be-probed-not-inferred) names.

The second is more likely right, because the first leaves the same failure available on a busier machine.
Confirm which by reproducing under a synthetic load rather than waiting for it to recur.

Adjacent to [Q822](Q822.md) and not a duplicate of it, which is worth stating because `make queue-id` surfaced no near-duplicate and the titles share almost no words.
Q822 is the generic class, suites that fail under concurrent load and pass on rerun, and its open question is whether to cap `run-parallel.sh`'s fan-out, which it calls a machine-wide throughput decision.
It also says plainly that nothing under it reproduces a suite failing *because of* the fan-out, since a property of the runner and a failure traced to it are separate claims.
This row is that traced instance: the hook's own deny reason names the mechanism, so the causal step Q822 lacks is in hand here.
The fixes are independent in the useful direction, which is why they stay separate rows: capping the fan-out would probably close both and needs the throughput decision, while stubbing the probe closes this one and needs nothing.
