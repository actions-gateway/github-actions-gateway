# release.md detaches the gate with nohup, bypassing the launch record

`docs/operations/release.md:394` detaches the release-validation gate as `nohup scripts/dogfood/validate-release.sh vX.Y.Z-rc.N >tmp/validate-release.log 2>&1 &`, and `:404` starts the sentinel as a bare `bash scripts/dogfood/release-sentinel.sh`.
Neither goes through [`record-launch.sh`](../../scripts/agent/record-launch.sh), so the longest-running commands in the repo, registered at 60-minute and 120-minute minimums, leave no stop handle on disk.
The `release-candidate` skill's own copy of the same step (`.claude/skills/release-candidate/SKILL.md:149`) does use the wrapper, so the two recipes for one action disagree.

That matters more since Q739, which enforces the wrapper for an *agent* backgrounding a registered tier: a session following release.md's form through `run_in_background` is now denied and told to rewrite, while a session following the skill is not.
The guard does not fire on the doc's shell `&`, so nothing is broken for a human at a terminal.
The cost is one recipe teaching the shape the other repo rule forbids.

Fix: give both lines the wrapper, matching the skill, and say what the record buys at that length of run.
Check the surrounding reclaim and recovery steps for the same shape rather than only the two lines cited: the row lists where someone looked, not a census.
