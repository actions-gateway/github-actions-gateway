# Attribute egress proxy failures to the job that hit them

Build [05-security.md § Proxy failure attribution](../design/05-security.md#proxy-failure-attribution), which settles the posture: off by default on two switches (one on the `EgressProxy`, one on the consuming `ActionsGateway`), failures only, held for minutes in an in-memory buffer partitioned by consumer namespace and capped per source address.
Two retry uses consume it: an upstream dial failure as a retry class, and a policy denial as a futile retry whose Event names the blocked host.
Separate from Q1178, which counts outcomes by destination for operators and holds no per-job data.

The proxy has no client identity on the CONNECT path today: it reads no `Proxy-Authorization` and requires a client certificate only on its metrics listener (`cmd/proxy/proxy.go:596`), and its denial and dial-failure lines log the host and not the client (`cmd/proxy/proxy.go:713`, `:721`).
So the proxy learns the consumer from the port a connection arrives on: the existing port stays unattributed and records nothing, and a namespace gets a port of its own on the pool's one Service only when one of its own gateways opts in, admitted by NetworkPolicy (by container port number) to that namespace only, with the GMC moving that namespace's `HTTPS_PROXY` to it.
That keeps a pool edit from rolling gateways in any namespace where no gateway has opted in, and keeps a namespace that has not opted in from having its failures served to another's certificate.
One Service, not one per consumer, because the proxy's serving certificate lists a single Service's DNS names (`cmd/gmc/internal/controller/egressproxy_cert.go:34`) and per-consumer Services would reissue it on every grant change.

The AGC reads its records over a dedicated mTLS listener with its own CA, presenting a GMC-minted client certificate that names its namespace.
The metrics port is not usable: its ingress admits only `metrics=enabled` namespaces (`metricsScrapeIngressRule`, L-8), and `<ep>-metrics-client` lives in the proxy's namespace for the monitoring stack.
The AGC attributes a record to a worker only inside the window that pod held the address, from its pod informer, because worker addresses are reused.

**Before it ships:** measure on the Calico lane that per-port ingress is enforced, with a worker in one namespace refused on another consumer's port (the kindnet lane cannot show it: its enforcer does not drop NetworkPolicy negatives, and every enforcement spec skips there); and cap `spec.sharing.allowedNamespaces`, which has no maximum (`api/v2/shared_types.go:236`), at admission when attribution is on.
Open implementation questions: how the proxy learns its port map without a rollout on every grant change, and how the AGC reaches each replica's buffer.
Q1183 is the consumer and is blocked, so nothing reads this data until it lands.
