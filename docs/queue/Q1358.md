# A gateway created with the GMC finalizer skips the raced-pair refusal

A second tenant that creates its ActionsGateway with the GMC's finalizer already in `metadata.finalizers` defeats the bound `05-security.md` gives Q1325's raced pair: the gateway is provisioned onto a scale-set name another tenant holds.

**Measured 2026-11-17 in the GMC envtest suite**, while working Q1342, with a temporary probe that repeats `TestV2_ScaleSetNameGuard_ConcurrentPairIsReported`'s race but adds `actions-gateway.com/gmc-cleanup` (`ActionsGatewayFinalizer`) to the second tenant's gateway before creating it.
With Q1342's exemption disabled, so the webhook behaved as on `main` at e25db67fb, 15 of 30 pairs were both admitted, all 15 raced gateways carried the finalizer, and 10 of them had reconciled through to `ReconcileSucceeded` with `ScaleSetNameCollision=True` 10 seconds later.
The unmodified race test, in the same run, had 0 of 28 raced gateways finalized.

**Mechanism, read from source.** The bound is the gateway webhook refusing the GMC's finalizer update while the pair collides, and provisioning starts only after that update (`cmd/gmc/internal/controller/actionsgateway_v2_controller.go:226:if !controllerutil.ContainsFinalizer(&ag, gmcv2.ActionsGatewayFinalizer) {`).
A gateway that already carries the finalizer skips that branch, so no update happens to refuse; `ValidateCreate` does not look at finalizers, and Kubernetes lets whoever may create the object set them.
The chart ships no role for tenant users, so who holds that create is the operator's RBAC: the same premise Q1325's residual already makes about a second tenant.

**Fix direction, not decided.** Either refuse a create carrying `ActionsGatewayFinalizer` (only the GMC adds it), or have the reconciler refuse to provision a gateway whose own RunnerSets collide, which reverses the advisory-only choice `05-security.md` §5.2 argues for.
The first is admission-only and matches the existing bound; check whether any install path (GitOps restore, `kubectl apply` of an exported object) legitimately writes the finalizer on create before choosing it.
The probe test and both runs' output are in the v2.0.1 run's notes folder under `q1342/`, outside the repo.
