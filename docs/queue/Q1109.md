# Audience pills split a sentence on its commas into fragments

`docs/javascripts/extra.js` turns a page's leading `> **Audience:**` blockquote into pills by splitting the text on commas, which assumes the line is a list.
Most pages write one ("Platform engineer, Tenant operator") and render correctly.
Two do not, and their commas are sentence punctuation rather than separators.

On [migration-from-arc.md](../operations/migration-from-arc.md) the line is one sentence, so it renders as two pills reading "Platform engineer running Actions Runner Controller (ARC) scale-set mode on a shared" and "multi-tenant Kubernetes cluster and evaluating GitHub Actions Gateway (GAG) as a replacement." — a noun phrase cut in half across two chips.
[tenant-onboarding.md](../operations/tenant-onboarding.md) has the same shape at line 747.

This was invisible until 2026-09-14, because the pills overflowed the page and the text ran off-screen rather than wrapping where a reader could see it.
Fixing the overflow (`.persona-pills-top .persona-pill { white-space: normal }`) made the copy legible and the fragments obvious.
So this is a pre-existing defect the fix exposed, not one it caused.

**Two candidate fixes, and the choice is the work.** Rewrite both audience lines as actual comma-separated lists, which keeps the pill component honest and is XS.
Or stop splitting when the text reads as prose rather than a list, which is a guess the JavaScript has to make and will get wrong somewhere else.
Prefer the first unless a third page turns up.

A pill is a scanning surface like the card bullets, so the same argument applies as in [website.md](../development/website.md#card-bullets-fit-on-one-line): the copy is written to the component rather than the component stretched to the copy.

**Done when** no published page renders an audience pill that is a sentence fragment.
