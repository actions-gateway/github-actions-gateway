# Queue metrics report zero completions because removals name no verb

`queue.py metrics` splits throughput from garbage collection by matching `complete|prune|merge|defer` in the subject of the commit that deletes an item, and falls back to `removed` when none is present.
Measured 2026-08-23 over the store's whole history: of 86 removals, 81 classify as `removed` and 5 as `merge`, so the summary reads `completed 0` and `pruned 5` for a repo that has shipped 239 filed items.
Zero throughput is not an imprecise reading, it is an inverted one, and the prune ratio derived from it is meaningless.

Two candidate fixes, and the choice is the work.
Either the convention gets enforced, which needs a gate on the deleting commit's subject rather than on the tree, and the gate has to accept `retire` as well, since [the flake lifecycle](../development/maintaining-backlog.md#retiring-a-flake-watch-row) sends rows to the ledger under that word and `maintaining-backlog.md` never told anyone to write a verb at all.
Or the verb is abandoned as the signal and closure is derived instead, which is available here: a flake row that lands in `flake-watch-retired.md` retired, an item whose ID appears in a merged PR's body shipped.

Note that `queue.py` is [vendored from the skill](../development/skills.md#vendored-from-the-skills-repo) and carries only two declared local edits, neither of them in the matcher, so a fix there belongs upstream and only the convention half is this repo's to change.
Related: Q955 owns the vendored-drift detection; the re-vendor Q956 asked for has shipped, so the matcher here is upstream's current one.

**Re-measured 2026-09-11, and the choice is settled against the convention half.** `queue.py metrics` now reads `filed 372, completed 1, pruned 8, removed 201, open 162`, so the inversion is unchanged at four times the volume: one completion recorded for 210 rows closed.
The reason is not that nobody writes the verb.
Of the 141 commits that delete a `docs/queue/QNNN.md`, **139 carry a trailing `(#NNNN)`** — they landed as squash merges, so the subject the matcher reads is the *pull request title*, and the `docs(queue): close QNNN` commit that does carry the verb is folded away inside it.
Only 17 of the 141 subjects hold a closure verb at all, and a PR closing several rows at once has no single verb-and-row to name in its title.
So enforcing the convention would mean gating PR titles rather than commit subjects, which is the wrong rung for a metric: closure is derivable from evidence that survives the squash, and deriving it is the fix.

That fix is upstream in the vendored matcher, not here.
