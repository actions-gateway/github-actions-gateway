# Pending worker lost to node shutdown re-runs instead of force-cancelling

A worker still `Pending` when its node shuts down takes the `node_shutdown` arm (Q1179) and goes straight to `rerun-failed-jobs`, ahead of the abandoned arm that force-cancels a never-started worker's run first (Q691/Q766).
Read from source, not observed: the kubelet's shutdown manager kills every active pod on the node, `Pending` ones included, and fails each one (kubernetes v1.35.0, `pkg/kubelet/nodeshutdown/nodeshutdown_manager.go:153-166`); the classic tier sets `DeletedBeforeStart` only on its deletion paths, so a terminal `Failed` never reaches the abandon branch, and the scale-set arm keys on the condition alone.
Unverified: what GitHub does with a re-run of a run whose job never started.
The abandoned-row reasoning in the design table predicts a refusal until GitHub's ~15-minute unstarted-job timeout concludes the run, which would end as `rerun_failures_total{reason="run_never_concluded"}` with a spent retry slot.
It is no regression, because no arm caught this shape before Q1179.
The likely fix is to route a `node_shutdown` pod with no container start record (`podEverStarted`) to the abandoned handling on both tiers.
Raised as a note in the PR #2108 review.
