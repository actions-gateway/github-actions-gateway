# Dogfood keeps no AGC or proxy metrics past the pod's life

Dogfood stores no `actions_gateway_*` series until [`deploy/dogfood-metrics/`](../../deploy/dogfood-metrics/README.md) is applied, so every retry counter dies with the pod and Q555 and Q1179 have no history to measure against.
The scrape is written: a Google Managed Prometheus (GMP) `PodMonitoring` that presents the GMC-published `dogfood-agc-metrics-client` bundle over mTLS, plus a `Role` letting GMP's collector read that one Secret.
What is left is a change to the prod-classified dogfood cluster, which is why it is a row rather than part of the PR that wrote the manifest:

1. Label `gmp-system` `metrics=enabled`, which the tenant NetworkPolicy requires before it admits the scrape to `:8443`.
2. `kubectl apply -k deploy/dogfood-metrics`, pinned to the dogfood context.
3. Confirm `up{namespace="gag-dogfood"}` reads `1` in Cloud Monitoring.
4. Count the AGC's live series from one `/metrics` sample, so a cost estimate rests on a measurement rather than an assumption.

The README carries the commands and the caveats.
`gmp-system` is addon-managed (`addonmanager.kubernetes.io/mode=Reconcile`), so whether GKE keeps the label is unmeasured; re-check it after a cluster upgrade.
Dogfood runs no `EgressProxy`, so there is no proxy to scrape until one is attached.
