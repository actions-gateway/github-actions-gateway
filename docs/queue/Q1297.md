# An AGC restart re-mints a JIT config for each replayed Pending worker

**Measured** on 2026-11-06 with `test/fakegithub`, while Q1107 walked an AGC through the `v2.0.0` upgrade and rollback: with workers held `Pending`, the fake's JIT call counter rose by exactly two per outstanding job across each AGC restart, 2 to 6 with two jobs and 8 to 16 with four, with no new job and no new pod.
Each direction of the upgrade did the same, so a release is not what causes it.

**Read from the code, not measured.** `Listener.provisionAssigned` checks the in-memory `provisioned` map before minting, a restart empties that map, and the replayed assignment reaches `generateJITConfig` before the provisioner's pod create finds its own pod.
The two calls would then be the base-name conflict and the re-mint after `DeregisterRunnerByName`.
That reading also implies a deregistration per replayed job, which the counter does not show.

**Why it is worth a look.** Q576 and Q1233 each moved a check ahead of the mint because a mint registers a runner at GitHub.
This path pays for one on every restart for every worker still waiting, so a fleet-wide AGC roll spends a deregister and two mints per such job against the installation's rate limit.
What it does to the waiting worker is unknown: whether the pod that later starts holds a config GitHub still honours has not been run against github.com, and the fake does not settle it.
