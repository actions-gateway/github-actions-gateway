# release-delta.sh still diffs docs/STATUS.md, so closed rows read (none)

The report that [release.md § When to cut](../operations/release.md#when-to-cut) says to start from prints an empty *Queue rows closed* section for every window since the store cutover, and nothing in the output says the section is unreadable rather than empty.

**Measured 2026-09-07** on `v1.7.0..origin/main`: the report prints `(none)`, while `git log --diff-filter=D v1.7.0..origin/main -- docs/queue` shows 19 item files deleted in the same window.
The mechanism is `STATUS_FILE="docs/STATUS.md"` (scripts/release/release-delta.sh:48): the closed-rows walk runs `git rev-list "$range" -- "$STATUS_FILE"`, and that path was deleted on 2026-08-18 in #1603 (Q889 phase 6), so the walk visits no commit and the section is a silent zero.
The script's own header, and the archived [release-decision-support.md](../plan/archive/release-decision-support.md) plan, both still describe the section as diffing STATUS.md's Queue section across revisions, so the docs answer the question wrongly rather than not at all.

The fix reads the store the way `queue.py metrics --events` already does: one `--diff-filter=D` walk over `docs/queue/`, one line per deleted `QNNN.md` with the outcome read out of the deleting commit's message.
Parking no longer needs the Deferred subtraction the STATUS.md version did, because a parked row is a `status:` edit rather than a deletion.
A deletion no longer hides whether it was a completion or a prune either: Q959's fix landed with the 2026-09-12 re-vendor, so `--events` carries a per-row verb this report can print rather than inheriting the ambiguity.
This row owns the (none) measurement.
Not Q940, which was a doc naming a different script's deleted read.
