# Flake: an attribution pool gaining a namespace never reissues its certs

**Event:** `E2E_V2_ProxyAttribution`'s `BeforeAll` times out on `main` at `v2_proxy_attribution_test.go:56`, waiting for `proxy-attribution-v2-attr-pool-pool`.
Read the failure dump's `v2-attr-pool/pool status` and `GMC log lines naming v2-attr-*` sections first: they name the refused request if this is the same defect, and they did not exist when it was found.

The spec waits 4 minutes for that ConfigMap in each consumer namespace, and on two merge-queue runs one never appeared.
Both lanes failed it: e2e-test in group `be1708703` ([run 40379757319](https://github.com/actions-gateway/github-actions-gateway/actions/runs/40379757319), job 121772606982) and e2e-calico in `f26667a5c` ([run 40384324013](https://github.com/actions-gateway/github-actions-gateway/actions/runs/40384324013), job 121788560407).
Each dump showed one proxy pod that was never replaced, with `PROXY_ATTRIBUTION_PORTS=v2-attr-alpha=8100`, so the pool rolled once with alpha alone and never again.

**Cause, measured 2026-10-26 on a local kind cluster.** Reissuing the attribution certificate bundle for a changed namespace set is a `patch` on two Secrets the pool owns, and the GMC's manager role granted Secrets `create` and `update` only.
Applying the pool and alpha's gateway, then beta's after the first rollout, left the pool `Degraded` with `cannot patch resource "secrets" ... in the namespace "rp-pool"` on every retry.
A forced reconcile with no RBAC change was refused the same way, and granting `patch` alone converged the pool in 3 s to `rp-alpha=8100,rp-beta=8101`.
The e2e passed whenever the pool's first reconcile already saw both gateways, which is why one tree produced both outcomes.

The fix writes the GMC's owned Secrets with fetch-then-`update` instead of a patch, closing Q1200, which had filed the missing verb unverified.
Granting `patch` was the other route and is refused on purpose: measured on the same cluster, an empty merge patch returned a Secret's `.data` to a ServiceAccount holding `patch` alone, so the verb would undo Q1188's read scoping wherever `gmc-tenant-resource-guard` is not in `Deny` ([05-security.md](../design/05-security.md#gmc-privilege-escalation-blast-radius-and-compensating-controls)).
`TestV2_EgressProxy_Attribution_AddsASecondConsumerUnderTheShippedRBAC` runs the pool as the GMC ServiceAccount, and `TestEgressProxyReconcile_PortsAndBundleAreStableAcrossGrantChanges` runs it against a fake refusing Secret patches; both fail with the patch path restored.
