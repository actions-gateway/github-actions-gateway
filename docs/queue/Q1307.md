# Bump the e2e runner image off 2.338.1 before its update window closes

The self-hosted e2e image still runs `actions/runner` 2.338.1, so a release candidate's e2e jobs on `gag-ci-e2e` should stop being queued from about 2026-11-25, which would block any candidate gate after that date, `v2.0.0`'s and `v1.10.1`'s included.
`scripts/dogfood/e2e-runner/Dockerfile` is `FROM ghcr.io/actions-gateway/dogfood-runner:2.338.1`, and its header says to bump that in lockstep with `scripts/dogfood/runner/Dockerfile`, which #2170 moved to 2.338.2.
The `2.338.1-2` image #2268 pinned kept the old base.

**Unmeasured.** The date is the 30-day rule as `scripts/release/check-runner-window.sh --pinned 2.338.1` reads it (19 days left on 2026-11-06); this is read from the Dockerfiles, and nothing here has observed GitHub stop queueing to this image.
Found by the independent review of #2234.

**Done when** both `deploy/dogfood-e2e/overlays/` kustomizations pin an e2e runner image built on the newest stable runner, and a dispatched e2e run has been picked up on it.
Building that image is still a manual push until [Q1305](Q1305.md) lands.
