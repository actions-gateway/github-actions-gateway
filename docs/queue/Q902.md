# The integration and e2e tiers drop the same out-of-module cache inputs

Q895 fixed the cached unit tier and scoped the tagged tiers out, because they share the defect but not the invocation.
Twelve reads behind `//go:build integration` or `e2e` still resolve outside their module root, so go drops them from the test-cache key: `cmd/gmc/internal/controller/integration` installs CRDs from `../../../../../api/config/crd`, `cmd/agc/.../integration` reads `../../../../../deploy/templates`, and both e2e suites resolve a repo root from `runtime.Caller`.
Regenerating a CRD without touching the package would replay a cached green.

`-count=1` is applied only when `RUN` is set (`cmd/agc/Makefile:48`, `cmd/gmc/Makefile:66`), so a default `make test-integration` can serve a cached result.
That makes the exposure narrower than the unit tier's but not absent, and it needs its own measurement rather than an inference: an envtest run is expensive, and `manifests`/`generate` run as prerequisites, so whether a cache hit is reachable in practice is unverified.

Measure first, on one package, by deleting the mechanism the way Q895 did: warm, confirm a literal `(cached)` line, change a CRD, require red.
If reachable, either extend the `testdata/` symlink convention to these packages or force `-count=1` on the tier, where the cost is already dominated by envtest bring-up.
Then narrow the `//go:build` skip in `scripts/go/check-test-cache-inputs.py`, which is what keeps this invisible today.
