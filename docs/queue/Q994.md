# Nothing pins the listener's `RunnerVersionTooOld` reason set

Two sites hardcode which reasons the classic listener owns on this condition type, and neither is derived from what the listener emits.
`isSessionSourcedRunnerVersion` in [`runnerversion.go`](../../cmd/agc/internal/runnercore/runnerversion.go) switches on `VersionTooOld`/`VersionAccepted` to arbitrate the clear, and `setRunnerVersionStatus` in [`runnerset_controller.go`](../../cmd/agc/internal/controller/runnerset_controller.go) and [`runnergroup_controller.go`](../../cmd/agc/internal/controller/runnergroup_controller.go) separately compares `prev.Reason` against `ReasonVersionTooOld` alone to decide whether the image reading defers.
The listener emits its two from [`session.go`](../../cmd/agc/internal/listener/session.go) and [`goroutine.go`](../../cmd/agc/internal/listener/goroutine.go); adding a third and updating neither membership site is the omission the godoc contemplates and calls conservative.

Measured 2026-08-25 by probing both paths with a stand-in third reason, `VersionRejectedByPolicy`.
`DropListenerCondition` returns `true` for it, identically to `WorkerImageBelowMinimum`, so the listener's clear is refused.
`setRunnerVersionStatus` then does not defer either, so the image reading overwrites the live `True` with `False`/`WorkerImageCurrent`.
The godoc's "merely stays stale … rather than a wipe" is true of the drain in isolation, and the second site is not in that argument: a rejection GitHub actually made is gone from status, which is the failure direction the switch's polarity was chosen to forbid.
Stale-forever is the narrower case, reached only where no reconcile gets as far as the image reading (`template == nil`, or no provisioner).

The prose consequence does not depend on [#1717](https://github.com/actions-gateway/github-actions-gateway/pull/1717).
`main` today says the clear is dropped when the live condition is "image-sourced", and #1717 restates that by ownership role instead.
An unrecognized listener reason is neither image-sourced nor foreign to the listener, so both wordings read as kept while the code drops.
Four sites carry the role wording once #1717 lands, one of them pinning the cardinality outright ("the listener's own two", [`02-architecture.md`](../design/02-architecture.md)).
Nothing in that PR should change: its prose is correct for the reason set as it stands, and a gate is what keeps it correct.

Nothing gates the membership.
`isSessionSourcedRunnerVersion` has one call site and no other reference in Go or shell.
`conditions_parity_test.go` asserts constant aliasing across `v1alpha1`/`v2alpha1`/`v2beta1`, not membership.
[`check-reason-tiers.sh`](../../scripts/docs/check-reason-tiers.sh) reconciles emitted reasons against the ledger and the runbook, as its own godoc says, and never against this switch.
The only future-reason test is `WorkerImageSomeFutureReason` in [`runner_version_status_test.go`](../../cmd/agc/internal/controller/runner_version_status_test.go), an unknown *image* reason whose assertion would be wrong for a listener one.

**This is a gate row, not a prose row.** The deliverable is an assertion, and it must go red when a reason emitted on `RunnerVersionTooOld` from `internal/listener` is absent from either membership site.
Two controls must stay green: today's tree, where the listener's two are in both; and adding a fourth `WorkerImage*` reason, which must stay *out* of the switch, since enumerating the image half is the failure direction the polarity already rejects.
[`devtools/docs/reasontiers`](../../devtools/docs/reasontiers/main.go) is the nearest seam, already resolving each reason argument from source and classifying it by tier directory, but it does not pair a reason to its condition type today and that pairing is the work.
A new gate registers in [`mk/gate-lists.mk`](../../mk/gate-lists.mk), which the `gatelists` merge driver merges as a set; `reason-tiers-check` is already an entry there to model.
