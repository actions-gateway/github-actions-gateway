# Nothing pins the listener's `RunnerVersionTooOld` reason set

Two sites decide which reasons the classic listener owns on this condition type, at different widths, and neither is derived from what the listener emits.
`isSessionSourcedRunnerVersion` in [`runnerversion.go`](../../cmd/agc/internal/runnercore/runnerversion.go) switches on `VersionTooOld`/`VersionAccepted` and gates whether the listener's clear is dropped.
`setRunnerVersionStatus` in [`runnerset_controller.go`](../../cmd/agc/internal/controller/runnerset_controller.go) and [`runnergroup_controller.go`](../../cmd/agc/internal/controller/runnergroup_controller.go) compares `prev.Reason` against `ReasonVersionTooOld` alone, not through the switch, and gates whether the image reading defers.
The listener emits its two from [`session.go`](../../cmd/agc/internal/listener/session.go) and [`goroutine.go`](../../cmd/agc/internal/listener/goroutine.go).

The two widths coincide today only by accident of arithmetic.
`VersionAccepted` is only ever pushed `False`, so restricted to a live `True` the listener owns exactly one reason and both sites agree on `{VersionTooOld}`.
A second `True`-capable listener reason ends that.

Measured 2026-08-25 with a stand-in reason `VersionRejectedByPolicy`, probing each path directly.
`DropListenerCondition` returns `true` for it, identically to `WorkerImageBelowMinimum`, so the listener's clear is refused.
`setRunnerVersionStatus` does not defer either, so the image reading overwrites the live `True` with `False`/`WorkerImageCurrent`.
The godoc's "merely stays stale … rather than a wipe" is true of the drain in isolation, and the second site is not in that argument: a rejection GitHub actually made is gone from status, which is the failure direction the switch's polarity was chosen to forbid.
Stale-forever is the narrower case, reached only where no reconcile gets as far as the image reading (`template == nil`, or no provisioner).

**Updating the switch does not fix this**, which is the trap, because it is what the godoc sends a reader to do.
Measured the same day by adding the stand-in reason to the switch and re-probing: the drain is repaired (`DropListenerCondition` returns `false`, the clear lands) and the image reading still returns `False`/`WorkerImageCurrent`.
The wipe is unchanged, because `setRunnerVersionStatus` never consults the switch.

Four prose sites now describe the guard by ownership role, since [#1717](https://github.com/actions-gateway/github-actions-gateway/pull/1717) landed.
[`conditions.go`](../../cmd/agc/api/v1alpha1/conditions.go), [`goroutine.go`](../../cmd/agc/internal/listener/goroutine.go), [`runnerversion.go`](../../cmd/agc/internal/runnercore/runnerversion.go) and [`02-architecture.md`](../design/02-architecture.md) each say the clear is dropped when a live condition stands whose reason is not the listener's own, and the last pins the cardinality outright ("the listener's own two").
A forgotten listener reason *is* the listener's own, so all four read as kept while the code drops, and they go false together.
That wording is correct for the reason set as it stands, and naming the set by role is what buys it: add a reason and a membership entry together and the three role-only sites stay true.
The fourth does not, because it pins the count: a third listener reason falsifies "two" whatever the membership sites say, so it needs an edit of its own.
Dropping the count from that sentence would fold it back into the pairing permanently.
The gate below pins membership and cannot see a stale count, so that one stays a prose obligation.

Nothing gates either site.
`isSessionSourcedRunnerVersion` has one call site and no other reference in Go or shell.
`conditions_parity_test.go` asserts constant aliasing across `v1alpha1`/`v2alpha1`/`v2beta1`, not membership.
[`check-reason-tiers.sh`](../../scripts/docs/check-reason-tiers.sh) reconciles emitted reasons against the ledger and the runbook, as its own godoc says, and never against either site.
The only future-reason test is `WorkerImageSomeFutureReason` in [`runner_version_status_test.go`](../../cmd/agc/internal/controller/runner_version_status_test.go), an unknown *image* reason whose assertion would be wrong for a listener one.

**This is a gate row, not a prose row, and it must pin both sites.** A gate reconciling only the switch against the listener's emitted reasons passes while the wipe stays live, so it would close this row with the defect intact.
Collapsing the two into one membership site is the better shape: have `setRunnerVersionStatus` call `isSessionSourcedRunnerVersion` on a `True` condition, leaving a single place a gate has to pin.
The assertion must go red when a reason emitted on `RunnerVersionTooOld` from `internal/listener` is absent from the membership the reconcilers honour.
Two controls must stay green: today's tree, where the listener's two reasons are honoured by both sites; and adding a fourth `WorkerImage*` reason, which must stay *out* of the session set, since enumerating the image half is the failure direction the polarity already rejects.
[`devtools/docs/reasontiers`](../../devtools/docs/reasontiers/main.go) is the nearest seam, already resolving each reason argument from source and classifying it by tier directory, but it does not pair a reason to its condition type today and that pairing is the work.
A new gate registers in [`mk/gate-lists.mk`](../../mk/gate-lists.mk), which the `gatelists` merge driver merges as a set; `reason-tiers-check` is already an entry there to model.
