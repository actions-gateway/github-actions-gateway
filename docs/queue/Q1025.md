# The release gate cannot drive the placeability rung on real infra

**Event:** `spec.capacityGate.mode` gains a value that yields a negative placeability verdict without a scale-up: the `Probe` mode sketched in [appendix-g](../design/appendix-g-future-enhancements.md).

Q637 added `capacity_leg`, which drives the admission ladder's **quota** rung through bind and release by patching the e2e tenant's `ResourceQuota` to zero pods headroom.
The same leg asserts all three rungs are *evaluated*: `quota`, `capacity` and `scaleup` must each appear in `status.withheldCapacity`, because a rung that publishes no entry was never evaluated on that tier.
So the placeability rung is covered for evaluation and not for binding.

Binding it needs a worker pod the cluster cannot place, and the dogfood cluster autoscales: the autoscaler answers unplaceability by growing a node, which is the opposite of the verdict the rung acts on.
Defeating that means pinning the `workers` ceiling for the leg's duration, which collides with the CPU reservation `quota_preflight` already derives across the same budget.

The cheap half of that is now done (2026-08-29).
The e2e tenant opts in at `spec.capacityGate.mode: Observe`, and `capacity_leg` asserts the rung publishes a real verdict: absent `WorkerCapacityDeclined` and `GateModeUnsupported` both fail the gate.
That matters because the rung's `withheldCapacity` zero is written whether or not the set opted in, and mode `Off` *removes* the condition rather than publishing it `False` — so the condition is the only evidence on this cluster that the opt-in path evaluates end to end.
It cannot starve the tenant: the gateway leaves `clusterCapacity.nodeAutoscaling` at its `Present` default, under which a decline needs the autoscaler's own declination.

One gap remains, measured 2026-08-28:

- `nodeAutoscaling`, the `ScaleUpDeclined` source (Q406), needs the autoscaler to decline a scale-up it *could* satisfy, which no cluster with budget headroom will do.

Appendix-g already argues the negative verdict this rung acts on needs no scale-up to reproduce **once `Probe` exists**, which is why this is an Event rather than ready work: building a bespoke unplaceability harness now would be defeated by the same `Probe` mode landing.

Until then `capacity_leg` says out loud that the *negative verdict* is undriven rather than reporting only what it proved, so the gap is visible in every gate run instead of inferred from this row.
A decline it does observe is reported loudly and passes: on a headroom pool that is a fact about the cluster rather than the release, and it is the verdict the leg cannot manufacture.
