# `version-cmds-answer` flakes on kubectl, and discards the evidence

Measured 2026-08-21 on an unmodified tree: `make check` failed `check-tools-test` with `no version from: kubectl, checked=5`, and the same test run alone passed `5 probed` immediately after.
By hand the registry's own probe — `kubectl version --client` piped to the assertion's `grep -qE '[0-9]+(\.[0-9]+)+'` — exits 0 and prints `v1.36.3`, in and out of the sandbox.
The only difference is that the failing run sat inside `run-parallel`'s 43-way fan-out, so saturation is the hypothesis and it is **unverified**.
Whatever the cause, the assertion sends the probe's stderr to `/dev/null` and reports only the tool's name, so a failure carries nothing to diagnose it with; keeping stderr is worth doing even if the retry question stays open.
