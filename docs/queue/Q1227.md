# Persist GitHub IP ranges so a GMC restart keeps proxy egress

Split out of Q1203, whose rate-limit-aware retry shipped without this part; Q1203 is closed, so it is named here rather than linked.

A GMC restart leaves every proxy pool with no GitHub egress until its first `api.github.com/meta` fetch succeeds, because `IPRangeCache` lives only in memory.
`buildProxyNetworkPolicy` and its v2 analogues add the GitHub `443` rule only when the cache has CIDRs, so until then a pool's NetworkPolicy permits DNS and nothing else.

That fetch is unauthenticated, with a budget of 60 calls an hour per source IP that every GMC and anything else behind the same egress IP share.
A 2026-10-24 kind measurement found that budget at zero: `curl -sSI https://api.github.com/meta` read `x-ratelimit-remaining: 0`, the proxy's NetworkPolicy had a single DNS egress rule, and the proxy's dials to a GitHub address timed out while the same address answered from the node.
The rate-limit-aware retry that shipped with this row's parent now waits for the reset instead of spending each new window, but a restart inside a limited window still means up to an hour with no tenant egress.

Fix shape, unmeasured: write the last good CIDR set to an object the GMC owns, for example a ConfigMap in its own namespace, and seed the cache from it at startup before the first fetch.
That is a new GMC-owned child object, so it is a design change to state in the PR.
The GMC's ClusterRole already grants `configmaps` (`cmd/gmc/config/rbac/role.yaml:10:  - configmaps`); read whether that grant covers a write in its own namespace before adding RBAC.
Decide whether a seeded cache stamps `MarkRefreshed`: if it does, `EgressRulesStale` cannot see that the ranges came from disk; if it does not, a seeded cache reads as never refreshed.
