# Re-run only the classified job, found by its runner's name

Every automatic re-run today uses `rerun-failed-jobs`, so a class firing on one job also re-runs every other failed job of the run, including genuine failures the boundary says must never be re-run.
Detection's `gag_collateral` count measures that cost, and a single-job re-run (`POST …/jobs/{id}/rerun`) removes it.
Whether one can find its job was the design's M6, measured on 2026-11-24 ([the readings](../plan/q555-automatic-recovery-design.md#m6-readings-from-the-job-granular-probe-2026-11-24)): job names match the API exactly and can be ambiguous, while `runner_name` identifies the job, a killed one included.

What is left is to build it, for the out-of-memory class first:

- Find the job in the **latest** attempt's jobs list by `runner_name` equal to the dead worker's runner-name annotation, then by display name where that names exactly one job, else fall back to `rerun-failed-jobs` and say so.
- Call with the latest attempt's job ID, since GitHub refuses an earlier attempt's, and only once the run has concluded, since it refuses one in progress.
  The class already waits for that.
- Decide what a run with two classified jobs does: GitHub takes one single-job re-run at a time, each is an attempt and spends a slot of `maxEvictionRetries` (2 by default), and `rerun-failed-jobs` would take both in one.
- Say in the operator docs that `needs:` dependents run again even when they passed, and that a run stays `failure` while a failed sibling is not re-run.
- Keep the futility checks and the reservation's merge right when the attempt is a single-job re-run of another job, which the design's test plan names.

The disruption arms stay run-granular.
The design's [granularity section](../plan/q555-automatic-recovery-design.md#run--or-job-granular-re-run-open-question-2) and the API shape's `retry.scope` (`FailedJobs` or `Job`) are where it lands.
Another session's change that decides whether a run's attempt re-ran a given job reads the same list by the same key, so reuse its decode rather than adding a second.
Gated on 2.1 ([release-2.1.md](../plan/release-2.1.md)): more classes means more collateral re-runs, so this is what makes adding them cheap.
