# A bare Off enum value decodes as a YAML boolean

YAML reads bare `Off`/`On`/`Yes`/`No` as booleans, so an operator writing `auditLogging: Off` in a manifest has admission reject a value they never typed.
The decoder never errors; it coerces, and the two client paths coerce differently.
Measured with the repo's own vendored `sigs.k8s.io/yaml`: `YAMLToJSON` (the unstructured path `kubectl` takes) yields the JSON boolean `{"auditLogging":false}`, so the apiserver rejects on TYPE against `type: string`; `Unmarshal` into a typed Go client's string field yields the STRING `"false"`, so the ENUM rejects instead.
Reproduce through the wrong path and the error does not match, which is what makes this look stale rather than real.
Affects `capacityGate.mode` and `agcAutoscaling.updateMode` too, so it is a convention question for api-review, not one field's bug.
