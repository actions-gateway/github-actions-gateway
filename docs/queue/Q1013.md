# Six dogfood entrypoints are committed non-executable

`git ls-files -s scripts/dogfood/` reports mode `100644` for `e2e-setup.sh`, `e2e-start.sh`, `e2e-stop.sh`, `start.sh`, `stop.sh` and `runner-build.sh`, while every other top-level script there (`setup.sh`, `delete.sh`, `ops.sh`, `validate-release.sh`, `e2e-run-watch.sh`) and all their own `*-test.sh` siblings are `100755`.
Measured 2026-08-28 booking the Q408 Phase 2 dogfood session: `scripts/dogfood/e2e-start.sh` exits **126, `Permission denied`**, before it reads a single env var.
[release.md](../operations/release.md) prescribes the bare form for all six.
Steps 4 and 5 of the dogfood validation are `scripts/dogfood/e2e-start.sh` and `scripts/dogfood/e2e-stop.sh`, and the teardown pairs `stop.sh` with them, so four of the runbook's five bring-up/teardown commands do not execute as written.
An operator following the page hits 126 and has to guess `bash` in front of it.
The fix is `git update-index --chmod=+x` on the six, not a docs change: the split is with their own siblings and their own tests, so 755 is the convention and these are the outliers.
Worth pairing with a gate: nothing checks that a script a doc invokes bare is executable, which is how six accumulated.
