# `FlakyJobDetected` names a run with no repository

A flaky verdict cannot be followed to its run from what it reports.
The Event's message is `Job "<name>" of run <id> failed with no disruption attributed and then succeeded when re-run by …`, from `reportRerunJob` in `cmd/agc/internal/provisioner/flaky_jobs.go`, and a run ID does not resolve at GitHub without its repository.
A `RunnerSet` registered to an organization serves many repositories, so the reader has to find the repository in the AGC log.

`actions_gateway_scaleset_flaky_jobs_total` carries no job or repository label, which is right for its cardinality, so the Event and the log line are the only places a verdict names its job.
Read from source on 2026-11-27.

**A fix:** put `owner/repo` in the Event message, and the workflow's name if the failure record holds it.
Whether the record holds the repository at the point the verdict is reported is not checked.
