# caBundleRef refuses a scheme-less TLS tracing endpoint

**`spec.tracing.caBundleRef`'s admission rule requires an endpoint starting `https://`, and the exporter also uses TLS for an endpoint with no scheme.** Read from the vendored `otlptracegrpc` v1.47.0, not run: `withEndpointScheme` in `internal/otlpconfig/envconfig.go` picks plaintext only for `http` and `unix` and TLS for everything else, and the endpoint rule (Q1283) accepts a scheme-less `collector.ns.svc.cluster.local:4317`.
So an operator with that endpoint and a private-CA collector cannot set the bundle the connection would verify against, and has to add `https://` to get past admission.

Loosening the rule to "not `http://` or `unix://`, and `insecure` not true" is additive: everything accepted today stays accepted, so this needs no release gate.
The exporter lowercases the scheme before comparing it, so the loosened rule should too.
Run a scheme-less endpoint with a bundle against a TLS collector before loosening it, since this row's premise is a code read.

**Done when** the rule admits a scheme-less endpoint with `caBundleRef`, a test covers it, and the field godoc and the `caBundleRef` row in [observability-logging.md](../operations/observability-logging.md) stop saying admission requires `https://`.
