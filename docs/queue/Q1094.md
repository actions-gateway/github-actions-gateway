# `rank-vectors-test.sh` is vendored from the skill and registered nowhere

`scripts/docs/rank-vectors-test.sh` came out of `karlkfi/claude-skills` in `bbc2578f5`, beside the four files [vendored-skills.tsv](../../scripts/ci/vendored-skills.tsv) declares, and holds no row of its own.
It is `session-backlog/scripts/test-rank-vectors.sh` upstream: `bbc2578f5` renamed it on adoption, so grepping upstream for the local name finds nothing.
So `make vendored-skills-check` cannot see it: it is the unregistered fifth file [skills.md](../development/skills.md#vendored-from-the-skills-repo) warns nothing derives, because nothing in the tree marks a file as vendored.
An edit to it is an ordinary hunk rather than a declared fork, and an upstream fix reaches it only if somebody remembers the file came from there.

Measured 2026-09-10 on `origin/main`: the manifest holds four data rows and none names this file, against a control of the four that are named, all of which `--report` classifies.
That adoption also dropped the "not live yet" qualifier upstream carried at the time, so this copy has asserted things about the cross-check more flatly than upstream did.

The repair is a row in the manifest and a line in `skills.md`'s table, which makes the file's provenance and its fork state both readable.
It is forked rather than byte-identical, so the row's two digests will differ and `--report` will say `forked`; that is the state to declare, not one to remove.

**This finding was Q1057's second half and outlived it.** [#1888](https://github.com/actions-gateway/github-actions-gateway/pull/1888) closed Q1057 as already fixed, correctly for the finding it addressed — three files citing a discarded Go queuestore, repaired by [#1855](https://github.com/actions-gateway/github-actions-gateway/pull/1855) — but that reasoning does not reach this one, and deleting the row took it with it.
So a row carrying two findings was closed on one of them.
The general lesson is [Q1045](Q1045.md)'s neighbour rather than its case: a row whose findings have different fixes is closed one finding at a time, and nothing today asks whether a deletion leaves any behind.

[Q955](Q955.md) owns whether anything asks if the vendored files have moved upstream, which is the gap that let Q1057's first finding age in the first place.
