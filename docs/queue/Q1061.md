# security-operations abuse alerts: two shipped expressions cannot fire

Two rules in the `actions-gateway-security` group the doc tells an operator to drop into their `PrometheusRule` are inert as written, and one threat-map row rests on the same wrong claim.

**`ActionsGatewayWebhookRejections` selects a code the counter never carries.** Its expression is `rate(controller_runtime_webhook_requests_total{code="403"}[10m])`. controller-runtime writes a validating-webhook denial as an HTTP 200 whose `AdmissionReview` body carries the 403: `ValidationResponse` sets `Result.Code = 403` on the response struct, and `writeAdmissionResponse` JSON-encodes it without calling `WriteHeader` (vendored `sigs.k8s.io/controller-runtime/pkg/webhook/admission/response.go` and `http.go`, read 2026-09-07).
The `code` label is the HTTP status `promhttp.InstrumentHandlerCounter` observed, so a deny increments `code="200"` and the `403` series never exists.
The threat-map row "`ActionsGateway` CR in reserved namespace / spec probing → admission webhook `403` rejection rate" is the same claim in prose.
No metric today counts webhook rejections; the fix is either a GMC counter on the deny path or pointing the row and the rule at the apiserver's `apiserver_validating_admission_policy_check_total{enforcement_action="Deny"}` for the policies the chart ships, which is what the security dashboard (Q725) reads instead.

**`ActionsGatewayProxyLongLivedTunnels` subtracts two selectors that differ on `le`.** `increase(…_bucket{le="3600"}[1h]) - increase(…_bucket{le="1800"}[1h])` is a one-to-one vector match on every label, and the two sides carry different `le` values, so the result is empty and the rule never fires.
It needs `ignoring(le)` or a `sum by (namespace)` on each side, which is the form the security dashboard's tunnel panel uses.

Both were found while building that dashboard from the doc's own alert group.
`make promql-check` parses the doc's expressions and both parse, which is why neither surfaced: a well-formed query that selects nothing is exactly what that gate cannot see.
