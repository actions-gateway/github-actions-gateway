# Retry a job failed while its colocated egress proxy pool was unavailable

A job that fails because the tenant's egress proxy pool was down is a platform failure, and today it needs a manual re-run.
The design's second retry class recognises it from the worker snapshot: the colocated `EgressProxy`'s `Ready` condition was `False`, or `readyReplicas` was 0, while the job ran, and the class clears by observation once `Ready` is true again.

- **Reproduce first (R12).** Scale a dogfood set's colocated pool to zero mid-job, then show the discriminator separates it from the nearest tenant-caused shape, a job that fails on a host its allowlist denies.
- **The `observable` release is not built.** Q1244 built only the `freshPod` release the out-of-memory class needs; this class needs the deferred path to wait on `ready` ([How it waits](../plan/q555-automatic-recovery-design.md#how-it-waits)).
- **A shared pool in another namespace is out of scope**: the AGC watches EgressProxies in its own namespace only, so the class cannot see one.

It counts under its own `cause`, goes through the breaker (a pool outage is exactly a stampede) and the futility checks ([Q1320](Q1320.md)), and needs nothing from the proxy outcome metrics.
Gated on 2.1 as part of its headline ([release-2.1.md](../plan/release-2.1.md)).
