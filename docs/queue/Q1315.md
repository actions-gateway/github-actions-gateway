# Retry a job failed while its colocated egress proxy pool was unavailable

A job that fails because the tenant's egress proxy pool was down is a platform failure, and today it needs a manual re-run.
The design's second retry class recognises it from the worker snapshot at the job's completion, and that reading misses an outage the worker outlives and that is over when the completion arrives.
[The readings](../plan/q555-automatic-recovery-design.md#readings-for-the-egress-proxy-class-q1315), taken on 2026-11-24 on kind against GitHub, one run of each case, show these points:

- A pool that is back before the completion arrives reads healthy on both gateway shapes, because a runner that outlives the outage reports through the pool.
- A pool that stays down until GitHub gives up on the job is recorded with 0 replicas on a direct gateway, and as healthy on a proxied one, which hears nothing from GitHub while its own pool is down.
- A worker that ends inside the outage was not run; by source its end is read from the pod, so both shapes should record 0.
- `Ready` is the wrong fact: it reads `True` at 0 of 0 and `False` while a replica serves.
  The recogniser needs zero ready replicas, the release needs a ready one.

What is left:

- **A reading taken during the job**: the AGC noting when a watched pool has no ready replica, matched against the job's span.
  Not designed or tested, a managed pool's outage was not run, and the note has to outlive the moment the AGC learns of the job.
  A recogniser on `Ready`'s transition time is untested, and the readings show where it would not hold.
- **The dogfood reproduction (R12)**, owed by the design before the class merges: scale a dogfood set's colocated pool to zero mid-job.
  These readings are kind only.
- **The nearest tenant-caused shape (R12)**, a job that fails on a host its allowlist denies: read from source, and not run.
- **A fact that separates a job failed by the outage** from one that failed for its own reason during it: overlap in time alone does not.
- **The `observable` release is not built.** Q1244 built only the `freshPod` release the out-of-memory class needs; this class needs the deferred path to wait on a ready replica ([How it waits](../plan/q555-automatic-recovery-design.md#how-it-waits)).
- **A shared pool in another namespace is out of scope**: the AGC watches EgressProxies in its own namespace only, so the class cannot see one.
- **If nothing separates them**, the class is not buildable as designed and [the design](../plan/q555-automatic-recovery-design.md#classes-after-the-first) has to say so.

It counts under its own `cause`, goes through the breaker (a pool outage is exactly a stampede) and the futility checks (Q1320, built), and needs nothing from the proxy outcome metrics.
Not a 2.1 gate: nothing separates an outage's victims from the tenant's own failures, and how often a pool loses every replica is unmeasured ([release-2.1.md](../plan/release-2.1.md#explicitly-out-of-scope)).
