# Filing a queue row adds a page no local gate builds

`docs/queue/` publishes at `/dev/queue/`, so every new row is a new page under `docs/`.
`make check` never builds the site and `make docs-gates` does not either, so the whole `mkdocs --strict` class is invisible until CI.

**Measured 2026-09-04** on [#1839](https://github.com/actions-gateway/github-actions-gateway/pull/1839).
A new row's `target:` was written `../../docs/development/go-workspaces.md`, which escapes the mkdocs root and then points back into the docs tree; `docs/queue/README.md` renders `target` as a link, so `mkdocs --strict` aborted.
Three checks went red on one cause: `build` and `release-links` both abort on the warning and `doc-links-gate` aggregates them.
The session ran `make check` twice and `make docs-gates` once before pushing, all green, all structurally blind to it.

**The gap is between the rule's wording and the act it has to fire on.** [CLAUDE.md](../../CLAUDE.md) already says that adding or moving a page under `docs/` needs `make docs-build`.
Nobody filing a backlog row reads that as adding a page, and every worker in every dispatch wave files rows, so the exposure recurs on a schedule.

**Only the escaping form breaks.** A batch-wide read of every row touched by the six PRs of the 2026-09-04 wave found `../../.mdreflow.yaml`, `../../scripts/go/coverage.sh`, `../../.github/workflows/dependabot-go-sync.yml`, `../../scripts/manifest/check-registry-mirror-catalog-deny.py` and `../../.github/workflows/e2e-reusable.yml`, all leaving `docs/` for a code file and all fine.
So the check wants the escaping-into-`docs/` shape rather than a ban on `../../`.

**Done when** a row whose `target:` would break the site render fails before CI.
The cheap rung is a `queue-lint` rule keyed on that shape, which needs no site build and so can join the fast gates; the thorough rung is putting `docs-build` in reach of the docs gates, which costs a full mkdocs run.
Prefer the first unless the second is wanted for a reason this row does not carry.
