# render-overflow-check cannot load a Mermaid page while unpkg.com stalls

Separate from [Q1165](Q1165.md): that row's page made no load-blocking off-host request, and this one is a page that does.
A navigation retry cannot close this one, because every attempt waits on the same stalled host.

Measured 2026-10-09 against a local `make docs-build`, by routing every off-host request in the checker's browser context to a handler that never answers: `/design/04-operational-flows/`, the one page carrying a `class="mermaid"` diagram in each scope, then timed out waiting for `load`.
The request it hung on was `https://unpkg.com/mermaid@11/dist/mermaid.min.js`, a script Material's own bundle injects for the diagram; an unhung run then also requested `mermaid@11.17.2`, which reads as unpkg resolving the floating major (not checked).
`404.html` also hangs, on `https://actions-gateway.com/assets/wormhole-animation.webp`, but the checker only discovers `index.html` pages, so it is never navigated.
Every other page's off-host traffic is the two `api.github.com` repository-stats XHRs, which do not delay `load`.

So the gate's verdict on that page depends on unpkg.com answering within 30 seconds, three times over.
Blocking off-host requests in the browser context would remove the dependency, but it also changes what gets measured: the diagram would stay as unrendered source text, and its width is not the rendered SVG's.
Self-hosting Mermaid would remove it for the gate and for readers alike, since the published site loads a floating `mermaid@11` from a third-party CDN today; that is a site change, and it needs its own call.
