# Put the image digests in the copy-paste helm install commands

**A reader cannot paste the install command as written.** The five pages `release-pins-check` reads carry 40 `sha256:<component>` placeholders between them (README.md 4, `docs/index.md` 4, `install.md` 12, `upgrade.md` 12, `gitops.md` 8, counted 2026-11-17), and each page says to copy the four real digests from the release notes.
The chart ships no digests on purpose: an empty one fails the render, so nothing installs by a mutable tag ([install.md](../operations/install.md#pin-images-by-digest)).

**The digests exist only after the tag.** `publish.yml`'s `publish` job builds and pushes the images, and `chart-publish` runs after it (`needs: publish`).
The site builds each version's docs from the tag's own tree, so that tree can only hold placeholders, and the release skill's step 5 republishes the docs from a `release-X.Y` branch that may carry the pin bump and nothing else.

Two ways to close it, which this row decides between before any code:

- **Option A, write the digests into the pages after publish.** Step 5 already resolves the four index digests from the registry for the notes' Container images section.
  The same step would write them into the five pages on `main` and on the `release-X.Y` branch, and `scripts/release/check-release-digests.sh` would reconcile the pages against the registry as it does the notes.
  The chart's fail-closed default is unchanged.
  The cost is a second transcribed set of four values per release, and the runbook's rule that the docs branch carries only the pin bump.
- **Option B, bake the digests into the published chart.** `chart-publish` would set `gmc`, `agc`, `proxy` and `wrapper` `image.digest` in the chart before it packages and signs it, so `helm install --version X.Y.Z` needs no `--set`, and the pages have nothing to transcribe.
  A local `charts/actions-gateway` render stays empty and fails closed.
  This changes a documented security default, so it needs [the render-time enforcement's reasoning](../design/05-security.md#first-party-digests-are-enforced-at-chart-render-time) revisited and a sign-off, and every published chart then differs from its source tree by those four values.

Raised during the `v2.0.0` cut, on 2026-11-17, whose chart was already frozen at `v2.0.0-rc.3`'s bytes, so neither option can reach `2.0.0`.
