# Shell gates skip every script outside `scripts/`

`shellcheck`, `errexit-prologue-check` and `script-modes-check` all select their files with the same expression, `git_candidates 'scripts/*.sh'` ([shellcheck-scripts.sh:33](../../scripts/ci/shellcheck-scripts.sh), [check-errexit-prologue.sh:57](../../scripts/ci/check-errexit-prologue.sh), [check-script-modes.sh:99](../../scripts/ci/check-script-modes.sh)).
The rationale each states is about shell, not about a directory: `check-errexit-prologue.sh` exists because `set -e` does not reach inside a command substitution (Q733), which is true of any bash file in the tree.

**Measured 2026-09-09.** Four non-vendored, non-testdata scripts sit outside that selection, and every one of them declares `set -euo pipefail` without `shopt -s inherit_errexit`, which is the exact state `errexit-prologue-check` exists to reject:

| Script | Reader |
| --- | --- |
| [`deploy/monitoring/preview/render.sh`](../../deploy/monitoring/preview/render.sh) | the dashboard preview harness |
| [`docs/operations/examples/install-apiserver-audit-policy.sh`](../operations/examples/install-apiserver-audit-policy.sh) | **operators**, who copy and run it |
| [`docs/assets/render-wormhole-animation.sh`](../assets/render-wormhole-animation.sh) | the website asset build |
| `cmd/gmc/.devcontainer/post-install.sh` | devcontainer setup |

All four are shellcheck-clean today, which is what makes this worth adding rather than urgent, and also why "it passes" proves nothing on its own: assert a seeded fault fails.
The operator example is the one with a reader outside this repo.

**What it already cost.** Q1072 added a lock to `render.sh` and had to hand-run `shellcheck` to get any verdict on it at all, because no target in the tree would read the file.
A hand-run check is not a gate: it holds for exactly the session that remembered.

**The gap has a second layer, and CI measured it on that PR.** The file selection above is what the gate reads once it runs; whether it runs at all is a path filter, and that filter misses the same tree.
`unit-test.yml:134:            scripts:` lists `scripts/**` plus `deploy/templates/**`, `deploy/dogfood-e2e/**` and the MkDocs hooks, but not `deploy/monitoring/preview/**`.
Measured on [#1887](https://github.com/actions-gateway/github-actions-gateway/pull/1887) at head `13bf50b2e`, whose largest single-file change is 90 inserted lines of bash in `render.sh`: `gh pr checks` reported 40 pass and 26 skipping, and `shellcheck` was one of the 26.
So a PR can be entirely a shell change and still show a green check set in which no shellcheck ran: the [skipped-is-not-passed](../development/testing.md#path-gated-workflows-verify-the-heavy-gates-actually-ran) shape, reached through the filter rather than the gate.
Widening one half without the other fixes nothing: the filter decides whether the job starts, the pathspec decides what it then reads.

**The open question is the selection, not the gates.** Widening the pathspec to every tracked `*.sh` pulls in ~50 vendored scripts under `vendor/` and `tools/vendor/` and the two `testdata/` fixtures, none of which this repo may reformat.
So the shape to settle is whether to enumerate the non-vendored roots, exclude `vendor/` and `testdata/` by pattern, or keep a registry file the way `mk/gate-lists.mk` does for gates.
`script-modes-check` is the one that may not want widening as-is: a `docs/operations/examples/` script an operator copies has different mode expectations than an entry point under `scripts/`.
