# gate-lists-check accepts a gate or suite listed twice

`gate-lists-check` reconciles every managed list in `mk/gate-lists.mk` against the files on disk in both directions, which is what stops a gate being dropped or invented.
It says nothing about an entry appearing twice in one list.

Measured 2026-09-16 by duplicating the first `QUEUE_GATES` entry and running the gate: it passed, and the rendered command carried `queue-lint queue-lint`.
A duplicated entry runs that gate twice, taking a second slot out of the capped fan-out for a result nobody reads.
The five lists are all distinct today (59, 3, 13, 30 and 129 entries, no repeats), so this is a latent gap rather than a live defect.

The gate-lists merge driver refuses a merge of a file in this state rather than carrying the duplicate through, and names the entry.
That refusal is the only thing that currently reports the condition, and it reports it at merge time to whoever is rebasing rather than to whoever introduced it.
The reconciler is where it belongs, because that is what runs on the PR that adds the duplicate.

Unrelated to [Q574](Q574.md), which is one registry for the path lists the *workflows* write twice; this is one list assigning one entry twice.
