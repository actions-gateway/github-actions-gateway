# check-template-library ignores a column-0 patches list

`check-template-library.sh` reads an overlay's `patches:` items only when they sit at two-space indent (`check_patch_form` and `patch_targets` both key on `^  - `).
A column-0 list (`- target:`) is valid YAML that kustomize accepts (measured below), and may be what `kustomize edit` writes (unmeasured), so a hand-reformatted or tool-edited overlay can make both the JSON 6902 rule and the unmatched-target rule (Q1213, PR #2208) parse nothing and pass.

**Measured 2026-11-01** on the Q1213 scratch tree (`privileged-dind` template at a new `apiVersion`, `overlays/dind` target left, `patches:` items dedented to column 0): `kubectl kustomize` exited 0 and the gate exited 0, where the two-space form of the same tree exits 1.
Found by the Q1213 reviewer, who measured the gate side on the PR.

**Done when** the gate fails when the `target:` lines in an overlay's kustomization outnumber the targets it parsed (or parses any indent), with a `check-template-library-test.sh` case using a column-0 list.
The count-comparison form is unmeasured.
Distinct from Q1213's deliverable (PR #2208), which handled the two-space form.
