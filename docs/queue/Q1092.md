# Rotation section is v1-only while the page recommends v2

`docs/getting-started.md` § Rotating GitHub App Credentials is written entirely against the v1 API: it follows the `v1-gateway` block, patches `spec.gitHubAppRef` on an `actions-gateway.github.com/v1alpha1` `ActionsGateway`, and addresses the AGC as `deploy/actions-gateway-controller`.
That Deployment name is v1's.
In v2 the AGC is named per gateway: `agcNameV2` is `ag.Name + agcResourceSuffix` (`cmd/gmc/internal/controller/actionsgateway_v2_builder.go:72`), so a `team-a-gateway` tenant gets `team-a-gateway-agc` and the doc's `deploy/actions-gateway-controller` names nothing.

The page calls v2 the recommended path in five places (lines 6, 16, 48, 85 and 151), including the § 4 heading itself ("Create your gateway and runner set (v2, recommended)") and line 6 ("The recommended shape for a new tenant is the **v2 API**").
So an operator who followed the recommendation and then needs to rotate a compromised key is sent to steps that do not apply, and the first one that fails is `kubectl rollout status` against a Deployment that does not exist, during a credential compromise, which is the worst time to find out.

Measured 2026-09-10 on `claude/q958-fdef07`.
Not introduced by Q958; surfaced by its review, which asked what the two skipped rotation blocks actually name.

**Q958 narrowed the blast radius rather than fixing it.** `TestGettingStarted_SkipBlockNames` now pins the doc's `deploy/<name>` operands to `agcnames.ControllerName`, so the v1 name cannot silently drift, but that certifies the v1 name specifically, and a v2 rotation path would need a different assertion (the name is per gateway, so there is no constant to pin).
Deciding what the section should say comes first: either scope it explicitly to v1 and add a v2 sibling, or rewrite it for v2 with v1 as the note.

**The harness decides the shape, and the row did not say so.** Measured 2026-09-10.
`TestGettingStarted_SkipBlockNames` (`cmd/gmc/internal/controller/integration/getting_started_test.go:183`) requires *every* `deploy/<name>` operand in *every* `mode=skip` block to equal `agcnames.ControllerName`, the v1 name, and holds a floor of 3 such operands (`skippedDeployRefFloor`).
Both rotation blocks that name a Deployment are `mode=skip`, so **either** repair fails that test: rewriting for v2 changes the operands, and adding a v2 sibling adds new ones.
Whichever shape is chosen, the test changes with it, which is what makes this M rather than S.

**The row said there is no constant to pin, and there is one.** `agcResourceSuffix = "-agc"` at `cmd/gmc/internal/controller/actionsgateway_v2_builder.go:61` is package-private, but `cmd/gmc/internal/controller/integration` sits under the same `cmd/gmc/internal/` tree, so exporting it is importable there and is **not** an API-surface change: nothing under `internal/` is on the wire or in `api/`, so [api-review.md](../development/api-review.md) does not bind.
That is the cheap route: export the suffix, and assert a skipped block's operand is either `agcnames.ControllerName` or the page's own v2 gateway name joined to that suffix.
The alternative, moving the derivation to `api/apinames`, *is* an API change and needs the review; prefer the first unless something else wants the name too.

Do not dodge the test by writing the v2 rollout as a label selector (`kubectl rollout status deploy -l app=<gateway>-agc`) — that passes only because `deployRefRE` stops matching, which is the floor assertion's exact failure mode.
