# Untrusted-PR egress posture for Kata workers

Phase 1 validated 2026-08-24: four green self-hosted Kata runs name no non-GitHub non-registry host, graded against a Phase 0 control that fires on both.
Phase 2 is done as of 2026-08-28: the mirror manifests, over five upstreams rather than four once the grading added `gcr.io`, are validated on the dogfood cluster at 25 of 25 checks by `scripts/dogfood/e2e-mirror-validate.sh`.
Every instance serves a real upstream manifest, refuses uploads with 405, and exposes no debug listener, so the mirrors are measured serving rather than merely applied.
Phase 3's wiring is built as of 2026-08-28 and books the next dogfood session for its validation: dockerd via a mounted `daemon.json`, the non-Hub docker refs rewritten at the one chokepoint every `docker pull` shares, buildkit given a generated `buildkitd.toml`, and helm's OCI ref pointed at the ghcr mirror, with `make registry-mirror-wiring-check` holding the three files that name the endpoint set to each other.
None of that says a pull rode a mirror: open egress is still in place, so an unwired client reaches its upstream and the suite is green either way.
The reading that discriminates is `scripts/dogfood/e2e-mirror-hits.sh` over the mirrors' access logs, run after a green Kata run and before `e2e-stop.sh` takes the logs with the pods.
Enforcement, the deletion of `e2e-open-egress`, stays Phase 4.
