# Use the egress proxy as a failure sensor for conditions, events, retry

The per-tenant egress proxy sits on the path of the failures that dominate this repo's flake record (outbound fetches inside job steps), and joining a proxy event to the job it broke is something an operator-supplied proxy under ARC cannot do; the maintainer wants that advantage exploited (2026-10-10).
Today the proxy's counters carry no labels, its denial and dial-failure log lines name the host but not the client, and per-job attribution exists only behind the opt-in `ConnectionsWithSource` audit mode (Q986), all read from `cmd/proxy` on 2026-10-10.
Q555's draft lists the retry uses: upstream-unreachable as a retry class, a per-destination breaker, policy denial as a futile retry, and an egress-IP self-probe against GitHub.
This row is the wider inventory beyond retry: per-set conditions naming a degraded destination, a warning before a registry rate-limits the tenant's egress IP, flagging jobs that bypass a configured mirror, and per-job egress bytes for cost attribution.
**Ask:** which uses to build first, since each costs a proxy change and most need a security review.
Constraints: no TLS termination, destination labels keyed on the matched allowlist entry, and a security review of failure-only attribution against `05-security.md` before any of it ships.
