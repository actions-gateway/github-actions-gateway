# Label egress proxy outcome metrics by allowlist entry and outcome

The proxy's `actions_gateway_proxy_dial_errors_total` and `_connect_denied_total` carry no labels, so neither an operator nor the AGC can tell which destination is failing (read from `cmd/proxy`, 2026-10-10).
Count every CONNECT by the allowlist entry that matched and an outcome (allowed, denied, DNS failure, dial refused, dial timeout), keyed on the entry rather than the raw host so cardinality stays bounded by the allowlist.
This is metrics, not a bespoke API: aggregates, bounded labels, read by dashboards and alerts, and fine a scrape interval late.
The AGC can read the same endpoint to derive a per-set condition naming a degraded destination, which is the per-destination breaker and "wait until it clears" signal Q1183's classes need.
Per-job attribution is Q1184; the longer-horizon proxy-as-sensor ideas, including cluster-level aggregation, are in [G.18](../design/appendix-g-future-enhancements.md#g18-the-egress-proxy-as-a-platform-sensor).
Constraint: no TLS termination, so an upstream's HTTP status stays invisible.
