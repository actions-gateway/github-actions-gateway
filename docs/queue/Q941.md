# `session-worker`'s contract has seven gaps workers hit independently

Reported by workers during the 2026-08-18 batch, each quoting the copy loaded into its own context.
Four gaps: §4 says a per-item store commits the row with the code, contradicting CLAUDE.md's split-when-code-is-touched (Q889), and four workers hit this one independently and all followed the repo; §6 covers the post-`ready` window only "with no dispatcher", so a dispatcher awaiting a wake from an already-exited watcher is unhandled; nothing covers closing a second pre-existing row naming the same defect; nothing covers changing a shared script's output format, which no path-based sweep can see and the consuming side cannot detect either.
A fifth surfaced later: nothing says to check a pinned dependency's changelog when a row's asserted cause could have been retired by a version bump the repo already took, which is what settled Q835.
Two more surfaced in the 2026-08-19 release-harness batch, and the first gap took its fifth and sixth sightings there.
Sixth gap: nothing says whether a worker may add repo-wide verification machinery for an in-scope change.
Q899's worker added `publish-digest-check` because `publish.yml` runs only on a `v*` tag, so no PR exercises it and a bad edit surfaces during a release; the dispatcher accepted it on the `check-cosign-pin.sh`/Q903 precedent.
Seventh: nothing covers a change whose verification needs the network and cannot be gated locally.
Q927's worker had to verify cosign's release signature live, and filed [Q944](Q944.md) for the tooling gap it found doing so.
An eighth surfaced in the 2026-08-27 dispatch batch, and it is the only one so far that let a worker damage another worker's PR.
The takeover route is written for a branch whose worker has exited, but its precondition check is `gh pr view <n> --json state,mergedAt`, which reads *PR* liveness and never *author* liveness.
So a dispatcher that wrongly reads a session as gone hands a takeover a premise nothing downstream can refute.
Two takeovers adopted live authors' branches that morning; one ran `gh pr ready --undo` on a PR whose author was still working, and because `gh` authenticates as the same account for every session here, the timeline recorded the maintainer drafting it.
The three reads that settle ownership come from the remote rather than from `ListAgents`: `git rev-parse origin/<branch>` matching `headRefOid`, `git rev-parse --abbrev-ref @{u}`, and `git reflog --format=%H` containing the head.
`--format=%H` is load-bearing on the third, because the default abbreviates and a grep for a 40-character SHA returns 0 for a commit the session made itself.
Filed upstream 2026-08-27 with the two other gaps that run found.

The skill lives in `karlkfi/claude-skills`, so this needs a human to file upstream.
The repo-side halves are documented in [parallel-dispatch.md](../development/parallel-dispatch.md).
