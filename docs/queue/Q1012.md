# Nothing checks that a make target named in docs exists

`make next-task` was taught by CLAUDE.md and had no rule behind it, so a session following the entrypoint the repo names ran `make -n next-task` and got `No rule to make target`.
Measured 2026-08-27 across every tracked `*.md`: four targets named in prose exist in no Makefile in the tree — `next-task` (CLAUDE.md, corrected by Q990), `status-gates` (scripts/README.md's `run-parallel.sh` row), and `e2e-load-images` and `e2e-netpol` (plan docs).
The repo already gates the neighbouring classes: `doc-links` for hrefs, `check-script-docs.sh` for scripts missing a README row, `gate-lists-check` for the gate registry.
A named-but-absent target is the same family and the only one unguarded.

Two things any implementation has to get right, both measured while filing this:
- **Union every Makefile, not the root one.** `deploy`, `undeploy` and `deepcopy` are real targets in `api/Makefile` and `cmd/*/Makefile`, and docs name them bare.
  Checking only the root Makefile flags 16 of 23 mentions wrongly, which is a gate nobody would keep.
- **Decide what `docs/plan/` means.** Two of the four live in plan docs, which are point-in-time records rather than instructions, so either scope them out or accept that archiving a plan is what clears the finding.

Parse targets from `make -qp` rather than by grepping recipe lines, since `-qp` resolves includes and pattern rules; note it exits 1 by design when a target is out of date, so the exit status is not the signal.
