# Rate-limited refusal can transiently report `reason=ceiling`

`Admit` reserves before the scale-up rung refuses (Q717), so inside the reserve-to-release window a concurrent delivery reads an inflated count and is told `ceiling` while the set is really ramp-limited.
Transient, spends no token, and cannot over-admit — `admit` refuses at `reserved >= limit`, so the churn inflates the count only within the ceiling.
Needs ceiling-many `Admit` calls in one sub-microsecond window, so it concentrates on a small `maxWorkers` with many listeners.
Measured at `burst=1`: ceiling 2 / 200 concurrent gives 194 `ceiling` labels for 1 admitted job, and it still fires at ceiling 2 / 50.
A `tokens()` peek ahead of the ceiling rung removes it and was rejected: it makes the both-bound case report `scaleup` persistently, trading a rare transient for a common systematic mislabel.
Found in review of #1702.
