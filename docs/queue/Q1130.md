# Nothing spaces a batch across the registry files that still collide

`.gitattributes` routes four paths to per-clone merge drivers: `scripts/README.md`, `mk/gate-lists.mk`, `docs/plan/README.md` and `docs/roadmap.md`.
Two pull requests editing *different* rows of one of those files conflict on GitHub whenever their rows are directly adjacent.
The same merge resolves cleanly in any clone that has run `make merge-driver`, so the cost lands entirely on the host: a `DIRTY` pull request, or a merge-queue eviction, and a rebase plus a force-push plus a full CI cycle each time.

**The mechanism is already written down, and restating it is not what this row is for.** The driver's own header says it (`scripts/docs/git-merge-script-index.sh:18:reduce merge-queue evictions, and no local driver can`), and [parallel-dispatch.md](../development/parallel-dispatch.md#the-dispatcher-owns-assignment-not-coordination-files) carries the rule that follows: space the assignment.
[Q1121](Q1121.md) owns the adjacent defect that `git merge-tree` answers the driver's question rather than the queue's, and is not this.

**What is missing is anything that applies that rule to the paths which still collide.** The pre-flight checklist item is `docs/development/parallel-dispatch.md:509:No two assigned Queue rows adjacent`, and Queue rows no longer share a file.
`docs/STATUS.md` is gone and the backlog is one file per item, which `.gitattributes` states outright when it declares the backlog deliberately unrouted.
So the checklist names a shape that cannot collide and none of the four shapes that can.
The `gh pr create` guard that compared colliding line ranges is retired (`CONTRIBUTING.md:342:Nothing checks this for you`), leaving a hand comparison nothing prompts anyone to run.
`scripts/README.md` is the one that bites, because `check-script-docs.sh` fails a gated script with no row, so a batch adding scripts has no choice but to land rows in one table.

## The measurement

**Taken 2026-09-19** over the 2026-09-18/19 dispatch run, with `git merge-file` on the three blobs rather than `git merge-tree`, for the reason Q1121 gives.
At `71ced4d76` the file carries 263 table rows over 394 lines, `check-queue-rules-test.sh` is line 200, and `queue.py` is directly beneath it at line 201.

- **#1965 against #1964.** #1964 edits line 201 and #1965 edits line 200.
  Against base `5b7550305`: exit 1, one conflict hunk. #1964 merged at 17:09:40Z and #1965 force-pushed a rebase at 17:17:42Z.
- **#1965 against #1967.** #1967 edits that same line 201 while #1965's head `ebbaffd39` still edits line 200.
  Against base `c8a323361`: exit 1, one conflict hunk. #1965 entered the merge queue at 15:46:54Z and was removed from it at 15:51:13Z.
- **Control, #1962 against #1965.** #1962 edits line 58, far from #1965's lines 200, 236 and 297.
  Exit 0, no markers.
  Adjacency decides this, not the shared file.
- **Negative control.** Identical sides exit 0, so the harness is able to report clean.

Every resolution under the `scriptindex` driver came back clean at exit 0, reconciled at 263 rows and 394 lines on every side, with no row added, dropped or reordered.
A third eviction followed at 16:06:33Z to 16:06:51Z; its cause is unmeasured and it is not counted above.

**The conflict window is one line, not six.** `CONTRIBUTING.md:345:Two edits within six lines of each other collide` describes the diff-context overlap the retired guard keyed on, which is a fair trigger for *read the other diff* and over-reports the merge itself by five lines.
Measured by a synthetic sweep on this file at base `c8a323361`: edits on lines 200 and 201 conflict, and 200 against each of 202, 203, 204 and 205 merges clean at exit 0.
Git needs one unchanged line between two changes and adjacent table rows leave none, so the hazard is exactly the zero-gap case and any check keying on six lines is conservative by design rather than correct.

## What to do is open

Three directions, none of them measured for cost or feasibility, and there may be better ones:

- Give the file a row order that is stable under append, so a new row cannot land beside an edited one.
- Split it, so concurrent work touches different files the way the backlog store already does.
- Accept the tax and name the four paths in the pre-flight checklist, so a dispatcher spaces the assignment across them the way it used to across Queue rows.

**Measure:** how often two open pull requests in one run land within one line of each other in a driver-routed file, read off the `gh pr diff` hunks of the last several dispatch runs rather than estimated; and what splitting `scripts/README.md` by group would cost `check-script-docs.sh`, which reads column 1 of every table in it.
The deliverable is this row rewritten with a direction chosen, not an implementation.
