# `mdreflow` joins an author's sentence split, and the gate ratifies it

`make md-reflow` rejoins two sentences an author has split onto separate source lines, producing a line that violates the one-sentence-per-line rule [documentation-standards.md](../development/documentation-standards.md#line-breaks-in-prose-one-sentence-per-line) states.
`make md-reflow-check` then returns 0 on the result, because it asks the same code the same question: the formatter that enforces the rule is what breaks it, and the gate that checks the rule is blind to it by construction.
The class is therefore unfixable by hand, and a contributor who splits such a line has it silently rejoined by the pre-commit hook.
`max-width: 0` means nothing re-wraps, so the defect is in the sentence-boundary detector rather than the wrapper.

**One trigger is identified and verified.** A sentence whose terminating period falls *inside* an emphasis or code span defeats the splitter: `**Bold sentence ends here.** Next sentence follows.` stays joined, while moving the period outside the span (`**…here**. Next…`) splits correctly.

**A second trigger exists and is NOT identified**, which is the part to start from rather than assume closed.
[Q970](Q970.md) body line 4 (568 chars, two sentences, live on `main`) joins although its terminating period is *outside* its span, so the identified trigger does not explain it.
Measured 2026-08-25 by deleting the mechanism, restoring after each probe: splitting the line and running `make md-reflow` rejoins it; so does restructuring the second sentence to open with a word, and ending the first in a plain word.
Every component tested alone splits correctly — the leading link, the escaped-bracket regex span, the quoted `rp` span, a dotted token in a code span, and the line's own tail — and removing the leading link leaves it joined at 509 chars.
`mdreflow --explain` reports nothing for it, so it is processed rather than declined and no reason code is offered.
Whoever picks this up starts from those exclusions.

Neighbour: Q975 (in flight, so not linkable here) covers `md-reflow-check` being `mdreflow --check`; this sits inside that rather than against it, and is the opposite direction from the re-wrapping claim Q975 retracted.
