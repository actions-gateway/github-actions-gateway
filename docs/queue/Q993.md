# `mdreflow` joins an author's sentence split, and the gate ratifies it

`make md-reflow` rejoins two sentences an author has split onto separate source lines, producing a line that violates the one-sentence-per-line rule [documentation-standards.md](../development/documentation-standards.md#line-breaks-in-prose-one-sentence-per-line) states.
`make md-reflow-check` then returns 0 on the result, because it asks the same code the same question: the formatter that enforces the rule is what breaks it, and the gate that checks the rule ratifies whatever it produced.
**The compliant form is what the gate rejects.** Measured on mdreflow v0.3.0 (pinned in [tools/go.mod](../../tools/go.mod)): `mdreflow --check` exits **1** on the hand-split form with `would reformat`, and `make md-reflow-check` exits non-zero, while both pass on the joined form.
`md-reflow-check` sits in `CHECK_FAST_GATES` and in the `--queue` and `--docs` lists ([mk/gate-lists.mk](../../mk/gate-lists.mk)), so a contributor who writes the sentence-per-line form reddens `make check`, `make docs-gates` and `make queue-gates`.
The class is therefore unfixable by hand, and the reason is the gate rather than any hook: the tracked [.githooks/pre-commit](../../.githooks/pre-commit) runs gofmt and em-dash density and mentions `reflow` nowhere, so nothing rewrites the file behind the author.
`max-width: 0` means nothing re-wraps, so the defect is in the sentence-boundary detector rather than the wrapper.

**One trigger is identified and verified.** A sentence whose terminating period falls *inside* an emphasis or code span defeats the splitter: `**Bold sentence ends here.** Next sentence follows.` stays joined, while moving the period outside the span (`**…here**. Next…`) splits correctly.

**A second trigger exists and is NOT identified**, which is the part to start from rather than assume closed.
The live instance is `docs/queue/Q970.md` file line 14, two sentences: it joins although its terminating period is *outside* its span, so the identified trigger does not explain it.
Q970 has since completed and its file is gone from `main`, so read the instance out of git rather than the tree: `git show 073da2f5a:docs/queue/Q970.md | sed -n 14p`, 579 chars at that blob.
Re-anchor to a live instance before working it if that blob will not serve.
Measured 2026-08-25 by deleting the mechanism, restoring after each probe: splitting the line and running `make md-reflow` rejoins it; so does restructuring the second sentence to open with a word, and ending the first in a plain word.
Every component tested alone splits correctly — the leading link, the escaped-bracket regex span, the quoted `rp` span, a dotted token in a code span, and the line's own tail — and replacing the leading link with a short plain word still leaves the whole line joined, at 509 chars against the original 568.
`mdreflow --explain` reports nothing for it, so it is processed rather than declined and no reason code is offered.
Whoever picks this up starts from those exclusions.

Neighbour: the [stranded-connective note](../development/documentation-standards.md#splitting-an-em-dash-sentence-must-not-strand-the-connective) (Q975, shipped) covers `md-reflow-check` being `mdreflow --check`; this sits inside that rather than against it, and is the opposite direction from the re-wrapping claim Q975 retracted.

## A second trigger, identified and verified, 2026-09-10

**A sentence whose first character is `#` is never split onto its own line.** Splitting there would produce a line opening with `#`, which Markdown reads as a heading, so the splitter declines it and the two sentences stay joined.
Met live while writing the Q861 rule into [maintaining-backlog.md](../development/maintaining-backlog.md#a-rows-asserted-defect-is-a-claim-not-a-finding) and the Q830 rule into [documentation-standards.md](../development/documentation-standards.md), both of which open a sentence with a PR reference.

Measured on the pinned mdreflow by three arms over one fixture, varying only the second sentence's opening token:

| Second sentence opens with | Result |
|---|---|
| `#1417 shipped on that framing…` | **joined** |
| `Then #1417 shipped on that framing…` | split |
| `1417 shipped on that framing…` | split |

So it is the `#`, not the number: a bare `#hashtag` opener joins too.
The gate ratifies it in exactly the shape this row already states: `--check` exits **0** on the joined form and **1** on the hand-split compliant form, and `--explain` reports nothing, so the line is processed rather than declined.

**It does not explain this row's open instance**, so the unidentified trigger above is still unidentified and this row does not close on it.
`Q970` file line 14's second sentence opens with a link, and a leading link, a leading `[bracket]`, a leading code span and a leading plain word all split correctly on the same fixture, which agrees with the exclusions already recorded above.

The workaround is to open the sentence with a word, which is what both prose sites now do.
