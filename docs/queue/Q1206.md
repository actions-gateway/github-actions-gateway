# Drop the Dragonfly node-client caveat once a candidate's gate runs it

**Event:** a release candidate's dogfood gate completes its `dragonfly` leg with `E2E_DRAGONFLY_NODES=1`.

Once that happens, the [reference-architectures page](../operations/reference-architectures.md#untrusted-pull-requests-at-scale) states something false.
Its "Untrusted pull requests at scale" table row says the node client is gated "from the next candidate", and the profile's section says no candidate has run it yet and that `v1.9.0`'s gate ran the Dragonfly back end without it.

Those caveats exist because #2094 added the node client to the leg on 2026-10-23, after `v1.9.0-rc.2` (2026-10-05): `DRAGONFLY_NODES` has 0 matches in `validate-release.sh` and `e2e-start.sh` at `v1.9.0`.
The fix is to drop the "from the next candidate" qualifier from the table cell and replace the two-sentence caveat with the candidate that first ran it.
