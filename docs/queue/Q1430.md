# An abandoned run's re-run wait is lost on an AGC restart

A run the gateway force-cancelled, because its worker never started, stays cancelled with no re-run and no signal when the AGC restarts before capacity returns.
Read from source on 2026-11-27, not run: the wait is the in-process map `abandonedReruns`, filled by `registerAbandonedRerun` after the cancel and read by `sweepAbandonedReruns`, and nothing persists or re-adopts it.
The wait lasts up to 30 minutes, and a starved pool is when an AGC is most likely to be rescheduled.
The runbook section on the wait does not mention a restart.

The same wait ending at its 30-minute window is quiet too: a Warn log line and `actions_gateway_abandoned_run_rerun_waits_total{outcome="expired"}`, with no Event on the `RunnerSet` naming the run that now needs a manual re-run.
A recovery whose re-run GitHub never accepts, or whose budget is spent, emits one.

**A fix:** park the wait in the set's failure ledger as the out-of-memory class parks its re-run (`parkRerun`, adopted on start by `AdoptPendingReruns`), keyed by run, and emit a Warning Event naming the run when the window closes.
The ledger already holds the attempt GAG force-cancelled, which is the fact a restarted AGC needs to tell its own cancel from a user's.
