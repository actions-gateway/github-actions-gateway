# A clean result that meant nothing, fifteen times across two batches

One 2026-08-18 batch produced five: a non-fence-aware heading regex; `gh run list --commit` empty on queue-merged commits (runs attach to the `merge_group` ref); `git diff HEAD..origin/main` reporting both directions; cwd drift making a path-scoped `git diff` read clean; `grep -c` counting passing lines.

One 2026-08-27 dispatch run produced ten more, six of them the dispatcher's own: an em-dash *ceiling* read for the Q742 diff *ratchet*; `gh run list` conclusions read at run level for a job-level claim; `ListAgents` absence read as a session exit rather than a rename, three times, costing two wrongly dispatched takeovers; `--jq '.conclusion // .status'` printing blank because the field is an empty string in flight; `grep -c` twice more under ugrep, once counting lines and once from a pattern ugrep rejected outright; a plus-or-minus-2-line census window narrowing the population before the count; `actor.login` naming the shared credential rather than the person; and turn timestamps read as CI latency.

**The rule already exists at two rungs and did not hold.** This file's [status-is-a-claim section](../development/testing.md#the-status-you-report-is-a-claim-too) states it ("a sound instrument still answers only its own question"), and the global agent instructions state the scoping fix explicitly, that it applies to any output you act on and not only to what you report.
So the gap is not a missing rule and the fix is not another sentence.
Fourteen of the fifteen were caught by a *different* session re-deriving the reading, and the one self-caught instance was corrected only after the claim had already been sent.

What this row wants is the mechanical half: which of these can be made to fail loudly instead of quietly.
Three look tractable.
`grep` here dispatches to ugrep, so a rejected pattern exits non-zero while printing usage, and a wrapper or a documented preference for the Grep tool would convert a silent zero into a stop.
A job-level reading has a concrete instrument (`gh run view <id> --json jobs`) that a helper could make the default.
An empty-string `conclusion` is a one-line `--jq` fix wherever the repo's own scripts read it.
The rest may only be documentable, and saying which is which is the deliverable.
