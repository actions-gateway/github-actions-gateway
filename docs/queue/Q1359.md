# semver-floor misses a Dockerfile base bump as shipping nothing

**`semver-floor.sh` reports a commit that changes a shipped image's base as shipping nothing.** Measured 2026-11-17 over `v2.0.0..f156d4c53`: it listed `e25db67fb` (#2344) under *Withheld*, "whose type would raise the floor, but which ship nothing".
That commit moved `build-runner`'s `docker:29-cli` base from `2357639a` to `34507eb5` in the root `Dockerfile`, which changes the Docker CLI, buildx and compose binaries `build-runner` and `cache-runner` ship, and clears CVE-2026-78669 from them.
The `distroless/static` bump `6c770110c` (#2335), which changes the GMC, AGC and proxy bases and touches only the `Dockerfile`, is also absent from its *What sets it* list.

The script's own header says it derives the surface from `publish.yml`'s image matrix and "the Dockerfile stages behind it", and its summary line counts package directories and chart trees only, so a `FROM` line is read as no surface at all.
That the cause is the `Dockerfile` itself being outside the surface is inferred from the two commits above, not read from the code.

**Why it matters.** Its *Withheld* section is what a release author reads to decide what the notes and the floor leave out.
Taken at its word for `v2.0.1`, it would have dropped the release's one vulnerability fix from the notes.
Here the floor stays `PATCH` either way, but a `feat` that changed only a base would lower a `minor` floor to `patch`.

**Done when** a commit changing a `FROM` line of a stage `publish.yml` publishes counts as touching the released surface, with a case in `release-delta-test.sh` or a semver-floor test pinning it.
