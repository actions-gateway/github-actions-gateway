# `MaxWorkersCeiling` breaches its 20s wait on main, cause unmeasured

**Top of queue per the [flakes-first rule](../development/maintaining-backlog.md#flake-fixes-go-first).**

`TestAGC_PodProvisioning_MaxWorkersCeiling` failed on `main` in [integration-test run 32934660757](https://github.com/actions-gateway/github-actions-gateway/actions/runs/32934660757), 2026-08-26 05:39 UTC on `ubuntu-latest`: `Condition never satisfied` at `pod_provisioning_test.go:457` after 20.38 s, on "a runner pod should be created once the maxWorkers ceiling is lifted".
No code change intervened and the suite has been green on `main` since, so it fits the flake definition.
This is the only genuine test failure in `integration-test`'s last 25 `main` runs; the other red is a run whose two module jobs concluded failure with no failed step, which is a cancellation rather than a verdict.

**A candidate the log offers, and it is unverified.** The assertion waits on a *second* job being acquired after the ceiling lifts: the test advances `preexisting-worker-0` to `Succeeded`, enqueues a fresh job, and expects a runner pod.
The run log shows the first job dropped at 05:39:03 with `provisioner: concurrency ceiling reached (2 active pods)`, and then no further `AcquireJob` for `ceiling-rg` in the 20 s window.
Whether the listener simply had not polled again, whether the ceiling-lift has no event source to wake the reconciler, or whether the CI runner was starved, is not established by the log alone.
Settle which before changing the wait, because a budget raise is the remedy that fits none of the three.

Reproduce against the full `cmd/agc` suite rather than alone: [Q968](Q968.md) is the same suite and the same `Eventually` shape, and it reproduced only in-suite, at 1 red in 4 runs on one unchanged tree.
Its investigation traced that breach to a shutdown defect rather than to load ([#1754](https://github.com/actions-gateway/github-actions-gateway/pull/1754), merged 2026-08-27 as `17de0762f`), so treat a product cause here as live too.
[Q1007](Q1007.md) is the GMC-side sibling and owns the measurement showing that machine load reproduces the *suite slowdown* in this class without reproducing the *failure*, so do not assume load here without measuring it.
