# Image-build guide says PSS baseline permits Unconfined seccomp

**`in-runner-image-builds.md` recommends rootless BuildKit on the `baseline` profile on the strength of a claim about Pod Security Standards that the upstream checks contradict.** The profile table says `baseline` "**Permits** running as root (uid 0) inside the container and `seccompProfile: Unconfined`", and Approach 1 says "`baseline` permits `seccompProfile: Unconfined` and the `unconfined` AppArmor annotation; `restricted` forbids both".

Measured 2026-11-10 with the vendored `k8s.io/pod-security-admission/policy` v0.37.2 at the `baseline` level, which is the code Pod Security Admission runs: a pod-level and a container-level `seccompProfile.type: Unconfined` are each refused (`seccompProfile (pod must not set securityContext.seccompProfile.type to "Unconfined")`), and so is an `Unconfined` AppArmor profile.
The cases are `pod seccomp Unconfined`, `container seccomp Unconfined` and `AppArmor Unconfined` in `TestRunnerTemplate_PodShape_Create` (`cmd/gmc/internal/webhook/v2/runnertemplate_podshape_test.go`).
Not run against an apiserver; the neighbouring `TestUpstream_PodSecurity_BaselineAdmitsNetworkVolumes` shows the envtest apiserver enforcing `baseline`, so a pod case there would settle it in one run.
Running as root is permitted at `baseline`, so that half of the table cell is right.

The page now also disagrees with the tree: the `RunnerTemplate` webhook holds a namespaced template to `baseline` (Q1322), and [its runbook](../operations/troubleshooting.md#runnertemplate-rejected-pod-shape-past-baseline-volume-type-or-serviceaccount-token) lists an `Unconfined` profile among the refusals.

What is unmeasured is the consequence: whether rootless BuildKit works on the nodes GAG is tested on under `RuntimeDefault` seccomp, which decides whether Approach 1 keeps `baseline` as its recommended profile, moves to a `Localhost` profile, or needs a `ClusterRunnerTemplate` on the `privileged` profile.
Correcting the two sentences without that answer would leave the recommendation unsupported.

**Done when** the profile table and Approach 1 state what `baseline` forbids, and the BuildKit recommendation names a profile it was run under.
