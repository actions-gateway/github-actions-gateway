# `manifest-validate` never triggers on a `deploy/kata-ci` change

`scripts/manifest/manifest-validate.sh` yamllints `deploy/kata-ci` and kubeconforms two of its files by name, but `deploy/kata-ci` appears nowhere in `.github/workflows/`, so a PR changing only those files runs neither check and goes green by skipping.
Measured 2026-08-27: a recursive search for `kata-ci` under `.github/` returns nothing, against the same search for `deploy/templates` returning three filter entries.
The fix is one entry in the `manifests` filter beside `deploy/templates/**` and `deploy/monitoring/**`, which are on that list for exactly this reason.
A third instance of [Q948](Q948.md)'s class and separable from it: Q948 wants the reverse assertion that would have found this, and this row is the entry that assertion would demand.
