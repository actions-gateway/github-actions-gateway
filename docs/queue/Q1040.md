# A new backlog row can pass `make docs-gates` and redden CI

Two mechanisms compound, and a row that breaks a store rule survives both.

**`DOCS_GATES` omits the store's own gates.** [`mk/gate-lists.mk:146`](../../mk/gate-lists.mk) lists 20 gates and neither `queue-lint` nor `queue-rules-check` is among them, though both sit in `ALL_GATES` and in the `QUEUE_GATES` group defined 43 lines above.
So the target whose help text reads *every gate a prose change can fail* cannot fail on a malformed row.
`CLAUDE.md` states the opposite, that after Q930 a prose edit needs no hand-run checker of its own; for a `docs/queue/` edit that is not true.

**Running the checker by hand before committing also misses it.** [`check-queue-rules.py:266`](../../scripts/docs/check-queue-rules.py) sets `head_items = items_at("HEAD")`, the committed tree, because rules 8 and 9 diff it against the merge base.
Rule 11, the label vocabulary check, reads the same set.
A row written and not yet committed is therefore invisible to the rule that would reject it, and the run prints `ok` with a count that looks like it included the new file.

**Measured 2026-08-29** on [#1796](https://github.com/actions-gateway/github-actions-gateway/pull/1796).
`Q1038` was filed wearing an `e2e` label that is not on the `**Labels:**` line.
`make queue-lint` and `make queue-rules-check` were both run by hand before the commit and both printed `ok`; `make docs-gates` was run after the commit and passed, because it does not include either.
CI failed `lint-status` on rule 11, which took `status-lint-gate` down with it.
Re-running `queue-rules-check` after the commit reproduces the finding immediately.

**Done when** a `docs/queue/` edit cannot reach CI with an undeclared label.
Adding `$(QUEUE_GATES)` to `DOCS_GATES` closes the first half and is probably the whole fix, since the gate then runs after whatever commit the developer made.
The pre-commit blind spot is inherent to a merge-base diff and is better documented than engineered around; note it in [maintaining-backlog.md](../development/maintaining-backlog.md) so the workflow says commit first, then check.
