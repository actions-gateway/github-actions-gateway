# Drop the one-valued tier label from the disruption metrics

Seven disruption and re-run series carry a `tier` label whose only value is now `scaleset` (`cmd/agc/internal/runnercore/metrics.go`, the label lists at lines 184-214 and 285, read 2026-11-05).
An operator gets nothing from a label with one value.

**Who reads it, measured 2026-11-05 with a word-boundary scan of tracked files.** No shipped alert or recording rule does: `prometheusrule.yaml` mentions a tier only in prose, and `tier=` appears nowhere under `deploy/` outside the preview exporter.
Two panels on `grafana-dashboard-tenant.json` group on it and print it in their legends, *Disruption retries (1h)* and *Abandoned runs awaiting capacity (1h)*; the other three dashboards do not.
`deploy/monitoring/preview/exporter.py` writes it, and `devtools/docs/metricreference/values.go` knows its name.
`tier` is also a log field, which `github_e2e_test.go:1325` asserts, so that is a separate decision from the metric label.

**What breaks if it goes.** A query filtering `{tier="scaleset"}` returns nothing rather than erroring, which is how an operator's own dashboard would fail; `by (tier)` keeps working and loses the split.
Series recorded before the upgrade keep the label, so an `increase()` across the upgrade spans two series, the same continuity [Q417's change](../operations/observability-metrics.md#breaking-observability-changes-q417) documented going the other way.

**What each side costs.** Keeping it costs one always-equal label, and a sentence in the metrics reference and each `Help` saying so.
Removing it takes the seven label lists and their `WithLabelValues` calls, and optionally the parameter threaded through 13 functions (46 source lines match `, tier` in `cmd/agc/internal/provisioner`, plus 89 test lines naming the tier constants), which [Q1272](Q1272.md) already approaches by removing `evictionTierClassic`.

**Timing is weaker than it looks.** `v2.0.0` is a convenient moment, because its upgrade guide already makes an operator rework queries against the removed classic series.
It is not the last chance: no document found here promises metric-label stability, and Q417 and Q497 changed these label sets in `1.x` with an upgrade note.

This is Karl's call and has not been asked; Q1273 left the label in place and states it as always `scaleset` in the metrics reference and in each `Help`.
