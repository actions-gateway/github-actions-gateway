# Run the release gate's e2e legs in parallel across GCP projects

**Event:** the release gate's wall clock becomes the thing that delays a release, or a fourth e2e leg is proposed.

With the DinD leg (Q1159) and the Dragonfly leg (Q1160, both shipped) the gate runs three e2e legs in series on one cluster, each a healthy 25–33 minutes by the runbook's measure.
They run in series because they share one tenant namespace, RunnerSet and node pool, and one project-wide `CPUS_ALL_REGIONS` quota the deploy leg also draws on.
A cluster per leg, each in its own project, removes all four contentions and brings the gate back to roughly one leg's duration.

**What it costs is unpriced.** The expectation is that it costs more than the serial gate, because GKE's free tier covers one cluster and every extra project's cluster pays its own management fee and nodes; that is an expectation, not a measurement.
It also multiplies what `validate-release.sh` assumes is singular: the resolved target the wrapper confirms, the lease it takes per target, and the keyless CI identity Q880 bootstrapped on the one dogfood project.
Not a duplicate of [Q1158](Q1158.md), which makes one target's lease visible across hosts; this needs a target per leg.
