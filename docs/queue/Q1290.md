# First-label prefix overlap lets a sweep deregister another set's runners

Two `RunnerSet`s with first labels `ci` and `ci-linux` pass the Q791 guard, because it compares first labels as exact strings.
At listener start the stale-record sweep for `ci` lists every runner named `ci-*` under the GitHub owner (`listener.go`, `ListRunnersWithPrefix`), treats only its own set's worker pods as claimed (`claimedRunnerNames` in `runnerset_scaleset.go`), and deregisters each record that is offline and not busy.
A `ci-linux-<job>` record registered for a pod that has not come online yet fits that description, whether the two sets share a namespace or not.

**The shorter label does the deleting.** A tenant hits an existing `ci-linux` by naming `ci`, and `ci-linux`'s own sweep never touches `ci`'s records.
The sweep runs only when a listener starts, so each hit needs the shorter set's listener to start while the other set's record is offline.

**Measured 2026-11-06 at db34c1e38, and never on github.com.** With a real AGC in kind and fakegithub patched so its REST routes reach the scale-set registry, creating the `ci` set deleted a Pending worker's `ci-linux` record, and a non-overlapping pair kept its record.
Stock fakegithub cannot show it, because those routes read its classic registry.

**The worker does not visibly fail.** The real worker image (runner 2.338.2), given a token answer of `invalid_client`, prints that the registration was deleted and exits 0 in 2 s, or 30 s on the older flow, so its pod reads `Completed` with the job never run; a `server_error` control was still running at 90 s.
In kind a worker exiting 0 without a job drew no re-run, new Event or condition change within the 45 s observed.
Whether github.com answers `invalid_client` for such a record, and what it does with the assigned job, are unmeasured.

**Why it blocks the tag.** One tenant can cost another a job with no visible failure, and `v2.0.0` admits the pair.
Tightening the Q791 guard cannot cover a pair already running, so the fix belongs in the sweep.
