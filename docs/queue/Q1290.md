# First-label prefix overlap lets a sweep deregister another set's runners

Two `RunnerSet`s with first labels `ci` and `ci-linux` pass the Q791 guard, because it compares first labels as exact strings.
At listener start the stale-record sweep for `ci` lists every runner named `ci-*` under the GitHub owner (`listener.go`, `ListRunnersWithPrefix`), treats only its own set's worker pods as claimed (`claimedRunnerNames` in `runnerset_scaleset.go`), and deregisters each record that is offline and not busy.
A `ci-linux-<job>` record registered for a pod that has not come online yet fits that description, and the sweep runs regardless of namespace.

One tenant can cause this alone, because naming a first label that extends another tenant's under one org is all it takes.
Read from the source on 2026-11-05 and not run, so the effect on the `ci-linux` worker is inferred: its job would presumably fail to start with its runner record gone.
The sweep's prefix is the scale-set name plus a dash, and a runner name is `<scale set>-<job id>`, so the names cannot say which set a record belongs to.

Measure it first with two overlapping sets against fakegithub.
Candidate fixes, neither measured: refuse a first label that extends another's in the Q791 guard, or match the suffix against the job-id format in the sweep.
