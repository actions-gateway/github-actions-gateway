# Define what a declared untrusted runner class would mean

"Untrusted" is a posture an operator assembles by hand today, and nothing says what the platform would apply if it were a declared thing.
This is the third of three gaps [the multi-tenant goal](../plan/secure-multi-tenant-oss-ci.md#open-decisions-the-map-surfaced) surfaced.

Its two prerequisites are settled.
The credential half: the plan doc's [credential list](../plan/secure-multi-tenant-oss-ci.md#credentials-a-job-can-read) found nothing to narrow per class, so the class carries no credential item.
The fork half (Q1220, 2026-11-09): an opt-in `RunnerSet` refusal of fork pull request jobs ([Q1330](Q1330.md)), which a declared class would switch on.

**Today's assembly** is the Kata `ClusterRunnerTemplate`, the registry mirrors and their wiring, a tenant namespace with no allow-all egress rule, and a mirror topology choice ([kata-dind-workloads.md](../operations/kata-dind-workloads.md#untrusted-pull-requests--the-tight-egress-posture)).
The goal doc's Definition of Done #1 already declines one shape of this: shipping the Kata template as a cluster default, because a default template applies to every `RunnerSet` naming none.
It also records that the moat review rejected building the surface while its dependencies were open, so this row asks for the meaning and not an API.

**Settles:** a section in [secure-multi-tenant-oss-ci.md](../plan/secure-multi-tenant-oss-ci.md) stating what a `RunnerSet` declared untrusted would get that one not declared would not, which of those the platform could enforce rather than recommend, and which stay the repository's or the operator's.
