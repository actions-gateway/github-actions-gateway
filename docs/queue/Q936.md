# The test-cache-input gate cannot see a runtime.Caller-derived repo root

The gate is a lexical sweep for a `"../x"` literal and for `filepath.Join("..", "x")`, so it is blind to a path built from a variable, and above all to the repo root a suite derives from `runtime.Caller(0)`.
That shape is already in the tree, at `cmd/gmc/test/e2e/e2e_suite_test.go:317` and `cmd/gmc/test/e2e/migration_v1_to_v2_test.go:278`.

Not exposed today: both sites sit behind `//go:build e2e`, and the e2e tier consults no test-result cache at all, because `ginkgo run` compiles with `go test -c` and execs the binary itself (measured, Q902).
The gap is that Q902 widened the gate to the `integration` tier, which *is* cached, so the same idiom in an integration test would pass the gate silently while replaying a stale green.

Fix is a detector that reads the shape rather than the spelling: flag `runtime.Caller` in a test file outside the e2e tier, or resolve paths through the AST instead of a regex.
Measure first by grepping for the idiom under the cached tiers, and confirm it is genuinely absent before building anything, since a gate for a pattern nobody uses is cost without cover.
