# Give the preview harness's Grafana render a timeout above 30 s

`render()` in `deploy/monitoring/preview/render.sh` calls `/render/d/<uid>/<uid>` with no `timeout` parameter, so Grafana's image renderer gives up at its 30 s default, and the harness then dies `Grafana render of '<uid>' returned HTTP 500` after the 660 s `WAIT` has already been spent.

**Measured 2026-10-12** rendering Q1070, load average 6 to 11 on this 18-core box: the tenant, platform and budget dashboards rendered, and the security dashboard returned HTTP 500.
Grafana's log read `level=error msg="Failed to render image" path="d/actions-gateway-security/…" error="[rendering.serverTimeout] "`, with `time_ms=33198`.
The same URL with `&timeout=120` appended, against the same Grafana minutes later, returned HTTP 200 and a complete 1500×2300 PNG, so the dashboard was not at fault.

Fix shape, unmeasured beyond that one call: append a `timeout=` query parameter to the render URL (a knob beside `WIDTH`/`HEIGHT`, defaulting to something like 120), so a slow host costs seconds instead of a whole re-run.
