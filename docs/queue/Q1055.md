# Roll the signal-death guard out to the suites still comparing rc raw

`die_if_killed` (scripts/lib/common.sh) draws the line Q1023 asked for: a status above 128 is a signal, not a verdict, so it is handed back with that status rather than compared against a wanted one.
Q1023 adopted it in the 33 suites where the insertion needed no judgement.
35 suites and 139 comparison sites still read a kill as the subject having answered wrongly.

Measured 2026-09-04 over `scripts/**/*-test.sh`, counting any numeric comparison of a `VAR=$?` capture against a wanted status, over every capture name found in the tree (52 of them, not just `rc`), in both `(( ))` and `[[ ]]`/`[ ]` form.
That query returns 181 sites across 68 suites, against the 51 across 31 Q1023 estimated with a narrower two-pattern regex.
The gap is the point: the surface is wider than any single helper name or comparison shape, which is why keying on `expect_rc` reaches 9 suites and keying on one regex reaches a third of it.

**181 is a floor, and re-derive it rather than working the list.** The query keys on `VAR=$?` in the same file, so it cannot see a status laundered through something else on its way to the comparison, and that shape is already in flight. Q1006's `scripts/ci/workflow-acting-steps-test.sh` (measured 2026-09-04 at `b71bd4c5d`, unmerged) has a `drive()` that captures `... || rc=$?` and then `printf '%s\n' "$rc"`, so callers hold the status as `got="$(drive ...)"`; one more site reads it back out of a file the workflow wrote, `step_rc="$(awk -F= '/^rc=/ { print $2 }' "$dir/outputs")"`. Four real sites there (210, 345, 443, 540), and this query returns none of them. It also returns one false positive in that same file, `[[ "$rc" == kill ]]` at line 152, where `rc` is a mode parameter (`local dir="$1" rc="$2"`) that merely shares the name.
So the query is a starting point with error in both directions, exactly as Q1023's narrower one was for it.
Re-run it, then read what it returns and what it cannot reach.

**What is left needs judgement per site, which is why it is not more of Q1023.** Of the 139, most sit where the guard cannot be inserted mechanically:
- a comparison compounded with a content assertion (`(( status == want )) && [[ "$output" == *"$needle"* ]]`), 58 sites across 14 suites, `check-tools-test.sh` and `check-release-pins-test.sh` densest;
- a site at top level with no enclosing helper, so there is no `name` in scope to report and one has to be named (`check-dep-advisory-test.sh:96`, `check-errexit-prologue-test.sh:196`);
- a suite whose assertion helper carries no `name` local at all (`queue-test.sh`, 13 sites; `validate-release-test.sh`, 10; `git-merge-plan-index-test.sh`, 14).

**Two traps, both of which will make a careless pass wrong.** `die_if_killed` takes an optional WANT precisely because `run-parallel-test.sh` asserts 137 and 143 against the runner's own KILLED path: a want-blind guard exits before those assertions run and breaks the one suite that proves the distinction works.
And the split is `> 128`, not `>= 128`: git spends 128 on any fatal error, which is the line `run-parallel.sh` already drew in Q837 and the one Q1023's own prose got wrong.

`expect_output`-shaped helpers are in scope too even though they compare no status: `out="$(cmd 2>&1 || true)"` discards it, so a kill lands as a missing needle and the report blames the gate's wording.
One fix closes both, which is why they are one row.

**The operator is not the discriminator; whether the value came from `$?` is.** A string compare of a captured status has the defect identically, because 143 is not 1 whichever way the test is spelled: `[[ "$got_rc" == "$want_rc" ]]` at `scripts/ci/check-conflict-markers-test.sh:39` is two of the 181 sites, and a `grep -E '\-(eq|ne|ge|gt|le|lt) '` over that whole file returns 0.
So a query keyed on the numeric operators reports a suite with the defect as clean.
Both readings were taken 2026-09-04, and this is the shape most likely to make a roll-out pass believe it is finished.

## The population is `scripts/**/*-test.sh`, and that boundary is not the class

Workflow `run:` bodies hold the same comparison and were never swept, because they are YAML rather than a script the gate lists.
Measured 2026-09-04 with the same query over `.github/workflows/*.yml`: **5 sites across 3 workflows**, none of them guarded, and none reachable by sourcing `scripts/lib/common.sh` from a `run:` block.

| Site | Comparison |
|---|---|
| `e2e-reusable.yml:562` | `[[ "$bake_rc" -ne 0 ]]` |
| `e2e-reusable.yml:723` | `[[ $gh_rc -ne 0 ]]` |
| `publish.yml:200` | `[ "${rc}" -eq 0 ]` |
| `publish.yml:207` | `[ "${rc}" -ge 2 ]` |
| `release-freeze-watch.yml:79` | `[ "${rc}" -ge 2 ]` |

Whether these are defects is a separate judgement per site, and one of the five is already settled the other way.

**`release-freeze-watch.yml:79` is correct as written; do not guard it.** Its own comment at lines 74 to 78 says a signal death belongs inside that bucket: exit 2 is "could not measure", and "anything above it is the delegate crashing (126 not executable, 137 killed) rather than exiting", which fails the job loudly instead of reaching a report step that would read any non-zero as a spent candidate.
A `die_if_killed`-shaped guard here would abort on precisely the case the classifier is written to catch, turning a working path into a broken one.
Read 2026-09-04 from the workflow; Q1006's suite asserts both directions against real deaths, a 126 by removing the delegate's executable bit and a 137 by `kill -KILL $$`.

That inversion is the argument for judging each site rather than sweeping them.
The boundary reasoning behind `die_if_killed` is right and its conclusion flips here, because a test suite asking "did the subject answer" and a classifier asking "can I trust this measurement" want opposite things from a 137.
Q1006's own history is the counter-example in the same venue: that classifier reached review as `-eq 2` and let 7, 126 and 137 through before becoming `-ge 2`.
Deciding the remaining four is not this row, and a row that closed the 139 while leaving them unexamined should say so rather than read as having finished the class.

Distinct from [Q822](Q822.md), which is the uncapped fan-out producing the contention; this is what the suites do with a kill once it lands, and is worth having whether or not the fan-out is ever capped.
