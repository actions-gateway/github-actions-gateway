# `verify-pages-live-test` retry cases rest on a clock it does not control

Three cases fail under host load and pass on rerun, and the mechanism is `SECONDS` rather than anything about the subject.

**Measured 2026-08-29 03:24 PDT** in `make check` on a branch touching no file under `scripts/pages/`, host at load average 28.35 over 18 cores.
The three that failed are the retry cases: *a site that goes correct on a later attempt passes*, *the check polls rather than sampling once*, and *each attempt carries its own cache-busting query*.
Their reported reason is one line:

```
did not serve 1.6.0 after 606s (60s budget, 1 attempt(s))
```

Re-run alone eight minutes later on the same tree: all assertions pass.

**Why the budget is the wrong instrument here.** [`verify-pages-live.sh`](../../scripts/pages/verify-pages-live.sh) stops starting attempts when `((SECONDS + INTERVAL >= TIMEOUT))`, so the loop's attempt count is a function of wall clock.
That is correct for the real subject, where the budget bounds how long a release waits on Pages.
Under a stubbed `curl` the same expression measures the host instead: one simulated attempt took 606 s against a 60 s budget, so the loop made a single attempt and every assertion about *retrying* had nothing to observe.
The three failures are one cause, and none of them is about the code under test.

Two candidate fixes, neither measured:

- Inject the clock.
  The loop reads `SECONDS`; a test that could set it would make the attempt count a property of the scenario rather than of the machine.
- Or assert the retry behaviour without a budget at all: drive the loop with a stub that succeeds on attempt N and assert N attempts happened, with `TIMEOUT` set high enough that it cannot bind.

The second is likely right, because the first leaves the same failure available on a slower machine and the cases are about *how many attempts*, not *how long*.

This is a second traced instance with a different mechanism, a wall-clock budget consumed by the host, and it is the one of the three that names a fix needing nobody's permission.
