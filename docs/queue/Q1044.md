# queue-id-allocation.md analyses a Queue table that no longer exists

Two of its sections are written about the single-table backlog [Q889](../plan/q889-backlog-item-store.md) retired.

*What this fixes, and what it does not* measures conflicts on "a 10-row table" and tabulates seven concurrent-edit outcomes by row adjacency, then says every verdict is a line-position one that the merge driver re-decides by row ID.
The store has no rows and no backlog merge driver: `.gitattributes` registers `scriptindex`, `gatelists`, `planindex` and `roadmap`, and none of them is the backlog.
*Alternatives considered* is partly updated and partly not, which is what makes it misleading rather than merely old: the merge-driver entry says "Shipped, then retired with the table it served (Q889)", while its neighbours still argue against a store that shipped.

The measurement is worth keeping.
It is the evidence the ref allocator was built on, and a reader needs it to understand why IDs are refs.
So this is a framing fix, not a deletion: say the section measures the table era, and stop asserting present-tense conclusions from it.

Scoped out of the Q922 sweep deliberately, and that PR says so.
Q922's test was whether a sentence would send a reader to run `lint-backlog.sh` today, so it reached the four references in this file plus the two sentences directly adjacent to an edit, and nothing else.
The residue is a different defect: a doc describing a retired data model, with no dead tool name in it to catch a grep.
