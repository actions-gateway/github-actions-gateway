# The sweep's format check assumes UUID job IDs on every backend

**Event:** a job ID read from GitHub Enterprise Server or another non-github.com backend is not a UUID.

The start-up sweep decides a record is its own from the name's shape, `mintedRunnerSuffix`, and that separates sets only while every job ID is a UUID.
With another format a job ID can complete the pattern after a label's text, so one set's sweep can delete another's record.
Run against the pattern in Python, not through a sweep: under `ci-`, the remainder `<UUID>-123` matches (label `ci-<UUID>`, job ID `123`), and so does `11111111-2222-5333-8444-abcdef012345` (label `ci-11111111-2222-5333-8444`, a 12-hex job ID).

Nothing reaches this on github.com as measured: all 56 self-hosted job runner names read on 2026-11-06 were `<scale set>-<UUID>`.
GitHub Enterprise Server's format is unmeasured, and so is any other backend's.

The same format change would also leave a set's own stale records unswept, so they wait for the per-name reclaim or the manual cleanup.

When the trigger fires, the sweep needs an ownership test that does not rest on the name's shape, and the choice is open.
The options #2265 rejected are the place to start: the record's REST `labels`, which were not measurable there, and a write-ahead ledger of minted names.
A test can seed these names through `FailJITConfigName` today, so it needs no such backend.
