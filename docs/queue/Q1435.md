# A release's plan-index row makes every gate-closing PR edit one cell

The `release-2.1.md` row in [`docs/plan/README.md`](../plan/README.md) lists every open `2.1-gate` item as a link in its Status cell, and one table row is one line.
[`check-plan-index.sh`](../../scripts/docs/check-plan-index.sh) invariant 3 fails a Status cell that links an item no longer in the store, so a PR that closes a gate item has to delete its own link from that line.
Two such PRs open at once therefore change the same line, each for its own item, and nothing about either PR can avoid it.

The `planindex` merge driver keys on the plan path, so it sees one row changed differently on both sides and refuses, which is [what a keyed merge should do](../development/maintaining-backlog.md#the-same-treatment-for-docsplanreadmemd).
Measured 2026-11-27 with `git merge-tree` on the heads of #2400 (`01a528e3f`) and #2409 (`ee507ac0b`): exit 1, `merge-plan-index: table 1: release-2.1.md was changed differently on both sides`, conflicts in `docs/plan/README.md` and `docs/plan/release-2.1.md`. pr-sentinel's overlap check at `gh pr create` runs the same trial merge, so it refuses the second PR.

**What it cost, from session transcripts in this repo, timestamps UTC.** Since pr-sentinel 0.13.0 (2026-11-17) there were 15 distinct overlap refusals of `gh pr create`, the last on 2026-11-25 02:51, and 13 of them named `docs/plan/README.md`: the `release-2.1.md` row in 9, and before it the `security-audit-2026-11.md` and `release-gate-speed.md` rows, which list their open items the same way, in 2 each.
In the 11 from 2026-11-24 on, the file was the only collision in 3; the other 8 also named the release plan's own ledger, another doc, or code, and 4 named `docs/roadmap.md`, whose bullet annotation lists the same IDs and whose driver refuses for the same reason.
At first the refused workers reached for `PR_SENTINEL_OVERRIDE`: from 2026-11-17 to 2026-11-24, 14 creates carried one, the auto-mode classifier refused 6, and three went to the maintainer as questions.
None has carried one since, and the workers waited instead: two streams moved their ledger edits into separate close-out PRs (#2409, #2411), and each close-out was refused in turn on the same cell.
One hand resolution of the cell, on 2026-11-25, put the closed Q1381 back into the gate list; the worker caught it before pushing.

The two append-style registries the same drivers own tell the other half.
`scripts/README.md` was named in 14 refusals and `mk/gate-lists.mk` in 6 before 2026-11-17, and in none since: once the check trial-merges, a set-merged append is silent with no configuration.
So `PR_SENTINEL_OVERLAP_IGNORE` is not needed for the files branches append to, and for this cell it would hide a conflict git still has.
Set to `docs/plan/README.md` it would have let 3 of those 11 creates through, each to a PR that conflicts when its sibling merges.

**Done when** two PRs that each close a different gate item of one release trial-merge clean, measured on a pair rather than asserted.
Three candidate remedies, none measured:

- **Take the list out of the row.** The release plan's ledger already has one row per gate item, and the index says authoritative state lives in the plan.
  The Status cell would carry the marker and a pointer.
  Unverified: whether invariant 1 (an open marker needs a live item behind it) can read the ledger instead, and whether adjacent ledger rows then conflict in `release-2.1.md`, which no driver owns and which 6 of the 11 refusals named.
- **Merge the cell's link list as a set.** The driver would resolve a row whose two sides differ only in which `[QN](../queue/QN.md)` links the Status cell holds.
  Unverified: how often the sides differ in prose too. #2391 and #2396 both rewrote words in the cell beside their link.
- **Ignore the file in the overlap check.** One `env` entry in `.claude/settings.json`.
  It removes the refusal and keeps the conflict, so it is the fallback if the other two cost more than the rebases do.
