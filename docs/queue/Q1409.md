# No gate ties the published image lists to each other

**Dropping an image from `publish.yml`'s matrix and its release-notes loop leaves every suite green**, so an image can stop being signed, or stop being in the Release's digests, with nothing red.
Measured 2026-11-25 on the Q1403 image branch (found by rev-ci, reproduced by Claude): with `oomreporter` removed from the `name:` matrix and from the `for name in …` loop, `workflow-publish-steps-test.sh`, `make publish-digest-check` and `make semver-floor-sources-check` all exit 0, and the last reports 7 images where 8 are in the `Dockerfile`'s published stages.
Removing the same name from `verify-release.sh`'s loop is caught, by `verify-release-test.sh`, which lists the images itself.

**Why it matters.** The image names are spelled in the matrix, the digest loop, `verify-release.sh` and its test, `trivy-scan.sh`, the `security-scan.yml` matrix and the docs, and the only list a test reads is `verify-release.sh`'s.
A release that drops an image reads as a smaller release, and nobody finds out until an operator pins a digest that is not in the notes.

**Done when** one registry names the published images and a gate fails when the matrix, the notes loop, `verify-release.sh`, `trivy-scan.sh` and the `security-scan.yml` matrix disagree with it, with a case for each place that goes red when its entry is removed.
`semver-floor.sh --check-sources` already derives the image set from the matrix, so start from what it reads.
