# semver-floor drops a Dockerfile syntax-directive digest bump

**A digest bump of the `# syntax=` BuildKit directive stays under *Withheld*, because the Dockerfile parser drops it as a comment.** Found by rev-ci probing the Q1359 PR's head with a local commit, not measured on a real release window.
The directive is real: `Dockerfile` line 1 is `# syntax=docker/dockerfile:1.7@sha256:...`, the frontend every published image is built with, so changing it can change a published image.

**Mechanism, read from the code.** `logicalLines` in `devtools/release/semverfloor/sources.go` drops every `#` line, and `dockerfileChanged` in `devtools/release/semverfloor/dockerfile.go` compares published stage bodies built from those lines, so the directive never reaches the comparison.
That is deliberate for ordinary comments, which must not count, and wrong for the two parser directives, `# syntax=` and `# escape=`, which are comments to Dockerfile syntax and instructions to BuildKit.

**Done when** a commit that changes the `syntax` or `escape` directive on the first lines of the `Dockerfile` is classified as shipping, and a commit that changes any other comment is not, with a case for each in `devtools/release/semverfloor/dockerfile_test.go`.
Settle first whether the directive belongs in the comparison as its own preamble entry (the shape Q1359 gave a global `ARG`) or in `logicalLines`.
