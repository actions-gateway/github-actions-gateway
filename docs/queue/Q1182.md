# The re-run budget resets when the AGC restarts

`reserveEvictionRetry` keeps each run's re-run count in a process-local `sync.Map`, and nothing reloads it on start (read from `eviction.go`, 2026-10-10), so an AGC restart refills every run's `maxEvictionRetries` budget.
Rare disruptions make that tolerable today; Q1183 adds classes that fire more often, and a crash-looping AGC could re-run a failing run without bound.
The same in-memory reservation lets one run be re-run twice: two disruptions in one run each reserve a slot and start a retry loop (`handleEviction`, read 2026-10-11), and the second keeps meeting `403 This workflow is already running` until the first re-run's attempt concludes, then re-runs it again; read from source, not observed live.
The fix the maintainer chose (2026-10-12) keeps counting only GAG's own re-runs, so `maxEvictionRetries` keeps its meaning: move the count into the per-set failure ledger ConfigMap Q555 introduces, reserved by a compare-and-swap that merges a second disruption of the same `(run id, run_attempt)` into the first ([design](../plan/q555-automatic-recovery-design.md#the-budget-is-gags-own-count-in-the-ledger-r15)).
Capping on `run_attempt` instead was rejected because it counts human re-runs and changes the field's meaning.
This row creates that ledger store, with the version rules that let two AGC versions share it, before Q555 adds detection to it; the classic tier keeps its in-memory count.
The reservation is taken once per disruption and records what each re-run covered, so a single-job re-run never absorbs a second job's disruption.
It also replaces Q1181's abandoned-arm exemption with a per-attempt record of GAG's own force-cancel.
This is R15 of [the draft](../plan/q555-flaky-job-retry.md#classified-platform-retry-phase-2), and it blocks Q1183.
