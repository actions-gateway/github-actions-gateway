# The re-run budget resets when the AGC restarts

`reserveEvictionRetry` keeps each run's re-run count in a process-local `sync.Map`, and nothing reloads it on start (read from `eviction.go`, 2026-10-10), so an AGC restart refills every run's `maxEvictionRetries` budget.
Rare disruptions make that tolerable today; Q1183 adds classes that fire more often, and a crash-looping AGC could re-run a failing run without bound.
Capping on GitHub's own `run_attempt`, which no restart resets and which also counts human re-runs, needs no new state and keeps the AGC inside GitHub's 50-re-run limit.
The same in-memory reservation lets one run be re-run twice: two disruptions in one run each reserve a slot and start a retry loop (`handleEviction`, read 2026-10-11), and the second keeps meeting `403 This workflow is already running` until the first re-run's attempt concludes, then re-runs it again; read from source, not observed live.
Keying the reservation on `(run id, run_attempt)` fixes both ([design](../plan/q555-automatic-recovery-design.md#the-budget-becomes-run_attempt-r15)); because the budget then counts human re-runs, it changes what `maxEvictionRetries` means and needs a breaking-change release note.
This is R15 of [the draft](../plan/q555-flaky-job-retry.md#classified-platform-retry-phase-2), and it blocks Q1183.
