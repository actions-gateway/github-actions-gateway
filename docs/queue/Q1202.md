# Flake: lease-test's lost-lease renewer races the owner's sleep 2

**Event:** `lease-test` fails `a renewer that lost its lease stops renewing` on `main`, or locally on a tree that passes it alone.

Observed 2026-10-23 at about 20:00 PDT in a local `make check` on a branch that touches nothing under `scripts/dogfood/lease*` or `scripts/dogfood/lib/`, at load averages of 223 on the 18-core host:

```
[lease-test] FAIL a renewer that lost its lease stops renewing: want '0', got '1'
```

**Mechanism, measured 2026-10-27.** The case runs the renewer at `RELEASE_LEASE_RENEW_INTERVAL=0.2` against an owner that sleeps 2 s, and read `kill -0` once the owner returned.
The renewer notices the lost lease, or the gone owner, only on its next tick, and exits then.
Stretching the interval to 2.5 s in a copy of the unfixed test reproduces the exact line above (`want '0', got '1'`, exit 1, every other case `ok`); the same stretch against the fixed test exits 0 with no `FAIL`.
At 0.2 s the margin is generous unless the host is oversubscribed enough to delay the renewer past the remaining window.

**Fix shipped:** the case waits up to 10 s, polling every 0.1 s, for the renewer to exit, the bounded wait the next case uses for the same renewer.
A grep for `kill -0` in the file finds those two reads and no others.

**Not this row:** `kill -0` succeeds on a zombie, which is how the same suite fails deterministically on GAG runners.
The row for the renewer-exit check carries that state check, and the same one belongs in this loop.
