# A percent sign in a job name garbles, or loses, the Event naming it

An Event whose text holds a `%` reads wrong, because the text is passed where a format string goes: a job named `cover 80% d (50%)` reads `cover 80%!d(MISSING) (50%!)(MISSING)` (measured: `fmt.Sprintf` with no arguments, which is what client-go's recorder calls, `event_recorder.go`, vendored, read).
A workflow author chooses the name, and a matrix leg's name can hold one without trying.

**Beyond garbling, it can lose the Event.** Each verb with no argument grows about six times (`%s`, 2 bytes to 12; 127 of them, 254 bytes to 1,524), and the API server refuses a note past 1,024 (`NoteLengthLimit`, `core/validation/events.go`, v1.35.5, read), so a short enough name can push an operator's Event about its own job out of existence.
A long plain name can do that too, at about six times the length.
Nothing else was found: there are no arguments to read, Go's `fmt` writes nothing, and a width is not applied where the argument is missing (`%1000000d` gave 12 bytes).
Not run through a live recorder or an API server.

**Where the text reaches a format position** (read):

- `drainEvents` (`cmd/agc/internal/controller/runnerset_controller.go:582`), which passes every note a provisioner or listener queues through `RecordEvent` with no arguments.
  Those that carry a job's name: `FlakyJobDetected`, `PlatformFaultOnFailedJob`, `CancelledJobUnread`, `MemoryLimitRaisedForRetry` and `EvictionRerunWithheld`.
  Others carry an error's text, as `WorkerPodCreateFailed` does, and a URL-escaped one is garbled the same way.
- Six more calls on the reconciler's own text: `cmd/agc/internal/controller/runnerset_controller.go:619`, `:753` and `:782`, `cmd/agc/internal/controller/runnerset_capacity.go:76`, `:122` and `:193`.
  Whether any of their text comes from outside the AGC was not read.

The GMC's calls pass `"%s"` first, and so does `cmd/agc/internal/controller/runnerset_scaleset.go:698`, which is the fix: `"%s", note` at each of the seven, or a `recordEvent` with no variadic arguments.
A test names a job with a `%` and requires the recorded text to hold it unchanged.

The duplicate search flags Q1389, which is about which job a killed worker ran and not how its name is printed.
