# Retire the classic tier ledgers, runbooks and unread AGC env vars

Q264 removed classic acquisition, its alerts, recording rule and dashboard panels, and left four things an operator can still see or hit that describe or carry the removed tier.
They have to be gone before `v2.0.0` ships, which is why this ranks ahead of [Q1107](Q1107.md).
The classic code nothing can reach is [Q1272](Q1272.md), not this row.

**The tier ledgers.** [observability-metrics.md § Acquisition-tier reach](../operations/observability-metrics.md#acquisition-tier-reach) and § Condition and Event tier reach classify every series and reason as Classic only, Scale-set only or Both, and `make metric-tiers-check` and `make reason-tiers-check` (`devtools/docs/metrictiers`, `devtools/docs/reasontiers`) reconcile them against the source by package.
Q264 deleted the rows for what no longer exists; the rest still argue against a tier that is gone, and the tier label on the eviction metrics is now one-valued.
The metrics reference rows say the same in places: `actions_gateway_message_poll_errors_total` calls itself "Both acquisition tiers", and `actions_gateway_scaleset_session_open` "the tier's analogue of the classic `actions_gateway_active_sessions`".
Whether the ledgers and their gates collapse to a single tier or retire is an implementation choice with no security or operator cost either way, so the session working this row makes it and states the reason in its PR.

**Operator docs that still describe the classic tier.** Q264 fixed every validation step and symptom line that named a removed series; these whole sections and tables remain, measured 2026-11-03 on the Q264 branch:

- [troubleshooting.md](../operations/troubleshooting.md): *AGC CrashLoopBackOff or Not Acquiring Jobs* (its RunnerGroup diagnostics block and the Events it lists: `TokenUnavailable`, `AgentPoolError`, `ListenerStartFailed`, `AgentDeregistrationFailed`, `JobAcquisitionFailed`, `RunnerVersionTooOld` and `VersionTooOld`), *RunnerGroup ActiveSessions Exceeds maxListeners*, *RateLimited Condition on ActionsGateway* (its `active_sessions` and `maxListeners` budget), *RenewJob Failures Rising*, *Sessions Stuck in 401/EOF GetMessage Loops*, both *Concurrent Job Burst Serializes to ~1 Worker* sections, *Jobs Failing Due to Namespace ResourceQuota Exhaustion* (its `maxListeners` arithmetic), *Jobs Not Being Acquired Despite Queued Work (Capacity Gate Saturated)*, and the `maxListeners: 0` step in *Worker Pod Crashes With `configuredSettings` ArgumentNullException*.
- [runbook.md](../operations/runbook.md) *Scaling maxListeners*, which tells operators to tune a field no code reads.
- [tenant-onboarding.md](../operations/tenant-onboarding.md): the `maxListeners` example and minimum (around lines 375 and 521), the memory budget `sum(maxListeners) × 60 KiB` (around 1022), and the handoff line naming `maxListeners` tuning (around 1288).
- [02-architecture.md](../design/02-architecture.md)'s metrics table, which lists the removed classic series as current, and [appendix-e § E.4. Sizing `maxListeners`](../design/appendix-e-capacity-planning.md#e4-sizing-maxlisteners).

**The GMC's unread AGC env vars.** [`actionsgateway_v2_builder.go`](../../cmd/gmc/internal/controller/actionsgateway_v2_builder.go) injects `GITHUB_ORG_URL` and `GITHUB_RUNNER_VERSION` into every AGC Deployment, and no AGC code reads either after Q264 (`git grep` finds them in `cmd/agc` only in comments, 2026-11-03).
An operator reading the pod spec sees them, and `docs/operations/upgrade.md`'s env table lists `GITHUB_RUNNER_VERSION`.
Dropping them changes the AGC pod template, which costs nothing extra at `v2.0.0` because the new AGC image rolls every AGC anyway.
The tests pinning them are in `shared_agc_deployment_test.go` and the envtest `v2_actionsgateway_test.go`; `cmd/agc/names/names.go`, `runner_version_test.go`, the `Dockerfile` header and `docs/development/building.md` describe `GITHUB_RUNNER_VERSION` as the `agent.version` GitHub validates, and `cmd/probe` reads both names for its own, separate configuration.

**The agent-identity admission guard (Q1011), which needs sign-off to remove.** The GMC's RunnerSet webhook rejects a set whose name another RunnerSet already holds in the same namespace or under the same GitHub scope (`cmd/gmc/internal/webhook/v2/agent_identity.go`), because the classic agent pool derived its agent Secret and runner names from the CR name.
After Q264 no AGC code derives that stem (`git grep RunnerSetAgentStem -- cmd/agc` is empty, 2026-11-03), and a scale-set runner is named `<scale set>-<job id>` (`scalesetlistener/listener.go`, `runnerName`), which the Q791 first-label guard already keeps unique per scope.
So the guard now refuses one configuration nothing would break: two RunnerSets with the same name in different namespaces whose gateways bind one GitHub org.
It is an admission check, and the security principles want a removal raised rather than made silently, so the session working this row puts it to the maintainer with `AskUserQuestion` before writing the removal, and keeps the guard if the answer is no; `TestAgentStemNonInjective` in `api/apinames` and the `RunnerGroupAgentStem` it pins go with it.

**Done when** `make metric-tiers-check` and `make reason-tiers-check` either reconcile a one-tier ledger or no longer exist, no doc listed above describes `maxListeners`, `active_sessions`, the renew loop or the classic Events as current, the GMC no longer injects `GITHUB_ORG_URL` or `GITHUB_RUNNER_VERSION`, and the Q1011 guard is either removed on a recorded yes or kept with its godoc saying what it now protects.
