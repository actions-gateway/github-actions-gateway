# Retire the classic-only monitoring, Admit chain and eviction budget

Q264 removed classic acquisition and deregistered the 13 `actions_gateway_*` series only the classic path wrote, because `make metric-tiers-check` fails a series that is registered and never emitted.
It left the monitoring that queries them, so shipped alerts and dashboards can never fire or draw and nothing says so; that has to be gone before `v2.0.0` ships, which is why this ranks ahead of [Q1107](Q1107.md).

**Alerts and rules, measured 2026-11-02 on the Q264 branch** (`grep` of `deploy/monitoring/prometheusrule.yaml` for the 13 names): `ActionsGatewayNoActiveSessions`, `ActionsGatewayRenewJobErrors`, `ActionsGatewayAgentRecycleErrors`, `ActionsGatewayFanoutFallbackTimeout`, `ActionsGatewayAbandonedDeliveryErrors` and `ActionsGatewayCapacityGateRejectingJobs` query only removed series, as does the `actions_gateway:job_acquisition_success_rate:rate5m` recording rule.
`make promql-check` holds the rules to [observability-alerting.md](../operations/observability-alerting.md), so each alert's doc entry goes with it.

**Dashboards.** The three Grafana dashboards and `deploy/monitoring/preview/exporter.py` name removed series too (`git grep -l` over `deploy/monitoring`).
`make dashboard-render-check` requires a regenerated screenshot for any dashboard change beyond panel descriptions, which is why this did not ride with Q264: it needs the preview render pipeline in `deploy/monitoring/preview/README.md`.

**The tier ledgers.** [observability-metrics.md § Acquisition-tier reach](../operations/observability-metrics.md#acquisition-tier-reach) and § Condition and Event tier reach classify every series and reason as Classic only, Scale-set only or Both, and `make metric-tiers-check` and `make reason-tiers-check` (`devtools/docs/metrictiers`, `devtools/docs/reasontiers`) reconcile them against the source by package.
Q264 deleted the rows for what no longer exists; the rest still argue against a tier that is gone, and the tier label on the eviction metrics is now one-valued.
Whether the ledgers and their gates collapse to a single tier, or retire, is this row's call.

**Operator runbooks.** [troubleshooting.md](../operations/troubleshooting.md) still carries classic runbook sections for Events and conditions nothing records any more: `TokenUnavailable`, `AgentPoolError`, `ListenerStartFailed`, `AgentDeregistrationFailed`, `JobAcquisitionFailed`, `RunnerVersionTooOld` and `VersionTooOld`, and the renew-teardown section around `job_abandoned`.
`upgrade.md` needs telling operators which alerts went quiet; it is contended by the Q1258 stream, so check that first.

**Dead code.** `Provisioner.Admit` and the `runnercore.AdmitFunc` / `AdmitOutcome` types it returns (`hooks.go` says the classic listener is its only caller); the `AdmitReason*` constants stay, because the scale-set capacity advertiser labels its withhold metric with them.
`handleEviction`'s classic branch, the in-process `evictionCounts` budget chosen when `tier` is not `evictionTierScaleSet`, has about 20 tests in `eviction_internal_test.go` and `abandoned_rerun_internal_test.go` passing `evictionTierClassic`.

**Comment narration.** About 280 comment lines across 55 AGC files still mention the classic tier (`git grep -c -i -w -E 'classic|AcquireJob' -- 'cmd/agc/*.go'`, excluding `vendor` and `test/load`).
Q264 fixed the ones that stated something false; most of the rest compare the scale-set path against code that no longer exists ("identical to the classic path", "classic parity"), which the comment standard's no-history rule rules out.
`listener.go`, `metrics.go`, `runnerset_scaleset.go`, `provisioner.go` and `eviction_scaleset.go` hold the most.
