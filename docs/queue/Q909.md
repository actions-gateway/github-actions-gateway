# A queue-store edit passes every gate a session actually runs

Measured 2026-08-18: `make docs-gates` runs neither `queue-lint` nor `queue-rules-check` (zero "queue" in its output), so a session that edits a row and runs the fast prose gate has not linted the store.
`check-queue-rules` then reads the store at HEAD, so a staged-only edit reports "150 item(s), 150 at the merge base" and reads exactly like a pass.
Reading HEAD is deliberate, the script exits 2 rather than guess; nothing says the reading is void before committing, as in [Q841](Q841.md).
