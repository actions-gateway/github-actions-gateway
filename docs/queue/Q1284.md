# Raise the Kubernetes floor to a version CI tests

Both charts declare `kubeVersion: ">=1.30.0-0"`, `migration-from-arc.md` states 1.31 for v2, and `troubleshooting.md` says an AGC on 1.30 will not become ready, while `ENVTEST_K8S_VERSION` and the e2e node image are both 1.35.
So the charts promise versions nothing here tests.

Karl's reason for a higher floor, on 2026-11-04: "1.33 is end of life now".
That date is his statement and is not checked against upstream's schedule here, and the dogfood cluster's version is not read either, so read both before choosing the number.

The status-write refusal that raised the question is not a reason for this row.
On 1.31.0 and 1.32.0 ratcheting misses the status subresource, which the `spec.tracing.endpoint` rule handles itself with `optionalOldSelf`.
Another rule tightened without that clause would meet the same refusal on those versions, and no gate here would see it.

Done when the charts, `migration-from-arc.md` and the rest of `docs/operations/` state one floor that CI covers, and `upgrade.md` tells an operator below it what they get.
