# Gate teardown drops its lease on a failed stop, so reclaim misses nodes

`teardown()` in `scripts/dogfood/validate-release.sh` continues past a failed `e2e-stop.sh` or `stop.sh` and then calls `lease_release` unconditionally, so a teardown that *returned* with nodes still up drops the claim that says this run owns billable state.
`--reclaim` keys on that lease alone, so it then reports `No release gate holds … — nothing to reclaim` while the nodes bill.
The function's own comment argues for releasing last so a teardown *killed* mid-drain keeps the lease; a teardown whose stop scripts fail and return is the same state and gets the opposite treatment.

**Measured 2026-10-02 on the `v1.9.0-rc.1` validation.** The e2e job never reached a runner, so `e2e-stop.sh` refused on its queued-job drain and `stop.sh` refused on a non-converging worker drain, and the trap printed `Teardown complete (exit 124)`.
`ops.sh at-rest` then reported three instances running (two `e2-standard-2`, one `n2-standard-8`), and `validate-release.sh --reclaim` reported no lease.
Reclaiming took running both stop scripts by hand with `SKIP_E2E_DRAIN=1 SKIP_DRAIN=1`.

**The fix:** keep the lease when either stop script fails, so the documented `--reclaim` path still finds the run, and say so in the teardown's last line.
The refusals themselves are correct and stay: they are what stops a scale-down under live work.
Assert both directions in `scripts/dogfood/validate-release-test.sh`: a failing stop script leaves the lease held, and a clean teardown still releases it.
