# `gate-lists-check` cannot see a gate that hardcodes the page it reads

Rules 7 and 10 derive a gate's file set from the pathspecs its script hands git, which is the right question for a gate that walks a tree and no question at all for one that assigns its subject as a literal default.
Measured 2026-08-18 by reading the three page-scoped docs gates: `roadmap-check` takes `docs/roadmap.md` and `docs/features.md` as defaulted arguments and `comparison-stamps-check` takes `docs/why-gag.md` from a `DEFAULT_FILES` array, so neither reaches `git ls-files` and rule 10 reports `DOCS_GATES` complete with both outside it.
Editing either page is a prose change `make docs-gates` cannot fail, which is why CLAUDE.md already tells sessions to run `scripts/docs/check-roadmap.sh` by hand after touching `docs/features.md`.
Rule 7 has the same hole and no gate in it today, so the fix is one derivation for both: read a script's defaulted subject as well as its pathspecs, or require a page-scoped gate to declare its subject where the rules can find it.
