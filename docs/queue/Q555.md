# Opt-in auto-retry for flaky jobs

**Demand:** this repository's own CI, which runs on GAG, is the operator ask (maintainer decision, 2026-10-10).
The job outcome detection needs already arrives on the scale-set tier as `JobCompleted.result`.
First, one dogfood turn-up reads `actions_gateway_scaleset_jobs_completed_total` by `result` for a failed step, a cancelled run and a timed-out job: only a disruption's `failed` has been observed live.
Then a design session settles the [draft](../plan/q555-flaky-job-retry.md#open-questions-for-the-design-session)'s open questions and the CRD shape, and phase 1 (detection) ships before phase 2.
Phase 2 first widens the classified platform failures the re-run arms already retry, and only then adds an opt-in `spec.flakyRetry` for unclassified ones; the maintainer accepted on 2026-10-10 that the opt-in hides a flake from the pull request author.
