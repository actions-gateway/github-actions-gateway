# Detect flaky jobs, and auto-retry more classified platform failures

**Demand:** this repository's own CI, which runs on GAG, is the operator ask (maintainer decision, 2026-10-10).
The job outcome detection needs already arrives on the scale-set tier as `JobCompleted.result`.
First, one dogfood turn-up reads `actions_gateway_scaleset_jobs_completed_total` by `result` for a failed step, a cancelled run and a timed-out job: only a disruption's `failed` has been observed live.
Then a design session settles the [draft](../plan/q555-flaky-job-retry.md#open-questions-for-the-design-session)'s open questions, and phase 1 (detection, recording each failure's platform context) ships before phase 2.
Phase 2 adds retry for failure classes GAG recognises as platform-caused and cleared, one evidenced class at a time, on the existing re-run arms; the maintainer judged that more useful than a blanket flake retry, which is not scheduled.
The first candidate is `OOMKilled` under a right-sizing profile, retried only when the next pod gets a higher memory limit.
