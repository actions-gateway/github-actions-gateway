# Detect flaky jobs and record each failure's platform context

**Goal:** automatic recovery that cuts human intervention and so operating cost; success is a falling rate of manual re-runs per set (draft R8).
**Demand:** this repository's own CI, which runs on GAG, is the operator ask (maintainer decision, 2026-10-10).
This row is phase 1 of [the draft](../plan/q555-flaky-job-retry.md), detection only (R1 to R8): pair a job's `failed` completion with a later `succeeded` attempt, record the platform context of each failure in a form that outlives the AGC pod, and report the rate of re-runs nobody automated.
The job outcome it needs already arrives on the scale-set tier as `JobCompleted.result`.
First, one dogfood turn-up reads `actions_gateway_scaleset_jobs_completed_total` by `result` for a failed step, a cancelled run and a timed-out job: only a disruption's `failed` has been observed live.
[The design](../plan/q555-automatic-recovery-design.md) settles the draft's open questions; detection adds the `failures` map, the snapshot and the pairing to the ledger store Q1182 creates.
Retry lives in its own rows: Q1183 (classified retry, blocked on this row), Q1181 (futile re-runs on the existing arms), Q1182 (a restart-proof budget); a blanket flake retry is not scheduled.
