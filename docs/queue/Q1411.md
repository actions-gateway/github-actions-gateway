# Cover .dockerignore and load-pins.sh in the e2e path filters

Both e2e lanes' path filters in `e2e-test.yml`, `e2e` and `oomreporter`, leave out `.dockerignore`, which decides what the image builds see, and `scripts/ci/load-pins.sh`, which both jobs run to read their tool versions.
A change to either alone reaches the merge queue with both lanes skipped, so a break in them surfaces only on push to `main` or a dispatch.
Read 2026-11-26 off the filters at #2431's head; nothing has measured a change to either file going untested.
These are two more instances of [Q948](Q948.md)'s defect, which asks for an assertion that a filter covers every input its jobs read; this row adds the two paths by hand and does not build that assertion.

The same change can make `e2e-gate`'s step summary name the `oomreporter` job: it narrates only the kindnet job's result, so a run whose oom-reporter lane ran or was skipped says nothing about it.
Found by review of #2431, which added the `oomreporter` filter with the same two gaps the `e2e` filter already had.
