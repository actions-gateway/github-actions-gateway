# Validate four scale-set identity leads from the security audit

**Leads, not confirmed vulnerabilities.** Source supports each path and something outside the repository decides the outcome, so none has a severity.
[Each lead, with evidence, blockers and a validation plan](../plan/security-audit-2026-11.md#scale-set-identity-leads):

- Worker-pod reaper deletes whichever GitHub runner the pod's runner-name annotation names, with no ownership test (needs validation).
- Editing runnerLabels[0] releases the scale-set name claim while the AGC keeps its live session on the old name (needs validation).
- Scale-set name uniqueness guard is check-then-act across two objects, so one tenant creating its RunnerSet and ActionsGateway concurrently may claim another tenant's scale-set name (needs validation).
- AGC adopts the first scale set a server-side name filter returns without comparing its name, while admission compares first labels as exact case-sensitive strings (needs validation).

The first two are the class Q1290 gated, where one tenant's edit can cost another a job with no visible failure: the worker-pod reaper has none of the ownership tests Q1290 gave the start-up sweep, and a listener stays on a scale-set name its RunnerSet has released.
They are not gated because both are unvalidated and need two mutually untrusted tenants in one GitHub org or repository.

**Measure:** each lead's local test in the plan doc is an envtest or unit case that needs no cluster; the GitHub-side behaviour (two sessions on one scale set, a runner delete by name) needs a reading against github.com.

**Done when** each lead is either confirmed and fixed, refuted with the measurement recorded, or written into `05-security.md` as an accepted residual with its bound.
The plan doc gives each one a bounded local test and the fact an owner has to observe.
