# E2E_GMC_RBAC reads the AGC RoleBinding once, racing the GMC

**Top of queue per [flakes-first rule](../development/maintaining-backlog.md#flake-fixes-go-first).**

`E2E_GMC_AGCServiceAccountHasRole` failed the merge group of PR #2250 ([job 126035688552](https://github.com/actions-gateway/github-actions-gateway/actions/runs/41670008248/job/126035688552)), the queue's only failing spec, with `rolebindings.rbac.authorization.k8s.io "test-ag-agc" not found` at [`rbac_e2e_test.go`](https://github.com/actions-gateway/github-actions-gateway/blob/0a2f4276342af7d11167abc5f271e01edd66f74f/cmd/gmc/test/e2e/rbac_e2e_test.go#L53) line 53.
The merge group of #2249, the commit #2250's group was based on, passed the same suite minutes earlier.

The spec's `BeforeAll` waits for the egress proxy Deployment to be ready and nothing else, then the spec reads the AGC RoleBinding with one `kubectl get` and no retry.
The GMC does not order those two: the EgressProxy reconciler provisions the proxy, and `ActionsGatewayV2Reconciler.reconcileResources` applies the AGC ServiceAccounts, RoleBinding and Deployment in its own pass, needing only the EgressProxy object to exist.
In the failing run the namespace events put the AGC pod's scheduling about 5 s after the proxy pod's, the read failed at 16:09:04Z, and the ActionsGateway's conditions first read `ReconcileSucceeded` at 16:09:05Z.

That timing is the measured part.
That #2250's change (Q1271, the GMC deleting its reader RoleBinding outside tenants) played no part is inferred: its controller logged no failed or denied delete in the dump, but the GMC log tail holds no line for `tenant-rbac` at all, so nothing shows why the gateway's pass came when it did.
The re-run of #2250 in the queue is the rerun that settles whether this is a flake.

The fix waits for the AGC RoleBinding with `Eventually` before asserting its subject.
Sweep the idiom with it: `E2E_GMC_AGCCanManagePods` in the same file runs `kubectl auth can-i` as the AGC ServiceAccount once, which answers `no` until that RoleBinding exists, and any other e2e spec that reads a gateway child once after waiting only on the proxy has the same race.
