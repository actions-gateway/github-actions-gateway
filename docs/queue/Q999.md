# Cross-namespace proxy revoke has no event source, so its test races

**Event:** `TestV2_RunnerSet_GrantedCrossNamespaceProxy_ResolvesAndRevokes` or `TestV2_RunnerSet_CrossNamespaceProxy_GrantArrivingLaterResolves` fails on `main`.

The projection is a ConfigMap the AGC may `get` but not `watch`: its Role grants no `list`/`watch`, and `SetupWithManager` registers no ConfigMap watch, so neither writing nor deleting one produces a reconcile event for a `RunnerSet` that resolves through it.
The revoke leg passed only when an unrelated trigger happened to land inside the 20-second `require.Eventually`, and failed on PR 1726 (2026-08-26) when none did.

Measured 2026-08-27 as a controlled pair on `main` at 18e5f8b9a, before any change: a new test creating the projection *after* the reference failed at the full 20.42 s budget with `Condition never satisfied`, while `TestV2_RunnerSet_FailsClosedUntilRefsResolve` (the same wait, the same helper, three referents that *are* watched, created after the fact) passed in 0.76 s.
That rules out the `Eventually` budget and the harness both.
The grant direction was the worse half and unfiled: a set sitting `ProxyShareNotGranted` has both listeners stopped, owns no worker pods and returns no requeue, so it had no incidental trigger at all and waited out the informer resync (10 h ± 10%).

Mitigation is a bounded re-check on both directions rather than `list`/`watch` RBAC: Kubernetes RBAC has no label selector, so a watch could not be narrowed to the labelled share ConfigMaps and the grant would cover every ConfigMap in the tenant namespace, reversing §H.9's least-privilege decision to buy a watch on one object.
The GMC already polls a tenant ConfigMap it cannot watch for the same reason (`githubCABundleReprobeInterval`).
Enforcement was never the lagging half, since the provider's ingress peer drops on the GMC's `EgressProxy` watch, so what the cadence bounds is reporting and how long the set keeps acquiring jobs its workers can no longer route.
