# `status-lint`'s filter misses four data-file inputs its jobs read

Four tracked files are read by `lint-status` and matched by no pattern in either of the workflow's two path lists, so a PR changing only one of them skips the gate that reads it and `status-lint-gate` reports green.

**Measured 2026-09-16 against `6d9d90454`**, the head at which Q947 closed four other inputs of the same job.
At that tree the enumeration identified 16 inputs, 12 covered and these 4 not.
Both numbers are floors rather than a census: the 16 is what two instruments plus three reviewing sessions found, and the section below is why that is not the same as what is there.
Re-derive both before acting on the ratio, and note the denominator can grow without the gap growing.

- `docs/index.md` and `docs/why-gag.md`, built into `badge_pages` at `scripts/docs/check-roadmap.sh:48:for page in` and passed to `roadmapcheck`, which validates badge markup on them (`devtools/docs/roadmapcheck/badges.go`).
- `docs/development/flake-watch-retired.md` and `docs/plan/README.md`, held as `LEDGER` and `PLAN_INDEX` at `scripts/docs/check-queue-rules.py:63:LEDGER =` and `:64`.

**The second pair is the severity argument.** Both are `read_text()` at `scripts/docs/check-queue-rules.py:399:ledger =` and the line after behind `if ... is_file() else ""`, so an unreadable or changed file yields empty rather than failing.
Rule 8 (a flake item may not vanish) and rule 9 (a plan's last item obliges its index row) then return a verdict computed against nothing, and the gate reports `ok`.
That is a silent wrong verdict, not a skipped check.

**Separate from [Q948](Q948.md), which is the general reverse assertion.** This row is four entries in two lists, and Q948 is the gate that would find them.
Filing rather than folding into the PR that found them (Q947's, which fixed four other inputs of the same job): those were scripts the job runs or reaches, and these are data files passed as arguments under `docs/`, which is a different shape wearing the same symptom.

## Four shapes, which is what a gate has to model

Measured 2026-09-16 on `status-lint.yml` alone, across the window from `59c70462` to `6d9d90454`.
Eight inputs were found uncovered over four shapes, four of them fixed in that window and four still open:

| Shape | Instance |
| --- | --- |
| A wrapper script the job `run:`s | `lint-queue.sh`, `check-queue-rules.sh` |
| A lib a `run:` script sources | `scripts/lib/common.sh` |
| A backend a Python backend execs | `find-duplicate-rows.sh` |
| A data file passed as an argument | the four above |

The instance count is the less useful number.
A shape is what an enumerator has to handle, and the fourth shape is reachable by no walk of the execution graph, because the files are not scripts and the paths are built by string concatenation.

## A census instrument that fails open is the same defect class, one level up

Two instruments were written to enumerate this job's inputs and **both returned clean, small, plausible under-reports**:

1. A walk of execution edges resolved `$SCRIPT_DIR` by deleting it, which left a leading `/` and made the path join absolute.
   It reported seven files and had silently dropped the `check-roadmap.sh` → `common.sh` edge already known to exist.
   Caught only because that edge was known; undetectable to anyone who did not already have the answer.
2. Its Python-constant matcher was anchored to `(?:scripts|devtools)/`, so it could not match a constant holding a `docs/` path, which is exactly what `LEDGER` and `PLAN_INDEX` are.
   Caught only by a third method with a different blind spot.

Neither failure had a symptom.
The repair for the first was to assert a known edge as a control and fail when the walk misses it; an enumerator that cannot come back the other way is not a check.
Anything built for Q948 needs that property, or it reproduces the defect it is gating one level up.

## A fifth instance is one call away, with nothing to catch it

`scripts/agent/local-throttle.sh` is deliberately **not** an input today, and that is measured rather than judged.
The measurement is the reviewing session's on PR #1944, not this row's author's: a `bash -x` trace of `check-roadmap.sh` at head `6d9d90454` shows the script zero times, with the `roadmapcheck` build, the `common.sh` source and `resolve_release_tag` in the same trace as positive controls.
But `common.sh` reaches it from two functions, `init_throttle` and `serialize_heavy_build`, and `check-roadmap.sh` both sources that file and builds a Go binary, which is what `serialize_heavy_build` exists for.
One future call from anything those scripts reach makes the filter stale, and no gate catches the transition.
A comment naming the condition belongs beside the definition in `scripts/lib/common.sh` rather than in the workflow, since it is the person editing `common.sh` who needs it.
