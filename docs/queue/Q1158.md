# Make the release gate's lease visible across hosts

`lib/lease.sh` records the gate's ownership as a file holding a pid, under `~/.local/state` on the host that ran it, and only that host can act on it.
Once Q880's workflow runs the gate in CI, a CI run and a maintainer's local gate cannot see each other: either can start while the other owns billable cluster state, and a CI run's lease vanishes with its runner.

Q880 contains the CI half without this: the workflow's `concurrency` group serializes CI runs, and a final step on the same runner runs `--reclaim` after a failure or cancellation while the lease is still there.
What it does not cover is a local run overlapping a CI one, and a runner lost before that step runs.

**The likely shape** is a lease the cluster itself holds, such as a `coordination.k8s.io` Lease naming the holder and renewed while the gate runs, so any host reads the same record.
The pid check that makes a host-local lease safe has no cross-host equivalent, so expiry by renewal time replaces it, and that trade needs its own reasoning before it is built.

Not Q880, which runs the gate in CI and accepts this gap for its first runs; not Q1155, which keeps the host-local lease when a teardown stop script refuses.
