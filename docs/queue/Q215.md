# Ship the in-cluster worker cache as a reference architecture

A tenant asked for an in-cluster cache on 2026-10-27, which fired this row's trigger, and the design is settled and spiked in [q215-worker-cache.md](../plan/q215-worker-cache.md).
The untrusted-PR tenant is the case it exists for: a cache shared across jobs is a poisoning vector unless the server enforces GitHub's ref scope, and this server applies GitHub's own rule from the job's token.
Tight egress does not make GitHub's cache unreachable: Azure blob storage is in GitHub's required ranges, and a Kata worker reached it ([the Kata run](../plan/q215-worker-cache.md#the-kata-run-2026-11-01); the wider exposure is [Q1253](Q1253.md)).

What is built, all in draft #2173: the opt-in `cache-runner` target in the root `Dockerfile`, which patches `Runner.Worker.dll` so actions take `ACTIONS_RESULTS_URL` from the pod, published and signed on each release and scanned on every code PR; the `deploy/gha-cache/` base on falcondev v10.0.0 with an `emptyDir` default, a persistent component, 7-day eviction and a 10 GiB cap; its render gate; and the [operator page](../operations/in-cluster-cache.md).
Save, restore, artifacts and the sibling-branch refusal hold on kind and on the dogfood cluster under Kata with the untrusted-PR egress profile, and a fork pull request saves under `refs/pull/<n>/merge` where its base branch cannot restore it ([the fork run](../plan/q215-worker-cache.md#the-fork-pull-request-run-2026-11-01)), all on 2026-11-01.

What is left is closing the row in the same pull request: the roadmap and features entries, and the plan's archive.

The server goes in the tenant namespace, so the tenant's `ResourceQuota` pays for it; the shared and platform-operated modes in [tenancy modes](../plan/q215-worker-cache.md#tenancy-modes) are [Q1225](Q1225.md).
The patch itself is temporary; [Q1224](Q1224.md) retires it once upstream takes an override.
