# Ship the in-cluster worker cache as a reference architecture

A tenant asked for an in-cluster cache on 2026-10-27, which fired this row's trigger, and the design is settled and spiked in [q215-worker-cache.md](../plan/q215-worker-cache.md).
The untrusted-PR tenant is the case it exists for: under the tight egress posture `actions/cache` has no store to reach, and a cache shared across jobs is a poisoning vector unless the server enforces GitHub's ref scope.

What is built: the opt-in `cache-runner` target in the root `Dockerfile`, which patches `Runner.Worker.dll` so actions take `ACTIONS_RESULTS_URL` from the pod, with a build check that fails when a runner bump moves the literal.
The spike ran it on kind against real GitHub with falcondev-oss's cache server: save, restore and artifacts all worked through the in-cluster server, GitHub's cache held nothing, and a sibling branch could not restore the entry.

What is left, in order:

1. **Close the tokenless blob transport.** falcondev v9.8.0 authenticates its three `CacheService` calls by the job's token, but the upload URLs they hand out carry no secret beyond a 10-digit ID, and a `PUT` with no credential writes the entry (measured 2026-10-27, [the residuals](../plan/q215-worker-cache.md#the-write-path-is-a-contract)).
   Upstream #299 tracks the maintainer's fix, a per-upload token in the URL; nothing below ships until a release carries it or something in front of the server closes it.
   Bump the pin from 9.8.0 in the same step, and re-read the residuals if that release is the Rust rewrite.
2. **Publish `cache-runner`** as a seventh image: the `publish.yml` matrix and its verify loop, `verify-release.sh`, `trivy-scan.sh`, `security-scan.yml`, `dockerfile-lint.yml`, and the image lists in `release.md`, `air-gapped-install.md` and `security-operations.md` (every file naming `build-runner` today).
3. **A `deploy/gha-cache/` base** shaped like `deploy/registry-mirror/`: the server pinned by digest, its Service, the two NetworkPolicies from the spike, an `emptyDir` default and a persistent overlay.
4. **An operator page** under `docs/operations/` and a runner template library entry, saying that the image is opt-in and that a pod running it without `ACTIONS_RESULTS_URL` loses cache and artifacts.
5. **Validate on the untrusted pull requests profile** (Kata, tight egress): the server answers from a worker, `*.blob.core.windows.net` does not.
6. **Measure a fork pull request's scope**, which the spike could not: its saves must land in `refs/pull/<n>/merge` and a push to the base branch must not restore them.
7. **Eviction**: set `CACHE_CLEANUP_OLDER_THAN_DAYS` to GitHub's 7 days, and pick a default for `CACHE_MAX_SIZE_BYTES`, which caps the whole server rather than GitHub's 10 GB per repository.

The server goes in the tenant namespace, so the tenant's `ResourceQuota` pays for it; the shared and platform-operated modes in [tenancy modes](../plan/q215-worker-cache.md#tenancy-modes) are [Q1225](Q1225.md).
The patch itself is temporary; [Q1224](Q1224.md) retires it once upstream takes an override.
