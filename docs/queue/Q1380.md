# semver-floor --notes omits a shipping build(deps) base bump

**A dependency bump that changes a published image appears in neither list `--notes` prints.** Measured 2026-11-22: `scripts/release/semver-floor.sh v2.0.0 f156d4c53 --notes` names `e25db67f` (#2344, a `feat`) and nothing for `6c770110c` (#2335, `build(deps): bump distroless/static`), which moved the base of the GMC, AGC and proxy images.
The `Notes` type partitions only the window's `feat`, `fix` and `perf` commits into *Ships* and *Residue* (`devtools/release/semverfloor/notes.go`), so a `build(deps)` commit is in neither however much it ships.

**Why it matters.** The release author curates the notes from those two lists, so a base-image bump that clears a vulnerability reads as nothing to say.
The `v2.0.1` notes list both bumps (`docs/releases/v2.0.1.md`), by hand.
The floor is a different question and stays as it is: `levelFor` gives no level to any type other than `feat`, `fix` and `perf`, so a dependency bump never raises it, and that is deliberate (found by rev-ci reviewing Q1359; the Q1359 change leaves it alone).

**Done when** `--notes` reports a window's non-`feat`/`fix`/`perf` commits that touch the released surface under a third heading, so the three lists account for every commit that ships, with a test in `devtools/release/semverfloor/notes_test.go` for a `build(deps)` commit that edits a published stage of the `Dockerfile` (which Q1359's `dockerfileChanged` answers) and one that edits only a dev tool.
The remedy is a reading of the code, not a measurement: whether a third heading is the right shape, or those commits belong in *Ships*, is the first thing to settle.
