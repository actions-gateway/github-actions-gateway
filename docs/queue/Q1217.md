# Gate reports e2e test counts for its first leg only

The release gate prints a pass/fail/skip summary for its first e2e leg (Kata) and `no JUnit artifact on run … — skipping the report` for the other two (privileged DinD and Kata on Dragonfly), although both runs upload one.
A reader of the gate's log then has a test count for one leg in three, and the other two read as if the suite never produced a report.

**Measured 2026-10-26 on the `v1.10.0-rc.2` local gate run.** Runs 40416616015 (dind) and 40418655837 (dragonfly) each carry an unexpired `e2e-junit-report-kindnet` artifact, and downloading each into its own folder gave 93 tests, 76 passed, 0 failed, 17 skipped, the same as the Kata leg.
The report step downloads every leg into the one `${WORKDIR}/e2e-report` folder, and a second `gh run download` into a folder that already holds `e2e-report.xml` exits 1 with `error extracting "e2e-report.xml"`, which the step reads as a missing artifact.
Re-running the download for run 40416616015 into a folder that already held its report reproduced that error.

The fix is a folder per run, such as `${WORKDIR}/e2e-report/${run_id}`.
It is separate from Q1161, which would run the legs in parallel across projects; this row changes only where each leg's report is downloaded.
The leg verdicts are unaffected: each leg passes or fails on the dispatched run's conclusion, not on the report, so no candidate has been passed on a missing count.
