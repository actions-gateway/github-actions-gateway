# Nothing compares the dashboard doc's panel tables to the shipped JSON

Q961 reconciled the four sections by hand and closed.
The drift it fixed was silent in both directions: the tenant section numbered nine rows 1..7, **7**, 8, and a Cross-tenant Throughput panel had escaped its table to render as literal pipe-separated text mid-paragraph.
Neither is visible to any gate.
`promql-check` parses panel expressions out of the JSON (Q910) and never reads the prose; `dashboard-render-check` is a screenshot gate (Q868).

Both sides are machine-readable, so a comparison is cheap: row titles and order, and the set of panel titles per row.

**Row titles and order already match exactly** across all four dashboards, measured 2026-09-09 after Q961.
**Panel titles do not**, and that is what a gate has to decide about first.
Six panels carry a shortened label in the doc:

| JSON | doc |
|---|---|
| `p95 pod creation latency` | `p95 latency` |
| `p99 pod creation latency` | `p99 latency` |
| `Pod creation latency heatmap` | `Latency heatmap` |
| `Jobs assigned vs provisioned/min` | `Jobs assigned vs. provisioned/min` |
| `Proxy HPA desired vs current` | `HPA desired vs. current` |
| `Jobs acquired/min by namespace` | `Jobs acquired/min by namespace (classic)` |

Plus the `(1h)` window suffixes the Job Throughput table drops.
The doc's labels read better in a table that already carries the query beside them, so verbatim parity is a real cost rather than a free win.

So the gate is a design question, not a transcription: assert row title and order parity strictly, and assert panel **count** per row rather than title equality; or align the labels first and assert titles too.
The count rule alone would have caught the escaped panel, and the order rule the duplicate `Row 7`, which is both of Q961's instances.
