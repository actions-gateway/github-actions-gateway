# Retry cannot span a release-CDN incident on the cert-manager manifest

**Event:** the `Pre-pull cert-manager images` step (or the Calico or metrics-server pre-pull through the same script) fails on `main` or in the merge queue with `failed to fetch <name> manifest … after 6 attempts`. → top of Queue, escalated.

## What shipped

`scripts/fetch/prepull-manifest-images.sh` fetches the pinned manifest on the exponential, jittered, capped schedule `download-verified.sh` and `pull-image-with-retry.sh` already use: six attempts, bases 5, 10, 20, 40 and 60 seconds plus up to half again in jitter, so 135-202s of backoff where the old `--retry 5 --retry-delay 2` gave about 13s.
Every nonzero curl exit is retried.
`scripts/fetch/prepull-manifest-images-test.sh` pins the attempt count, the schedule, recovery on a later attempt, and that a cache hit never fetches; run against the previous script it fails 14 of its assertions.

## Why the window and not the cache key

The row as filed held that a dead cache key made the fetch run on every e2e run.
[Q1125](Q1125.md)'s `-m2` key generation had already fixed that before this change.
**Measured 2026-10-09** over the last 40 merge-group runs of each e2e lane: 11 ran the e2e job (2026-09-30 to 2026-10-05), and all 11 logged `Cache hit for: cert-manager-images-m2-v1.20.2` and `loading cert-manager images from cache`, with no manifest fetch.
Run [35139093856](https://github.com/actions-gateway/github-actions-gateway/actions/runs/35139093856), from before the bump, logs the fetch, which shows the same grep finds it when it happens.

So the fetch now runs only where no warm cache entry exists:

- a `CERTMANAGER_VERSION` bump, the first run after it;
- an entry evicted after seven days unused (GitHub's documented `actions/cache` policy, not measured here), which the merge-group-only e2e lanes can reach in a quiet week;
- every run on a self-hosted runner, where the `actions/cache` steps are skipped (`runner.environment == 'github-hosted'`); `scripts/dogfood/validate-release.sh` routes the release gate's e2e run to the `gag-ci-e2e` scale set.

On those runs the old 13-second budget was the whole defense, and it lost to the first incident below.

## The incidents

Run [34539304371](https://github.com/actions-gateway/github-actions-gateway/actions/runs/34539304371), `e2e (calico)` on `push main`, 2026-09-10, died in `Pre-pull cert-manager images`:

```
curl: (22) The requested URL returned error: 500   (x6, 22:52:03.5 -> 22:52:16.2)

```

Run [34856925669](https://github.com/actions-gateway/github-actions-gateway/actions/runs/34856925669), 2026-09-14, was a 504 on the same asset through the unretried apply that [Q1125](Q1125.md) removed.
Neither incident's full duration was measured, so whether 202s spans the next one is unknown.

## If it recurs

Vendoring the pinned manifest into the repo removes the fetch outright and puts the bytes under `updatecli`'s version bump as a reviewable diff.
It is the next step if this window is exceeded, and was not taken here because the fetch now runs only on cold or self-hosted runs.
