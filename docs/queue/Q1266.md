# Webhook-rejection panel and alert still match the pre-1.9 -v2alpha1 names

The security dashboard's webhook-rejection panel (`deploy/monitoring/grafana-dashboard-security.json`, the `apiserver_admission_webhook_rejection_count` query) and the `ActionsGatewayWebhookRejections` alert documented in [security-operations.md](../operations/security-operations.md) select `name=~"v(actionsgateway-v2alpha1|…|runnertemplate-v2alpha1)\.kb\.io"`.
Q1150 (#2015, in 1.9) renamed all five validating webhooks to `v<kind>-v2.kb.io`, so the regex matches no webhook the GMC serves.
Since 1.9 the panel reads zero and the alert cannot fire, whatever a tenant is denied.

**Measured** as a source read: the five names in `cmd/gmc/config/webhook/manifests.yaml` all end `-v2.kb.io`, and `git log -S'vactionsgateway-v2.kb.io'` dates the rename to 583bbc8f8 (2026-10-01).
Not run against a live apiserver; the claim rests on the regex and the names, which do not overlap.

**Done when** both matchers select the served names, preferably by the version-free shape `deploy/monitoring/preview/README.md` recommends (`v(.*)\.kb\.io` scoped to the five kinds), so the next version rename cannot strand them again, and `make promql-check` or a dashboard test fails a matcher that selects no webhook name in `cmd/gmc/config/webhook/manifests.yaml`.
The troubleshooting runbook's denial examples still quote `vactionsgateway-v1alpha1.kb.io` too; they describe the error text an operator sees and belong with the operator-docs rewrite rather than here.
