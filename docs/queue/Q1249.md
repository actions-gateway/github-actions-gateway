# Report stale or missing GitHub ranges on a v2 direct-egress gateway

A v2 `ActionsGateway` with no `defaultProxyRef` egresses directly, and its `<gateway>-workload` and `<gateway>-agc` NetworkPolicies carry the GitHub CIDR allowlist from the shared IP-range cache.
No condition on that gateway reports the cache's state: it carries no `EgressRulesStale` at all, so neither a stalled refresh (`RefreshStalled`) nor a cache that never filled (`RefreshNeverSucceeded`, added by Q1228 for the v1 `ActionsGateway` and the CIDR-mode `EgressProxy`) is visible on a direct-egress tenant.

Measured 2026-11-01 at `76eed6e`: `git grep -c EgressRulesStale -- 'cmd/gmc/internal/controller/actionsgateway_v2*.go'` matched nothing, against 4 lines in `egressproxy_quota.go`; the v2 type's godoc lists `Ready, AGCAvailable, CredentialUnavailable, Degraded, EgressUnattributed, RunnerSetsDegraded` (`api/v2/actionsgateway_types.go:608:	// Conditions are the observed conditions of the gateway. Known types: Ready,`).

The never-filled case is narrower here than on a proxy pool: `preserveExistingEgress` keeps an already-programmed direct-egress policy's rules while the cache is empty (Q246), so only a first-ever provision or a policy deleted while the cache is empty shows no GitHub rule.
The stalled case is not narrowed by that.

Fix shape, unmeasured: add `EgressRulesStale` to the v2 `ActionsGateway`'s known condition types, set only in direct mode, with the evaluation the `EgressProxy` uses, and export it on `actions_gateway_egress_rules_stale`.
That is a new condition type on a served API, so read `docs/development/api-review.md` first.
