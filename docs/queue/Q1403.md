# Say which memory limit killed a container, with a node reporter

Nothing the AGC reads says which limit ran out when a runner is killed for memory, so Q1400's Events name no cause.
A small tool could say it on the pod, as a condition and an Event, for anyone debugging such a kill, with or without GAG.
It gates 2.1, and puts the limit that ran out in place of that text.
It does not say whose memory it was: a job and its neighbours can each fill the limit all pods share, or the node, so that is the operator's to judge.

[The design](../plan/q1403-oom-kill-reporter.md) is decided: cgroup counters read by an unprivileged node agent, a controller that writes the answer, off by default, in its own module and chart here.
It carries what is read, measured and from recall, who could forge each part, and the build.
This row is its PRs 4 to 6 and reading 8; `cmd/oomreporter` and `charts/oom-reporter` are the first three's; [Q1406](Q1406.md) and [Q1407](Q1407.md) ride 2.1, and [Q1408](Q1408.md) is after it.
Its rule agrees with the kernel on the kills a kind run made; [Q1316](Q1316.md)'s dogfood reproduction reads the counters it rests on, and says whether they hold on GKE.

The duplicate search flags Q1399, about a job GitHub lists as cancelled, and Q1389, which was about which job a killed worker ran; neither reads a node.
