# api-reference-check flakes when two gate runs share tmp/api-reference

**Top of queue per [flakes-first rule](../development/maintaining-backlog.md#flake-fixes-go-first).**

`gen-api-reference.sh` renders into a fixed `tmp/api-reference/` and `rm -rf`s it both before generating and in its `EXIT` trap.
`api-reference-check` is in both `make check` and `make docs-gates`, so running the two in one worktree at once (the [inner loop](../development/testing.md#the-inner-loop-cheap-checks-while-iterating-make-check-once-pre-pr) invites exactly that) lets one run delete the other's output mid-check.

Observed 2026-10-10 ~11:40 PDT in worktree `serene-euler-8f33de` (PR #2060), first `make check` after rebasing onto `63824ad79`:

```
[api-reference-check] grep: tmp/api-reference/api.md: No such file or directory
[api-reference-check] error: generated reference has no '#### RunnerTemplate' section — crd-ref-docs found no API types?
[run-parallel] FAILED: api-reference-check (exit 2)
```

`make api-reference-check` alone minutes later passed, as did a second full `make check` on the same tree.

**The failure output refutes the first hypothesis**, that crd-ref-docs exited 0 without writing its output (a Go 1.27.2 toolchain download or `api/go.work.gen` race was suspected).
The kind loop checks `ActionsGateway` first and `RunnerTemplate` last, exiting on the first miss, so a file that was never written would have been reported as missing `ActionsGateway`.
Five greps found the file and the sixth did not: it was written, then deleted.

**Mechanism measured**, two ways:

- The session transcript shows `make check` launched in the background at 18:36:45Z and `make docs-gates` in the foreground at 18:36:46Z, in the same worktree; the second `make check` that passed ran alone.
- Two `make api-reference-check` runs started together failed 9 of 10 times over five rounds (2026-10-10, this worktree), with three symptoms: the `no '#### …' section` message, a diff against a truncated page, and crd-ref-docs' own `Failed to render … open tmp/api-reference/api.md: no such file or directory`.

The fix is a per-invocation work directory (`mktemp -d tmp/api-reference.XXXXXX`), so concurrent runs never share a path.
No other `scripts/**/*.sh` assigns a fixed `tmp/<name>` work dir or `rm -rf`s one (grepped 2026-10-10), so the class is this one script.
