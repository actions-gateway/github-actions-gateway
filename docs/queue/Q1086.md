# Storage-migrate stored objects to `v2` before the `v2.0.0` removals

**Event:** [Q413](Q413.md) lands and 1.9 ships `v2` served beside `v2beta1`.
The migration cannot run before `v2` exists, and must complete before `v2beta1` is dropped.

[v2-ga.md](../plan/v2-ga.md#phase-3--the-storage-advance-and-the-coupled-removals) Phase 3 opens by marking `v2` the storage version and rewriting stored objects, and Phase 4 cuts the tag on top of that.
Both assume a migration mechanism this repo does not have: `StorageVersionMigration` and `storedVersions` appear nowhere outside `vendor/`, measured 2026-09-08 across the whole tree.
Until this row existed the gap was recorded in one sentence of a plan doc and tracked nowhere, which is what makes it `L` rather than the `M` the phase table implies.

Marking `+kubebuilder:storageversion` on `v2` changes only what the apiserver writes *next*.
Objects already stored as `v2beta1` stay that way, and `metadata.storedVersions` on each CustomResourceDefinition keeps listing `v2beta1` until every object is rewritten and the list is pruned.
An apiserver refuses to drop a version still named in `storedVersions`, so skipping this does not fail loudly at the tag: it fails when the removal is attempted, on a cluster, mid-upgrade.

The deliverable is the migration itself plus the evidence it completed: rewrite every stored object of all five kinds, prune `storedVersions` to `["v2"]`, and record the reading.
Decide the mechanism first, and the choice is the row's first question: the `StorageVersionMigrator` is a separate controller with its own CRD and its own install story, while a read-write sweep over each kind needs no new component and no new dependency.
Both need the same evidence, so `storedVersions` is the assertion either way.

The pre-upgrade alias check in [Q1085](Q1085.md) is a precondition rather than a neighbour: an `EgressProxy` naming `CiliumFQDN` or `CalicoFQDN` cannot be rewritten as `v2` at all, because `v2` does not define those values ([Q452](../plan/v2-ga.md#decided-v2-omits-ciliumfqdncalicofqdn)).
Running this before that check has cleared is how one unmigrated object stalls the migration partway.
