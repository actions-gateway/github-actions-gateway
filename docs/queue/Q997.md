# Prose that counts a set goes stale on an insertion nothing checks

An insertion falsifies neighbouring prose asserting a property of the set **without touching that prose**.
`metric-tiers` reads the ledger, `promql-check` reads expressions, `queue-gates` reads the store; nothing reads prose adjacency, and `observability-dashboards.md` is read by no semantic gate at all.

Three instances in Q906 alone, none of which any gate could have caught:

- `observability-dashboards.md`: "the first three capacity panels union the v1 `RunnerGroup` family with its v2 twin", after a v2-only panel went in third.
- `runnerset_capacity_test.go`: a godoc naming `TestApplyWorkerCapacityConditions_SetsAllThree` and "all three conditions", above a function renamed to `SetsAllFour`.
  The test body was correct and green throughout.
- `v2_runnerset_capacity_metrics_test.go`: "explicit zeros on the other two families" where three now exist.

The first two were written and caught in review, not shipped.
The repair that survives the next insertion is to name the members rather than count them.

**The sibling is the same failure from the layout side**, and worth fixing together because the tell is identical: a true statement about a set, invalidated by a change that never touches it.
Six dashboard panels at `w=4` is exactly 24 columns; rendered, four previously-full titles came back ellipsed.
The arithmetic was right and the source could not answer the question.
Two instances already ship on the tenant dashboard (`Denied CONNECTs/s (SSRF signal)` at 31 chars, `Tunnel duration p95` at 19), which is what makes it a class rather than one mistake.
