# Published dashboard doc renders table-cell queries with a literal \|

A pipe inside a table cell is written `\|` in Markdown, and GitHub drops the backslash inside a code span, but the MkDocs build does not: on the published site the four queries in `docs/operations/observability-dashboards.md` that contain an alternation render with `\|` in place of `|`.
An operator who copies one gets a regex in which `\|` is a literal pipe, so `component=~"agc\|proxy"` matches neither component and the query returns nothing.

Measured 2026-11-02 by the Q1267 worker on a `make docs-build` of `site-dev/`, reading each `td code` element's text on `/operations/observability-dashboards/`: four carried `\|`, among them `actions_gateway_build_info{component=~"agc\|proxy"}` and the webhook-rejection denied series.
Other pages with tables were not swept.

The same source renders correctly on github.com, which is why the drift is invisible from a source read, and `make check` never builds the site.
`check-webhook-selectors.py` and `check-dashboard-tables.py` both read the cell the GitHub way, so neither can see it.

**Done when** a table-cell query renders on the site exactly as an operator should paste it, on every published page, with a gate over the built site, or over the source shape that breaks it, that fails on a reintroduced `\|`.
The fix might be a Markdown extension setting, `&#124;` in the source, or moving the queries out of table cells; which one is open.
