# An unstaged delete reddens `make check` via a still-listed tracked path

`head_snapshot` walks `git ls-files -s` and opens every tracked path from the working tree, so a tracked file deleted but not yet staged is listed and absent, and the open raises `FileNotFoundError`.
Measured 2026-08-28: `make check` failed `claude-usage-test` with `No such file or directory: docs/queue/Q986.md` after that row was closed with `rm`; `git rm --cached` on the same path turned the target green with no other change.
This is exactly the state a session is in between closing a backlog row and committing it, which is where the workflow tells it to run `make check`, so the gate is red for a reason that is neither a defect nor the session's to fix.
The fix is one guard at the open, not a narrower file list: an unreadable tracked path should skip rather than abort, the way a census over a moving tree has to.
