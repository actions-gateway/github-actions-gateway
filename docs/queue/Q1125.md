# e2e setup fetches cert-manager's manifest live and unretried

The e2e cluster step runs `make apply-cert-manager`, which is `cmd/gmc/Makefile:100:kubectl apply -f $(_CERTMANAGER_URL)` in that module, and the URL behind it is `cmd/gmc/Makefile:24:releases/download/$(CERTMANAGER_VERSION)/cert-manager.yaml` on github.com.
One fetch, no retry, on the critical path of every e2e run in both CNI lanes.

## Measured 2026-09-17

Run [34856925669](https://github.com/actions-gateway/github-actions-gateway/actions/runs/34856925669), `e2e (calico)` on `push main` at 2026-09-14 14:45Z, went red on exactly that:

```
error: unable to read URL "https://github.com/cert-manager/cert-manager/releases/download/v1.20.2/cert-manager.yaml", server reported 504 Gateway Timeout, status code=504
make[1]: *** [Makefile:100: apply-cert-manager] Error 1
```

The lane had already stood a three-node cluster up and preloaded cert-manager's controller, webhook and cainjector images, so the run was almost entirely spent before the fetch that killed it.

## The repo already states the goal this path misses

The images are cached and the manifest is not, in the same step.
`actions/cache` keyed on `cert-manager-images-${CERTMANAGER_VERSION}` restores `/tmp/cert-manager-images`, the preload loop reads its `images.txt`, and the very next line is `.github/workflows/e2e-reusable.yml:654:make apply-cert-manager`, which goes back to github.com for the manifest.

The sibling metrics-server cache states the goal outright at `.github/workflows/e2e-reusable.yml:529:The cached dir holds the image tar and the image list` in that comment, finishing on the line below: so a hit needs no manifest fetch.
That is the property the cert-manager path was given a cache for and does not have.

So the fix has a precedent in the file it belongs in: cache the manifest beside the images it was parsed for, and apply from the cached copy.
`scripts/fetch/prepull-manifest-images.sh` already downloads that exact URL to extract the image refs, so a cache hit has the bytes in hand and discards them.

## Not bumped, deliberately

[maintaining-backlog.md](../development/maintaining-backlog.md#flake-fixes-go-first) exempts this shape from the flakes-first rule at `docs/development/maintaining-backlog.md:672:a flake rooted in an outside service that hasn't recurred (file, don't bump)` on that page.
A 504 from github.com's release CDN is an outside service and this is one occurrence, so the row is filed on its own merit rather than moved to the top.
It gets bumped if it recurs.

## The two paths disagree about retry, not only about caching

`scripts/fetch/prepull-manifest-images.sh` fetches **the same URL** on a cache miss and fetches it properly: `scripts/fetch/prepull-manifest-images.sh:61:curl -fsSL --retry 5 --retry-all-errors --retry-delay 2 -o` is the line.
`make apply-cert-manager` then fetches it again through `kubectl apply -f` with no retry at all.
So the repo already knows this URL is worth retrying, in the script that reads it first.
