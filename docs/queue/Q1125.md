# e2e setup fetches cert-manager's manifest live and unretried

**Event:** the e2e cluster step's `make apply-cert-manager` fails on `main` or in the merge queue, either fetching the cert-manager release URL again or finding no `/tmp/cert-manager-images/manifest.yaml` to read. → top of Queue, escalated.

## What shipped

`scripts/fetch/prepull-manifest-images.sh` persists the manifest it fetched beside the image tar it already caches, and the cluster step applies from that copy through a `CERTMANAGER_MANIFEST` variable on `make apply-cert-manager`.
A warm run now makes no manifest fetch at all; a cold run makes one, retried.
The cert-manager `actions/cache` key carries an `-m2` generation, because an entry is immutable once written and the pre-change entry would otherwise keep hitting with no manifest in it.

## The defect

The e2e cluster step ran `make apply-cert-manager`, which was `kubectl apply -f` against the pinned release URL on github.com with no retry, on the critical path of every e2e run in both CNI lanes.
The images were cached and the manifest was not, in the same step: `actions/cache` keyed on `cert-manager-images-${CERTMANAGER_VERSION}` restored `/tmp/cert-manager-images`, the preload loop read its `images.txt`, and the very next line went back to github.com for the manifest those images had been parsed out of.

The two paths also disagreed about retry.
`scripts/fetch/prepull-manifest-images.sh:70:curl -fsSL --retry 5 --retry-all-errors --retry-delay 2 -o` fetches the same URL on a cache miss and fetches it properly; the apply then fetched it again with no retry at all.
So the repo already knew the URL was worth retrying, in the script that reads it first.

## Measured 2026-09-17

Run [34856925669](https://github.com/actions-gateway/github-actions-gateway/actions/runs/34856925669), `e2e (calico)` on `push main` at 2026-09-14 14:45Z, went red on exactly that:

```
error: unable to read URL "https://github.com/cert-manager/cert-manager/releases/download/v1.20.2/cert-manager.yaml", server reported 504 Gateway Timeout, status code=504
make[1]: *** [Makefile:100: apply-cert-manager] Error 1
```

The lane had already stood a three-node cluster up and preloaded cert-manager's controller, webhook and cainjector images, so the run was almost entirely spent before the fetch that killed it.

## The two candidate siblings, both settled

- **Six `curl: (22)` responses of 500 before exit 22** (`push main`, 2026-09-10 22:52Z) is the same class and the same URL, on the *other* line: `prepull-manifest-images.sh cert-manager` took them on its retried fetch and gave up.
  [Q1133](Q1133.md) owns that residual, which this fix concentrates rather than removes.
- **`ErrImagePull` in `E2E_V2_TwoGatewaysCoexist`'s `BeforeAll`** (merge group, 2026-09-16 19:11Z) is not this class and is not a fetch failure.
  Run [35139093856](https://github.com/actions-gateway/github-actions-gateway/actions/runs/35139093856) died on a conversion-webhook POST to `webhook-service.gmc-system.svc`, and the `ErrImagePull` in its log is `registry.invalid/preempt-probe-runner:none`, a deliberately unresolvable image in an unrelated preemption-probe fixture.

The proxy 502s are a separate class and are [Q1119](Q1119.md).
