# Eight stricter admission rules from the November security audit

**Eight audit findings are fixed by a stricter admission rule, and an open major is the only cheap time to add one.** A manifest that applies today would be refused afterwards, so a minor cannot take these and `v3` is the next place they could land, which is why Q1283 and Q1312 were gated.
Three of the eight remain, listed below; the other five have theirs: the two `noProxyCIDRs` guard rules, the `EgressPeer` CIDR bound, the allowlist gate on a `githubURL` host, and the public GitHub alias fold.
One is confirmed from source and two are leads whose rule gap is visible in source ([each finding, with evidence and the proposed rule](../plan/security-audit-2026-11.md#stricter-admission-rules)):

- Namespaced RunnerTemplate privilege gate checks only securityContext.privileged, so the documented 'platform-owned template pins the pod shape' property is not enforced in a privileged-profile namespace (confirmed, low).
- Tenant RunnerTemplate volume sources are unfiltered, so a node-mounted network volume (nfs, iscsi) may give workers a data path outside the worker NetworkPolicy and egress proxy (needs validation).
- Template projected serviceAccountToken volume survives buildPod despite the documented 'no Kubernetes API credentials in the worker pod' floor invariant (needs validation).

Fix sizes are unmeasured; the row is sized on the count, not on a reading of each webhook.
Each rule must let an unchanged stored value through, as `spec.tracing.endpoint`'s does (Q1283), so a stored object is not refused when an unrelated field is edited.
Re-check each asserted gap against source before writing its rule: these were read on 2026-11-09 at `7b3f016ad`, and the leads' downstream effect was never run.
A finding whose rule turns out to cost more than it protects can be declined here with the reason recorded in the plan doc; it should not silently drop off the list.

**Done when** each of the three has a rule with tests covering a refused new value and an accepted unchanged stored one, or a recorded decision not to add it; `upgrade.md` tells operators what `v2.0.0` now refuses and how to find a stored object that has it; and the `v2.0.0` release notes list each rule under breaking changes.

The `security` label is left off deliberately: with a gate label it would oblige a public roadmap bullet (`roadmapcheck` rule 7), and Q1312 set the precedent of gating a pre-release tightening as `debt`.
