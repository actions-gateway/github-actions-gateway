# Sweep for assertions that could not have gone red

A green assertion means the suite ran, not that the assertion could have failed.
Six turned up on one day across three lanes, each passing for a reason unrelated to what it claimed to pin, and a green run is the expected output at every one of them.
No coverage number moves, because the assertion does execute.

## What was measured, and by whom

Measured here, in `scripts/ci/dependabot-rebase-stale-test.sh` while fixing Q1118:

- **An assertion handed the value the code under test produces.** The eligibility decision is two pure functions composed by `eligible()`; the suite reached each through its own flag, so the assertion naming the loop guard was invoked as `--verdict MERGEABLE 12 NONE` and was handed `NONE`, which is precisely what the classifier exists to compute.
  Mutating the classifier's empty-rollup arm to `FAILING` reddened four other assertions and left that one green.
- **An assertion on a branch the live system never enters.** The same suite pinned the guard on a `ACTION_REQUIRED` rollup entry that GitHub does not produce for a withheld head; the real path runs through an empty rollup.
  Found by the reviewing lane, driven by mutation.

**Measured by other lanes today, cited as corroboration and not verified here.** Three of these are in a pull request that had not opened when this row was written, so read them from that lane rather than from this row:

- A selector matching no pods ([#1963](https://github.com/actions-gateway/github-actions-gateway/pull/1963)).
- A fixture row present but inert, because `printf '\uXXXX'` expanded literally with no UTF-8 locale.
- A block exercising the kubectl-absent path, gated on kubectl being present, so it never ran at all.
- `kill -0` reported a process alive where the process was a zombie.

## Why one sweep will not close it

The remedies do not transfer, which is the whole difficulty and the reason to say so in the row rather than leave it to whoever picks it up.

- Requiring **non-zero cardinality** on a subject finds the selector and the absent fixture row, and finds neither of the two measured here.
- **Mutating the mechanism and requiring red** finds the stand-in and the unreachable branch, and would pass over an inert fixture that is genuinely present.
- Asking, per probe, **what result would have falsified the claim** is what catches `kill -0` on a zombie, where the instrument is sound and answers a narrower question than the sentence quoting it.
- Making a **fixture prove it is what it claims**, by asserting its decoded bytes rather than its presence, is the only one that reaches the `printf` case.

A single cardinality sweep is the cheapest of these and finds the largest number of instances, so it is what gets written first and what a Done-when phrased as "sweep the suites" will be closed against.
That leaves the mutation-only cases, which no green run anywhere surfaces.

**Deliberately not filed as a taxonomy.** A three-way split of these was proposed and checked against the day's measurements; it failed on two of three placements, so the categories above are named as remedies rather than as a classification anything should be sorted into.

## Done when

- Each of the four remedies has been run over the suites it can reach, and the row records which suites each one covered.
- At least one instance found by mutation rather than by cardinality, or a statement of what was mutated and why nothing reddened.
- Every composed subject in `make scripts-test`, meaning a pair of functions one calls through the other, has either an assertion exercising the real composition or a note saying the consumer does not depend on the producer.
- Closing on the cardinality pass alone is explicitly not sufficient.

## Notes

`make scripts-test` runs 130 shell suites, which bounds the sweep but not its order; start where a subject is split into separately reachable functions, since that is the shape the two locally measured cases share.
