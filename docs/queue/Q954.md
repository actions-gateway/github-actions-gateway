# `compute_scope` reads `CI` ambiently and no test pins it

Measured 2026-08-21: four scripts branch on `${CI:-}` and no test in the repo sets or unsets it, so whichever branch the runner takes is the only one that tree ever exercises.
`go-lint.sh` is the one that decides something: `compute_scope` returns `full CI` when the variable is set, and the suite covers `lint_scope`, the pure helper beneath it, never the wrapper that reads the environment.
The same file already has the shape that fixes it, one function down: `lint_cache_dir` takes `CI` as a positional argument and `expect_cache` asserts both verdicts.
Thread the variable in as a parameter, or pin it in the harness.
Not [Q929](Q929.md), which is a `nolintlint` flake in the linter's own output.
This is the class, not a measured misbehaviour: PR #1681 shipped an em-dash gate keyed on `CI`, went red on the runner and green locally, and was fixed by making the opt-in explicit.
