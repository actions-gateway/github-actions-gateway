# Spegel reference architecture as a simpler node-layer P2P alternative

Q540 built the node layer on Dragonfly ([`deploy/dragonfly-node/`](../../deploy/dragonfly-node/README.md)), which pre-heats nodes and already backs the registry mirrors (Q539).
Spegel is the lighter option: one DaemonSet, no scheduler, and on kind no containerd restart, for an operator who wants pull-storm relief without Dragonfly's footprint and does not need pre-heating.

The [Q540 plan](../plan/q540-node-layer-p2p.md#2-spegel-graded) graded Spegel v0.7.4 on kind and is the starting point.
It shared images between nodes, stayed read-only, and fetched only from peers; an ingress NetworkPolicy closed its pod ports and the same-node hostPort, but not another node's hostPort.
Not measured: the cross-tenant read of a privately pulled image, which follows from the source, and a rise in cache misses under the policy that the readings do not explain.

The deliverable is a supported recipe beside Dragonfly's: manifests or chart values with `resolveTags: false` and the ingress policy, validated with a Kata worker's reachable set unchanged, and the operator guidance in `docs/operations/p2p-image-distribution.md` updated to point at it.
GKE's containerd reads `certs.d` only once `config_path` is set and containerd restarts ([Q540 plan §6](../plan/q540-node-layer-p2p.md#6-dogfood-validation)), and on kind Spegel did not restart containerd, so a GKE recipe needs the `config_path` change and a restart added; neither was tested with Spegel.
