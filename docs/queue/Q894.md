# Archive the plans left active only by the deleted Progress table

Q889 deleted the Progress table, whose ✅ rows were 21 active plans' only backlog reference, and rekeyed `plan-index-check` invariant 1.
Reconcile, do not eyeball.

Re-measured 2026-09-11, and the set has grown: **39 of the 68 active rows in `docs/plan/README.md` carry ✅**, of which **24 are cited by no live queue row** and so are the archive candidates; the other 15 stay put, which several rows say in so many words (`runner-sizing-profiles.md` is retained as the validation record Q416 still cites).

`make plan-index-check` passes over all of them and always will: its invariant is an *open*-marked row backed by no live item, and a ✅ row is not open-marked, so the gate that catches a plan which should have been archived cannot see one that already claims to be done.
Whether that gap gets a rule of its own is part of this item, because 24 is what one audit found and audits are what the archive-on-close protocol exists to avoid.

Each move is `git mv` plus four edits the protocol names, and one more it does not: a plan carrying an em-dash ceiling in [`em-dash-baseline.txt`](../../scripts/docs/em-dash-baseline.txt) needs the entry re-pathed, or the gate fails the moved file at its new path with no ceiling.
