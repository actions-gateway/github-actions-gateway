# Condition transition Events fire once per object, never on a later flip

`prev := meta.FindStatusCondition(...)` returns a pointer INTO the slice, and the `SetStatusCondition` below it overwrites that element, so the `prev.Status != status` guard reads the value just written.
Measured: `Ready` True→False→True emits 1 Event, not 3; a `workerImage` downgrade to below-minimum emits 0.
Six sites share the shape (`runnerset_controller.go` 836/905/936, `runnergroup_controller.go` 717/743, `runnerset_capacity.go` 117); fix by copying `prev` by value.
Found while measuring Q795.
