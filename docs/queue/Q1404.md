# Recover two fail-fast matrices that each lost a leg behind a gate

A run holds two matrices under GitHub's default `fail-fast: true`, each with an aggregate job of its own (`if: always()`, red when one it needs is), and each loses a leg to memory.
The out-of-memory retry recovers both legs and neither matrix's cancelled siblings, with a log line and no Event.
`v2.0.0` re-runs that run whole, on one slot of `maxEvictionRetries`.

Reproduced on the unit-test fake of GitHub's run and jobs endpoints, budget 3, by review and by a row of `TestSiblings_ARedGateIsNoOtherFailure` (`a matrix of its own lost a leg too`), not on a live run.
How often a run has this shape has not been measured.

**The cause:** a red job is told from a genuine failure only in the attempt the last single-job re-run started.
The second leg's attempt carries the first aggregate, which that attempt did not run, so it counts as another failure and the siblings' turn is dropped.

**A fix:** keep the red dependents found in one attempt in the parked entry, and go on reading a carried one as a dependent while every attempt since is one the AGC started.
About 20 lines by estimate, not built or measured.
It takes three slots, one for each leg and one for the siblings of both, and `maxEvictionRetries` defaults to 2, so at the default the run still ends short: with `EvictionRetriesExhausted` where today it is a log line.

**Not built for 2.1** because the default budget does not reach it; the shape is documented instead.

Cancelled legs stay cancelled in three more cases, which [the upgrade note](../operations/upgrade.md#non-breaking-an-out-of-memory-retry-re-runs-the-killed-job-not-every-failed-job-of-its-run) lists beside this one and this fix leaves alone:

- Beside a job that fails on its own, which is the rule rather than a gap: one `rerun-failed-jobs` would re-run that failure too.
- Behind an aggregate at `maxEvictionRetries: 1`, since the siblings take a second slot.
- Behind an aggregate, where a killed job nothing red needs went first: it takes a slot and shows no dependent, so the run needs three where the other order takes two.

`fail-fast: false` on the matrix leaves no leg to cancel, in all four.
