# `v2.0.0` removing `v2alpha1` un-matches every validating webhook rule

All five `actions-gateway.com` kinds are validated by rules that name `apiVersions: [v2alpha1]` and nothing else, and no rule sets `matchPolicy`, so they reach `v2beta1` writes only through the apiserver default `Equivalent` ([q74](../plan/archive/q74-v2beta1-conversion-webhook.md) records the same routing).
Measured 2026-09-07 over [`webhook.yaml`](../../charts/actions-gateway/templates/webhook.yaml): `vactionsgateway`, `vclusterrunnertemplate`, `vegressproxy`, `vrunnerset` and `vrunnertemplate` are each `v2alpha1`-only, with zero occurrences of `matchPolicy` in the file.

`Equivalent` converts a request into a version the rule names, so a rule whose only version has been removed matches nothing.
[v2-ga.md](../plan/v2-ga.md#phase-3--the-storage-advance-and-the-coupled-removals) Phase 3 removes `v2alpha1` **and `v2beta1`** at `v2.0.0`, leaving `v2` as the only served version, so every rule's version list is empty of anything that still exists.
That drops admission validation for every `v2` write at once, silently, since an unmatched rule is not a `failurePolicy: Fail` rejection.
Surfaced while deciding Q452, through the `CiliumFQDN`/`CalicoFQDN` deprecation warning, which rides the same routing; the aliases are themselves removed at `v2.0.0`, so that warning is not what is at risk here.
The other four kinds' validators are.

**The obvious fix is a trap, and it inverts the failure rather than removing it.** Adding the surviving versions to each rule's `versions=` list means the apiserver has no conversion to do and sends the object at its own version, so a `v2beta1` write reaches a handler typed `*agcv2alpha1.EgressProxy`.
Admission decoding goes through `runtime.DecodeInto` ([`decode.go`](../../vendor/sigs.k8s.io/controller-runtime/pkg/webhook/admission/decode.go)), which fails when the decoded type differs from the target (`unable to decode %s into %v`, [`codec.go`](../../vendor/k8s.io/apimachinery/pkg/runtime/codec.go)).
Under `failurePolicy: Fail` that turns a silent loss of validation into every write being rejected.
The repo's own shape agrees: `v1alpha1` has its own rule, path and handler rather than sharing one.

So the fix needs a per-version path and handler for each kind, or one version-agnostic handler, which is why this is `M` rather than the `S` it first looks like.
The decoding half is measured in the vendored tree; the apiserver half, that a rule naming the request's own version suppresses conversion, is documented upstream behaviour this row has **not** measured.
An envtest with a multi-version rule settles it, and that same test is the inversion the fix needs: it must go red when a rule names only `v2alpha1` and the version is gone.

It gates the `v2.0.0` tag rather than gating [Q273](Q273.md)/[Q264](Q264.md): those rows can land whenever, and the tag cannot ship without this.
Ships beside them if it has not landed sooner.

Raised in review of #1867, which is also where the original single-line fix was refuted.
