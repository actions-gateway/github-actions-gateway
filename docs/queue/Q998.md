# Broker-mediated pod-per-step `container:` and `services:` execution

**Demand:** an adopter who cannot run Kata reports the gap.
Q727 declined ARC's `containerMode: kubernetes` permanently on 2026-08-25: its hook needs a pod-`create` grant RBAC cannot scope below a namespace, and GAG puts many runner shapes plus every job's registration Secret in that one namespace, so the grant is a credential-theft path between jobs.
Docker-in-Docker under Kata is the supported answer, and it needs nested virtualization, which GKE Autopilot, GKE E2/C2D/N2D, and every AMD, Graviton, or GPU EC2 family cannot provide.
That population gets a platform-granted privileged template where ARC needed no privilege, which is what this row would close.
The design keeps the token invariant: a GAG container-hooks implementation in the worker requests step pods from the AGC, so the AGC stays the only component that creates pods.
Costed in the plan doc: it needs an authenticated worker-to-AGC endpoint reachable from untrusted job code through a NetworkPolicy that today allows the per-tenant proxy alone, plus step-pod lifecycle, quota accounting, and `fsGroup` propagation.
Serves both acquisition paths, unlike a provisioning-time translation, because the hook runs at job time.
