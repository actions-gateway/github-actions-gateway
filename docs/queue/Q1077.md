# Preview scrape overrides the exporter's namespace label

`exporter.py` fakes a two-tenant fleet by emitting explicit `namespace="team-a"` and `namespace="team-b"` labels from a single pod.
The ServiceMonitor at `workload.yaml` sets no `honorLabels`, which defaults to `false`, so Prometheus resolves the collision in the scrape target's favour: the exposed label is renamed `exported_namespace` and `namespace` becomes the pod's own namespace, `team-a`, on every series.

Every per-tenant panel in all four published screenshots is therefore single-tenant, and the images undersell the dashboards they document.

Measured 2026-09-07 against the live preview stack:

```
count by (namespace) (actions_gateway_active_sessions)
  -> [{namespace: team-a}]
count by (exported_namespace) (actions_gateway_active_sessions)
  -> [{exported_namespace: team-a}, {exported_namespace: team-b}]
```

One series carried `exported_namespace="team-b"` beside `namespace="team-a"`, which is the collision itself in a single sample.

The fix is `honorLabels: true` on the ServiceMonitor endpoint.
That is right for the preview specifically and would be wrong in a real install: there the AGC runs one pod per tenant, so the target's `namespace` is the tenant's and the scrape default is what you want.
The preview stands a fleet up from one pod, so only the exposed label carries the tenant.
Re-render all four screenshots after the change, since every per-tenant panel moves.

Spotted by the Q969 session while opening its render rather than trusting the harness's exit code, and confirmed here from the config and the query above.
