# Re-render the preview screenshots now the namespace collision is fixed

`exporter.py` fakes a two-tenant fleet by emitting explicit `namespace="team-a"` and `namespace="team-b"` labels from a single pod.
The ServiceMonitor at `workload.yaml` set no `honorLabels`, which defaults to `false`, so Prometheus resolved the collision in the scrape target's favour: the exposed label was renamed `exported_namespace` and `namespace` became the pod's own namespace, `team-a`, on every series.

Measured 2026-09-07 against the live preview stack:

```
count by (namespace) (actions_gateway_active_sessions)
  -> [{namespace: team-a}]
count by (exported_namespace) (actions_gateway_active_sessions)
  -> [{exported_namespace: team-a}, {exported_namespace: team-b}]
```

One series carried `exported_namespace="team-b"` beside `namespace="team-a"`, which is the collision itself in a single sample.

`honorLabels: true` on the ServiceMonitor endpoint is the fix and has shipped.
It is right for the preview specifically and would be wrong in a real install: there the AGC runs one pod per tenant, so the target's `namespace` is the tenant's and the scrape default is what you want, which is why the comment beside it says so.

**What remains is the render.** All four published screenshots were shot under the collision, so every per-tenant panel in them is single-tenant and the images undersell the dashboards they document.
The fix does not reach a committed PNG.
Re-run `render.sh` per [the preview README](../../deploy/monitoring/preview/README.md) and commit the four images, which needs the kind plus Prometheus Operator plus Grafana stack rather than a gate.
Confirm the repair in the same run with the `count by (namespace)` query above: it must return both tenants.
