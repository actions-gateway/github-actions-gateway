# Two repo-local hooks refuse without naming themselves

Neither `PreToolUse` hook this repo wires emits its own name, so a session it refuses cannot tell which of the six-odd guards spoke.
`claude-no-subagent-workers-hook.sh` asks with `This looks like a parallel-dispatch worker (own worktree or PR-producing prompt).`; `devtools/agent/gothrottle`'s three verdicts open `Auto-throttled `, `Blocked: this ` and `Blocked: the throttle probe `.
Measured 2026-09-16 by reading the emit sites.

A deny leaves no decision record, because Claude Code persists a hook's stdout only for a call it goes on to run, so the reason string is the only evidence the hook ran at all.
That makes an unprefixed refusal unattributable forever: the session cannot work out which override variable is on offer, and a friction report that recovers denials by matching an opener finds none of these.
The installed plugin guards all do carry it (`foreground-guard: `, `exit-status-guard: `, `workspace-guard: `), which is what makes the two local ones read as somebody else's.

Fix: open every `permissionDecisionReason` with the hook script's own filename stem plus a colon and one space, at position 0.
That is the repo-local form of the rule, since neither hook is a plugin with a `plugin.json` to take a name from.
`record-launch-guard.py` already does and asserts it, so the shape and its assertion are both in `scripts/agent/` to copy.

Notes: the gothrottle strings are in `devtools/agent/gothrottle/decide.go`, so that half is a Go change with table-test churn; the sub-agent hook is one string.
Split if the Go half grows.
