# Operator docs address the v1 AGC Deployment name under v2

Twenty-six `kubectl` invocations across eight docs address the AGC as `deploy/actions-gateway-controller` (or `deployment/...`), which is the v1 name.
Under v2 the AGC is named per gateway, `<gateway>-agc`, from `agcNameV2` in `cmd/gmc/internal/controller/actionsgateway_v2_builder.go`.
So every one of those commands names nothing on a v2 tenant.
None of the 26 is scoped to v1 in its surrounding prose, so a reader on the recommended path has no signal that the command does not apply to them.

This is the class Q1092 scoped down from.
Q1092 repaired `docs/getting-started.md` § Rotating GitHub App Credentials alone, splitting each affected block into a v2 form and a `-v1` sibling; the three remaining hits in that page are the v1 siblings, which are correct.

**The name is derivable now, which is what makes a gate possible.** Q1092 exported `AGCResourceSuffix` from `cmd/gmc/internal/controller`, so a checker can join a page's own gateway name to it rather than hardcoding a string.
`TestGettingStarted_SkipBlockNames` already does exactly this for the install page; the open question is whether the same assertion generalizes to pages that carry no CR of their own: troubleshooting and the runbook use `<namespace>` placeholders and never name a gateway, so there is nothing for a test to join.

**Decide the presentation before editing 26 sites.** The install page's split-block shape is verbose and does not obviously scale to a 14-hit troubleshooting page.
A placeholder convention (`deploy/<gateway>-agc`, with one paragraph per page saying that v1 tenants substitute `actions-gateway-controller`) may be the cheaper answer, but it changes copy-paste-ability, which [documentation-standards.md](../development/documentation-standards.md) treats as load-bearing.
Settle that first; the sweep is mechanical once it is settled, and a mechanical sweep is verified by reconciliation, not by an empty leftover grep.
