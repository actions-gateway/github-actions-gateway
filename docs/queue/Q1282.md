# spec.tracing.endpoint needs an admission check for its scheme and host

`spec.tracing.endpoint` is admitted unchecked, so two spellings the AGC cannot use reach a cluster and fail only as a `traces export:` line in the AGC's log, or not at all.
[Reaching the collector](../operations/observability-logging.md#reaching-the-collector) documents both, and Q1281 left them out of scope because neither of Karl's two `v2.0.0` decisions covers them and neither blocked its Done when.

- **A value with no scheme.** Q1278 recorded that a bare IP such as `10.0.0.5:4317` fails the SDK's URL parse, so the AGC exports to `127.0.0.1:4317`.
  That reading was not re-measured on a cluster for this row.
- **A proxied tenant's short name.** `otel-collector.observability:4317` and `otel-collector.observability.svc:4317` are sent through the egress proxy, whose own NetworkPolicy blocks them, so no spans arrive whatever `spec.tracing.networkPolicy` says.
  Measured 2026-11-03 against 5c46c1b on kind with Calico.
  A CEL rule on the `ActionsGateway` cannot see `defaultProxyRef`'s `NO_PROXY`, so this half is a webhook check or a status condition rather than a schema rule.

Routing the export through an `EgressProxy` with `destinationFQDNs`, rather than exempting the collector with `NO_PROXY`, is a third option nobody has measured, including what it costs in worker egress.

Done when a value the exporter would misread is rejected at admission, and a proxied gateway naming a collector the proxy would carry gets a signal an operator sees without reading the AGC's log.
