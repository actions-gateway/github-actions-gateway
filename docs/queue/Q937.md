# Prose can call a deleted row live; only plan README column 3 is gated

Closing Q900 left `testing.md` saying "Q900 is measuring which way that actually falls", and no gate could see it.
Every check here is typed, and a bare ID in a sentence is neither a link, a Status cell, nor a roadmap bullet.
Measured on this branch with Q900 already deleted, `doc-links` passed over 438 files and 6592 links; an orchestrator run over six chained PRs was clean too.
Every row a batch deletes can leave this, and a batch deletes a dozen.
The obvious gate does not survive measurement.
2263 file/absent-id pairs across `docs/` cite a row not in the store; narrowing to `QNNN is|will|owns|…` still leaves 81, and every sampled one is correct prose ("Q495 is the worked example").
`scripts/docs/check-plan-index.sh:34-48` already holds the discriminator, for one table: linked iff live, because "the anchor dies with the row and `make doc-links` says so".
It keeps the bare form where the ID "describes what the plan was about and stays true".
So the cheap half is a convention in maintaining-backlog.md: prose deferring an open question to a row links it, which makes the existing link gates catch the deletion.
Whether the free-prose half is gateable at all is the open question; a claim that goes stale is not distinguishable from a citation by any pattern tried here.
