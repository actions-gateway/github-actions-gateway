# check-runner-window.sh exits 2 on an empty releases feed

**`scripts/release/check-runner-window.sh --pinned 2.338.1` exited 2 with `could not read the releases feed: it was empty`.** The orchestrator of the 2026-11-22 run saw it while checking the runner update window for Q1307; the run was not reproduced from this session, and the mechanism is unverified.
The message comes from the check on `verdict` after the `jq` call (`scripts/release/check-runner-window.sh`, `[[ -n "$verdict" ]] || die ...`), which is reached only when `jq` exited 0 and printed nothing, which `jq` does for a zero-byte input.
So the feed arriving empty is the likeliest cause (a `gh api` call that returned no body), but which call produced it, and whether it was a transient failure or a repeatable one, is not known.

**Why it matters.** The script is the instrument that says whether a pinned runner is about to leave GitHub's 30-day window, and a window closing is silent on the cluster (jobs stop arriving with no error). A transient empty read that exits 2 is a loud failure, which is the right direction; a repeatable one means the check cannot be run when it is needed.

**Done when** the cause of the empty feed is measured (run the script and its feed fetch with the same arguments, and record what the fetch returned), and the script either retries a transient empty read or names the failing call in its message, with a case in `scripts/release/check-runner-window-test.sh` for a zero-byte feed.
