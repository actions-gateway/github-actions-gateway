# No gate runs `queue.py claims` over this repo's own store

[Q889](../plan/q889-backlog-item-store.md) moved the table-era linter's rule 12 (every Q-ID a branch *adds* holds a `refs/queue-ids/QN` claim) into `queue.py claims`, and the subcommand is complete: a merge-base baseline, a `QUEUE_CLAIMS_ALLOW`/`--allow` escape, and a `--strict` that turns an unreadable remote from a skip into a failure.

It is also exercised.
Measured 2026-08-30: `scripts/docs/queue-test.sh` invokes it twelve times, `docs/queue-test` is in `SCRIPTS_TESTS` and `scripts-test` is in `CHECK_FAST_GATES`, so `make check` runs it on every gate.

Every one of those invocations passes `--store` a fixture (`$TMP/claims/work/docs/queue`, or `$TMP/clean`).
None is pointed at `docs/queue/`, and no `make` target, workflow or hook points it there either: it is absent from `QUEUE_GATES`, `status-lint.yml` runs `lint-queue.sh` and `check-queue-rules.sh` only, and the pre-commit hook runs `gofmt` and `check-em-dash.sh`.

So the checker is well tested and this repo's store is never its subject, which is the gap: the one property `alloc-queue-id.sh` cannot enforce on its own, that an ID read off the store and incremented never reaches a commit, is asserted nowhere against the real ids.
An unreserved ID surfaces at the rebase that collides.

The subcommand's own header says of `--strict` that CI, which always has a network, is where it is passed.
Nothing passes it, so that records design intent rather than behaviour.

Wiring it needs a decision the code already frames: the skip-on-unreadable-remote default is what keeps an offline clone green, so a local `make` target wants the default and the workflow step wants `--strict`.
`queue.py claims` reads the working tree rather than `HEAD`, so unlike `check-queue-rules.sh` it is not subject to [Q909](Q909.md)'s staged-edit blind spot; that row is about which gate set `make docs-gates` runs and does not reach this.

Found while closing Q922, Q924 and Q987, whose docs asserted rule 12 "runs in the pre-commit hook, `make check`, and CI".
