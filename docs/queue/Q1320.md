# Build the already_rerun, run_succeeded and worker_unstartable checks

Three of the design's futility checks, which withhold a re-run that cannot help, were left unbuilt when Q1181 shipped the other four, so a re-run can still fire where the design says it should not.

- **`already_rerun`**: a disruption detected late (the vanished arm, or a scan after a restart) can read an attempt another re-run already started and reserve against it ([04-operational-flows.md](../design/04-operational-flows.md), the paragraph naming `already_rerun`; `cmd/agc/internal/provisioner/eviction.go` says the same at the reservation).
  The check asks about the job, not the run: an unchanged `run_attempt` rules it out with no extra call, and a moved one is settled by the latest attempt's jobs list.
  The deferred path already records `failedAttempt` for this purpose (Q1244).
- **`run_succeeded`**: `conclusion: success`, which GitHub refuses with a 403; today the refusal is the only thing stopping it.
- **`worker_unstartable`**: the set's capacity gate holds a startup or placeability verdict (Q714) that every next pod fails.
  New wiring, since no re-run path consults `worker_startup_verdict.go`; it matters most on the abandoned arm, which releases on any pod of the set being bound, including one stuck pulling an image every next pod will fail to pull too.

Each counts on `actions_gateway_eviction_rerun_withheld_total` with its own `reason`, and the `EvictionRerunWithheld` Event names the fix the [design table](../plan/q555-automatic-recovery-design.md#the-futility-checks-r18-in-order) gives.
Gated on 2.1 with the rest of the retry work ([release-2.1.md](../plan/release-2.1.md)): every new class re-runs through these same checks, so they bound what each class can cost.
