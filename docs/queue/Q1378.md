# Direct-egress gateway's workload policy opens GitHub to proxied workers

**In a namespace holding a direct-egress gateway and a proxied one, the proxied gateway's workers can reach GitHub directly, while their status reports `Proxied` and attributed.** Confirmed from source by the November security audit (2026-11-09), low severity; one of the five findings Q1323 carried, filed on its own because its fix is a design choice the other four did not need.

The GMC builds one workload NetworkPolicy per gateway, and each one selects the namespace-wide `component=workload` label (`cmd/gmc/internal/controller/actionsgateway_v2_builder.go:92:// workloadNPNameV2 is the per-gateway workload NetworkPolicy name. Its selector`).
A direct gateway's policy adds the GitHub CIDR egress rule, and NetworkPolicy is additive, so that rule reaches every workload pod in the namespace, the proxied gateway's included.
`setEgressMode` and the gateway's `updateStatus` each read only their own object's proxy reference, so nothing reports it.
Whether a given CNI then passes the packet was not observed.

The audit gives two directions, and choosing between them is the design question:

- **Scope the rule.** The AGC stamps workers with a selectable egress-mode or gateway label, and the GitHub CIDR rule moves into a policy selecting only direct-mode pods, leaving the shared default-deny with DNS and the proxy peers.
  This edits `actionsgateway_v2_builder.go` and the AGC's pod build, and changes the policy set an operator sees.
- **Keep the shared posture and report it.** Set `EgressUnattributed=True`, or a dedicated condition, on every proxied `RunnerSet` and gateway whose namespace also holds a direct gateway, and say so in `05-security.md`, `network-architecture.md` and `tenant-onboarding.md`.

Either way `docs/design/05-security.md` and `docs/operations/troubleshooting.md` currently say proxied workers cannot egress directly (the audit cites `05-security.md:147` and `troubleshooting.md:3936`, cited as of 2026-11-09 and not re-checked here), so the docs change with the fix.

Contention, read 2026-11-22: draft PR 2084 (the GKE Workload Identity opt-in) edits `actionsgateway_v2_builder.go`, `05-security.md` and `troubleshooting.md`, so the first option collides with it in code and either option in docs; re-take its file list before starting.

**Done when** no NetworkPolicy whose selector matches a proxied set's workers carries an `ipBlock` egress peer, pinned by a test building a direct and a proxied gateway's policies in one namespace, or the shared posture is reported on the affected objects and documented as a residual in `05-security.md`.
