# Operator docs give GKE Managed Prometheus no way to scrape tenants

The per-tenant scrape docs ([observability-metrics-access.md](../operations/observability-metrics-access.md#scraping-per-tenant-agc-and-proxy-metrics-mtls)) describe only the GMC-rendered Prometheus-Operator `ServiceMonitor`, and Google Managed Prometheus (GMP) managed collection reads `PodMonitoring` instead, so an operator on GKE's default metrics stack has no documented path to the AGC and proxy metrics.
Q1180 found this while writing the dogfood scrape: [`deploy/dogfood-metrics/`](../../deploy/dogfood-metrics/README.md) is a worked `PodMonitoring` with the mTLS client Secret, the collector `Role`, and the `metrics=enabled` label GMP's `gmp-system` namespace needs before the tenant NetworkPolicy admits it.
GMP's API (`ScrapeEndpoint.tls.ca`/`cert`/`key` as Secret references) and its docs (a `Role` granting the `gmp-system/collector` ServiceAccount read on the Secret) were read 2026-10-27; whether any GKE version in support lacks the Secret references was not checked.
The fix is a docs section adapting that example to the v2 names (`<gateway>-agc-metrics-client`, `<ep>-metrics-client`), and a note in the `ServiceMonitor` toggle's text that it does nothing for GMP.
Whether the GMC should render `PodMonitoring` itself is a separate question; it is not this row.
