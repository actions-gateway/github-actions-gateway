# check-artifact-unchanged misses a Dockerfile base bump

**The freeze check reports "nothing that ships has changed" for a window whose only change is a published image's base.** It filters a path list through `semverfloor -ships`, and a path list cannot say what changed inside the `Dockerfile`, so `Dockerfile` never counts.
Measured 2026-11-22 on `origin/main` after Q1359: `printf 'Dockerfile\ncmd/gmc/internal/webhook/v2/actionsgateway_webhook.go\n' | .build/semverfloor -ships` prints only the webhook path.

**Why it matters.** The check guards the gap between a validated candidate and the stable tag, so a base-image bump merged in that gap would ship in an image the candidate never validated, with the freeze check reading clean.
Q1359 made `semver-floor.sh` read the `Dockerfile` by diff for exactly this case; `-ships` is the path-only mode and was not part of that change.

**Done when** a window that edits a stage a published image is built from (a `FROM` base or digest, or an instruction in it) is reported as changing what ships, with a case in `check-artifact-unchanged-test.sh` for both a base bump and a comment-only `Dockerfile` edit.
`devtools/release/semverfloor/dockerfile.go` has `dockerfileChanged(root, sha, images)`, which answers it per commit; the check would need to ask it per commit in the window rather than per path.
