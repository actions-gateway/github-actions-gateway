# tidy-check fails on a proxy.golang.org stream error downloading a module

**Top of queue per [flakes-first rule](../development/maintaining-backlog.md#flake-fixes-go-first)**: the second sighting below fired the deferred trigger, and it evicted a release PR from the merge queue.

`tidy-check` fails on a module download from `proxy.golang.org` rather than on drift, on branches that changed no module file.
Both sightings carry the same stderr shape, an HTTP/2 stream reset while `go mod tidy` reads a module zip in `scripts/go/go-work-tidy.sh`:

- 2026-11-09, PR #2286's first `unit-test.yml` run (42722656004), job `tidy-check` (129520311058), at `make tidy-check` (Makefile:961), reached through `tools` → golangci-lint → `unqueryvet`:
  `github.com/MirrexOne/unqueryvet@v1.5.4: read "https://proxy.golang.org/github.com/%21mirrex%21one/unqueryvet/@v/v1.5.4.zip": stream error: stream ID 1; INTERNAL_ERROR; received from peer`.
  `tidy-check` passed on the PR's next head (fb9391a).
- 2026-11-17, the merge_group `unit-test.yml` run 44003152766 for PR #2331, job `tidy-check` (133772013892), at Makefile:971, reached through the `agc/internal/provisioner` test → `google.golang.org/grpc` → `internal/testutils/roundrobin` → `gonum/stat/distuv`:
  `gonum.org/v1/gonum@v0.17.0: read "https://proxy.golang.org/gonum.org/v1/gonum/@v/v0.17.0.zip": stream error: stream ID 241; INTERNAL_ERROR; received from peer`.
  #2331 changed no module file and passed `tidy-check` on its PR run; the failure evicted it from the merge queue.

Measured 2026-11-09 over the 40 most recent failed `unit-test.yml` runs (back to 2026-10-05): 13 had a failed `tidy-check`, and the other 12 each failed on a `diff --git` of module files, so the first sighting was the only proxy error in that window.

Both logs show the module cache cold: the second prints 102 `go: downloading` lines, and setup-go warns `Restore cache failed: Dependencies file is not found ... Supported file pattern: go.mod`, because the repo root has `go.work` and no `go.mod`.
**The cause of the reset is unverified**: whether it came from the proxy, the runner's network, or something between is not known.

Fix: a bounded retry of the tidy flow keyed on the measured `: read "<url>": stream error: ` text, failing with a message that names the network rather than untidiness when retries run out.
