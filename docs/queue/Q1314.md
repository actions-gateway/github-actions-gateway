# tidy-check fails on a proxy.golang.org stream error downloading a module

**Event:** `tidy-check` fails a second time on a module download from `proxy.golang.org` rather than on drift, on any branch.
Filed without a bump under the outside-service exception in [flake fixes go first](../development/maintaining-backlog.md#flake-fixes-go-first): one sighting, rooted in the module proxy, not yet recurred.

The sighting, 2026-11-09: PR #2286's first `unit-test.yml` run (42722656004), job `tidy-check` (129520311058), failed at `make tidy-check` (Makefile:961) with:

```
github.com/MirrexOne/unqueryvet@v1.5.4: read "https://proxy.golang.org/github.com/%21mirrex%21one/unqueryvet/@v/v1.5.4.zip": stream error: stream ID 1; INTERNAL_ERROR; received from peer
```

It was reached through `tools` → golangci-lint → `unqueryvet`, during `go mod tidy` in `scripts/go/go-work-tidy.sh`.
The same log shows `go: downloading` lines for golangci-lint's dependencies, so the setup-go module cache did not hold them on that run.
The PR touched no `go.mod` or `go.sum`, and `tidy-check` passed on its next head (fb9391a), so the failure was a download, not untidiness.

Measured 2026-11-09 over the 40 most recent failed `unit-test.yml` runs (back to 2026-10-05): 13 had a failed `tidy-check`, and the other 12 each failed on a `diff --git` of module files; their only `proxy.golang.org` text is the `GOPROXY` line in the job's env dump.
So this is the only proxy-error failure in that window.

**The cause is unverified past that one log.** Whether the HTTP/2 `INTERNAL_ERROR` came from the proxy, the runner's network, or something between is not known.

Candidate fixes, all unmeasured:

- Retry the module download (for example a `go mod download` pass with a retry before the tidy flow), so one dropped stream does not fail the job.
- Warm the module cache so golangci-lint's dependency tree is not fetched on every cache miss.
- Use `GOFLAGS=-mod=mod` with the vendored `tools/vendor`.
  Go documents that `go mod tidy` does not read `vendor/`, so this one may not reach the failing call at all; check that before building it.
