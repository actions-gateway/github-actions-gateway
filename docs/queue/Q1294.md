# Drop the AGC's Secret list and update grants the agent pool justified

The AGC's tenant Role grants Secret `list`, `update` and `patch`, and the comments justifying all three name the classic agent pool that Q264 removed ([`agc-tenant-role-rules.yaml`](../../charts/actions-gateway/files/agc-tenant-role-rules.yaml), lines 48-62, read 2026-11-06).
A grant nothing uses is standing authority over every Secret in a tenant namespace, so it should go if it is unused.

A scan of `corev1.Secret` in `cmd/agc` source on 2026-11-06 finds gets, a create and deletes, and no `List` or `Update`, which is read rather than run.
Measure it first: remove the verbs and run the AGC integration and e2e suites, because a missing verb fails only at the call.

The audit guidance names the same removed paths and moves with it: [security-operations.md](../operations/security-operations.md), the *AGC full-body Secret list* and *AGC Secret access outside its label scope* rows, which still expect `actions-gateway/runner-group=*` and agent-pool Secrets, and section 3 of [`apiserver-audit-policy.yaml`](../operations/examples/apiserver-audit-policy.yaml).
