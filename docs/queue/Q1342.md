# A stored scale-set name collision refuses every update to either gateway

While two stored RunnerSets in one GitHub scope share a first label, the ActionsGateway webhook refuses every update to either side's gateway, including the GMC's own finalizer write and the established tenant's edits to its own gateway.

**Measured 2026-11-11 in the GMC envtest suite**, while closing Q1325: a RunnerSet and an ActionsGateway created concurrently in a second namespace were both admitted onto a first label a first namespace already held (25 of 50 attempts).
From then on the GMC's update adding its finalizer to the first namespace's gateway was denied with `spec.githubURL binds GitHub scope ... where RunnerSet "held" in this namespace would claim scale-set name ...` on every reconcile, though that update changed only metadata.
The raced gateway's finalizer write is denied the same way, which is what keeps it from being provisioned, so that half is wanted.

**Mechanism, read from source.** `validateScaleSetLabelsVsScope` runs on every update, and an update that leaves `githubURL` alone is judged with `CollidesAsWritten`, which only drops the public-GitHub alias fold: a genuinely colliding stored pair still fails it.
So the second tenant, by racing a pair (or by any route into a stored collision: an upgrade from before Q791, a window with the webhook uninstalled), freezes the first tenant's gateway against its own edits until the second tenant's set is gone.
The gateway's status subresource is not intercepted, so the `ScaleSetNameCollision` report still lands.

**Fix direction, not decided.** Exempt an update whose own namespace's claims are unchanged from the scope check, the way `scaleSetClaimUnchanged` exempts a RunnerSet edit, while keeping the refusal for a gateway that has never been reconciled (no GMC finalizer), since that refusal is what holds a raced gateway unprovisioned.
`TestV2_ScaleSetNameGuard_ConcurrentPairIsReported` builds the state; a test that edits the held gateway's labels there should go green with the fix.
