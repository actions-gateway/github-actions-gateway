# Key a security-dashboard panel on the egress-audit attribution gauge

Q1062 shipped `actions_gateway_egress_audit_attributable`, the series the security dashboard's own Row 1 prose says a consumer-keyed panel would have to gate on so a pool's traffic is never read under a consumer's name without the join to back it.
No panel reads it yet, so the dashboard still keys egress entirely on the pool.

The minimum is a panel of the gauge itself, which tells the audit persona which tenants' egress resolves to a job and since when.
It does **not** belong in the existing "Egress posture per gateway" state timeline: that one is `1 = flagged` and this gauge is normal-is-True, so a `1` there would read as an alarm and its `0`, the supported default since both halves of the pair are opt-in, as healthy.

The reason this was not folded into Q1062 is the render, not the JSON: `make dashboard-render-check` fails a dashboard changed beyond its panel descriptions whose screenshot did not, so the panel needs a live Grafana + Prometheus to re-render `docs/assets/grafana-dashboard-security.png` per [`deploy/monitoring/preview/README.md`](../../deploy/monitoring/preview/README.md).
A consumer-keyed *traffic* panel, proxy series filtered to the gateways reading `1`, is the larger question behind it and needs its own decision about what a mixed pool should show.
