# `TestHandleEviction_RunNeverConcludingIsSurfaced` measures the host

The test sets `EvictionRerunWindow: 50ms` and `EvictionRerunRetryInterval: 5ms`, drives `handleEviction` against a real `httptest.Server` that answers 403, and then asserts `calls > 1` ("the window must span several refused attempts").
Nothing in that assertion is about the retry loop.
It is about whether two loopback HTTP round trips plus goroutine scheduling fit inside 50ms of wall clock, which is a property of the host.

**Observed 2026-09-09 (Q1078).** A `make check` failed it with `"1" is not greater than "1"` while the box was at load average 82.64 on 18 cores and the gate fan-out took 424s.
The same tree passed the same test twice afterwards: once under `make -C cmd/agc test-integration` (the package is not integration-tagged, so it runs there too) and once under a `make check` at load 40.70 where the fan-out took 100s.
No code changed between the three runs.

**Not yet seen in CI**, which is why this is filed rather than escalated: `git log -S` on the `50 * time.Millisecond` literal returns only #1010, which introduced it (Q503/Q510), and #1515 (Q811).
Neither widens it for a flake.
CI's runners are 2-vCPU, so the margin there is not obviously better than a loaded dev Mac's; that it has not fired is an absence of evidence rather than evidence of headroom.

**The shape is the one [testing.md](../development/testing.md) already argues against** in [Script tests: neutralize the clock, never measure it](../development/testing.md#script-tests-neutralize-the-clock-never-measure-it) and [A test that can reach a timeout path controls the deadline](../development/testing.md#a-test-that-can-reach-a-timeout-path-controls-the-deadline).
The neighbouring test avoids it (`cmd/agc/internal/provisioner/eviction_internal_test.go:274:assert.Equal(t, int64(3), calls.Load(), "two refusals then the accepted call")`): it asserts an exact call count against a handler that refuses twice and then accepts, so it counts attempts the handler decided rather than attempts the clock allowed.

**The work.** Make the number of attempts a property the test controls rather than one it races for.
Injecting a clock is the thorough fix; driving the window off the handler (refuse N times, then let the window close) is the cheaper one and matches the neighbour.
Widening the window is not a fix, only a wider race, and the same reasoning applies to the second site (`cmd/agc/internal/provisioner/eviction_internal_test.go:534:EvictionRerunWindow:        50 * time.Millisecond`), which carries the identical window and has not been observed failing.
