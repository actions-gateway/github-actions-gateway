# Abandoned arm force-cancels a run a user already cancelled

On the scale-set tier, `forceCancelAbandonedRun` reads the run only for its attempt, then records that attempt as GAG's own cancel and force-cancels, whatever the read's conclusion says (`cmd/agc/internal/provisioner/abandoned.go:89:	if err := p.recordSelfCancel(ctx, target, runID, run.attempt); err != nil {`).
If a user or a concurrency group had already cancelled that attempt, the ledger now calls the cancel GAG's, so Q1181's `run_cancelled` check re-runs the run once capacity returns and undoes the user's cancel.
The design asks for the abandoned arm to read the conclusion **before** force-cancelling and withhold a run already concluded `cancelled`, not cancel it again ([design](../plan/q555-automatic-recovery-design.md#the-futility-checks-r18-in-order), its notes on `selfCancelledAttempt`).
The read is already there, so the fix is a branch on `run.status`/`run.conclusion` before `recordSelfCancel`, a withhold counted as `run_cancelled` under `cause="abandoned"`, and no `registerAbandonedRerun`.
Unmeasured: what GitHub's force-cancel answers for a run already concluded, which decides whether today's path registers the re-run at all (a non-202 ends as `outcome="error"` and registers nothing).
The mechanism is read from source on 2026-10-27, not reproduced.
