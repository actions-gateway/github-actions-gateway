# Refuse nodeName and schedulerName on namespaced worker templates

**A tenant's `RunnerTemplate` can put a worker on a controller's node, past the GMC's worker separation term.** The GMC, AGC and egress proxy pods carry a required pod anti-affinity against worker pods, and the default scheduler enforces it from both sides, so a worker it places never lands beside a controller.
A worker pod with `spec.nodeName` set is bound to that node without the scheduler, and one naming another `spec.schedulerName` is placed by a scheduler that need not read the term.
Read at `0bd9dfb60`: `api/v2/scheduling_types.go:72:// priorityClassName, schedulerName, runtimeClassName, and nodeName; these pods cannot.` says worker templates can express both, and `git grep -n NodeName` over `cmd/gmc/internal/webhook/v2` and `cmd/agc/internal/provisioner` finds no rule refusing or clearing either.
Whether the AGC copies a template's `nodeName` onto the worker pod unchanged was not driven for this row; `buildPod` takes `template.Spec` as the pod spec, which suggests it does.

A worker that escapes beside the AGC can read that tenant's GitHub App private key, and beside the GMC every tenant's.
The tenant needs a node name, which `kubectl get pods -o wide` in its own namespace shows for its own AGC.

The fix is to refuse both fields on a namespaced `RunnerTemplate` at admission, or to clear them in `buildPod` the way it already clears `hostPID` and the host namespaces.
A `ClusterRunnerTemplate` is platform-authored, so whether it may keep them is a choice to make and write down.
Clearing in `buildPod` also covers templates stored before the rule, as `dropAPICredentialProjections` does for projected tokens.

**Done when** a namespaced template cannot place a worker by `nodeName` or `schedulerName`, a test drives a template carrying each, and `security-operations.md § Keep GAG's control plane off worker nodes` drops the gap from its list.
