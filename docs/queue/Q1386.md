# A seeded GMC that cannot fetch /meta never owns its IP-range ConfigMap

**Event:** `e2e / e2e` fails in the step "Chart uninstall/reinstall check" with `FAIL: actions-gateway-gmc-ip-ranges has no Deployment owner`, or the GMC logs `not adopting the persisted GitHub IP ranges` (a conflicting write is retried first, so the line means the read or the write failed, or conflicts outlasted the retries). → top of Queue, escalated.
Q1119's event (an `UPSTREAM-DIAL-FAILED` banner) does not cover this: that is the suite failing on an empty proxy policy, and this is the step after a green suite failing on the seed's missing owner.

The e2e suite seeds the GMC's `actions-gateway-gmc-ip-ranges` ConfigMap from the job's token (Q1119), and the ConfigMap carries no owner reference.
`IPRangeStore.Save` was the only code that added the owner, and `Save` runs only after a successful `/meta` fetch.
A GMC whose unauthenticated fetch is rate-limited therefore seeded itself, served the seed, and never adopted the ConfigMap, so the check that `helm uninstall` removes it read an ownerless copy.
The GMC now adopts the persisted ConfigMap at startup (`IPRangeStore.AdoptOwner`, called from `wiring.go` after the seed), so the owner no longer waits on a fetch.

The unit tests drive `AdoptOwner` and `Save` directly, and deleting the owner write from either turns its test red; no run has shown the seeded GMC adopting under a spent quota.

## What the check covers

A seeded run's owner comes from one of two writes: adoption at startup, or `Save` when the GMC's own fetch succeeds.
Either alone satisfies the check, so it goes red only when neither happens, which under a spent quota means adoption.
It cannot say which write supplied the owner, so each is pinned by its own test: `TestSeedIPRanges` (`seedIPRanges` adopting, including a copy refused for age; nothing pins `registerControllers` calling `seedIPRanges`) and `TestIPRangeStore_AdoptOwner` (the write and its conflict retry) for adoption, `TestIPRangeStore_SaveWritesOwner` for `Save`.
Adoption is tried once per start and a failure is logged and not retried further, so a GMC whose adoption write fails and whose fetch is rate-limited still leaves the copy behind.
