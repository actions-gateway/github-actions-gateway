# Operator docs address v1-only AGC labels, SA, Service and NetworkPolicy

Twenty sites select or name the AGC by an identifier that is v1-only, in the same pages and often the same code blocks as the Deployment references Q1098 repaired.
The v2 builder mints every AGC control-plane child from `agcNameV2`, as `<gateway>-agc`, so the pod `app` label, the ServiceAccount, the Service, the RoleBinding and the AGC NetworkPolicy are all per-gateway, while the docs still spell the fixed v1 name.
A `kubectl get pod -l app=actions-gateway-controller` therefore selects nothing on a v2 tenant, exactly as the Deployment commands did.

**Not every one of those is a defect, which is the part to settle before editing.**
Three of them are `docs/design/network-architecture.md` describing the v1 NetworkPolicy *as design*, and the `docs/operations/upgrade.md` pair sits in the v1→v2 rename history, where the v1 name is the subject.
`docs/development/networkpolicy-port-matching.md`'s four are a selector-matching table whose rows may or may not be version-scoped.
So the sweep is smaller than twenty and the first task is classifying it, the way Q1098's own count needed correcting: its stated 26 missed four bare-name Deployment references its pattern could not see, and one of the 26 (`docs/development/local-kind-demo.md`) turned out to be correct, because that page applies a `v1alpha1` CR and the row's claim that none of the 26 was v1-scoped in its prose did not hold there.

**One identifier that looks like this class is not in it.** `app.kubernetes.io/name` stays `actions-gateway-controller` under v2: `agcAppName` is `names.ControllerName`, which `v2GatewayLabels` passes to `apilabels.Recommended` unchanged.
Every `-l app.kubernetes.io/name=actions-gateway-controller` in the docs is therefore correct as written and must not be swept along with the rest.
`app.kubernetes.io/managed-by` on the v2 control-plane children is `actions-gateway-gmc`, not the AGC name, so those need checking separately rather than assuming either answer.

The presentation is already settled: Q1098 landed the split `# v2` / `# v1 (legacy)` shape across eight pages, so this is the same convention applied to a second identifier rather than a new decision.

**`make agc-names-check` is the gate and already exists**, covering the Deployment name only ([`scripts/docs/check-agc-names.py`](../../scripts/docs/check-agc-names.py), [testing.md](../development/testing.md#the-agc-deployment-name-gate)).
Extending it to the selector is a second pattern beside `DEP_RE` plus its red-and-green pair in the test, not a new gate, but only over the scope classified above, since the design and history pages it would then reach are the ones where the v1 name is correct.
