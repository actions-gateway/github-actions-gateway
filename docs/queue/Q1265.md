# Port the v1alpha1-driven envtests, e2e fixtures and load harness to v2

The `v1alpha1` removal ([Q273](Q273.md)) deletes the types every v1 test builds on, so each test that exercises a mechanism v2 still has needs a v2 twin before the removal lands, or that coverage leaves with it.
This lands first, on a tree where v1 still exists; the removal then deletes the v1 originals.

A v1 test is deleted rather than ported when it exercises the classic broker path alone, since the classic removal (Q264) follows Q273 and no tag ships between them, or when a v2 test already covers its mechanism.
Measured off `7b292627a` on 2026-11-02:

- **AGC envtests.** Four RunnerGroup tests have no RunnerSet twin: the plain-Pending `WorkersUnschedulable` negative, the worker-Pod watch, a template edit taking effect without a restart, and priority-tier assignment.
  The rest are classic-only (listener lifecycle, Q260 dedup, SIGTERM sessions, agent Secret persistence, classic eviction) or already twinned.
- **GMC envtests.** 26 files reach v1 through `startGMCReconciler` or `newActionsGateway`.
  By test name, about 12 have no v2 twin, among them the AGC cross-namespace RBAC scope, tenant Secret access, certificate renewal, credential rotation, HPA bounds, owner-reference GC, the proxy NetworkPolicy's GitHub CIDRs and `managedNetworkPolicy: false`, and the PriorityClass guard on direct writes.
- **e2e.** The v1 `TenantFixture` drives 15 files and 6,365 lines; the suite has nine `E2E_V2_*` specs.
  The GMC-tier files (provisioning, isolation, RBAC, PSA labels, worker securityContext, teardown, HPA/PDB, resilience, worker lifecycle) port onto v2 tenants; the classic-tier ones do not.
- **Load harness.** `cmd/agc/test/load` drives the classic multiplexer directly and names `RunnerGroupReconciler` only in comments, so it is Q264's, not this row's.

New AGC tests follow their neighbours onto `v2alpha1`, which the AGC retype after Q264 changes for the whole suite at once.
