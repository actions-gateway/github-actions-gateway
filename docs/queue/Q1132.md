# Re-vendor the re-enqueue gate: --confirm cannot fail on head drift

**Event:** [`claude-skills#537`](https://github.com/karlkfi/claude-skills/pull/537) merged.

`scripts/agent/pr-requeue-eligible.py --confirm` returns `ELIGIBLE` for a head it never looks at.
[`confirm()`](../../scripts/agent/pr-requeue-eligible.py) unpacks the PR's live head from `pr_fields()` and then reads the name zero times, so an assessment recorded before a rebase authorizes the enqueue of an arbitrarily different commit, including one whose conflicts are **not** confined to the merge-driver-owned files, which is the sole property `--assess` exists to establish.

The freshness guard beside it compares `baseRefName`, the base *branch name*, which survives both a rebase and the base branch advancing, so it fires only on a retarget.

**Measured 2026-09-19 against [#1965](https://github.com/actions-gateway/github-actions-gateway/pull/1965).** `--assess` recorded `ELIGIBLE` against base `e8b6924e7a726c22e51cee700a1a70799bb45f1c` and head `ebbaffd39bc9dae4f0f1027611b4662b4ee9ed85`.
The branch was then rebased and force-pushed to `25f00a6e9a1b18173370ff547b7a251ac0e51e0a`, with the base advancing to `71ced4d76`.
`--confirm` returned `ELIGIBLE` with no complaint, printing `measured: git merge-tree --write-tree e8b6924e7... ebbaffd39...`.
Those are two superseded SHAs in a line that reads as current provenance.
The verdict was not acted on; #1965 was left for human merge review.

Both defects are live in the copy this repo runs, confirmed by reading it on 2026-09-19 at `local_sha256 70ec2949`, which [`vendored-skills.tsv`](../../scripts/ci/vendored-skills.tsv) records as equal to `upstream_sha256`, so this is upstream's defect rather than a local edit.

## Why it waits

The fix is upstream and this file is vendored byte-identical, so patching it here forks the copy and makes the next re-vendor a merge instead of an overwrite.
`claude-skills#537` was still open on 2026-09-19.
Nothing here reports the gap: [`check-vendored-skills.sh`](../../scripts/ci/check-vendored-skills.sh) pins `local_sha256` only and [cannot ask whether upstream has moved](../development/skills.md#vendored-from-the-skills-repo), a deliberate non-goal whose blocker is a token for the private repo.
[Q955](Q955.md) owns it, and this row is not a reason to reopen that decision.

## What the upstream fix changes

`#537` adds a third mode, `--rebased`, because the head always moves between `--assess` and `--confirm`, the rebase being what happens in between, so waking on head drift alone would refuse every re-enqueue the gate exists for.
`--rebased` runs once the rebase is pushed, re-probes against the new head, requires that merge clean, and re-binds the record to the commit the rebase produced.
`--confirm` then requires the live head to equal the head the last record names, with no exception.
The base check keeps comparing the branch name, now documented as the retarget guard it is; base *commit* drift stays deliberately not a refusal.
