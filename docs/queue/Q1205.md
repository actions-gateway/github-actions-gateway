# lease-test's renewer-exit check reads a zombie as alive on GAG runners

**Deterministic on GitHub Actions Gateway (GAG) runners, not a flake, so this row does not follow the [flake lifecycle](../development/maintaining-backlog.md#flake-fixes-go-first).** Ranked first anyway: `scripts/dogfood/start.sh` dispatches `unit-test.yml` onto the dogfood CI tenant as its standard burst, and every one of those runs goes red on this case alone.

```
[lease-test] FAIL the renewer exits once its gate is gone: want '1', got '0'
```

**Every dogfood dispatch since the case landed has failed it.** All six `workflow_dispatch` runs of `unit-test.yml` on `main` since Q1158 (#2036, merged 2026-10-04) failed `scripts-test` with that line and no other `FAIL`: runs 37269175484, 37274737448, 37359973622, 37384177284, 40047447737 and 40081202236 (the last at 2026-10-24T09:22Z on `gag-ci-scaleset`).
The next push run on `main` (09:25Z, GitHub-hosted) passed it, as did two local `make check` runs on macOS that morning.

**Mechanism, measured: `kill -0` succeeds on a zombie, and the worker's PID 1 does not reap orphans.** The case at `scripts/dogfood/lease-test.sh:401` lets the owner exit, then polls `kill -0` on the renewer for 3 s.
The renewer exits on its next 0.2 s tick, but its parent is already gone, so it reparents to PID 1 and stays a zombie until PID 1 waits on it.
Measured 2026-10-24 by running the suite in `ubuntu:24.04` under `docker exec`: with `sleep infinity` as PID 1 the case fails with the exact CI line and leaves 2 zombies; with `--init` (tini as PID 1) it passes with 0.
On a GAG worker, PID 1 is the injected wrapper (`c.Command` in `cmd/agc/internal/provisioner/pod.go`), `scripts-test` runs in that container with no job `container:`, and `cmd/worker/main.go` only `Wait`s on the child it started.
That PID 1 is the wrapper on the dogfood pod itself is read from source, not measured there.

**Fix: count a zombie as exited.** The case asserts the renewer *exited*, which a zombie has; check its state (`ps -o stat= -p "${renewer}"` reading `Z*`, or empty) rather than `kill -0` alone, since macOS has no `/proc`.
Q1202 proposes borrowing this case's bounded-wait loop for its own `kill -0` read at line 388; that shape tolerates load but not a zombie, so the same state check belongs in both.

**Not this row:** `lib/lease.sh`'s renewer judges its owner with the same `kill -0`, so under a non-reaping PID 1 it would keep renewing a SIGKILLed gate's lease.
The release gate runs on `ubuntu-latest` (`.github/workflows/validate-candidate.yml`), so nothing hits that today.
Whether the worker wrapper should reap orphans as PID 1, as tini does, is a separate product question: every tenant job that orphans a process leaks a zombie for the pod's lifetime.
