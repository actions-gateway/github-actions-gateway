# `git commit` with a pathspec resolves against the tree, not the commit

A pathspec matches the working tree and index, so `git commit -- <path>` fails `did not match any file(s) known to git` on a file that is new and unstaged, and `git commit --amend -- <path>` fails on one whose deletion the commit being amended already carries.
The amend case is the dangerous one: the obvious repair is to drop the path that errored, which rewrites the commit to hold only the paths still named and silently drops the deletion.
Closing a row deletes its file, so backlog commits are where it fires.
[CLAUDE.md](../../CLAUDE.md) tells you to prefer the pathspec form and warns only that amend rewrites `HEAD` rather than the owning commit, as does [maintaining-backlog.md](../development/maintaining-backlog.md); neither says the form needs `git add`/`git rm` first, nor that it cannot name a deletion already committed.
