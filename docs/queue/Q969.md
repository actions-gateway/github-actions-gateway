# Withheld-capacity panel on the budget dashboard

Q724 shipped the budget dashboard reading one metric, `job_duration_seconds`, which is tier-neutral.
It answers what was spent and leaves one budget-owner question unanswered: spend held down by a throttle rather than by demand.

The series for it are already on `main`, so this waits on nothing.
`actions_gateway_scaleset_advertised_capacity` is the ceiling the AGC declared, and `actions_gateway_scaleset_capacity_withheld{reason}` is what each rung removed from it, the two summing to the configured ceiling.
A Row 4 panel plotting withheld capacity by `reason` beside the ResourceQuota bars would say which rung is suppressing intake: `quota`, `capacity`, or the `scaleup` token bucket that Q717 is adding as a fourth reason value (a panel grouping by `reason` picks that up with no edit).

**The design question to settle first is the tier split**, which is why this is not a bolted-on target.
Both series are scale-set only: on the classic tier the same ladder is per-delivered-job counters (`jobs_admission_rejected_total{reason}`) rather than a capacity integer.
Every panel on the budget dashboard today is tier-neutral, so adding a scale-set-only row means either accepting a row that reads empty on a classic-only deploy, or unioning two metrics whose units differ (slots against jobs).
Decide that before building.
