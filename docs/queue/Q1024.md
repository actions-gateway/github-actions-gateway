# Nothing renders the registry-mirror kustomize overlays in CI

`deploy/registry-mirror/` ships four render targets an operator applies with `kubectl apply -k`, and no gate renders any of them: the root (isolated, ephemeral), `overlays/persistent/`, `overlays/shared-tenants/` and `overlays/shared-tenants-persistent/`.
Enumerate them rather than counting them, so the next overlay does not silently fall outside the check.
`components/shared-tenants/` is deliberately not on that list: a Component does not render alone, and `kubectl kustomize` on it exits 1 with `no matches for Id NetworkPolicy...registry-mirror-worker-access` (measured 2026-08-28), so it is covered through the two overlays that compose it.
`manifest-validate.yml` yamllints the tree and kubeconforms the files named in `scripts/manifest/manifest-validate.sh`'s `standalone_manifests` list, which is the base plus `overlays/persistent/pvc.yaml`; a `kustomization.yaml` that does not render is caught by neither, and first fails at apply time on the operator's cluster.

Separate from Q1022, which shared this target and has shipped: that one closed an exposure in what the shared overlay renders, this one is that nothing renders it at all.

`scripts/ci/check-template-library.sh` is the precedent to copy rather than a design to invent: it renders each `deploy/templates/` overlay and asserts a load-bearing line the base declares survived the render, and it does so only when kubectl is on PATH, degrading rather than failing where it is not.
**No host-tool decision blocks this.** kubectl is already on the hosted runner: on unit-test.yml run 33230881190 (`main`, push, so `runs-on` resolved to `ubuntu-latest`) that script's skip note, `kubectl not on PATH`, is absent from the log while its success line is present, so `command -v kubectl` succeeded.
`manifest-validate.yml`'s `validate` job is plain `runs-on: ubuntu-latest`, the same hosted image; that last step is inference, since the log read was of a different job.
Copy the `command -v kubectl` guard anyway, which keeps the check correct if a job ever moves to a runner without it.

Assert something load-bearing rather than exit status alone, in both directions.
For both shared targets, that the rendered `registry-mirror-worker-access` ingress peer is the tenant marker and that the base's single-namespace peer is gone; and that **nothing else the base declares was dropped**, because the patch replaces `ingress` wholesale.
For both persistent targets, that the five PVCs survive, which is what tells `shared-tenants-persistent` apart from `shared-tenants`.
A second ingress rule added to the base disappears from that render at exit 0, measured 2026-08-28 by adding one and rendering.
Both failures read as green, which is what the assertions are for.
