# Scope the egress-audit attribution gauge to a RunnerSet's own proxyRef

`EgressAuditUnattributed` and `actions_gateway_egress_audit_unattributed` (Q1062) read the proxy half from `ActionsGateway.spec.defaultProxyRef`, because that is the proxy the GMC's gateway reconciler has already resolved by the time the condition is written.

Not because an unresolvable reference makes the condition safe.
`Reconcile` returns at `setNotReady(ProxyNotFound` / `ProxyShareNotGranted)` ([actionsgateway_v2_controller.go](../../cmd/gmc/internal/controller/actionsgateway_v2_controller.go)) *before* `updateStatus` runs, and `setNotReady` writes only the named condition and `Ready`, so `EgressAuditUnattributed` keeps whatever it last held.
Measured 2026-09-07 on a fake-client reconcile, against the pre-inversion polarity: a joined gateway cleared the condition, and after deleting the `EgressProxy` it stayed cleared beside `Ready=False`/`ProxyNotFound`.
Inverted, that is a gateway whose pool is gone still reading `0` on the flag.
That staleness is the whole advisory set's rather than this condition's (`EgressUnattributed` read `False`/`ProxiedEgress` on the same pass), so it is [Q1079](Q1079.md) rather than this row.

Worker traffic does not have to leave through that pool.
`RunnerSet.spec.proxyRef` overrides `defaultProxyRef` for the set's workers ([runnerset_target.go](../../cmd/agc/internal/controller/runnerset_target.go) resolves `rs.proxyRef` → `gw.defaultProxyRef` → direct), and the Q986 join is worker source address against worker bind record, so it is the *set's* pool whose `auditLogging` decides whether a record carries an address to join on.
It is wrong in both directions, and the first is the one Q1062 exists to prevent:

- **False `0`.** A gateway logging `WorkerAddresses` whose `defaultProxyRef` pool logs `ConnectionsWithSource` clears the flag even where every bound `RunnerSet` overrides the ref to a pool with the source half off, so a consumer-keyed panel would show that pool's traffic under the tenant's name with no join behind it.
- **False `DirectEgress`.** A gateway with *no* `defaultProxyRef` reads `1` with reason `DirectEgress` however its sets egress, because `rs.proxyRef` is read first and is independent of the gateway's, so a tenant whose every set names a pool logging `ConnectionsWithSource` is reported as having no per-connection record to attribute when it has one per set.
  The message says so as of Q1062, which is a caveat rather than a fix.

Two shapes were weighed, and the second is the one to build (the answer below says why):
- **Widen the gateway condition** to require every bound `RunnerSet`'s resolved pool to log `ConnectionsWithSource`.
  The gateway reconciler already lists bound sets for the `RunnerSetsDegraded` rollup ([evalRunnerSetHealth](../../cmd/gmc/internal/controller/actionsgateway_v2_controller.go)), so the list is free, but resolving each set's own `proxyRef` (cross-namespace, sharing-gated) is new `Get`s per reconcile on the GMC's hot path, and it collapses a per-set fact into one gateway bit.
- **A per-`RunnerSet` twin**, set by the AGC's RunnerSet reconciler, which already resolves the set's pool for its own `EgressUnattributed` condition.
  Keeps the resolution where it happens and gives a panel a per-set key, at the cost of a second condition and gauge in a second binary.

When the twin lands, the gateway gauge's own caveat ("scoped to `defaultProxyRef`") becomes a pointer at the per-set series in `observability-metrics.md`, `observability-logging.md`, `tenant-onboarding.md`, `appendix-g-future-enhancements.md` §G.3, and the condition godoc in `api/apiconditions/conditions.go`.

**Settles (answered):** build the per-`RunnerSet` twin, read 2026-10-09 off `main` and corrected the same day in review.
The twin is a condition and a gauge beside `setEgressMode` in the AGC's RunnerSet reconciler, which holds the `ActionsGateway`, whose `spec.auditLogging` is the worker-address half of the join.
The source half is the set's `EgressProxy` `spec.auditLogging`, and the AGC holds it on one path only.
A same-namespace proxy is read at `cmd/agc/internal/controller/runnerset_target.go:535:if err := c.Get(ctx, types.NamespacedName{Namespace: ns, Name: proxyName}, proxy); err != nil {` and flattened into `resolvedProxy`, which drops the field, so that path needs a field carried and no new read.
A shared proxy is never read by the AGC at all: `resolveSharedProxy` reads the ConfigMap the GMC projects into the consumer's namespace, which carries host, port and no-proxy only (`cmd/gmc/internal/controller/egressproxy_sharing.go:36:shareHostKey     = "proxy-host"`).
So the twin also needs the GMC to project the provider's `auditLogging` as a fourth key, written when the grant is projected rather than on every reconcile.
Widening the gateway condition instead adds a cross-namespace, sharing-gated `Get` per bound set on every GMC reconcile, so the twin still costs less, by one projection key rather than by nothing.
The gateway condition stays as it is, scoped to `defaultProxyRef`, and its documented caveat changes from a limitation to a pointer at the per-set series, which is the key [Q1070](Q1070.md)'s panel wants.
