# Fixture builders as arguments hide a killed builder in four test suites

Four suites build fixtures inside a command substitution passed straight to an assertion helper, the shape [Q1145](Q1145.md) removed from `check-release-ladder-test.sh`:

- `scripts/docs/check-release-pins-test.sh`: 15 sites, `fixture`
- `scripts/docs/check-release-links-test.sh`: 11 sites
- `scripts/ci/check-tool-pins-test.sh`: 8 sites, `write_makefile`
- `scripts/ci/check-cosign-pin-test.sh`: 1 site

Bash drops a substitution's exit status when it is an argument, so a builder that fails or is killed hands the helper an empty path, and the suite reports the checker's answer to that empty path as a wrong verdict.
Measured 2026-10-09 on `02fb0338b` against the release-ladder suite: a SIGTERM injected into its page builder produced a FAIL blaming the checker, with no shell error line; the same injection after hoisting the builder into an assignment exited 143, which `run-parallel.sh` reports as KILLED.
None of these four has been sighted failing this way, so this is a reporting defect rather than a flake.
Separate from [Q991](Q991.md), which is suites sharing a fixed fixture path so that one run deletes another's: that fix changes where fixtures live, this one how a builder's failure is reported, and neither closes the other.

**The census is a floor.** It counted continuation lines opening with `"$(` followed by a builder-style name (`write`, `make`, `mk`, `fixture`, `build`, `new`, `setup`), over every `scripts/**/*-test.sh`.
A builder named otherwise, or one written on the helper's own line, is outside it, so recount with a wider match before closing.

**The fix** is the one Q1145 applied: assign each fixture (`page="$(fixture …)"`) and pass the variable, so errexit ends the suite with the builder's own status.
