# A script that exits 0 on skip makes its CI step unreadable

A gate script with a legitimate skip path exits 0 twice over: once because it checked and passed, once because it decided there was nothing to check.
The step's conclusion cannot separate them, so a green check reports "this ran and passed" when it may mean "this never ran".
That is the [instrument that measured nothing](../development/testing.md#the-status-you-report-is-a-claim-too), arriving through the status rather than through a parser.

Two instances ship today, both correct in their skip behaviour:

- `scripts/e2e/egress-negatives.sh` skips when `REGISTRY_MIRRORS` is unset, which is the hosted lane and a developer's `make e2e`.
  Its whole purpose is to hold the Q408 Phase 4 posture on every run of the Kata lane, so a green step that silently skipped is exactly the reading it exists to prevent.
- `scripts/e2e/buildkitd-mirror-config.sh` prints nothing on the same condition, and the empty value is load-bearing at the call site.

Measured 2026-08-28: grading Phase 4's validation needed a second instrument to settle whether the battery had run at all — the runner image's `curl/8.5.0` appearing exactly twice in the mirror access log, told apart from the probe pod's `curl/8.10.1`.
That worked, and it is not a reading anyone should have to reconstruct to trust a green check.

**The fix has a precedent in the tree.** Seven workflows already write `$GITHUB_STEP_SUMMARY` (`publish.yml`, `integration-test.yml`, `doc-links.yml` among them), so a skipping script can say so where a reviewer sees it without opening a 3,000-line log.
The shape to settle: whether the line is written by the script or the step, and whether a skip should also annotate, since a summary is read only by someone already looking.

**Do not "fix" it by failing on skip.** The skip is correct in both cases; what is missing is that it is *legible*.
A gate that failed the hosted lane for having no in-cluster mirror would be a worse instrument than the one described here.
