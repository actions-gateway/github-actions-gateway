# Nothing verifies buildx's `type=gha` cache works from a `run:` step

`docker-bake.hcl:40` says the cache env vars arrive "after docker/setup-buildx-action has injected" them; that action's v4.2.0 source exports no such variable, and Docker's own docs say an inline `buildx` must expose them itself.
The e2e bake sets `cache-to type=gha` from a `run:` step and passes, which argues the vars do reach it — from the runner, not the action — so either the comment misattributes the mechanism or the cache is a no-op.
A `cache-from` miss is only a warning, so it would read as a slow job, never a red one.
Measure a cache hit, then fix whichever is wrong.
