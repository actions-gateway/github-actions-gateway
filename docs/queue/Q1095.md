# Close the ownership consumer half by reference, not by spelling

`checkConsumers` in [`ownership.go`](../../devtools/docs/reasontiers/ownership.go) asks whether a package outside the enumeration's own compares a reason against one of its entries, and it answers by enumerating the *spellings* of that comparison: `==`/`!=` operands and `switch` case clauses, resolved through a `Reason*` selector or a bare string.
That set is open and cannot be closed by adding to it.
The scan builds no type information, so a reference one indirection away is invisible.

Measured 2026-09-10 on `41dac001c`, each reinstating the exact defect Q994 closed with `make reason-tiers-check` green at `EXIT=0`:

- `sessionTooOld := v2alpha1.ReasonVersionTooOld` then `prev.Reason == sessionTooOld`
- `const listenerTooOld = v2alpha1.ReasonVersionTooOld` then the same comparison
- `slices.Contains([]string{v2alpha1.ReasonVersionTooOld}, prev.Reason)`

The first two are the strongest: a straight `==` against the same constant, one named indirection away, and a const alias is a plausible way somebody writes a local membership decision.
Four such spellings surfaced in one review round after five had just been fixed, which is the signal that the enumeration has no fixed point rather than a coincidence.

**The fix is a different shape, not more spellings.** Any *reference* to a member `Reason*` constant, from a package that is neither the producer subtree nor the enumeration's own, is the finding, whatever is done with the value.
That needs no new AST shapes: a `SelectorExpr` walk through `constValue`, which [`collectConditions`](../../devtools/docs/reasontiers/main.go) already does for the inventory.
Its godoc argues this exact trade already, saying that references rather than writes are the inventory, and that over-approximating adds a ledger row but never drops one.
Same direction, and it catches all three consumer rows above, because an alias and a local are both initialized from the constant.

The producer half has the same class of hole and it belongs here rather than in a row of its own, since fixing it alone buys one spelling and restates the exhaustiveness claim: `var ct = v1alpha1.ConditionRunnerVersionTooOld` is a `ValueSpec`, not an `AssignStmt`, so `resolveConditionType` never sees it, measured green the same day.

**The cost is unmeasured and is the whole question.** Predicted green on today's tree: the only non-test references to `VersionTooOld`/`VersionAccepted` are `internal/listener`, `internal/runnercore`, and, since Q994, nothing in `internal/controller`.
That prediction has not been run, so the false-positive surface is unknown, and a reference-level rule refuses a legitimate non-membership question far more often than the comparison-level one does (a reason re-emitted as an Event, a log line, a test helper outside `_test.go`).
Whether the exemption list that buys back stays smaller than the spelling list it replaces is what this row has to establish before the change is worth making — run it first, count the findings, and drop the row if the answer is no.

Filed out of the Q994 review, where the enumerating approach was shipped deliberately and its claim narrowed to match ([`ownership.go`](../../devtools/docs/reasontiers/ownership.go) says the set is not closed).
Nothing is broken today: every spelling above is a defect somebody would have to write, and the gate catches the ones the tree actually uses.
