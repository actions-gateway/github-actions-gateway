# No PR gate judges whether a queue row's `target:` anchor resolves

A row's `target:` may name a heading anchor (`../plan/v2-ga.md#some-heading`), and nothing that runs on a pull request checks that the anchor exists.
`check-doc-links.sh` resolves links between files rather than headings within them, and `pages.yml`, which does run `mkdocs build --strict`, has no `pull_request` trigger.

Measured 2026-09-07 on #1867: a row filed with one missing hyphen in its anchor passed `make check` and `make docs-gates` twice, and failed CI only through `release-links` and `build` — two jobs that happen to run `mkdocs build --strict` for their own reasons and picked it up because the row renders into `docs/queue/README.md`.
A `target:` pointing into a page those two jobs do not build would have merged broken.

The fix is a gate that resolves every `target:` anchor against the headings of the file it names, run on pull requests.
`mkdocs build --strict` already does this for the rendered store, so the cheap form may be running it (or the existing `--strict` build) on the PR rather than writing a new checker; that trade is the row's first question.
The inversion is a fixture row whose `target:` anchor is off by one character: the gate must go red on it, and a leftover-anchor grep cannot, because it goes green both when the anchor is right and when the `target:` line is absent.

Found while closing Q452, whose PR the defect landed in ([#1867](https://github.com/actions-gateway/github-actions-gateway/pull/1867)).
Neighbour rather than duplicate of the webhook row filed on [#1867](https://github.com/actions-gateway/github-actions-gateway/pull/1867), which is not yet on `main`: that one is a validating webhook rule the `v2.0.0` cut un-matches, this one is a missing docs gate.
