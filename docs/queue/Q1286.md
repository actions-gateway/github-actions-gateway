# release-links job outruns its 10-minute limit provisioning the docs venv

**Top of queue per [flakes-first rule](../development/maintaining-backlog.md#flake-fixes-go-first).**

On 2026-11-05 the `release-links` job in run [42047586935](https://github.com/actions-gateway/github-actions-gateway/actions/runs/42047586935) hit `timeout-minutes: 10` and was cancelled, so `doc-links-gate` failed on `a gating job concluded 'cancelled'`.
It checked no link, and a rerun with no code change passed in 61 s (15:22:02Z to 15:23:03Z).

This is not [Q1280](Q1280.md)'s stall, which sits in a full-history checkout: here the checkout took 21 s (14:43:49Z to 14:44:10Z).
The job log's timeline after that:

| Time | Line |
|---|---|
| 14:44:32Z | `check-release-links: site/ is not built — building it now (make docs-build)` |
| 14:50:36Z | `docs-preview: provisioning venv from requirements-docs.txt…` |
| 14:54:08Z | `The operation was canceled.` |

So about 6 minutes passed before `ensure_venv` printed its first line, and the `python3 -m venv` and two `pip install` calls in `scripts/docs/docs-preview.sh` then used the remaining 3.5 minutes without finishing.
What took the first 6 minutes is unmeasured: nothing logs between those two lines, and a slow runner and a slow package index would look the same.
The commit under test changed only `docs/operations/upgrade.md` and `charts/actions-gateway/README.md`.

Fix by first timing those stages in the job, so a slow window names its stage.
Candidate fixes, none measured: cache `.venv-docs/` across runs, or give the build its own step timeout and a retry.
Sweep the other jobs that provision this venv under a tight limit, and state what the sweep found.
