# Reject an insecure https tracing endpoint

**A stricter admission rule, gated on `v2.0.0` because an open major is the only cheap time to add one.** It must let an unchanged stored value through, as `spec.tracing.endpoint`'s rule does (Q1283), so a stored object is not refused when an unrelated field is edited.
A manifest that applies today will still be refused on a fresh cluster, which is why a minor cannot take it and `v3` is the next place it could otherwise land ([Q1311](Q1311.md)).
Karl gated it on 2026-11-09, after the pre-`v2.0.0` API review.

**`spec.tracing` with `insecure: true` and an `https://` endpoint exports in plaintext.** Read from the vendored `otlptracegrpc` v1.47.0, not run: `internal/otlpconfig/envconfig.go` sets transport security from the endpoint's scheme, then applies `OTEL_EXPORTER_OTLP_TRACES_INSECURE` after it, so the GMC's `insecure: true` overrides the `https://` the operator also wrote.
The GMC sets that variable only when `insecure` is true (`tracingEnvV2`, `cmd/gmc/internal/controller/actionsgateway_v2_builder.go`), so `http://` with `insecure: false` is not a contradiction it can produce.
Run the pair once before writing the rule, since the rule's message will state what the exporter does.

**Done when** the rule is in `api/v2` with tests covering a refused new value and an accepted unchanged stored one, `upgrade.md` tells operators what `v2.0.0` now refuses and how to find a stored object that has it, and the `v2.0.0` release notes list it under breaking changes.
