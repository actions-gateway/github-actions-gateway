# check-artifact-unchanged-test: pathfilters killed by SIGTERM mid-gate

**Top of queue per [flakes-first rule](../development/maintaining-backlog.md#flake-fixes-go-first).**

Observed 2026-10-09 16:40 PDT in a local `make check` on a branch that touches nothing under `scripts/release/` or `devtools/`.
One case failed, the rest of the suite passed:

```
FAIL --lane e2e-test.yml: an AGC change is inside it (want exit 1, got 2)
check-artifact-unchanged: pathfilters match e2e-test.yml at bfef9dce7a9446a955b4b7fe995a2dc149e40b37 failed (exit 143)
13 passed, 1 failed
```

Running `scripts/release/check-artifact-unchanged-test.sh` alone straight afterwards, with no code change, passed `14 passed, 0 failed`.
`uptime` then read `load averages: 20.75 33.96 35.37` on the 18-core host.

**Mechanism unverified.** Exit 143 is a SIGTERM to `pathfilters`, and nothing in [check-artifact-unchanged.sh](../../scripts/release/check-artifact-unchanged.sh) or its test sets a timeout, so the signal came from outside the suite.
It is not [Q1144](Q1144.md)'s shared-binary hazard: this script builds `pathfilters` into its own `mktemp -d` directory, not `.build/`.
It is not [Q1106](Q1106.md)'s probe either: the read that failed is `git show` of a committed workflow into that same temp directory.
The same `make check` ran `scripts/lib/serialize-heavy-build-test.sh` concurrently, which sends TERM, HUP and INT, but only to pids it launched and the processes below them, so a stray hit would need pid reuse within milliseconds.
That is unmeasured rather than ruled out.
A first step is to record which process sent the signal on a recurrence, for example by running the suite under `make check` in a loop with the match wrapped to log its parent and process group on exit 143.
