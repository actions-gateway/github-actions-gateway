# Parallel githubapp tests break each other through http.DefaultTransport

**Top of queue per the [flakes-first rule](../development/maintaining-backlog.md#flake-fixes-go-first).** Sighted once, on the `push main` run of `35d1ccb4a` (#1999, run 36649692418, 2026-09-30), in `unit-test`'s `-race` step.
The merge-group run of the same tree had passed 20 minutes earlier.

```text
--- FAIL: TestToken_NonOKResponse (0.00s)
Error: "githubapp: POST access_tokens: Post \"https://api.github.com/app/installations/1/access_tokens\": net/http: HTTP/1.x transport connection broken: http: CloseIdleConnections called" does not contain "401"
```

**The mechanism reads off source; it has not been reproduced.** `redirectTransport.RoundTrip` sends every request through the process-wide transport, at `githubapp/auth_test.go:200:return http.DefaultTransport.RoundTrip(cloned)`.
Ten tests in that file call `t.Parallel()` and each one's `defer srv.Close()` runs `httptest.Server.Close`, which calls `CloseIdleConnections()` on `http.DefaultTransport` (Go 1.27.1, `net/http/httptest/server.go` line 514).
One test closing its server can therefore break a connection a sibling is still using, and `errCloseIdleConns` is the error text in the failure.

The likely fix is a transport per client: `http.DefaultTransport.(*http.Transport).Clone()` inside `testClientRedirectingTo`.
Sweep the idiom while you are there, since any other test helper routing through `http.DefaultTransport` beside a parallel `httptest.Server` has the same race; say what the sweep found, including nothing.
