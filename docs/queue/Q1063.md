# Migrate the ctrl.Result{Requeue: true} returns off the deprecated field

controller-runtime v0.24 deprecates `Result.Requeue` ("Use `RequeueAfter` instead"): a rate-limited requeue reuses a limiter meant for retry on error, so the doc asks for either the duration until the awaited event or a poll interval.
Twelve sites return it, counted 2026-09-07 from golangci-lint 2.13.2's SA1019 report over both controller modules: two in `cmd/agc` (`runnergroup_controller.go`, `runnerset_controller.go`, both after adding a finalizer) and ten in `cmd/gmc` (`actionsgateway_controller.go` ×2, `actionsgateway_v2_controller.go` ×3, `egressproxy_controller.go` ×2, and three test assertions in `actionsgateway_status_test.go` and `actionsgateway_v2_degraded_test.go`).
2.12.2 reported none of them, cold or warm; the bump to 2.13.2 ([Q929](Q929.md)) surfaced them, and `.golangci.yml` carries a `path`-scoped `SA1019` exclusion for the field so the gate stayed green without deciding this.

The replacement is a behaviour decision per site, which is why it did not ride in the bump:

- **After a finalizer add** (2 in agc, 1 in gmc): the `Update` that added the finalizer fires the primary watch, so the requeue is a second reconcile of a state the event already reconciles.
  Dropping it to `ctrl.Result{}` rests on the primary watch carrying no generation predicate, which holds today (`SetupWithManager` puts predicates on the secondary watches only) and is an argument until an envtest case pins it.
- **On a status-update conflict** (the rest): the conventional shape returns the conflict error and lets the workqueue back off; these swallow it and requeue silently by design (the archived k8s-best-practices plan, row A2, chose that in 2026-06).
  Either keep the silence with a short fixed `RequeueAfter`, or return the error and accept a `Reconciler error` log line per conflict.

Delete the exclusion in the same change, so a new use of the field fails the gate.
