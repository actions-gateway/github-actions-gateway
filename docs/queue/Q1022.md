# Close `/v2/_catalog` on a shared registry mirror

On the shared mirror topology ([`overlays/shared-tenants/`](../../deploy/registry-mirror/overlays/shared-tenants/kustomization.yaml)), any tenant that can reach a mirror can list what every other tenant pulled.
`GET /v2/_catalog` names every repository in the cache, answers 200 on port 5000 (the port `e2e-mirror-egress` admits), and needs one manifest fetch to list a repository.

**Measured 2026-08-28** against `registry:3.1.1` at the digest `base/deployment.yaml` pins, run locally as a pull-through cache with the deployed proxy configuration: cold it returned `{"repositories":[]}`; after a single fetch of `library/alpine:3.20`, `{"repositories":["library/alpine"]}`.
`REGISTRY_CATALOG_MAXENTRIES=0` does not close it, measured on a second instance: the endpoint still answered with the repository listed.
Only that one setting was tried, so "distribution offers no knob" is unverified; establish it before designing around it.

This is a documented registry API endpoint rather than a side channel, so it is not narrowed by anything done to cache timing, and it dominates the timing question [Q1020](Q1020.md) still holds.
Today it is a documented trade-off ([Choosing a mirror topology](../operations/kata-dind-workloads.md#choosing-a-mirror-topology)) an administrator opts into, which is correct for a shipped option and weak as a durable answer: the shared topology is the one an adopter with several tenants reaches for first, and the cost of the isolated alternative is a whole mirror set per tenant.

Deliverables: a way to serve pulls while refusing `/v2/_catalog`, rendered as part of the shared overlay rather than as prose; a test that the endpoint refuses and that a pull still succeeds, since a fix that breaks pulls fails silently in the direction nobody probes; and the operator page's decision section corrected to match, including the residual-risk bullet in [secure-multi-tenant-oss-ci.md](../plan/secure-multi-tenant-oss-ci.md#explicitly-out-of-scope-and-residual-risk-accepted).

Do not reach for `REGISTRY_AUTH` without checking what it costs: the mirror serves anonymous pulls today, and the four image clients wired to it ([README § How the job is wired](../../deploy/registry-mirror/README.md#how-the-job-is-wired-to-these-instances)) each read their own configuration, so credentials would have to reach all four.
