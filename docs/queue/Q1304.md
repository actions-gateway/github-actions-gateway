# Drop the code paths below the 1.35 floor

The charts now refuse a cluster below Kubernetes 1.35, so version checks written for older clusters no longer choose anything on a supported install.
Read from the code on 2026-11-06, not run.

The AGC's `useImageVolume` (`cmd/agc/main.go:754`) compares the server version against 1.33 and uses an initContainer below it, and that comparison now always picks the image volume.
The initContainer path itself stays reachable, through `WRAPPER_DELIVERY=init` and when the server version cannot be read, so whether it goes too is open.
`release.md`, `migration-from-arc.md` and `tenant-onboarding.md` describe the 1.33 split and move with the answer.

The comment on that function calls the feature "beta and on by default" from 1.33, which is false before 1.35: on kind at 1.34.11 on 2026-11-06, `kubernetes_feature_enabled{name="ImageVolume"}` read 0 and the volume was dropped from a stored Pod.
So `v1.10.0` workers fail on 1.33 and 1.34 unless `WRAPPER_DELIVERY=init` is set, which `upgrade.md` tells operators to do; the 1.35 floor makes the comparison correct from `v2.0.0`.

The `t.Skipf` guards on a server below 1.31 in `v2_crd_test.go` and `v2_multigateway_test.go` can never skip while `ENVTEST_K8S_VERSION` is 1.35.

Two more things exist only for clusters below the floor, and neither is a version branch.
`spec.tracing.endpoint`'s `oldSelf` clause (`api/v2/shared_types.go:259`) works around ratcheting missing the status subresource on 1.31 and 1.32, and removing it changes the CRD, so whether it goes is open.
`docs/operations/examples/kind-cluster-audit.yaml` defaults to the `extraArgs` form its own comment scopes to 1.30 and older; the example was not run.

Done when no branch tests for a version below the floor, the two above are decided, and the docs describe what remains.
