# The release notes' commit count is hand-written and goes stale

`docs/releases/v1.6.0.md` opens its "Everything since" section with a commit count that no tool derives.
During the 1.6 release it was wrong twice: written as 158 at the rc.1 cut, still 158 after rc.2 (actual 165), and corrected to 166 only because the promote pass re-derived it. #1736 edited that same file to fix two overclaims and left the count untouched, which is the tell -- it does not read as a number anyone owns.

`scripts/release/semver-floor.sh <last-tag>` already prints the figure (`N commits (merges excluded)`), so the value is available; nothing connects it to the note.
Either derive it at render time in `render-release-body.sh`, or have `check-release-notes.sh` compare the note's count against `semver-floor` for the tag the note is named for and fail on a mismatch.

Small, but it is a published number in the most-read paragraph of the notes, and the failure is silent: a stale count looks exactly like a fresh one.
