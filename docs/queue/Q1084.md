# local-throttle silently disables itself when CI is set on a dev Mac

`throttle_active` returns 1 on any non-empty `CI` before it reaches the OS or GUI check ([`local-throttle.sh:154`](../../scripts/agent/local-throttle.sh)).
On darwin the function would otherwise return 0 unconditionally, so on a dev Mac a set `CI` is the only thing that turns throttling off, and it turns off all of it at once: no `nice`/`taskpolicy` prefix, no physical-cores − 2 cap, and an empty jobs value, so `run-parallel.sh` starts all 119 script suites simultaneously.

Measured 2026-09-07 while working Q1061.
A session ran `CI=true make check` to mirror what CI does, on a box already carrying many concurrent agent sessions.
Two suites failed on wall-clock waits and read as flakes; re-running the same tree as plain `make check` was green.
The two shapes it produced are the ones [Q822](Q822.md) and [Q1031](Q1031.md) already track, which is what makes this expensive rather than merely slow: a manufactured failure is indistinguishable from a real sighting, and the session came close to adding one to a flake row's table that other sessions read as evidence of a real defect.

**The fix is a warning, not a refusal.** On darwin with `CI` set, print one line to stderr naming what has been disabled.
That combination is a local mistake by construction: a real runner for this repo is Linux or the self-hosted dogfood runner, and even on a genuine macOS runner a warning costs one stderr line and changes no behaviour, so it is safe in both directions.
Refusing would be the wrong rung, since a legitimate `CI` on darwin is possible and nothing here needs to be prevented, only noticed.

The doc half shipped with this row: [`testing.md`](../development/testing.md#resource-auto-throttle-on-gui-dev-machines) now says that setting `CI` locally turns the throttle off.
That is the mitigation; the warning is what closes the class, because a doc line only reaches somebody who reads it before typing the command rather than after.
