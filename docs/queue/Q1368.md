# Scope running the Kata and DinD gate legs concurrently on dogfood

**Once the tenant-swap hold (Q1362) is gone, the e2e jobs themselves pace the release gate, and running two legs at once is the only change left that takes a whole leg off its wall clock.** The DinD leg would take about 20 minutes once Q1362 lands (estimate, from its measured 17m23s and 19m31s jobs plus a fast swap).

On the one dogfood cluster, not a second one: the legs are serial so the gate stays on a single cluster inside GKE's free tier, and both legs already share the cluster's one `e2e` pool.
The cross-project form is [Q1161](Q1161.md), deferred, which expects to cost more.
Kata and DinD would each need their own tenant: today they are two overlays of one namespace (`gag-dogfood-e2e`), one ActionsGateway and one RunnerSet registered as scale set `gag-ci-e2e`, and the namespace security profile differs between them (baseline for Kata, privileged for DinD), so a second namespace with its own runner label is required, not optional.
The e2e pool already allows two nodes (the autoscaler's `max: 2`), e2e node-hours should stay about the same, and system-pool hours should fall.
CPU quota is not a blocker: `validate-release.sh` already reserves the e2e pool's full ceiling (2 × 8 vCPU) out of the project's `CPUS_ALL_REGIONS` budget before it caps the `workers` pool (Q631), so two concurrent e2e nodes fit the reservation the gate makes today.
`e2e-test.yml`'s concurrency group is a definite change: it keys on workflow and ref, so two dispatches on `main` share one group, the second waits as pending, and the legs run serially anyway; the group needs the `runner` input in its key.
Dragonfly stays serial: its mirror back end and node client are cluster-wide.

**Measure:** each question below is a reading on dogfood or a read of the workflows, not a maintainer decision.

**The scoping pass should answer:**

- whether the Kata leg's mirror census stays complete with a second tenant's clients on the same mirrors;
- whether sizing and capacity, which read the Kata tenant after its leg, are disturbed by a concurrent DinD tenant.

**Done when** those are measured and the row either becomes an implementation item with a cost reading or is closed with the blocker named.
