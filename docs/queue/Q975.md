# The em-dash ratchet strands connectives, and no gate checks the result

`check-em-dash.sh` (Q654) ratchets density against a per-file baseline, so a file already over the rule may only lose em-dashes.
Every prose change to such a file is under standing pressure to split an em-dash sentence, and splitting one strands the connective from both halves.
Measured 2026-08-24 on one PR: the gate fired twice, on six em-dashes then three, and one rewrite left `which also rules out staticcheck having been quiet on its own, which is the third cause below` in `testing.md`.

**Nothing automated checks whether the result still parses.** No member of `DOCS_GATES` has an opinion on prose grammar, and `md-reflow-check` is `mdreflow --check`, which is about line breaks alone.
So the only instrument is a human reading the diff, and here that is what failed: the artifact was a plain `+` line in the branch diff, and the author reading it did not see it while a reviewer reading the rendered prose did.

The gate stays.
The pressure it applies is the point, the artifact is a side effect, and nothing about this is unique to em-dashes: no edit in this repo has its grammar checked.
[Q650](Q650.md) is the exit rather than a fix here, because the pressure ends per file the moment that file reaches the rule.
Today the tree sits at 13.00 per 1,000 against a rule of 3, with 228 files still on the baseline.
