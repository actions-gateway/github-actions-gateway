# The em-dash ratchet strands connectives, and no gate sees them

`check-em-dash.sh` (Q654) ratchets density against a per-file baseline, so a file already over the rule may only lose em-dashes.
Every prose change to such a file is therefore under standing pressure to split an em-dash sentence, and splitting one strands the connective from both halves.

Measured 2026-08-24 on one PR: the gate fired twice, on six em-dashes then three, and one rewrite left `which also rules out staticcheck having been quiet on its own, which is the third cause below` in `testing.md`.
That artifact landed outside the passage being edited, because `mdreflow` re-wraps the paragraph and carries the changed clause onto a different line, so reading the diff does not surface it.
A reviewer reading the rendered prose caught it; the author reading the diff did not.

`md-reflow-check` normalises exactly those lines and has no opinion on whether the prose still parses, so nothing between the pressure and the artifact can see it.
The likely fix is a line in [documentation-standards.md](../development/documentation-standards.md) telling an author to re-read the whole paragraph rather than the diff after removing an em-dash.
Worth deciding first whether a per-file density ratchet is the right mechanism when it generates a defect class its own tooling is blind to.
