# Q466's `rs-` scoping is not injective, so kinds deregister each other

A RunnerGroup named `rs-foo` and a RunnerSet named `foo` derive the same registered runner name, `rs-foo-0`, and the same Secret name.
`createAgent` registers before it writes the Secret, so the loser's 409 path resolves the incumbent's ID and **deregisters its live GitHub record** before failing.
Measured against `StubRegistrar`: incumbent id 1001 destroyed and re-registered as 1002, `registerCalls` 1→3, `deregisterCalls` 0→1, and only then `secrets "agentpool-rs-foo-0" already exists`.
The incumbent's Secret still holds agentId 1001, which no longer exists, so its listener cannot authorize; the other pool repeats this every reconcile.
That is verbatim the loop `Pool.agentName`'s godoc says the discriminator exists to prevent.
Nothing validates a CR name against the prefix.
The registration damage never reaches the returned error, which is why a first reading of this called it a failed create.
