# e2e suite drain leaves namespaces stuck on a reused kind cluster

On a kind cluster reused across `make e2e` runs, a later run failed `BeforeAll` with `unable to create new content in namespace tenant-v2-multigw because it is being terminated`, held by `RunnerSet` `agentpool-cleanup` finalizers.
Clearing the finalizers by hand on that private cluster let the next run pass.
Measured once during the Q1167 work, 2026-11-04, when five namespaces also read `Terminating` for 15 hours on another session's kind cluster.

`drainTenantNamespaces` in `cmd/gmc/test/e2e/e2e_suite_test.go` already documents this as a local-only case (Q301): its wait is best-effort and bounded, and CI deletes the whole cluster per run.
So this costs a local rerun rather than a CI failure, and what the failure lacks is a message: it reads as a defect in the spec it happens to stop, not as state left by an earlier run.
Whether the finalizers came from an earlier spec or an interrupted run is unmeasured.
