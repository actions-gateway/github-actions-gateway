# Give the shipped alerts and dashboards scale-set twins before Q264

[Q264](Q264.md) removes the classic acquisition tier, and no commit that could become a release may ship monitoring whose only signal for a failure mode is a series nothing writes any more.
So this lands first, adding scale-set coverage beside the classic rules and panels, and Q264 deletes the classic-only half together with the code that writes it.

Deleting classic leaves 13 `actions_gateway_*` series with no writer: `active_sessions`, `jobs_acquired_total`, `job_acquisition_errors_total`, `jobs_admission_rejected_total`, `jobs_duplicate_delivery_total`, `abandoned_delivery_completions_total`, `fanout_loser_recycle_deferred_total`, `renew_job_errors_total`, `renew_job_teardowns_total`, `agent_recycles_total`, `agent_recycle_errors_total`, `broker_token_propagation_retries_total` and `broker_session_leaks_total`.
That list was measured on Q264's unpushed branch on 2026-11-02 by the session porting the e2e suite, and is carried here rather than re-taken.

Read on `main` at `abb6fcd7f`, 2026-11-02, most of those already have a scale-set twin in `deploy/monitoring/`:

- `ActionsGatewayCapacityGateRejectingJobs` has `ActionsGatewayScaleSetCapacityWithheld`, and the acquisition success-rate recording rule has `actions_gateway:scaleset_provision_success_rate:rate5m`.
- `ActionsGatewayAgentRecycleErrors` has `ActionsGatewayScaleSetProvisionErrors`, since a scale set mints its JIT config per job and a failure there is a provision error.
- Every tenant, platform and budget panel over `jobs_acquired_total`, `job_acquisition_errors_total`, `agent_recycle_errors_total` or `jobs_admission_rejected_total` has a scale-set sibling panel.
- `renew_job_*`, `agent_recycles_total`, `broker_*` and the three fan-out delivery series have no analogue by design: the scale-set runner renews its own job, assigns each job once, and opens no broker session of GAG's.

The gap is the page `ActionsGatewayNoActiveSessions` carries.
`ActionsGatewayScaleSetProvisioningStalled` is called its analogue, but it fires only while jobs are being assigned, and a listener whose long poll keeps failing is assigned nothing, so it stays silent through exactly the outage the classic page caught.
The scale-set listener counts those failures into the shared `actions_gateway_message_poll_errors_total`, and no rule reads it.
The `Active sessions` panels on the tenant and platform dashboards have no scale-set replacement either.

Done means: a rule on sustained poll errors, tenant and platform panels showing what a scale set has queued at GitHub against what it advertises, the preview exporter writing the series those read, the alerting doc, runbook and dashboard doc carrying them, re-rendered screenshots, and the PR body naming each classic rule that keeps no twin.
