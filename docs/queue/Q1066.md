# Registry read cannot present node-identity pull credentials (GAR, ECR)

The registry read behind `RunnerVersionTooOld` (Q988) authenticates with `kubernetes.io/dockerconfigjson` Secrets: those the pod template's `imagePullSecrets` names, or, when it names none, those on the worker ServiceAccount, read through the AGC's own Role.
A registry that kubelet reaches through the node's identity — Artifact Registry under Workload Identity, ECR under the node role — has no Secret to read at all.
Such an image pulls fine and reports `WorkerImageVersionUnknown` with an authentication failure in the message (the anonymous path phrases it `token exchange with <host>: HTTP <n> (anonymous)`; which status GAR and ECR return is unmeasured), while the tag verdict, if the tag names a version, stands.

Closing it means a credential helper per cloud: an Artifact Registry token from the AGC's own Workload Identity, and an ECR `GetAuthorizationToken` under an IAM role the AGC assumes.
Each is a dependency and an identity grant per provider, and is sized `M` on its own.

**Decided 2026-10-09 by the maintainer: rides release 1.10, and may slip without holding it.** This is the second stage of a staged decision; the first, reading the worker ServiceAccount's `imagePullSecrets`, has shipped and is why the air-gapped install path no longer depends on this row.
Each identity grant is a security-relevant change to what the AGC can read, so it needs the operator half of [doc-update-matrix.md](../development/doc-update-matrix.md) in the same PR.
