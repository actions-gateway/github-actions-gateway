# Registry read cannot present node-identity pull credentials (GAR, ECR)

The registry read behind `RunnerVersionTooOld` (Q988) authenticates with the `kubernetes.io/dockerconfigjson` Secrets the pod template's `imagePullSecrets` name, read through the AGC's own Role.
That is the only credential the AGC can obtain: the tenant Role grants no read on ServiceAccounts, so a pull secret attached to the worker ServiceAccount rather than the template is out of reach, and a registry that kubelet reaches through the node's identity — Artifact Registry under Workload Identity, ECR under the node role — has no Secret to read at all.
Such an image pulls fine and reports `WorkerImageVersionUnknown` with an authentication failure in the message (the anonymous path phrases it `token exchange with <host>: HTTP <n> (anonymous)`; which status GAR and ECR return is unmeasured), while the tag verdict, if the tag names a version, stands.

Closing it means one of: reading the worker SA's `imagePullSecrets` (a Role widening, `get` on `serviceaccounts`), or a credential helper per cloud (an Artifact Registry token from the AGC's own Workload Identity, an ECR `GetAuthorizationToken`), which is a dependency and an identity grant per provider.
The first is cheap and covers the SA-attached Secret only; the second is what the node-identity case needs and is sized `M` on its own.

The SA-attached case is this repo's own documented install path rather than an edge: `docs/operations/air-gapped-install.md` §5 patches `imagePullSecrets` onto the `actions-gateway-worker` ServiceAccount, which kubelet injects into every worker pod and the AGC never reads, since both call sites pass `Spec.PodTemplate.Spec.ImagePullSecrets` (`runnergroup_controller.go`, `runnerset_controller.go`).
Against a mirror that requires authentication, an air-gapped install therefore never completes the registry read unless the operator also names the same Secret in the pod template, which the operator docs say to do; the tag verdict still stands where the tag names a version, as above.
That is the workaround, so the first closure buys an install path that needs no workaround; it does not reach node identity.
