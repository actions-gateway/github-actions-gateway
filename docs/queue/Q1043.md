# `merge-keyed-records.awk`'s anchor key mode has no caller post-Q889

`row_id()` dispatches on `key_mode` to one of three key readers, and `anchor` is both the default and the one the file's own usage example shows.
It read the Queue table's `<a id="QN"></a>` anchor, which is what the backlog table's merge driver needed.

Measured 2026-08-30 on `origin/main`: `git grep 'key_mode' -- scripts/` returns three call sites and none of them is `anchor` — `git-merge-plan-index.sh` and `git-merge-script-index.sh` pass `link`, `git-merge-roadmap.sh` passes `marker`.
`.gitattributes` registers four drivers (`scriptindex`, `gatelists`, `planindex`, `roadmap`) and no backlog one, because [Q889](../plan/q889-backlog-item-store.md) retired the table the anchor mode served.

So `row_key_anchor` and the `anchor` branch of `row_id` are dead, and `anchor` being the *default* is the part that misleads: a fourth driver added without `-v key_mode=` gets the dead reader rather than an error.
Deleting it makes `key_mode` mandatory, which is the behaviour a new caller wants.

`scripts/README.md:333` describes `key_mode` as three live options, "the backlog anchor, a Markdown link target, or a roadmap bullet's `<!-- q:QN -->` annotation", so that line goes with the branch.

Left as a separate row rather than folded into the Q922/Q924/Q987 fix, which corrected the comment's reference to the deleted `lint-backlog.sh` and did not touch the code.
