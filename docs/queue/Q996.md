# promql-check and dashboard-render-check guard less than they read as

`promql-check` mirrors each alert in `prometheusrule.yaml` against the copy `observability-alerting.md` reproduces, and compares a typed struct rather than the decoded YAML: `rule` is Alert/Record/Expr/Annotations, and `diffRules` is a single `reflect.DeepEqual` over it.
So `for:` and every label are unguarded.

Measured by mutating the doc side alone, one line per run, green baseline before and after:

| doc-side mutation | result |
|---|---|
| `expr … == 1` → `== 0` | fails, names the alert |
| `for: 10m` → `45m` | passes, `ok` |
| `severity: critical` → `warning` | passes, `ok` |

Severity is the sharp one: the doc can promise a page while the shipped rule sends a ticket, and the gate that exists to keep the pair in step reports `ok`.
Exit is 1 from the script; `make promql-check` exits 2, which is make's own code.

**The fix is two things, because the file denies the gap.** `main.go`'s `rule` godoc says "the mirror check compares the raw decoded form instead, so an added field cannot slip past by being absent from this struct".
That is false (`diffRules` compares the struct), and it is the likeliest reason the gap survived review.
Correct the comparison and the comment together.

`dashboard-render-check` is a separate, milder case of reading less than it appears to: every read is `rev-parse <ref>:<path>` / `git show` / `ls-tree`, with `--head` defaulting to `HEAD`, so nothing consults the worktree.
That is right for judging a PR's whole diff, and its message is wrong for it: it reports that the screenshot "did not change" while a freshly re-rendered PNG sits modified on disk, and its remediation says re-render and copy, never commit.
The fix is the sentence, not the mechanism.
