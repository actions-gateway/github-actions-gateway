# pull-image-with-retry.sh has no time bound on a hung docker pull

The script's header says a registry that is down fails "on a bounded schedule", "never hanging", and that holds only for a pull that returns.
Read at 2026-11-05T05:17Z, a hand run of `scripts/e2e/chart-released-upgrade-check.sh` had sat in the script for over 6h30m, with `ps` showing `docker pull ghcr.io/actions-gateway/gmc:v1.10.0` and its child `docker-credential-desktop get`, both at about that age.
A second, orphaned `docker-credential-desktop get` was hung beside them, and a `docker pull` under `timeout 30` about an hour later exited 0.

The attempt count bounds retries, but nothing bounds one attempt, so a hung pull never reaches the retry.
That check treats its pre-pull as best-effort, and the hang kept it from ever reaching the fallback; killing the pull did reach it, and the kubelet then pulled the image.

The hang was on a developer's machine, in Docker Desktop's credential helper.
Whether a hung pull can happen on a CI runner was not checked, and its cause on this host is unmeasured.
Fix by bounding each attempt, or by correcting the header if the bound is left to the caller.
