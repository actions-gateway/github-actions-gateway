# Report a GMC IP-range cache that never filled on gateway conditions

Split out of Q1203, whose rate-limit-aware retry shipped without this part; Q1203 is closed, so it is named here rather than linked.

A GMC whose first `api.github.com/meta` fetch has not succeeded gives proxy pools no GitHub egress, and no gateway condition says so.
`EgressRulesStale` is derived from `IPRangeCache.LastRefresh`, which reports `false` before the first fetch, so the condition stays silent exactly when egress is entirely missing rather than merely old.

The operator-visible result, measured 2026-10-24 on the local kind e2e cluster: jobs stayed `queued` for 10 minutes, the tenant's proxy NetworkPolicy carried only a DNS egress rule, and the GMC's log was the only place the cause showed.
`docs/operations/troubleshooting.md` now has a section for this state, but an operator has to suspect it first.

Whether `Ready` reads `True` in this state is unmeasured; read it before choosing between a new condition reason and an existing one.
Fix shape, unmeasured: when the cache has never filled, set a condition (likely on the `EgressRulesStale` type with a distinct reason, or `Degraded`) on every gateway or EgressProxy whose policy is in CIDR mode and gateway-managed.
A new condition reason is an API change, so read `docs/development/api-review.md` first.
