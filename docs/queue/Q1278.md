# Trace the scale-set provision path; the AGC emits no spans after Q264

The AGC's only span was `Provisioner.provision`, with children `stageJobSecret`, `countActivePods`, `createPod` and `waitForCompletion`, and it wrapped the classic provision path alone (`git grep -n 'tracer.Start' origin/main -- cmd/agc` finds it at `provisioner.go:511` and nowhere else, 2026-11-03).
Q264 removed that path, and the scale-set path `ProvisionScaleSetWorker` never opened a span, so after Q264 the AGC creates none.
`make lint` then flagged the tracer and `traceStep` helper as unused, and Q264 deleted them.

**What an operator sees:** `spec.tracing` on an `ActionsGateway` still sets the AGC's `OTEL_*` variables and the AGC still installs the exporter (`cmd/agc/internal/tracing`), so tracing reads as on and the collector receives nothing.
[observability-logging.md § Distributed Tracing](../operations/observability-logging.md#distributed-tracing-agc) says so since Q264, and that this row restores it.
That knob producing nothing is why this gates `v2.0.0`; dropping `spec.tracing` instead would be the other way to close it, and is a breaking API change of its own.

**The work:** open a root span per job in `ProvisionScaleSetWorker`, with child spans for staging the JIT-config Secret, the ceiling count and the pod create; the scale-set path does not wait for completion, so there is no `waitForCompletion` child.
The old root span's attributes (`k8s.namespace.name`, `gateway.owner.name`, `k8s.pod.name`, `gateway.active_pods`, `gateway.ceiling_held`, `gateway.priority_class`) are the starting set; `gateway.plan.id` has no scale-set equivalent, and the job id does.
A test needs an in-memory span exporter (`go.opentelemetry.io/otel/sdk/trace/tracetest`) and must fail with the span removed.
