# Split Dependabot sync so tool code never shares a job with a write token

`dependabot-go-sync.yml` and `dependabot-rebase-stale.yml` run `make deps-sync`, which builds and runs tools such as controller-gen from a freshly bumped `tools/vendor`, in the same job that holds the `contents: write` token it pushes with.
So a malicious release of a module in the tools graph acts with that token.

**Measured 2026-11-11 under Q1326** on the Dependabot-triggered sync run `42702512168` (2026-11-09): the token was `Contents: write` and `Metadata: read`, checkout logged `persist-credentials: true`, and controller-gen was built and run under `make deps-sync` in that job.
The rebase job exports `GH_TOKEN` (`contents: write`, `pull-requests: write`) to the script that runs the replay's `make deps-sync`.
Neither job holds `actions: write`, so neither can dispatch `publish.yml`, and the reach that matters is creating a `v*` tag, which no ruleset stops today.
The proposed `v*` tag ruleset in [05-security.md](../design/05-security.md#who-can-start-a-release-is-held-by-a-headcount-not-a-control) closes that path whatever this row does; this row narrows what is left, such as pushes to other unprotected branches.

**Why a second job and not a step-level fix.** Dropping the persisted credential and adding the token only to the push step is not a boundary: tool code running earlier in the same job can write `.git/config` (a `core.fsmonitor` program runs on the next `git diff`) or `.git/hooks`, and so runs again inside the step that holds the token.
The shape that separates them is a read-only job that runs `make deps-sync` and uploads the diff as an artifact, and a `contents: write` job that runs no repository code, applies the diff to a fresh checkout and pushes only `HEAD:<head_ref>`.
The rebase replay force-pushes several branches per run, so its split is the larger half.

**Done when** no job that holds a write-scoped token builds or runs code taken from a Dependabot branch, with a test beside `scripts/ci/dependabot-rebase-stale-test.sh` asserting the replay's sync runs with no credential reachable.
