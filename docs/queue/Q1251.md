# e2e context check trusts a context named kind-<cluster> on any server

The suite's `requireKindContext` compares only the context *name* with `kind-$KIND_CLUSTER`.
A hand-made kubeconfig holding a context with that name but pointing at another server passes the check, and setup and teardown then act on that server.
`make e2e` cannot produce one, because it writes the kubeconfig from `kind get kubeconfig`, so only a hand-run `ginkgo` with a hand-edited kubeconfig is exposed.
Reported by the Q1201 review on PR 2212 and not measured beyond that reading of the code.

Fix shape, unmeasured: also require the resolved cluster's server (`kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}'`) to be a loopback address.
First measure what the server reads on the CI e2e runner (`e2e-reusable.yml`), because a kind API server that is not on `127.0.0.1` there would make the check refuse every queue run.
