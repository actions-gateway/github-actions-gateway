# `debt` labels 40% of the store, the shape that retired `infra`

**Measured 2026-09-17** with `python3 scripts/docs/queue.py metrics --labels` over the 152 rows this branch started from: `debt` is on **61**, which is 40.1%.
[maintaining-backlog.md](../development/maintaining-backlog.md#a-label-earns-its-place-by-discriminating) records that `infra` was retired at 69 of 160, which is 43.1%, and sets the bar for a label at `docs/development/maintaining-backlog.md:828:it would land on more than a third of rows` on that page.
So `debt` sits **three points** below the share that retired the label it replaced, on 61 rows against `tests` 51, `ci` 44, `docs` 21 and `feature` 21.

`tests` clears the population half of that bar too, which is not usually read as a problem: 51 of 152 is 33.6% against a third at 50.67 rows.
The bar's two halves are a disjunction, so clearing the count is enough on its own and naming the question does not rescue a label from it.
What defuses it here is arithmetic rather than grammar.
That margin is one row wide and does not survive this row being filed: at 154 rows a third is 51.33, so `tests` at 51 falls back under.
The number is a prompt rather than a verdict at this store's size, and that cuts the same way for `debt`.

`debt`'s declared scope is "refactors, dedup, and dead-surface removal with no behavior change", and the question it answers is *what can I clean up without a design decision*.
That question is still a real one, which is what makes this different from `infra`: `infra` had no question of its own and had become "engineering work that isn't docs, tests, or security".
The reading to take is whether 61 rows all answer `debt`'s question, or whether some of them are carrying it because nothing narrower exists.

The same page warns against applying the number past its argument: a store whose work is nearly all one kind runs that label high without anything being wrong, and this backlog is largely internal engineering hygiene by construction.
So the count is the finding and the retirement is not.

**Re-measured 2026-09-18 over the active rows alone**, which is the population a reader of the backlog actually meets: `debt` is on **55 of 85** `ready` plus `blocked` rows, 64.7%.
The 40% above is diluted by the 69 `deferred` rows, which the default render hides, so the share facing anyone picking work is two thirds rather than two fifths.
That does not change the call this row asks for, since a store of mostly internal hygiene runs the label high for the honest reason, but it is the number the decision should be taken on.

Measured 2026-09-18, and the reason the release axis cannot absorb the difference: `render --group release` sections the 85 active rows into 2 for 1.9, 1 for 2.0, and **82 under Unscheduled**.
Every row either live release plan names as gating already carries its label, so there is no labelling gap left to close; the store is long because almost none of it is release work.

**Ask:** whether 40% on `debt` reads as the `infra` failure or as a true reading of what this backlog is.
It is a call about the vocabulary an adopter and every future session navigate the store by, and both answers are defensible on the same number, so nothing here is a measurement waiting to be taken.
If it is the failure, the repair the page prescribes is a narrower split rather than a rename, and every split candidate is a second question about what this repo wants the column to cut.
