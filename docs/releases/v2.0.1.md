Zero-idle self-hosted GitHub Actions runners for multi-tenant Kubernetes.

> **Draft: written before `v2.0.1-rc.1` was cut.** The Validation section is empty until a candidate passes, and the prose passes run before publishing.

> [!NOTE]
> **`v2.0.1` is a patch release with nothing to do at upgrade.** No CRD, chart value or API field changed since `v2.0.0`, so `helm upgrade` with the new image digests is the whole upgrade.

## Highlights

**A tenant can no longer get round the raced scale-set name guard by creating its gateway with the GMC finalizer already set.** In `v2.0.0` the Gateway Manager Controller (GMC) passed a new `ActionsGateway` through admission once, by adding its finalizer, and the webhook refused that update while the gateway's scale-set name collided with another tenant's.
A gateway created with the finalizer already in place skipped it and was provisioned onto the held name.
The GMC now passes every gateway it has not yet written status for through one admission-checked update before provisioning it, which also covers a gateway restored by Velero, since Velero keeps finalizers (Q1358).

**On an IPv6 cluster, the Actions Gateway Controller (AGC) reaches the Kubernetes API directly again, not through the tenant's egress proxy.** The GMC wrote the API server's IPv6 address into the AGC's `NO_PROXY` in brackets, `[fd00::1]`, and Go's `net/http` ignores a bracketed entry with no port (Q1336).

**A gateway whose `githubURL` spells public GitHub in mixed case or with a trailing dot now uses the public GitHub API.** `https://GitHub.com/acme` or `https://github.com./acme` was treated as a GitHub Enterprise Server appliance, so the AGC's token exchange and scale-set calls went to `https://GitHub.com/api/v3` (Q1333).

**`build-runner` and `cache-runner` ship a newer Docker CLI, buildx and compose, which clears CVE-2026-78669.** Two fixable HIGH findings remain in those binaries until Docker ships a release carrying their fix (see Security below).

## Security

**No advisory accompanies this release.** It carries one vulnerability fix, in the Docker binaries `build-runner` and `cache-runner` ship.

`build-runner`'s `docker:29-cli` base moved from `2357639a` to `34507eb5` (#2344).
At `v2.0.0` its buildx and compose plugins carried four fixable HIGH findings, measured with `trivy` 0.72.0 on the published `v2.0.0` image on 2026-11-17.
The new base clears two of them: CVE-2026-78669 (`golang.org/x/net` in buildx) is gone, and CVE-2026-78661 is gone from buildx but not from compose.
The other two have no Docker release carrying their fix yet, so CI excuses each until 2026-12-17:

- CVE-2026-17106: `moby/go-archive` 0.2.0 in buildx v0.39.0, the newest buildx release, which waits on one linking go-archive 0.3.0.
- CVE-2026-78661: `golang.org/x/net` 0.60.0 in compose v5.7.1; compose v5.8.0 shipped 2026-11-17 and is not in `docker:29-cli` yet.

The other bumps close no known vulnerability.
`trivy` finds nothing in the published `v2.0.0` `gmc`, `agc` or `proxy` images, and GitHub's advisory database lists no advisory affecting `google.golang.org/grpc` 1.84.0 or `cel.dev/expr` 0.25.2, the versions `v2.0.0` shipped (both read 2026-11-17).
Those bumps are `google.golang.org/grpc` 1.84.0 to 1.85.0 in the AGC and, indirectly, the GMC; `cel.dev/expr` 0.25.2 to 0.25.3 in the GMC, indirectly; and the `distroless/static` base of the GMC, AGC and proxy from `25ac8f0` to `aafe993`.

Q1358 and Q1336 harden tenant isolation without patching a reported vulnerability.

The runner-based images inherit their upstream base's findings, which CI reports without blocking.
They run `actions/runner` 2.338.2, unchanged from `v2.0.0`, and carry 44 (`worker`), 43 (`build-runner`) and 43 (`cache-runner`) fixable HIGH or CRITICAL findings, summed per scan target.

`govulncheck` and `trivy` run on every push to `main` and on every pull request that changes code (`security-scan.yml`), and a release tag is refused while an image the project builds from a minimal base, or `build-runner`'s Docker binaries, carries an unexcused fixable HIGH or CRITICAL finding.
