Zero-idle self-hosted GitHub Actions runners for multi-tenant Kubernetes.

> [!WARNING]
> **Every `actions-gateway.com` kind now stores `v2`, so the only release you can roll back to is `v1.9.0`.** Any write after the upgrade, a controller's status update included, stores the object at `v2`, and a release that does not serve `v2` cannot read it.
> `v1.9.0` serves `v2` and reads what this release stores.
> If you are on `v1.8.0` or earlier, upgrade to `v1.9.0` first if you want a rollback target.

> [!NOTE]
> **`v1.9.0`'s default worker image runs `actions/runner` 2.337.0, which falls outside GitHub's 30-day update window around 2026-11-05.** After that, GitHub stops queueing jobs to those runners while each runner keeps logging `Listening for Jobs`, so nothing looks wrong.
> This release moves the default to 2.338.1.
> If you pin your own `workerImage`, read **Upgrading** below.

## Highlights

**[`v2` is the storage version, and `gag-migrate storage-version` rewrites what is already stored.](https://actions-gateway.com/1.10.0/operations/upgrade/#action-required-before-v200-v2-is-the-storage-version-and-stored-objects-need-rewriting)** This is the release that exists so `v2.0.0` can be removals only.
`v2.0.0` stops serving `v2beta1`, `v2alpha1` and `v1alpha1`, and the apiserver refuses to drop a version a CustomResourceDefinition (CRD) still lists in `status.storedVersions`.
The new subcommand of the signed `gag-migrate` binary writes every object back unchanged and prunes `storedVersions` to `["v2"]`.
Run it any time between this upgrade and `v2.0.0`.
Every version stays served meanwhile, so no client notices.

**[A job whose worker's node shuts down is now re-run.](https://actions-gateway.com/1.10.0/operations/troubleshooting/)** A Spot or preemptible node that the kubelet shuts down gracefully, or a Node object deleted under a running worker, used to leave the job failed for someone to re-run by hand.
The Actions Gateway Controller (AGC) now re-runs it on both acquisition tiers, Classic and scale-set, counted under `actions_gateway_eviction_retries_total{cause="node_shutdown"}`.
So is a job on a dead node an admin taints `node.kubernetes.io/out-of-service`, Kubernetes' confirmation that the node is not coming back.
A node that goes `NotReady` and keeps its Node object, with no such taint, is not covered: recovery starts only once the taint is applied or the Node object is deleted.

**[The scale-set re-run budget survives an AGC restart, and one run attempt is re-run once.](https://actions-gateway.com/1.10.0/operations/upgrade/#non-breaking-the-scale-set-re-run-budget-survives-an-agc-restart-and-one-run-attempt-is-re-run-once)** `maxEvictionRetries` on a scale-set `RunnerSet` was counted in AGC memory, so a restart refilled it, and each disrupted worker of one run spent a slot and re-ran the run.
The budget now lives in a `scaleset-failures-<set>` ConfigMap per set, and disruptions of one run attempt share one re-run, so a drain taking three workers of one run re-runs it once.
The budget is now per set rather than shared across tiers.

**Scale-set recovery follows the job a runner actually took.** GitHub gives a scale-set job to whichever of the set's runners asks first, so the worker created for one job can end up running another.
Five fixes follow from that one fact:

- An evicted, preempted or drained worker re-runs the run it was serving, not the one it was created for.
- A worker that never started a job no longer cancels or re-runs a run that is running elsewhere.
- An idle worker left behind by a cancelled queued job is reclaimed after five minutes, where it used to hold a node until `maxWorkerLifetime` (12 hours by default).
- A worker's just-in-time (JIT) runner config Secret, which holds a runner credential, is deleted with the worker pod instead of lingering until the `RunnerSet` is deleted.
- A replayed job whose old worker is gone gets a fresh JIT-config Secret instead of the previous runner's used one.

The [Upgrading guide](https://actions-gateway.com/1.10.0/operations/upgrade/) has a section for each of the first four.
None of these five scale-set fixes was reproduced on a cluster.
Each is covered by unit tests.

**[Egress-audit attribution is judged per `RunnerSet`.](https://actions-gateway.com/1.10.0/operations/observability-metrics/)** The gateway-level `EgressAuditUnattributed` condition reads only the gateway's `defaultProxyRef`, so for a set naming its own `proxyRef` it could miss a set whose egress records cannot be attributed, or flag one whose records can.
Each v2 `RunnerSet` now carries the condition itself, with the gauge `actions_gateway_runnerset_egress_audit_unattributed{namespace,runner_set,reason}`, and the security dashboard plots it.

**[The worker-image registry read presents the worker ServiceAccount's pull secrets.](https://actions-gateway.com/1.10.0/operations/upgrade/#non-breaking-the-worker-image-registry-read-presents-the-worker-serviceaccounts-pull-secrets)** On the air-gapped wiring, which puts the pull Secret on the ServiceAccount, the read behind `RunnerVersionTooOld` failed authentication on every reconcile while the pull itself worked.
It now presents the ServiceAccount's `imagePullSecrets` when the pod template names none.

## Upgrading

**No breaking change, and nothing is removed.** The upgrade is the ordinary one:

1. Apply both charts' CRDs, as every upgrade does: the `actions-gateway-crds-v2` render, and `helm show crds` for the main chart's `PriorityClassAllowlist`.
   Both now mark `v2` as the storage version.
2. `helm upgrade` the release.
   The `agc-tenant-role` ClusterRole gains `get` on `serviceaccounts`, with no `list`, `watch` or write.

The full command and its options are in [Upgrading](https://actions-gateway.com/1.10.0/operations/upgrade/).

**Then, before `v2.0.0`, run the storage sweep.** It is not needed for this release to work, and `v2.0.0`'s CRD apply fails without it.

1. Migrate any `EgressProxy` still on `CiliumFQDN` or `CalicoFQDN` ([the check](https://actions-gateway.com/1.10.0/operations/upgrade/#before-upgrading-to-v200-no-egressproxy-still-names-a-deprecated-fqdn-alias)).
   The sweep refuses to start while one exists.
2. Preview it with `gag-migrate storage-version --context <your-cluster-context>`, which writes nothing.
3. Run it with `--apply`, as a cluster administrator and with the Gateway Manager Controller (GMC) up, since every write passes through its webhooks.
4. Confirm every CRD reads `[v2]` with [the storedVersions check](https://actions-gateway.com/1.10.0/operations/upgrade/#before-upgrading-to-v200-every-actions-gatewaycom-crd-stores-only-v2).

A second run is safe: a CRD already reading `["v2"]` is skipped.

**Check a custom `workerImage`'s runner version.** The move to 2.338.1 changes only the default, so a `RunnerTemplate` pinned to its own image keeps the runner it was built on, and nothing on the cluster names the cause when jobs stop arriving ([what to compare](https://actions-gateway.com/1.10.0/operations/troubleshooting/#worker-image-runner-version)).

**Expect more `orphaned_running` reaps on busy scale-set `RunnerSet`s that cancel queued jobs.** Each `WorkerPodOrphanedRunning` Event and `actions_gateway_worker_pods_reaped_total{reason="orphaned_running"}` increment is an idle worker that used to sit until the lifetime cap.

**A worker evicted for exceeding its own storage limit is no longer re-run.** A re-run gets the same limit and fails the same way, so the AGC now withholds it, on both tiers, and emits an `EvictionRerunWithheld` Event quoting the kubelet's message.
A node-pressure eviction is re-run as before ([what to do](https://actions-gateway.com/1.10.0/operations/upgrade/#a-worker-evicted-for-its-own-storage-limit-is-no-longer-re-run)).

**A run that spans two `RunnerSet`s, or a Classic `RunnerGroup` and a `RunnerSet`, now has a re-run budget in each.** `maxEvictionRetries` used to bound re-runs per run across both tiers.

**Scale-set recovery now reads the run from GitHub before re-running it.** A run the AGC cannot read is not re-run, and counts under `actions_gateway_eviction_rerun_failures_total` as `conclusion_unknown` or `api_error`.

**Rolling back reaches `v1.9.0` and no further**, as the warning above says.

## Deprecations

**Nothing is removed in this release, and no notice is new.** Every removal below was announced in `v1.9.0` or earlier.

**`v2beta1`, `v2alpha1` and `v1alpha1` are removed at `v2.0.0`**, together with the Classic acquisition protocol.
The storage sweep above is what lets that release's CRD apply succeed.
Tenants on `v1alpha1` migrate with `gag-migrate` ([Migrating a tenant to v2](https://actions-gateway.com/1.10.0/operations/migration-v1-to-v2/)).

**The `CiliumFQDN` and `CalicoFQDN` `egressPolicyMode` aliases are removed at `v2.0.0`.** A new write naming one has been rejected since `v1.9.0`.

## Validation

**Pending.** No `v1.10.0` release candidate has been cut.
Beyond the usual legs, the candidate has to show the storage advance on a cluster that has run 1.x: the release gate's new `storage` leg runs the candidate's signed `gag-migrate storage-version` on the dogfood cluster, the project's own GKE cluster whose objects are stored as `v2beta1` today, and fails unless all six CRDs read `["v2"]`.

## Project and tooling

**The release gate gains a `storage` leg**, which applies the chart's `PriorityClassAllowlist` CRD, runs the sweep and reads `storedVersions` (#2076).
Only the first candidate's run rewrites anything, since it leaves the dogfood cluster at `["v2"]`.

**The DinD e2e tenant is now wired to the registry mirrors** (#2115).
Its egress stays open, so a pull that skips the mirrors still succeeds.
That is why the gate's Dragonfly leg stays on Kata, whose tenant can pull images only through the mirrors.

## Security

**No security advisory accompanies this release**, and no reported vulnerability in this project's own code is patched.

**Every binary is rebuilt on Go 1.27.3 and `golang.org/x/net` v0.60.0**, which fix vulnerabilities present in `v1.9.0`'s build:

- CVE-2026-111943, rated HIGH by Trivy: `crypto/x509` can accept a chain through untrusted intermediate certificates, letting a man-in-the-middle through.
  Fixed in Go 1.27.3 (#2111).
- GO-2026-6603, -6611, -6612, -6613 and -6617, in `golang.org/x/net` v0.58.0 and `net/http` in Go 1.27.1, which `govulncheck` reported reachable from the `api` module.
  Fixed by Go 1.27.2 and `golang.org/x/net` v0.60.0 (#2061).

**Two scale-set fixes tighten handling of runner credentials** without patching a reported vulnerability: a worker's JIT-config Secret is now deleted with its pod (#2063), and a replayed job no longer starts on the previous runner's already-used JIT config (#2101).

A pull request that changes code runs `govulncheck` and a Trivy image scan of every built image.
One that changes the chart runs a Polaris posture check of it.

## Verifying this release

We sign every image and both charts.

```bash
make verify-release VERSION=v1.10.0
```

The signed v2 CRD manifest and `SHA256SUMS` ship as release assets with detached cosign bundles, and the publish workflow attests build provenance.
