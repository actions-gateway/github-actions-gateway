    Kubernetes Best-Practices Audit¶

    Archived 2026-07-06. Every finding shipped (A–G) or folded into a test plan (H). Two durable conclusions were promoted out of this audit before archival so they survive as living design/security knowledge: the A6 CreateOrPatch-vs-Server-Side-Apply rationale → 02-architecture.md, and the HTTP/2 Rapid-Reset mitigation → 05-security.md. Residuals: D7 (conversion-webhook scaffolding) tracked as Q74; H2 (live-GitHub rerun-on-eviction e2e) as Q396. This doc is kept for the rationale.

    Findings from a project-wide Kubernetes best-practices audit performed 2026-05-30. Items are grouped by theme.

    Severity legend: 🔴 high · 🟡 medium · 🟢 low.

    Verified-good (not flagged here): GMC/AGC/proxy manager pods all set runAsNonRoot + RO rootfs + drop ALL + seccomp RuntimeDefault; NetworkPolicies are well-split (workload / proxy / AGC / k8s-API with documented kube-proxy DNAT notes); Secret cache DisableFor discipline + WatchesMetadata for credentials; finalizers + owner references for GC; HTTP/2 disabled on metrics/webhook (Rapid Reset CVE); admission webhook rejects privileged containers and cross-namespace SecretRef. These baseline properties are documented durably in 05-security.md §5 (the HTTP/2 Rapid Reset mitigation was promoted there from this audit); the list here is the point-in-time snapshot the audit verified.

    A. Controller correctness 🔴¶

    High-priority controller-runtime patterns whose absence causes silent staleness, lost events, or excessive API load.

    # Sev Finding Location Fix
    A1 ✅ ~~No EventRecorder used anywhere — kubectl describe ag/rg shows no events for credential/quota/eviction failures.~~ Fixed 2026-06-03. GMC already carried a Recorder (added with B2/B3); the AGC RunnerGroup reconciler now gets one too (mgr.GetEventRecorder("runnergroup-controller")), emitting Warning events on token-fetch, agent-provisioning, listener-restart, and deregistration failures, plus a Normal/Warning on genuine Ready transitions (not per-reconcile). runnergroup_controller.go (recordEvent), agc/main.go —
    A2 ✅ ~~GMC swallows IsConflict on Status().Update; in-memory ag is stale across the Update → Status().Update sequence in the deletion path.~~ Fixed 2026-06-03 for the status path: updateStatus/setCredentialUnavailable now return ctrl.Result{Requeue: true} on conflict (re-Get + recompute) instead of silently dropping the write. The deletion path's re-Get-before-second-mutation already landed earlier (reconcileDelete re-fetches before RemoveFinalizer). Covered by TestUpdateStatus_RequeuesOnConflict. actionsgateway_controller.go (updateStatus/setCredentialUnavailable) —
    A3 ✅ ~~RunnerGroup controller has no Owns() / watch on worker Pods or agent Secrets — evicted pods leave ActiveSessions stale until the next Generation bump.~~ Fixed 2026-06-03 (Q63): SetupWithManager now adds .Watches(&corev1.Pod{}, podToRunnerGroup) filtered by workerPodPredicate (label actions-gateway/runner-group present; Create/Delete, plus Update only on a phase change so eviction — which surfaces as Running→Failed, not a delete — still wakes the controller). The watch reuses the shared Pod informer (same one Q64's InformerPodWaiter drives), so it adds no second cache. Pods only, deliberately: the agent-Secret half is not implemented — a Secret watch would establish a Secret informer and cache credential material, violating W3/H-2 (Secrets bypass the cache via DisableFor). Covered by runnergroup_podwatch_internal_test.go (predicate/map-func) + TestAGC_Reconciler_WorkerPodEventTriggersReconcile (envtest end-to-end). runnergroup_controller.go (podToRunnerGroup/workerPodPredicate) —
    A4 ✅ ~~Provisioner polls pod state every 5 s via r.Get instead of watching — 5 s detection latency on a 10 s job, one ticker goroutine per in-flight session.~~ Fixed 2026-06-03 (Q64): completion is now event-driven via InformerPodWaiter, a single ResourceEventHandler on the shared Pod informer that wakes per-session waiter channels on terminal phase / delete. (The original "~200 gets/s API load" framing was inaccurate — the provisioner Client is the cache-backed mgr.GetClient(), so the polled Gets were already cache-served; the real wins are near-zero detection latency and no per-session ticker.) The legacy poll loop is retained only as a fake-client unit-test fallback when no Waiter is wired. Covered by podwaiter_internal_test.go + TestInformerPodWaiter_RealInformer (envtest). podwaiter.go, provisioner.go, agc/main.go —
    A5 ✅ ~~GMC never explicitly sets MaxConcurrentReconciles; comments assert =1 invariant but the default is implicit.~~ Fixed 2026-06-03: SetupWithManager now sets .WithOptions(controller.Options{MaxConcurrentReconciles: 1}) with a comment documenting that raising it requires making the apply* helpers safe under concurrent reconciles first. actionsgateway_controller.go (SetupWithManager) —
    A6 ✅ ~~Eleven apply* helpers do read-modify-write without IsConflict handling.~~ Fixed 2026-06-06 (Q65): the nine per-reconcile helpers (applyServiceAccount/RoleBinding/NetworkPolicy/ResourceQuota/Deployment/Service/PDB/HPA/RunnerGroup) plus applyOwnedSecret now use controllerutil.CreateOrPatch, which re-reads inside the call and writes a minimal merge patch of only the controller-managed fields — conflict-safe (a concurrent writer on unmanaged fields is neither clobbered nor forces an avoidable IsConflict) and no longer clobbers server-assigned fields (verified: applyService preserves ClusterIP). applyRoleBinding keeps the immutable-roleRef delete+recreate upgrade path via a sentinel error. ensureProxyCert now routes through applyOwnedSecret (DRY). The 11th helper, applyNamespacePSA, already uses Server-Side Apply (B2/B3) and is left as-is — already conflict-safe and conflict-reporting. Covered by apply_helpers_test.go (fake-client unit) + apply_nochurn_test.go (envtest: asserts child-resource resourceVersion stability across periodic reconciles, proving the whole-Spec helpers don't churn against a real apiserver that re-defaults + skips no-op writes). Why CreateOrPatch and not Server-Side Apply — see the A6 design note (rationale promoted to 02-architecture.md). actionsgateway_controller.go —
    A7 ✅ ~~Credential-missing path returns RequeueAfter: 30s — less than default backoff after the second failure; inconsistent.~~ Verified 2026-06-03 not a bug: setCredentialUnavailable returns (RequeueAfter: 30s, nil) — a nil error, so there is no error-driven exponential backoff to be "inconsistent" with (backoff only applies to error returns). The 30 s is a deliberate, documented fallback for a missed WatchesMetadata Secret event. No code change. actionsgateway_controller.go (setCredentialUnavailable) —
    A8 ✅ ~~RunnerGroup mergeCondition overwrites LastTransitionTime every reconcile, not only on Status transition.~~ Fixed 2026-06-03: mergeCondition now delegates to meta.SetStatusCondition, so LastTransitionTime advances only on a genuine status transition. Covered by TestReconcile_ConditionTransitionTimeStable. runnergroup_controller.go (mergeCondition) —
    A9 ✅ ~~Finalizer-add path races with deletion — can leak provisioner pool maps across reconciler restart.~~ Fixed 2026-06-03. The DeletionTimestamp.IsZero() guard before the finalizer-add Update was already present; added a cleanupLocalState helper that drops the in-memory multiplexer + pool for a key, and a NotFound branch in Reconcile that calls it so state cannot leak when the object disappears across a restart. Covered by TestReconcile_NotFoundCleansLocalState. runnergroup_controller.go (cleanupLocalState) —

    A6 design note: CreateOrPatch vs Server-Side Apply¶

    Promoted to the durable design layer. The rationale for why the GMC's apply* helpers use controllerutil.CreateOrPatch rather than Server-Side Apply — and why applyNamespacePSA keeps SSA — now lives in 02-architecture.md § Design choice: reconciler writes use CreateOrPatch, not Server-Side Apply. Moved out of this closed audit so it survives archival; the finding row above records the fix that landed.

    B. RBAC & cluster-wide privilege 🔴¶

    Privilege-escalation primitives on a compromised GMC pod.

    # Sev Finding Location Fix
    B1 ✅ ~~Manager ClusterRole grants rbac.authorization.k8s.io: escalate — lets a compromised GMC create Roles at any privilege level.~~ Fixed 2026-06-01 by removing per-tenant Role creation entirely. The AGC permission set ships as a singleton agc-tenant-role ClusterRole (config/agc-tenant-role/agc_tenant_role.yaml); per-tenant RoleBindings reference it. The GMC ClusterRole now holds rolebindings: {create,delete,get,list,patch,update,watch} (no bind/escalate) plus clusterroles: bind with resourceNames: [agc-tenant-role] — the canonical RBAC-native pattern for narrow controllers, and simpler than the originally-proposed ValidatingAdmissionPolicy. A compromised GMC cannot create arbitrary Roles, cannot escalate, and cannot bind its SA into any ClusterRole other than agc-tenant-role. roles: {get,delete} retained for legacy GC of pre-fix per-tenant Roles. actionsgateway_controller.go:10, builder.go (buildAGCRoleBinding), agc_tenant_role.yaml —
    B2 ✅ ~~patch/update on namespaces cluster-wide so the GMC can stamp PSA labels — also lets a compromised pod relabel kube-system PSA to privileged.~~ Fixed (Q56) via the namespace-psa-guard ValidatingAdmissionPolicy (namespace-psa-guard.yaml, applied by make deploy). Scoped to the GMC ServiceAccount, it denies any namespace UPDATE unless the existing namespace carries the trusted marker label actions-gateway.github.com/tenant: "true" (read from oldObject, unforgeable), and denies changes to any label other than the six pod-security.kubernetes.io/* keys or to annotations. RBAC stays cluster-wide (RBAC cannot express a label selector); the VAP is the gate. A blanket privileged-value ban was rejected because securityProfile: privileged is a supported per-tenant opt-in — the marker scope confines the blast radius to managed tenants. Covered by TestGMC_NamespacePSAGuard_EnforcesMarkerAndFieldScope. See q56-namespace-patch-vap.md. namespace-psa-guard.yaml, actionsgateway_controller.go (applyNamespacePSA) —
    B3 ✅ ~~applyNamespacePSA silently overwrites admin edits — no resourceVersion precondition, no event when admin intent loses.~~ Converted 2026-06-01 to Server-Side Apply with field manager actionsgateway-controller-psa; a 409 conflict on the first apply emits a PSALabelsOverridden Warning Event on the ActionsGateway before retrying with ForceOwnership. actionsgateway_controller.go (applyNamespacePSA) —
    B4 ✅ ~~AGC secrets:list returns full Secret bodies (including agent credential material) on every list.~~ Fixed (Q57): agentpool.Pool now enumerates its agent Secrets with a metadata-only PartialObjectMetadataList — bulk lists, run on every reconcile, return only names/labels. The bodies (agent private key, JIT config) are fetched per-name via Get only on the paths that need them (reload, deregistration on scale-down/delete). The metadata list carries a Secret GVK that matches Cache.DisableFor[*corev1.Secret], so it bypasses the cache and starts no Secret informer (preserves W3/H-2). The RBAC list verb is retained (RBAC has no glob resourceNames and agent Secret names are dynamic); the application-level bulk-body exposure is closed and the residual RBAC list capability is the accepted H-2 residual. Covered by TestPool_EnumeratesSecretsAsMetadataOnly. pool.go (listSecretMeta/getSecret) —

    C. Worker / proxy pod security defaults ✅¶

    The operator-created pods (worker pods from AGC, proxy pods from GMC) are the highest-blast-radius surface. PSA baseline (the project default) does not enforce runAsNonRoot or seccomp. Proxy pods (GMC buildProxyDeployment) already ship a full hardened SecurityContext + resources, so the findings below cover worker pods only; all are fixed.

    # Sev Finding Location Fix
    C1 ✅ ~~Worker pods get no default SecurityContext stamped — runAsNonRoot, RO rootfs, capability drop, seccomp absent unless tenant PodTemplate provides them.~~ Fixed: buildPod now gap-fills a profile-aware secure-by-default SecurityContext via applySecurityDefaults. baseline (default) gets pod-level runAsNonRoot + seccomp RuntimeDefault; restricted adds the per-container allowPrivilegeEscalation:false + drop-ALL floor (required for that namespace to admit the pod); privileged opts out entirely. SECURITY_PROFILE is plumbed GMC→AGC. Deviation: readOnlyRootFilesystem is deliberately not defaulted — the runner writes to its work/home dirs and RO-rootfs is not part of the PSA-restricted floor; tenants can opt in. Documented in 05-security.md §5.3. provisioner.go (applySecurityDefaults) —
    C2 ✅ ~~Worker pods have no default resource requests/limits when the tenant template omits them → Best-Effort, evictable, burns the eviction-retry budget fast.~~ Fixed: applyResourceDefaults stamps 500m/1Gi requests+limits (Guaranteed QoS) on every profile when the tenant container declares neither. provisioner.go (applyResourceDefaults) —
    C3 ✅ ~~No seccompProfile: RuntimeDefault on worker pods — blocks any future PSA restricted upgrade.~~ Fixed as part of C1 — RuntimeDefault stamped at pod level on every non-privileged profile, overridable. provisioner.go (applySecurityDefaults) —
    C4 ✅ ~~Worker labels missing app.kubernetes.io/{name,instance,component,part-of} recommended labels.~~ Fixed — buildPod stamps name=actions-runner, instance=<runnerGroup>, component=runner, part-of=actions-gateway. provisioner.go (buildPod) —

    # Sev Finding Location Fix
    D1 ✅ ~~No printer column for observedGeneration / Reason on RunnerGroup — operators can't see generation skew.~~ Fixed 2026-06-06: both CRDs now carry Reason + ObservedGen columns at priority=1 (shown only under kubectl get … -o wide, keeping the default view narrow). runnergroup_types.go, actionsgateway_types.go —
    D2 ✅ ~~RunnerGroupStatus.Conditions missing +listType=map / +listMapKey=type markers — server-side apply treats as atomic list, causing churn.~~ Fixed 2026-06-06: mirrored the markers already on ActionsGatewayStatus.Conditions. runnergroup_types.go —
    D3 ✅ ~~ProxyReadyReplicas, ActiveSessions, ObservedGeneration lack +optional / omitempty — always serialized as 0 on new objects.~~ Fixed 2026-06-06: marked +optional + ,omitempty (matches the k8s DeploymentStatus convention). ProxyReadyReplicas keeps its printer column; a fresh object now shows empty rather than a misleading 0. actionsgateway_types.go —
    D4 ✅ ~~No categories=actions-gateway on either CRD — kubectl get all -l ... and group selectors don't pick up the CRs.~~ Fixed 2026-06-06: categories=actions-gateway added to both CRDs (kubectl get actions-gateway now lists both kinds). both CRDs —
    D5 ✅ ~~No immutability / CEL XValidation on gitHubAppRef.name or securityProfile — silent security downgrades (e.g. restricted → baseline) possible.~~ Fixed 2026-06-06: the GMC validating webhook ranks privileged(0) < baseline(1) < restricted(2) and rejects any downgrade on update unless the object carries actions-gateway.github.com/allow-profile-downgrade: "true"; upgrades/hardening are always allowed. Done as a webhook (not CEL) because the decision reads metadata.annotations; the annotation keeps a deliberate rollback cheap while blocking a silent re-apply downgrade. gitHubAppRef.name deliberately not pinned: changing it is the supported credential-rotation mechanism (03-api-contracts §3.2, TestGMC_TenantProvisioning_CredentialRotation). Covered by TestWebhook_Update*Profile*. actionsgateway_webhook.go (validateSecurityProfileTransition) —
    D6 ✅ ~~RunnerLabels has no MinItems=1 or per-item pattern — empty list silently matches every workflow.~~ Fixed 2026-06-06: MinItems=1 + per-item MaxLength=256 and Pattern=^[^,\s]+$ (no whitespace/commas; comma is the runs-on separator). Covered by TestCRD_RunnerGroup_RunnerLabels_Validation. runnergroup_types.go —
    D7 💤 No conversion-webhook scaffolding — fine today, matters at the first API graduation. Now tracked as Q74 for the v2alpha1→v2beta1 hop (the v2 group graduates first; v1alpha1 is on the sunset track). Build blueprint + the P5 sequencing dependency: q74-v2beta1-conversion-webhook.md. v2 CRDs Stub Hub/Convertible interfaces.

    E. Manifest defaults & HA ✅¶

    The shipped kustomize bases were not HA-by-default and disabled several integrations behind comments. Resolved under Q34; the secure-by-default vs install-prerequisite trade-off for E3/E4 was decided with sign-off (see notes).

    # Sev Finding Location Resolution
    E1 ✅ Manager Deployment replicas: 1, no PDB, no PriorityClass — single node drain halts all GMC reconciliation. Leader election is already wired, so 2 replicas is safe. manager.yaml, pdb.yaml replicas: 2; PDB minAvailable: 1 (pdb.yaml); priorityClassName: system-cluster-critical.
    E2 ✅ No startupProbe on GMC manager; cold cluster cache-sync can race the liveness probe. manager.yaml startupProbe added with failureThreshold: 30 periodSeconds: 5 (≤150s cold-start grace).
    E3 ✅ Metrics endpoint uses controller-runtime self-signed cert; cert-manager [METRICS-WITH-CERTS] block commented out. Prometheus scrape requires insecure_skip_verify. kustomization.yaml Kept opt-in by decision. The /metrics endpoint is already TLS + RBAC-authn gated (metrics_auth_role); cert-manager only upgrades scrape-path verification — defense-in-depth, not a required control. Enabling by default would hard-require cert-manager at install. Documented as an opt-in; becomes a Helm values toggle in Q12.
    E4 ✅ ../prometheus (ServiceMonitor) commented out by default — no out-of-box Prom scraping. kustomization.yaml Kept opt-in by decision. Pure observability wiring, no security dimension; the ServiceMonitor CRD only exists with the Prometheus Operator installed, so default-on would break apply on clusters without it. Documented opt-in; Helm values toggle in Q12.
    E5 ✅ ../network-policy commented out by default — violates the project's secure-by-default principle. kustomization.yaml, allow-webhook-traffic.yaml Enabled by default. Required fixing two scaffold bugs first (the plan's "just uncomment" was unsafe): the manager pod hosts both /metrics and the webhook, so any ingress NP flips it default-deny; the scaffold webhook rule (a) admitted only webhook: enabled namespaces — but the apiserver caller is not a labeled pod, so with failurePolicy: Fail it dropped every admission — and (b) allowed port: 443 while the webhook listens post-DNAT on 9443. Rewrote the rule to allow 9443 from any source (TLS+caBundle authenticated); metrics (:8443) stays restricted to metrics: enabled. Runtime enforcement cluster-only verified on a Calico kind cluster on 2026-06-18 (deny-unlabelled / allow-labelled / admission-still-works); codified as the Manager NetworkPolicy e2e spec.
    E6 ✅ Proxy anti-affinity is PreferredDuringScheduling — 2 replicas can co-locate on one node, defeating the PDB. builder.go Switched to RequiredDuringScheduling. Dev trade-off documented (needs ≥minReplicas schedulable nodes; set proxy.minReplicas=1 on single-node/kind-config-1worker).
    E7 ✅ Proxy + AGC Deployments have no terminationGracePeriodSeconds — CONNECT tunnels truncated on rollout; AGC listener-renewals lose lock on SIGKILL. builder.go terminationGracePeriodSeconds: 60 on both. Both already have signal-driven graceful shutdown (proxy Shutdown, AGC ctrl.SetupSignalHandler).
    E8 ✅ HPA MaxReplicas allows 100 per tenant with no per-cluster guard. quota-pressure-conditions.md Resolved (Q82) via non-blocking two-tier status conditions + gauges, not a webhook: ProxyQuota{Pressure,Exceeded} on the ActionsGateway (GMC) and WorkerQuota{Pressure,Exceeded} on each RunnerGroup (AGC), correlating each pool's footprint against the platform-owned ResourceQuota headroom. Chosen over a webhook (no apply-time rejection of existing tenants, no failure-mode coupling) and over a hard CRD-max lowering. Complements Q59's configured-ceiling admission gate (quota axis vs. ceiling axis).
    E9 ✅ Proxy CPU limit 100m throttles before HPA's 60% util signal trips. builder.go Default proxy CPU limit raised 100m → 500m (operator-overridable via spec.proxy.resources).

    F. Observability & operational ✅¶

    # Sev Finding Location Fix
    F1 ✅ ~~Two logger libraries: slog (application logs) + zap (manager logs) → incompatible JSON schemas in aggregators.~~ A cross-module logging audit found this was worse than stated: slog.SetDefault was never called, so the AGC's busiest files logged through the stdlib TEXT handler — a single pod emitted mixed zap-JSON + text on one stream (ingestion-breaking, so 1.0-gating). Fixed: both controllers call slog.SetDefault(slog.New(logr.ToSlogHandler(ctrl.Log))) after ctrl.SetLogger, named loggers are injected into the provisioner/podwaiter/reconciler/ipranges (dead ActionsGatewayReconciler.Log removed), the worker uses a JSON slog handler, and the proxy reads a LOG_LEVEL source. One JSON shape, one level source per process. agc/main.go, gmc/main.go, worker/main.go, proxy/main.go —
    F2 ✅ ~~No OpenTelemetry tracing — Reconcile → provision → waitForPodCompletion spans would be operationally invaluable.~~ Added an opt-in OTel tracer (cmd/agc/internal/tracing) wired in cmd/agc/main.go: off by default (no exporter unless an OTLP endpoint is configured), enabled + fully tuned via the standard OTEL_* SDK env vars, honours OTEL_SDK_DISABLED, flushes on shutdown. Spans: RunnerGroup.Reconcile and Provisioner.provision (child spans stageJobSecret/countActivePods/createPod/waitForCompletion, with namespace/group/plan/pod/phase/duration attributes). Production wiring of OTEL_* through the GMC-built AGC Deployment is split to a follow-up Queue item (env-vs-spec + OTLP-auth-headers-in-env design). Documented in observability.md + 02-architecture.md. agc/main.go, provisioner.go, runnergroup_controller.go —
    F3 ✅ ~~GMC terminationGracePeriodSeconds: 10 shorter than default 15 s leader lease → ~5 s dead reconcile per rollout.~~ Fixed: LeaderElectionReleaseOnCancel is wired and defaults to true, so the active manager releases the lease on SIGTERM and the standby takes over in ~RetryPeriod (2 s) instead of waiting out LeaseDuration. The 10 s grace period now introduces no reconcile gap (manager.yaml comment updated). main.go, manager.yaml —
    F4 ✅ ~~Leader-election lease/retry/renew flags not exposed for tuning.~~ Fixed: added --leader-elect-lease-duration / --leader-elect-renew-deadline / --leader-elect-retry-period / --leader-elect-release-on-cancel (defaults match controller-runtime), wired into ctrl.Options, with startup validation of the lease > renew > retry×1.2 invariant. Documented in upgrade.md. main.go —
    F5 ✅ ~~AGC hard-codes zap.UseDevMode(true) — pretty colored logs in production.~~ Fixed: both controllers bind zap.Options.BindFlags and default to structured JSON (info level) — correct-by-default, since the AGC Deployment ships with no logging args; --zap-devel opts into console/debug for local dev. agc/main.go, gmc/main.go —
    F6 ✅ ~~AGC has no HealthProbeBindAddress wired and the AGC Deployment carries no liveness/readiness probes — wedged AGC is invisible.~~ Fixed: AGC wires HealthProbeBindAddress: ":8081" + healthz.Ping; the GMC stamps liveness/readiness + a startup probe (180s budget covering the initial-token wait) on the AGC Deployment. main.go, builder.go —
