# so a new unresolvable token still fails. The kind says why it is not a commit
# here, read from the sentence that cites it:
#
#   id        a scale-set plan or job ID, not a commit at all
#   digest    an abbreviated image digest
#   upstream  a commit in another project that the doc compares against
#   orphaned  a commit of this repository that a squash merge or rebase dropped
#             from the branches and tags a CI checkout fetches; it still resolves
#             on GitHub
#
# There is no kind for "this repository's commit that exists nowhere": that is
# the defect the rule exists to catch, so correct the doc instead of adding a
# line. The list is not checked for staleness, because whether an orphaned commit
# resolves depends on what the checkout fetched, so an entry unused on one
# machine can be the one CI needs.
