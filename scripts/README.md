# scripts/

Developer and CI helper scripts, grouped by **blast radius** — which gate consumes the script.
Nothing lives at the top level, so "which gate cares about this?" has to be answered when a script is added rather than defaulting to a catch-all.
Every CI path filter that names a script is a plain prefix glob over one of these directories, and [`ci/check-path-filters.sh`](ci/check-path-filters.sh) holds them to it (Q571).

| Directory | Holds | Gated by |
|---|---|---|
| [`ci/`](#ci--repo-hygiene-gates) | the repo-hygiene meta-gates and the gate runner | `unit-test.yml`, `conflict-markers.yml` |
| [`go/`](#go--go-build-test-lint-vendor) | build, test, lint, vendor, coverage, codegen drift | `unit-test.yml` |
| [`e2e/`](#e2e--live-cluster-tiers) | cluster bring-up, image bake, chart install checks, e2e venue fidelity | `e2e-test.yml`, `e2e-calico.yml`, `autoscaler-drift.yml`, `endpoint-parity.yml` |
| [`fetch/`](#fetch--the-download--retry-family) | the download/retry/pre-pull family every tier calls | every heavy tier |
| [`docs/`](#docs--docs-site-backlog-plan) | docs site, backlog, plan and roadmap tooling | `doc-links.yml`, `status-lint.yml`, `plan-hygiene.yml` |
| [`security/`](#security--vulnerability-and-posture-scans) | govulncheck, trivy, polaris | `security-scan.yml` |
| [`manifest/`](#manifest--chart-and-manifest-generation) | chart CRD/RBAC/webhook sync and install-artifact validation | `manifest-validate.yml` |
| [`release/`](#release--publish-sign-report) | publish, sign, notices, release decision support | `publish.yml`, `license-notices.yml` |
| [`agent/`](#agent--claude-code-hooks-and-the-local-throttle) | Claude Code hooks, the local throttle and its instruments | never CI-gating |
| [`dev/`](#dev--developer-only) | post-clone setup, live probes, cloud spikes | never CI-gating |
| [`dogfood/`](#dogfood--gke-dogfood-tenant-tooling) | GKE dogfood tenant tooling | `dogfood-*.yml` |
| [`lib/`](#lib--sourced-helpers-no-entry-points) | sourced helpers, no entry points | every group |
| [`updatecli/`](#updatecli--version-pin-resolvers) | version-pin resolvers for `updatecli.yml` | `updatecli.yml` |

A `*-test.sh` sits beside its subject, so it inherits its subject's gate: [`docs/source-links-hook-test.sh`](docs/source-links-hook-test.sh) belongs to the docs site and cannot trigger e2e.
It is usually named in its subject's row rather than given one of its own, since what it asserts is a property of the subject.

Every script here must appear somewhere on this page, in its own row or named in the row of the script it belongs to, and [`docs/check-script-docs.sh`](docs/check-script-docs.sh) fails when one does not (Q688).
An entry earns its place by saying which gate runs the script and what would go wrong without it; repeating the filename tells a reader nothing `ls` would not.

All scripts follow the [repo bash conventions](../docs/development/bash-style.md): `set -euo pipefail`, `local` for function variables, `[[ ]]` conditionals, quoted expansions, `trap` cleanup for background processes — see the doc for the full list.
Whatever more than one gate shares is sourced from [`lib/`](#lib--sourced-helpers-no-entry-points).
Every script here is linted by `make shellcheck` ([ci/shellcheck-scripts.sh](ci/shellcheck-scripts.sh)) as soon as the file exists — tracked or not — so opting a scratch script out means gitignoring it (write it under the gitignored `tmp/` at the repo root), not merely leaving it untracked.
The same holds for the doc-link, conflict-marker and plan-ref gates, which share that file selection via `git_candidates` (Q619).

The root `Makefile` keeps recipes as thin target→script wiring so the logic is shellcheck-covered; parameters are env-overridable and documented in each script's header.

A gate whose logic outgrows shell moves its core to Go in [`devtools/`](../devtools/), the first-party tooling module, keeping the script here as the entry point so the gate map stays in one place.
Packages there mirror these directories — `devtools/ci/pathfilters/` backs [`ci/check-path-filters.sh`](ci/check-path-filters.sh).
The module is deliberately outside `go.work`; the reasoning and the wiring a new one needs are in [go-workspaces.md](../docs/development/go-workspaces.md#first-party-go-tooling-stays-outside-the-workspace).

## `ci/` — repo-hygiene gates

| Script | Purpose |
|---|---|
| [check-path-filters.sh](ci/check-path-filters.sh) | Reconcile CI's hand-maintained `dorny/paths-filter` lists with `go.work` and with the paths they name — a filter missing a module makes its gate report green by *skipping* (Q400/Q429). Fails on an uncovered workspace module, an unclassified filter, a pattern whose path is gone, two lanes over one reusable workflow disagreeing about scripts/ (Q571), or a `**` placed where picomatch stops expanding it (Q659); assertions covered by `check-path-filters-test.sh` under `make scripts-test`. Backs `make path-filters-check` and the CI `path-filters` job. |
| [check-conflict-markers.sh](ci/check-conflict-markers.sh) | Fail on leftover merge-conflict marker lines in any present, non-vendored file — tracked or untracked-and-not-gitignored (Q379 — a stray marker from a rebase resolution once merged to main). Backs `make conflict-markers-check` and the CI `conflict-markers` workflow. The four marker forms, the near-misses that must stay legal (setext underlines, mid-line mentions, six- and eight-character runs) and the gitignore opt-out are asserted by `check-conflict-markers-test.sh` under `make scripts-test`. |
| [shellcheck-scripts.sh](ci/shellcheck-scripts.sh) | Shellcheck every present `scripts/**/*.sh` — tracked or untracked-and-not-gitignored, recursive (file selection asserted by `shellcheck-scripts-test.sh` under `make scripts-test`). Backs `make shellcheck`. |
| [check-errexit-prologue.sh](ci/check-errexit-prologue.sh) | Require the full errexit prologue, `set -euo pipefail` followed by `shopt -s inherit_errexit`, in every executable script here (Q733). `set -e` does not reach inside a command substitution, so `x="$(f)"` runs `f` past its own failure and takes the status of its *last* command: a gate that checked nothing, reporting success. Measured on `go-lint.sh`, where a fault injected into `scoped_module_dirs` left it announcing a full sweep, linting 1 module of 11, and exiting 0. Sourced `lib/` files are exempt, since they run under the caller's shell options. shellcheck has no check for this, and its SC2155 covers only the `local x="$(f)"` half. Backs `make errexit-prologue-check` and the CI step of the same name; assertions in `check-errexit-prologue-test.sh` under `make scripts-test`. |
| [check-script-modes.sh](ci/check-script-modes.sh) | Fail when a script here carries the wrong executable bit (Q1013): a file under a `lib/` directory is sourced and must not be executable, every other `.sh` is run as a command and must be. The same `*/lib/*` split `check-errexit-prologue.sh` uses, for the same reason. Nothing held the tree to it and six entrypoints had drifted to 644 (`e2e-setup.sh`, `e2e-start.sh`, `e2e-stop.sh`, `start.sh`, `stop.sh`, `runner-build.sh`), every one invoked bare by [release.md](../docs/operations/release.md), where the bare form exits 126 before reading an argument. Mode is read from the index for a tracked file, since the index is what a clone gets and an unstaged `chmod` is the drift this catches. Selection is `git_candidates` + `select_present_files` from `lib/common.sh`, not a local `git ls-files`: without `core.quotePath=false` a non-ASCII path is C-quoted, matches no file, and is dropped by the reader while still counting toward the total reported. Backs `make script-modes-check`. |
| [check-script-modes-test.sh](ci/check-script-modes-test.sh) | Unit tests for `check-script-modes.sh`: both failing directions in throwaway repos, the index-versus-filesystem split each way, an untracked script caught by its own first run, a non-ASCII path checked rather than silently skipped, an empty selection exiting 2 rather than passing, and a reconciliation against this repo's real `scripts/` tree. Runs under `make scripts-test`. |
| [actionlint-workflows.sh](ci/actionlint-workflows.sh) | actionlint every workflow under `.github/workflows/` — schema, `uses:` refs, expressions, and (via shellcheck) the inline `run:` blocks. Three docs credited actionlint with this while no job ran it, so a workflow-only PR shipped unlinted (Q579). Fails when shellcheck is missing rather than letting actionlint silently skip the `run:` half. Backs `make actionlint` and the CI `actionlint` job. |
| [check-uses-pinned.sh](ci/check-uses-pinned.sh) | Fail when a `uses:` reference is pinned to anything a third party can move (Q644). actionlint asserts a ref is present and well formed, never that it is a SHA (measured against v1.7.12 it accepts `@v4` and `@main` at exit 0), and a tag-pinned action runs against the job token. Checks every workflow and composite action in the tree, wider than actionlint's root-only scope; requires a 40-hex SHA plus the `# vX.Y.Z` comment Dependabot bumps, exempts local `./…` refs, and needs an `@sha256:` digest on `docker://`. Fails closed on an unparseable file and on an empty extraction. Checking is [devtools/ci/usespin](../devtools/ci/usespin) over a real YAML parser, since `uses:` also appears in comments and `run:` blocks. Backs `make uses-pinned-check` and the CI `uses-pinned` job; assertions in `check-uses-pinned-test.sh` under `make scripts-test`. |
| [check-cosign-pin.sh](ci/check-cosign-pin.sh) | Hold the Makefile's `COSIGN_VERSION` to the `cosign-release` [publish.yml](../.github/workflows/publish.yml) signs with (Q903). Two hand-kept pins name the same binary from opposite ends of the release: the workflow installs cosign to *sign*, the Makefile downloads it to *verify* (`make verify-release`, and the dogfood CRD smoke). Only a comment beside each asked them to agree, so a one-sided bump left the local check running a verifier the publish job never signed with. Also fails when a `sigstore/cosign-installer` step loses its `cosign-release` input, which floats the signer to the latest release: that is the same drift arriving by omission, and comparing only the pins that remain would pass it. Refuses with rc 2 rather than reporting green whenever a pin it compares is absent, since a pattern that stopped matching would otherwise call every tree in step. Backs `make cosign-pin-check` and the CI `cosign-pin` job; both directions asserted by `check-cosign-pin-test.sh` under `make scripts-test`. |
| [check-publish-digest.sh](ci/check-publish-digest.sh) | Hold [publish.yml](../.github/workflows/publish.yml)'s retried image build to the one digest it actually published (Q899). The release build is `no-cache: true`, so a second attempt rebuilds every layer and its index digest is not the first attempt's. Four steps bind the release to that digest: the signed SLSA provenance subject, the per-arch SBOM resolution, the cosign sign/attest, and the run-summary pin operators copy into chart values. A signature over the superseded index would verify cryptographically against an image the tag no longer serves, so the attempts feed one resolver step and every consumer reads that. Asserts the retry is gated on the first attempt's outcome and only the first attempt is `continue-on-error`, that the two attempts' `with:` blocks are identical (they are hand-kept copies, and a `no-cache: true` dropped from one side alone would let a cached retry serve PR-populated layers into a signed release), and that no step outside the resolver reads an attempt's digest. Refuses with rc 2 rather than reporting green whenever a subject it compares is absent. Publish runs only on a `v*` tag, so no PR ever executes that job and this static gate is the only reading available before a release rather than during one. Backs `make publish-digest-check` and the CI `publish-digest` job; every rule asserted in both directions by `check-publish-digest-test.sh` under `make scripts-test`. |
| [check-dep-advisory.sh](ci/check-dep-advisory.sh) | Print a one-line reminder when a change touches Go dependency files, and stay silent otherwise — `make check` deliberately omits the three dependency-drift gates, so this is the nudge to run `make vendor-sync`. Advisory: never fails the build. The classification is made from git state alone, and `check-dep-advisory-test.sh` pins it in hermetic throwaway repos under `make scripts-test`, so no assumption about the caller's tree leaks in. |
| [check-tools.sh](ci/check-tools.sh) | Verify the CLI tools the project needs (required / e2e / extended tiers) are installed, on PATH, and at or above any version floor the registry declares; for each miss, print a per-OS install command or the exact dir to add to PATH. Cross-platform (brew/apt/url). Backs `make doctor`. Exits nonzero if a required tool is missing or too old. bash carries the one floor today, 4.4 for `inherit_errexit` (Q751), and the floor is checked above this script's own prologue so it can still report on the bash 3.2 macOS ships. Assertions in `check-tools-test.sh` under `make scripts-test`. |
| [dependabot-rebase-stale.sh](ci/dependabot-rebase-stale.sh) | Rebase a conflicted Dependabot Go-module PR by **replaying** its version bumps on current `main` (`go get` per bump, then `make vendor-sync`) and force-pushing, never by merging: merging can silently downgrade a module. Backs the [`dependabot-rebase-stale`](../.github/workflows/dependabot-rebase-stale.yml) workflow (Q427); `--dry-run`, `--list`, and `--bumps` for local use. Bump extraction decides the version each module is replayed at, and so is the only place a wrong answer could downgrade one; `dependabot-rebase-stale-test.sh` asserts it under `make scripts-test`, while the impure half needs a live PR and is exercised by the workflow's own dry run. |
| [gate-list.sh](ci/gate-list.sh) | Render (`--list`, `--list-suites`) or reconcile (`--check`) the two lists `make check` derives from, the gates it runs and the `scripts/` suites `scripts-test` fans out over, from the `CHECK_FAST_GATES`/`CHECK_HEAVY_GATES`/`SCRIPTS_TESTS` variables make passes in. Both lists used to live in hand-kept copies that every gate- or suite-adding PR edited and conflicted on, and that drifted anyway (Q649, Q671). Fails on a gate with no `.PHONY` or `##` line, a recipe phase outside `CHECK_HEAVY_GATES`, a gate hand-wired into the fan-out, a target declared `.PHONY` twice, a `STATUS_GATES` member outside `CHECK_FAST_GATES`, a fast gate outside `STATUS_GATES` whose script selects `docs/STATUS.md` or whose file set is neither derivable nor declared `# status-scope: none` (Q749), a fast gate outside `DOCS_GATES` that hardcodes a page under `docs/` as its subject rather than handing git a pathspec, the shape every page-scoped gate is written in, which left seven of them invisible (Q930); that is the one derivation a declaration can silence, so a real pathspec still fails outright, a gate run only by workflows the merge queue never evaluates, so the candidate merge is never held to it unless it declares `# merge-queue-scope: none` (Q942), a `*-test.sh` on disk that `SCRIPTS_TESTS` omits (so `make scripts-test` reports green without running it) or a `SCRIPTS_TESTS` entry with no file, or a testing.md that stopped citing `make list-gates`/`make list-script-tests`. Backs `make list-gates`, `make list-script-tests`, `make gate-lists-check` and the CI `gate-lists` job; assertions in `gate-list-test.sh` under `make scripts-test`. |
| [git-merge-gate-lists.sh](ci/git-merge-gate-lists.sh) | A git merge driver for `mk/gate-lists.mk`, which holds the gate and suite lists `make check` derives from, resolving them entry by entry. `gate-list.sh --check` requires `SCRIPTS_TESTS` to match the `*-test.sh` files on disk, so a PR shipping a gated script must append to a backslash-continued list here, and two PRs doing that collide on adjacent lines. Only the variables the driver names are treated specially: each is lifted out behind a sentinel, the rest of the file is merged by git alone, and a conflict anywhere else in that file gets ordinary markers. That list and the assignments in `mk/gate-lists.mk` must name the same set, in both directions -- a name the file no longer assigns makes the driver refuse every merge of it, and a list the file gained that the driver does not name still collides by line position (Q915); `--managed-vars` reports the array so the suite reconciles the value the driver runs on. A list neither side touched is reused byte for byte and a list with only additions keeps its existing lines, so a merge does not rewrap 30 lines nobody changed. The rebuilt block is read back and required to round-trip to the entry set it was given; `gate-lists-check` is the backstop underneath that. It makes the local rebase trivial; it cannot stop a merge-queue eviction, because GitHub performs the queue's merge itself and never runs a per-clone driver. Installed by the one-time `make merge-driver`. Exercised by `git-merge-gate-lists-test.sh` under `make scripts-test`. |
| [git-merge-gate-lists-test.sh](ci/git-merge-gate-lists-test.sh) | Tests for the gate-list driver. Every resolution asserts two things, the merged entry set and that `make` still parses the result, because a correct-looking list with a dropped backslash breaks every build downstream and a set comparison alone would not see it; the variable is read back through make's own parser via a wrapper makefile, since the `make` shipped with macOS has no `--eval`. Also asserts the zero-churn property, after an earlier revision rewrapped a variable neither side had touched, and the refusals: a conflict outside the lists, and a side missing a managed variable. Every fixture is derived from `mk/gate-lists.mk` rather than restated, and the two lists are reconciled both ways, because a fixture naming its own variables asserts the shape it was written against: the driver spent #1603 onward refusing every merge of that file while this suite passed, its fixture still declaring the variable the file had dropped (Q915). Ends with a real `git rebase` through `.gitattributes`, on two branches each appending to the real file. Runs under `make scripts-test`. |
| [check-template-library.sh](ci/check-template-library.sh) | Reconcile the shipped runner template library (`deploy/templates/`) with the set CI exercises, both directions (Q554). A golden template is an implicit validation claim, so an entry no dogfood e2e overlay consumes fails the gate unless it is declared inert in the script with its reason, and an overlay that stops consuming the library fails it too. Also holds every patch against a `ClusterRunnerTemplate` to JSON 6902, because kustomize has no CRD schema and a strategic merge there silently replaces lists wholesale at exit 0 (measured, kustomize v5.8.1); and, when kubectl is on PATH, renders each overlay and fails on a load-bearing line its base declares and the render lost. Backs `make template-library-check` and the CI step of the same name; assertions in `check-template-library-test.sh` under `make scripts-test`. |
| [run-parallel.sh](ci/run-parallel.sh) | Run multiple commands in parallel with labeled, real-time output. Backs the fan-out in `make check`, `make status-gates` and `make scripts-test`. Every pid is waited, so one command failing never abandons its siblings, and each failure is summarised with its exit status. That status tells an assertion failure apart from a command the kernel killed (128+n; 137 is the OOM killer's signature) or one that was never found (127), a distinction five flakes in the Q703 family had to guess at. That status also sets the verdict: a signal death is summarised under `KILLED` rather than `FAILED` and exits with its own `128+n`, because it reached no verdict and is not a defect to go and read (Q837). Under `RUN_PARALLEL_GIT_TRACE_DIR` each child also runs with its own `GIT_TRACE`, named for its label so a finding stays attributable to one suite; that is what lets [check-fixture-maintenance.sh](ci/check-fixture-maintenance.sh) measure the tier off a run that already happens (Q921). The directory must be absolute: git 2.55.0 answers a relative `GIT_TRACE` with `unknown trace value` and traces to stderr, which this runner would label and merge into the gate's output. The variable reaches one level only, while `GIT_TRACE` itself cascades, so every git a child runs at any depth lands in that child's one file; letting the directory through would have a nested fan-out re-point the trace at its own labels, filing a suite's git under a name that is not a suite and never writing the suite's file at all. Assertions in `run-parallel-test.sh` under `make scripts-test`, the trace wiring in both directions. |
| [check-fixture-maintenance.sh](ci/check-fixture-maintenance.sh) | Hold every `make scripts-test` suite to the invariant that a throwaway fixture repo never spawns background git (Q820, Q921). Git runs `git maintenance run --auto --detach` from commit, merge, fetch, am and pull unless `maintenance.auto false` is set on the repo; detached, it outlives the command that started it and races the next one writing the same fixture, and once the fixture crosses `gc.auto` its prune removes an object fanout directory between the next command's `mkdir` and the `open` under it, giving `unable to create temporary file`, exit 128, green on rerun. Reads the per-suite `GIT_TRACE` files [run-parallel.sh](ci/run-parallel.sh) writes under `RUN_PARALLEL_GIT_TRACE_DIR`, so the tier is measured off the run that already happens rather than a second pass over `make check`'s slowest fast gate. The assertion is on behaviour, never on the config key: a suite that sets the key and greps for the key has tested its own setup, and this reaches the one suite no text query can: [pr-requeue-eligible-test.sh](agent/pr-requeue-eligible-test.sh) drives git from embedded Python through an args list. Refuses with rc 2 rather than reporting a clean tier on a missing directory, on a directory holding no traces, and on traces recording no git at all, since a loop over nothing counts zero spawns and exits 0, which is what this gate looks like once its wiring comes undone. Runs at the end of `make scripts-test`; both directions and all three refusals asserted by `check-fixture-maintenance-test.sh`. |
| [check-fixture-maintenance-test.sh](ci/check-fixture-maintenance-test.sh) | Unit tests for `check-fixture-maintenance.sh`, 18 checks. The fixtures are not canned strings: each is a real commit under a real `GIT_TRACE`, one repo with `maintenance.auto` unset and one with it false, and the suite asserts those two differ before anything else runs; without that, every red case below it would pass for the wrong reason. Pinned in both directions, because a gate that has stopped matching fails exactly as silently as one that matches everything: a spawning suite must be named and counted, a clean sibling must not be, and the count must be spawns rather than trace lines (each spawn writes three). The three refusals are asserted as rc 2, not as a pass. Runs under `make scripts-test`. |
| [check-tool-pins.sh](ci/check-tool-pins.sh) | Assert every `.build/` tool rule declares the file carrying its version pin as a prerequisite (Q904). Q842 set the pattern and a Makefile comment stated it, but nothing held a rule to it: without such a prerequisite make treats an existing binary as up to date forever, so a bump serves the old tool against the new target. That is how a stale mdreflow met an unknown `--explain` flag and then reported four false reflow failures on a clean tree, and how cosign shipped with no prerequisite at all and served a stale verifier until Q857. Not [check-cosign-pin.sh](ci/check-cosign-pin.sh), which holds two version *strings* to each other across two files and never asks whether a rule fires on a bump. Rules come from `make -pnq`, the resolved database, so variable expansion, backslash continuations and the eight-target rule the Go tools share are make's answer rather than a regexp's. A tool binary is a `.build/` target that is not a prerequisite of another one, which is what separates the tools from the pin sentinels. Fails on a rule with no normal prerequisite, on one carrying only order-only prerequisites (those never make a target out of date, so the defect survives behind an apparent fix), and on a prerequisite that is neither tracked nor version-keyed. Version-keyed is measured rather than pattern-matched: the database is read again with every makefile `*_VERSION` variable overridden, and the path must move, so a `.build/x.stamp` touched once and never again fails. Refuses with rc 2 when the read yields no `.build/` rule, since a database it could not parse would otherwise report every rule pinned. The database's shape is version-dependent in one place: a target-specific variable prints as a comment under the GNU make 3.81 macOS ships and in rule position under the 4.x CI runs, where reading it naively makes `TOOL_PKG`, `:=` and a package path three prerequisites. Assignment lines are dropped, and `--database PATH --print-rules` is the parser seam the suite drives a captured 4.x dump through, since no one machine runs both. Backs `make tool-pin-check`, in `make check` and the CI `shellcheck` job; both directions asserted by `check-tool-pins-test.sh` under `make scripts-test`. |
| [check-vendored-skills.sh](ci/check-vendored-skills.sh) | Hold each file vendored from `karlkfi/claude-skills` to the digest [vendored-skills.tsv](ci/vendored-skills.tsv) declares for it (Q890). Q889 phase 1 took four files byte-identical so an upstream fix would land as a clean overwrite, and nothing held them there. Measured 2026-08-21: all four matched an upstream commit exactly at vendor time and none had been edited here since, so the drift was one-way and unseen either way, because nothing named these files as vendored at all. The gate asserts the half a local read can: a vendored file still hashes to what its row declares, so forking one moves the digest in the same diff. `--report` separates an unmodified vendor from a declared fork; `--update` is how a fork is declared. It cannot ask whether upstream has moved, because that repo is private and a gate whose oracle is the network fails when a third party sneezes; nothing derives the set either, so a fifth adopted file needs a row by hand. Backs `make vendored-skills-check`, in `make check` and the CI `unit-test` shellcheck job. |
| [check-vendored-skills-test.sh](ci/check-vendored-skills-test.sh) | Unit tests for `check-vendored-skills.sh`, 16 checks, paired in both directions and each given its own control. The gate is a loop over a manifest, so its failure mode is silence: a comment-only manifest, an absent one, and a row missing a field each refuse with rc 2 rather than reporting every file intact having compared nothing. An edit with no digest change fails and the finding names the file; a declared file that has moved away fails rather than being skipped. `--update` must move `local_sha256` and leave `vendored_sha256` alone, or a re-stamp would erase what was adopted. The last two run the gate over this repo's own manifest and assert the count, since the fixtures prove the checker works and only that proves it is pointed at the real vendored set. Runs under `make scripts-test`. |
| [vendored-skills.tsv](ci/vendored-skills.tsv) | What `check-vendored-skills.sh` reads: one row per file vendored from `karlkfi/claude-skills`, carrying its upstream path, the upstream commit it was taken from, what that file hashed to there, and what it must hash to here. The two digests answer different questions, so a re-vendor can diff upstream forward from a known point while the gate asserts only the local one. Equal digests mean an unmodified vendor; unequal means a declared local edit. |


## `go/` — Go build, test, lint, vendor

| Script | Purpose |
|---|---|
| [go-test.sh](go/go-test.sh) | Workspace unit tests in one multi-module `go test` invocation; `--race` for the race-detector gate. Backs `make test` / `make test-race`. `RUN='TestName'` narrows to matching tests and **fails** when the regex selects none, since `go test -run` reports a green suite on a miss (Q680); assertions in `go-test-run-filter-test.sh` under `make scripts-test`. Streams `go test -json` through `devtools/gotest/progress` for a heartbeat naming what is still running (Q618) — `TEST_PROGRESS_INTERVAL=0` or `V=1` runs plain `go test` instead. A second forced `-count=1` pass covers the packages go's test cache cannot key a result for, read from `check-test-cache-inputs.sh --uncached-packages` so the two cannot drift (Q936). ## `fetch/` — the download / retry family

Three entry points by what they retry — an arbitrary command, a `curl`, a `docker pull` — plus the two pre-pull cachers built on the last.
Every heavy tier calls at least one, which is why `scripts/fetch/**` appears in the e2e, security-scan, manifest-validate and autoscaler-drift filters.

| Script | Purpose |
|---|---|
| [retry.sh](fetch/retry.sh) | Run an arbitrary command with bounded retries and linear backoff. Used by the publish workflow to absorb transient GHCR errors on idempotent push/sign steps, and by `trivy-scan.sh` to absorb a base-image pull denial during the image build (Q863). |
| [download-verified.sh](fetch/download-verified.sh) | `<url> <sha256> <output-path>`: download a pinned release asset, retrying any nonzero `curl` exit on exponential jittered backoff (`DOWNLOAD_RETRIES`/`DOWNLOAD_RETRY_DELAY`/`DOWNLOAD_RETRY_MAX_DELAY` env, default 5 retries, 5s doubling to a 60s cap, 135-202s), and write the output path only once the bytes match the digest. Used by every pinned-binary install: kind, shellcheck, kubeconform, polaris, syft, cosign. `download-verified-test.sh` holds both halves to that contract under `make scripts-test` (Q433, Q829): a mismatched digest leaves nothing at the output path and is not retried, a malformed or absent digest is rejected outright, no flag or environment variable skips verification, and, off a stubbed `curl`/`sleep` so nothing waits, a `curl: (22)` is retried rather than fatal and the schedule doubles, jitters and caps. |
| [pull-image-with-retry.sh](fetch/pull-image-with-retry.sh) | `docker pull <image-ref>` with bounded retries and exponential, jittered backoff (`PULL_RETRY_ATTEMPTS`/`PULL_RETRY_DELAY`/`PULL_RETRY_MAX_DELAY` env, default 6 attempts, 5s doubling to a 60s cap). Absorbs transient registry timeouts/429s in-step; the jitter keeps concurrent CI callers from retrying in lockstep (Q460). Used by the e2e, security-scan and publish workflows to pre-pull the buildkit builder and mirror the curl/Vault test images. The schedule *is* the fix, so `pull-image-with-retry-test.sh` asserts it under `make scripts-test`: exponential growth, jitter on every delay, and a cap, read off the arguments passed to a stubbed `sleep`, so none of it waits. Also the registry-mirror chokepoint (Q408 Phase 3): with `REGISTRY_MIRRORS` set it pulls from the mirror and re-tags to the caller's own ref, so every downstream `docker tag`/`docker save`/`kind load` is unaffected. The same suite asserts that, since a rewrite that left the image under the mirror's name would pass the pull and fail a `kind load` several steps later. |
| [prepull-image-cached.sh](fetch/prepull-image-cached.sh) | `<image-ref> <cache-dir> <local-tag>`: pre-pull one pinned image into the runner's Docker daemon (retried) and cache it as a tarball, exposing it under a local-only tag; a warm cache `docker load`s the tar without touching the registry. The single-image sibling of prepull-manifest-images.sh — the local tag exists because `docker load` cannot restore a manifest digest, so a digest-pinned ref would never resolve from the cache. Used by the security-scan trivy job's buildkit pre-pull. |
| [prepull-manifest-images.sh](fetch/prepull-manifest-images.sh) | `<name> <manifest-url> <cache-dir>`: extract the image refs a pinned Kubernetes manifest names, pre-pull them into the runner's Docker daemon (retried) and cache as a tarball + `images.txt`; on a warm cache `docker load`s the tar without touching the network. The shared pre-pull half of the e2e Calico/cert-manager/metrics-server caching pattern. |

## `dogfood/` — GKE dogfood tenant tooling

These drive a live, billable GKE cluster, so no gate ever executes one: they are run by hand or by the release gate.
What CI does run is their assertions: thirteen `*-test.sh` here run under `make scripts-test`, and so under `make check`, against stubbed `gcloud`/`kubectl`/`gh`.
That is deliberate, because every failure mode below is silent and costs money in one direction or the other.
The only CI reference to the group's files is `dockerfile-lint.yml`, over [runner/Dockerfile](dogfood/runner/Dockerfile).

The shared helpers sit in a nested [`lib/`](dogfood/lib/) rather than the tree-wide [`lib/`](#lib--sourced-helpers-no-entry-points) because every one of them reads or writes dogfood cluster state.
The five tests covering a `lib/` helper sit at the group root rather than beside their subject, since a sourced helper's behaviour is only reachable through a caller.

| [e2e-start.sh](dogfood/e2e-start.sh) | Spin up the on-demand e2e tenant by applying the selected worker-isolation overlay (Q231): its ~500m-CPU AGC is not kept always-on, since it competes with the CI AGC, the GMC and Athens on the system pool. Bring-up asserted by `e2e-start-test.sh`, including that the dind lane's own policy is left alone. |
| [e2e-mirror-hits.sh](dogfood/e2e-mirror-hits.sh) | Grade whether a finished Kata e2e run's image pulls actually rode the mirrors (Q408 Phase 3) by counting content requests in each instance's access log, which no unmirrored pull can write into. The reading exists because Phase 3 runs with open egress still in place: a client that ignored its wiring reaches its upstream and the suite is green either way. Read-only, and run before `e2e-stop.sh` scales the mirrors to zero. The kubelet probes `/v2/` on two probes per instance, so a bare request count is in the thousands on an instance nothing pulled through. A hit is a request *below* `/v2/` that was also served, and an instance answering 500 to everything (the §3.6 fsGroup shape) fails on the second half. It also discounts the Phase 2 battery's own probes, which write into the same log: measured on the dogfood cluster, `e2e-mirror-validate.sh` alone leaves 2 content requests and 1 served on every instance, so a session running it first would grade green having measured nothing. The probe is told apart by its user agent, and the exclusion fails safe, since an unrecognised client agent under-counts into a FAIL. `e2e-mirror-hits-test.sh` asserts the parser against a verbatim `registry:3.1.1` capture, the probe exclusion in both directions, and the grader against a missing instance, which reports nothing and must not shrink the battery. |
| [e2e-mirror-clients.sh](dogfood/e2e-mirror-clients.sh) | Who actually reached the registry mirrors in a window, and does every one of them carry `actions-gateway/component=workload` (Q1026)? The reading taken *before* the shared topology's ingress peer is narrowed to that label, because the narrowing is fail-closed and total: a client that does not carry it loses the path entirely. The client address lives in the `catalog-deny` container's log rather than the registry's, since the proxy is what connects to the registry and its access log therefore records loopback for everything (Q1022). Each address is resolved against every pod IP and every node address rather than pattern-matched, so the kubelet's probes are exempt because they resolved to a node; where BOTH match, since a hostNetwork pod's `podIP` is its node's address, the collision is reported rather than settled by lookup order, because neither answer is right and whichever way it were ordered the wrong one would be silent. Every declared instance is graded BY NAME on whether its log was readable, keyed on `kubectl logs`' exit status rather than on an empty address list: an instance read that saw nobody is a legitimate idle mirror, one that could not be read is a hole, and an earlier version pooled all five through one `sort -u` so a four-of-five read was byte-identical to a five-of-five one. An address that resolves to nothing is a **refusal**, not a pass: a worker pod is deleted at the end of its job, so that is the ordinary case after a finished window and grading it green would report safety over exactly the client that was not checked. A window in which nothing connected refuses for the same reason. |
| [e2e-mirror-clients-test.sh](dogfood/e2e-mirror-clients-test.sh) | Unit tests for `e2e-mirror-clients.sh`, 30 checks over the address parse, the collector and the verdict. A partial read must not grade as a whole one, which is the defect review caught and which the pooled collector made invisible; the idle-but-readable fleet is asserted to PASS, which is what stops the per-instance guard being keyed on an empty address list and refusing any window that did not touch all five mirrors. Both ways the reading can lie are asserted, and they are opposite: an unresolved or empty window must refuse rather than pass, and an unlabelled client must outrank a refusal sitting beside it so one deleted pod cannot bury the finding. The proxy's own startup NOTICE lines share the log stream and must not enter the client set: a parser taking the first field of every line would manufacture a refusal rather than find one. Runs under `make scripts-test`. |
| [e2e-mirror-validate.sh](dogfood/e2e-mirror-validate.sh) | Grade the in-cluster registry pull-through cache `e2e-start.sh` applied: every declared instance Available, `/v2/` and a real upstream manifest served, uploads refused, and the bundled image's `:5001` debug listener unbound (Q408 Phase 2). A script rather than a curl session because a booked dogfood session is the scarce resource and Phases 3 and 4 re-run the same battery. `/v2/` alone would grade a broken mirror green: one whose storage root is unwritable answers 200 there and 500 for every pull, so the manifest fetch is the check that discriminates. | [e2e-run-watch.sh](dogfood/e2e-run-watch.sh) | Watch a dispatched e2e run and relay its spec-level heartbeat locally (Q615), in place of `gh run watch`, which blocks and so leaves the operator with job-level status while the spec detail they want stays in a log. Relay helpers asserted by `e2e-run-watch-test.sh`. |
| [validate-release.sh](dogfood/validate-release.sh) | The one-command pre-GA validation gate for a release candidate: deploy, route CI, on-demand e2e, dispatch the e2e matrix on GAG runners, sizing-profile assertion, signed v2 CRD artifact smoke, teardown. | [release-status.sh](dogfood/release-status.sh) | Render where the release-validation gate is as one JSON object (Q616). Nulls mean "not yet known", never zero. Rendering asserted by `release-status-test.sh`: a failure attributed to the wrong phase sends the diagnosis in the wrong direction. |
| [record-validated-candidate.sh](dogfood/record-validated-candidate.sh) | Record that a candidate passed the dogfood gate, as `refs/validated/<rc-tag>` on the remote (Q879). Called by [validate-release.sh](dogfood/validate-release.sh) on a pass and safe to re-run by hand, which is what a record that failed on a network blip needs: the validation itself is not retracted by a failed record, so the gate reports the pass, prints this command, and exits non-zero. ## `lib/` — sourced helpers, no entry points

Sourced across the tree, never executed, and never a gate of their own.
Callers set `REPO_ROOT` and have `set -euo pipefail` active before sourcing.
A helper only one group calls belongs in that group instead, which is why the dogfood cluster-state helpers live in [`dogfood/lib/`](#dogfood--gke-dogfood-tenant-tooling).

| Script | Purpose |
|---|---|
| [registry-mirror.sh](lib/registry-mirror.sh) | The ref rewriting that points the e2e job's image clients at the in-cluster pull-through caches (Q408 Phase 3), off one env var, `REGISTRY_MIRRORS`, holding `<upstream>=<mirror>` pairs the dogfood Kata tenant supplies from its own ConfigMap. Unset, which is the hosted lane, `publish.yml` and a developer's `make e2e`, nothing is rewritten. Three clients share it because none can read another's config: the docker pulls, helm's OCI chart pull, and buildkit's generated `buildkitd.toml`. `registry-mirror-test.sh` asserts both directions under `make scripts-test`, including the traps in docker's reference grammar: a first component with no dot is a repository, not a host, and a bare Hub name carries an implicit `library/` only Hub's own resolution supplies. |
| [common.sh](lib/common.sh) | The tree-wide helpers: `require_cmd`, `step`/`die`/`gh_curl`, `workspace_modules`, `git_candidates`/`select_present_files`, and the throttle setup. |
| [chart-sync.sh](lib/chart-sync.sh) | The skeleton the three `manifest/sync-chart-{crds,rbac,webhook}.sh` generators had triplicated verbatim (Q370): a temp-file registry with a single EXIT-trap cleanup, so `--check` renders a candidate and diffs it without ever mutating the working tree, plus the `--check` / write / usage dispatch. The per-artifact render logic stays in each script, where it genuinely differs. |
| [merge-driver-common.sh](lib/merge-driver-common.sh) | The plumbing all three Markdown merge drivers share: argument handling, the per-clone `--install`, the conflict labels git only supplies from 2.44 on, and the one fallback path all uncertainty exits through. Three drivers over one copy is the point, since they must behave identically when they refuse and a second hand-maintained copy would drift. |
| [merge-keyed-records.awk](lib/merge-keyed-records.awk) | The set-semantics all three drivers merge by: a three-way merge of one block of keyed records, one per line. The table mode keys on cell 1 alone so an escaped pipe in a later cell cannot shift the key (Q613/Q614 are the same class of defect elsewhere); `key_mode` picks how the key is read (a Markdown link target, or a roadmap bullet's `<!-- q:QN -->` annotation) and is the only file-specific knowledge here. It is required rather than defaulted, so a fourth driver that forgets it is refused instead of keyed by a mode it never asked for (Q1043). The mode check is here rather than in the driver suites because each driver passes its own mode, so none of them can see the case the contract turns on: a caller that passes none at all. It uses records only one reader can parse, since a record neither can is refused whether the check fired or not. |

## `updatecli/` — version-pin resolvers

Shell sources for the manifests under [`updatecli.d/`](../updatecli.d/), each printing one value with no trailing newline so updatecli uses it verbatim.
They cover the pins Dependabot cannot track: a version and its checksum held in a workflow env var or a script rather than in a package manifest.
Bumping the *tested* Kubernetes version is reviewed, so these open a PR and never auto-merge.

| Script | Purpose |
|---|---|
| [sha256-of-url.sh](updatecli/sha256-of-url.sh) | Hash the file at a URL directly, for an upstream that publishes no checksum file (shellcheck). When an upstream does publish a per-asset checksum, fetch that instead: it is cheaper and it matches the value a human would copy by hand. |
| [kind-linux-amd64-sha256.sh](updatecli/kind-linux-amd64-sha256.sh) | Print the upstream SHA-256 of the kind linux/amd64 binary for a given tag, from the release's published `kind-linux-amd64.sha256sum` asset, so `KIND_BINARY_SHA256` in `e2e-reusable.yml` stays in lockstep with `KIND_VERSION`. |
| [polaris-linux-amd64-sha256.sh](updatecli/polaris-linux-amd64-sha256.sh) | The same for polaris, keeping `POLARIS_SHA256` in lockstep with `POLARIS_VERSION` in `security-scan.yml`. polaris drops the leading `v` from its v10+ asset names, so the tag's `v` is stripped to build the filename matched in `checksums.txt`. |
| [syft-linux-amd64-sha256.sh](updatecli/syft-linux-amd64-sha256.sh) | The same for syft, keeping `SYFT_SHA256` in lockstep with `SYFT_VERSION` in both `publish.yml` and `security-scan.yml`. syft is a runtime tool download rather than an action ref, so nothing else bumps it: it used to ride the `syft-version` input on `anchore/sbom-action`, whose unretried installer is what Q806 replaced. The version is stripped of its leading `v` for both the asset name and the `syft_<version>_checksums.txt` filename. |
| [latest-envtest-version.sh](updatecli/latest-envtest-version.sh) | Print the latest stable envtest Kubernetes version as `1.<minor>.x`, resolved from the same controller-tools index `setup-envtest` reads, so the chosen version provably has published binaries and the integration tier cannot be bumped onto a minor with no envtest release. The envtest twin of `KIND_NODE_IMAGE`, which is bumped by hand because release notes are not a clean datasource. |
| [latest-cluster-autoscaler-patch.sh](updatecli/latest-cluster-autoscaler-patch.sh) | Print the newest cluster-autoscaler patch *within* the minor the pin already names, so the live-autoscaler drift gate tests the version it pins rather than waiting on the next kind minor (Q483). The minor is a floor and a ceiling: cluster-autoscaler ships one series per Kubernetes minor, so crossing it is a decision about the kind version and is made by hand in the kind bump PR. Resolved from the registry tag list, not the git tags, because a tag exists before its image can be pulled. `latest-cluster-autoscaler-patch-test.sh` pins that it never crosses the minor and never goes backwards. |
| [cosign-release-sha256.sh](updatecli/cosign-release-sha256.sh) | Print one platform's cosign digest, read from the release's sigstore-signed `cosign_checksums.txt` after verifying that signature against a pinned identity with the *currently pinned* cosign, so the four digests in [release/download-cosign.sh](release/download-cosign.sh) move with `COSIGN_VERSION` instead of by hand (Q927). The verification is the point: release assets stay mutable for an existing tag (Q126/Q127), so a resolver that hashed the download, or trusted an unverified checksums file, would pin exactly the bytes the pin exists to distrust, weekly and unattended. Prints nothing when the signature does not verify. `cosign-release-sha256-test.sh` pins that the identity and issuer reach `verify-blob` and that a failed verification yields no digest. |

## Per-clone setup

The tracked git hooks live in [`.githooks/`](../.githooks/).
Install them with `make hooks` (or [dev/setup.sh](dev/setup.sh), which does it for you); the pre-commit hook runs a sub-second gate (gofmt on staged Go files, plus [check-em-dash.sh](docs/check-em-dash.sh) when Markdown is staged).
Bypass a single commit with `git commit --no-verify`.

The Markdown merge drivers are the other per-clone `git config`: `make merge-driver` (also run by [dev/setup.sh](dev/setup.sh)) installs all four.
The committed half is the `merge=` line each file carries in [`.gitattributes`](../.gitattributes); git refuses to let a tracked file supply the driver's command, so the config is opt-in per clone and the attributes are a no-op without it.
The backlog has no driver: one file per item means concurrent sessions touching different items touch different files, and two touching the same item have a real conflict that must not be resolved by ID behind anyone's back (Q889).
