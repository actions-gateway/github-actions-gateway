# scripts/

Developer and CI helper scripts, grouped by **blast radius** — which gate consumes the script.
Nothing lives at the top level, so "which gate cares about this?" has to be answered when a script is added rather than defaulting to a catch-all.
Every CI path filter that names a script is a plain prefix glob over one of these directories, and [`ci/check-path-filters.sh`](ci/check-path-filters.sh) holds them to it (Q571).

| Directory | Holds | Gated by |
|---|---|---|
| [`ci/`](#ci--repo-hygiene-gates) | the repo-hygiene meta-gates and the gate runner | `unit-test.yml`, `conflict-markers.yml` |
| [`go/`](#go--go-build-test-lint-vendor) | build, test, lint, vendor, coverage, codegen drift | `unit-test.yml` |
| [`e2e/`](#e2e--live-cluster-tiers) | cluster bring-up, image bake, chart install checks, e2e venue fidelity | `e2e-test.yml`, `e2e-calico.yml`, `autoscaler-drift.yml`, `endpoint-parity.yml` |
| [`fetch/`](#fetch--the-download--retry-family) | the download/retry/pre-pull family every tier calls | every heavy tier |
| [`docs/`](#docs--docs-site-backlog-plan) | docs site, backlog, plan and roadmap tooling | `doc-links.yml`, `status-lint.yml`, `plan-hygiene.yml` |
| [`security/`](#security--vulnerability-and-posture-scans) | govulncheck, trivy, polaris | `security-scan.yml` |
| [`manifest/`](#manifest--chart-and-manifest-generation) | chart CRD/RBAC/webhook sync and install-artifact validation | `manifest-validate.yml` |
| [`release/`](#release--publish-sign-report) | publish, sign, notices, release decision support | `publish.yml`, `license-notices.yml` |
| [`agent/`](#agent--claude-code-hooks-and-the-local-throttle) | Claude Code hooks, the local throttle and its instruments | never CI-gating |
| [`dev/`](#dev--developer-only) | post-clone setup, live probes, cloud spikes | never CI-gating |
| [`dogfood/`](#dogfood--gke-dogfood-tenant-tooling) | GKE dogfood tenant tooling | `dogfood-*.yml` |
| [`lib/`](#lib--sourced-helpers-no-entry-points) | sourced helpers, no entry points | every group |
| [`updatecli/`](#updatecli--version-pin-resolvers) | version-pin resolvers for `updatecli.yml` | `updatecli.yml` |

A `*-test.sh` sits beside its subject, so it inherits its subject's gate: [`docs/source-links-hook-test.sh`](docs/source-links-hook-test.sh) belongs to the docs site and cannot trigger e2e.
It is usually named in its subject's row rather than given one of its own, since what it asserts is a property of the subject.

Every script here must appear somewhere on this page, in its own row or named in the row of the script it belongs to, and [`docs/check-script-docs.sh`](docs/check-script-docs.sh) fails when one does not (Q688).
An entry earns its place by saying which gate runs the script and what would go wrong without it; repeating the filename tells a reader nothing `ls` would not.

All scripts follow the [repo bash conventions](../docs/development/bash-style.md): `set -euo pipefail`, `local` for function variables, `[[ ]]` conditionals, quoted expansions, `trap` cleanup for background processes — see the doc for the full list.
Whatever more than one gate shares is sourced from [`lib/`](#lib--sourced-helpers-no-entry-points).
Every script here is linted by `make shellcheck` ([ci/shellcheck-scripts.sh](ci/shellcheck-scripts.sh)) as soon as the file exists — tracked or not — so opting a scratch script out means gitignoring it (write it under the gitignored `tmp/` at the repo root), not merely leaving it untracked.
The same holds for the doc-link, conflict-marker and plan-ref gates, which share that file selection via `git_candidates` (Q619).

The root `Makefile` keeps recipes as thin target→script wiring so the logic is shellcheck-covered; parameters are env-overridable and documented in each script's header.

A gate whose logic outgrows shell moves its core to Go in [`devtools/`](../devtools/), the first-party tooling module, keeping the script here as the entry point so the gate map stays in one place.
Packages there mirror these directories — `devtools/ci/pathfilters/` backs [`ci/check-path-filters.sh`](ci/check-path-filters.sh).
The module is deliberately outside `go.work`; the reasoning and the wiring a new one needs are in [go-workspaces.md](../docs/development/go-workspaces.md#first-party-go-tooling-stays-outside-the-workspace).

## `ci/` — repo-hygiene gates

| Script | Purpose |
|---|---|
| [check-path-filters.sh](ci/check-path-filters.sh) | Reconcile CI's hand-maintained `dorny/paths-filter` lists with `go.work` and with the paths they name — a filter missing a module makes its gate report green by *skipping* (Q400/Q429). Fails on an uncovered workspace module, an unclassified filter, a pattern whose path is gone, two lanes over one reusable workflow disagreeing about scripts/ (Q571), or a `**` placed where picomatch stops expanding it (Q659); assertions covered by `check-path-filters-test.sh` under `make scripts-test`. Backs `make path-filters-check` and the CI `path-filters` job. |
| [check-conflict-markers.sh](ci/check-conflict-markers.sh) | Fail on leftover merge-conflict marker lines in any present, non-vendored file — tracked or untracked-and-not-gitignored (Q379 — a stray marker from a rebase resolution once merged to main). Backs `make conflict-markers-check` and the CI `conflict-markers` workflow. The four marker forms, the near-misses that must stay legal (setext underlines, mid-line mentions, six- and eight-character runs) and the gitignore opt-out are asserted by `check-conflict-markers-test.sh` under `make scripts-test`. |
| [shellcheck-scripts.sh](ci/shellcheck-scripts.sh) | Shellcheck every present `scripts/**/*.sh` — tracked or untracked-and-not-gitignored, recursive (file selection asserted by `shellcheck-scripts-test.sh` under `make scripts-test`). Backs `make shellcheck`. |
| [check-errexit-prologue.sh](ci/check-errexit-prologue.sh) | Require the full errexit prologue, `set -euo pipefail` followed by `shopt -s inherit_errexit`, in every executable script here (Q733). `set -e` does not reach inside a command substitution, so `x="$(f)"` runs `f` past its own failure and takes the status of its *last* command: a gate that checked nothing, reporting success. Measured on `go-lint.sh`, where a fault injected into `scoped_module_dirs` left it announcing a full sweep, linting 1 module of 11, and exiting 0. Sourced `lib/` files are exempt, since they run under the caller's shell options. shellcheck has no check for this, and its SC2155 covers only the `local x="$(f)"` half. Backs `make errexit-prologue-check` and the CI step of the same name; assertions in `check-errexit-prologue-test.sh` under `make scripts-test`. |
| [actionlint-workflows.sh](ci/actionlint-workflows.sh) | actionlint every workflow under `.github/workflows/` — schema, `uses:` refs, expressions, and (via shellcheck) the inline `run:` blocks. Three docs credited actionlint with this while no job ran it, so a workflow-only PR shipped unlinted (Q579). Fails when shellcheck is missing rather than letting actionlint silently skip the `run:` half. Backs `make actionlint` and the CI `actionlint` job. |
| [check-uses-pinned.sh](ci/check-uses-pinned.sh) | Fail when a `uses:` reference is pinned to anything a third party can move (Q644). actionlint asserts a ref is present and well formed, never that it is a SHA (measured against v1.7.12 it accepts `@v4` and `@main` at exit 0), and a tag-pinned action runs against the job token. Checks every workflow and composite action in the tree, wider than actionlint's root-only scope; requires a 40-hex SHA plus the `# vX.Y.Z` comment Dependabot bumps, exempts local `./…` refs, and needs an `@sha256:` digest on `docker://`. Fails closed on an unparseable file and on an empty extraction. Checking is [devtools/ci/usespin](../devtools/ci/usespin) over a real YAML parser, since `uses:` also appears in comments and `run:` blocks. Backs `make uses-pinned-check` and the CI `uses-pinned` job; assertions in `check-uses-pinned-test.sh` under `make scripts-test`. |
| [check-cosign-pin.sh](ci/check-cosign-pin.sh) | Hold the Makefile's `COSIGN_VERSION` to the `cosign-release` [publish.yml](../.github/workflows/publish.yml) signs with (Q903). Two hand-kept pins name the same binary from opposite ends of the release: the workflow installs cosign to *sign*, the Makefile downloads it to *verify* (`make verify-release`, and the dogfood CRD smoke). Only a comment beside each asked them to agree, so a one-sided bump left the local check running a verifier the publish job never signed with. Also fails when a `sigstore/cosign-installer` step loses its `cosign-release` input, which floats the signer to the latest release: that is the same drift arriving by omission, and comparing only the pins that remain would pass it. Refuses with rc 2 rather than reporting green whenever a pin it compares is absent, since a pattern that stopped matching would otherwise call every tree in step. Backs `make cosign-pin-check` and the CI `cosign-pin` job; both directions asserted by `check-cosign-pin-test.sh` under `make scripts-test`. |
| [check-dep-advisory.sh](ci/check-dep-advisory.sh) | Print a one-line reminder when a change touches Go dependency files, and stay silent otherwise — `make check` deliberately omits the three dependency-drift gates, so this is the nudge to run `make vendor-sync`. Advisory: never fails the build. The classification is made from git state alone, and `check-dep-advisory-test.sh` pins it in hermetic throwaway repos under `make scripts-test`, so no assumption about the caller's tree leaks in. |
| [check-tools.sh](ci/check-tools.sh) | Verify the CLI tools the project needs (required / e2e / extended tiers) are installed, on PATH, and at or above any version floor the registry declares; for each miss, print a per-OS install command or the exact dir to add to PATH. Cross-platform (brew/apt/url). Backs `make doctor`. Exits nonzero if a required tool is missing or too old. bash carries the one floor today, 4.4 for `inherit_errexit` (Q751), and the floor is checked above this script's own prologue so it can still report on the bash 3.2 macOS ships. Assertions in `check-tools-test.sh` under `make scripts-test`. |
| [dependabot-rebase-stale.sh](ci/dependabot-rebase-stale.sh) | Rebase a conflicted Dependabot Go-module PR by **replaying** its version bumps on current `main` (`go get` per bump, then `make vendor-sync`) and force-pushing, never by merging: merging can silently downgrade a module. Backs the [`dependabot-rebase-stale`](../.github/workflows/dependabot-rebase-stale.yml) workflow (Q427); `--dry-run`, `--list`, and `--bumps` for local use. Bump extraction decides the version each module is replayed at, and so is the only place a wrong answer could downgrade one; `dependabot-rebase-stale-test.sh` asserts it under `make scripts-test`, while the impure half needs a live PR and is exercised by the workflow's own dry run. |
| [gate-list.sh](ci/gate-list.sh) | Render (`--list`, `--list-suites`) or reconcile (`--check`) the two lists `make check` derives from, the gates it runs and the `scripts/` suites `scripts-test` fans out over, from the `CHECK_FAST_GATES`/`CHECK_HEAVY_GATES`/`SCRIPTS_TESTS` variables make passes in. Both lists used to live in hand-kept copies that every gate- or suite-adding PR edited and conflicted on, and that drifted anyway (Q649, Q671). Fails on a gate with no `.PHONY` or `##` line, a recipe phase outside `CHECK_HEAVY_GATES`, a gate hand-wired into the fan-out, a target declared `.PHONY` twice, a `STATUS_GATES` member outside `CHECK_FAST_GATES`, a fast gate outside `STATUS_GATES` whose script selects `docs/STATUS.md` or whose file set is neither derivable nor declared `# status-scope: none` (Q749), a `*-test.sh` on disk that `SCRIPTS_TESTS` omits (so `make scripts-test` reports green without running it) or a `SCRIPTS_TESTS` entry with no file, or a testing.md that stopped citing `make list-gates`/`make list-script-tests`. Backs `make list-gates`, `make list-script-tests`, `make gate-lists-check` and the CI `gate-lists` job; assertions in `gate-list-test.sh` under `make scripts-test`. |
| [git-merge-gate-lists.sh](ci/git-merge-gate-lists.sh) | A git merge driver for `mk/gate-lists.mk`, which holds the gate and suite lists `make check` derives from, resolving them entry by entry. `gate-list.sh --check` requires `SCRIPTS_TESTS` to match the `*-test.sh` files on disk, so a PR shipping a gated script must append to a backslash-continued list here, and two PRs doing that collide on adjacent lines. Only the variables the driver names are treated specially: each is lifted out behind a sentinel, the rest of the file is merged by git alone, and a conflict anywhere else in that file gets ordinary markers. That list and the assignments in `mk/gate-lists.mk` must name the same set, in both directions -- a name the file no longer assigns makes the driver refuse every merge of it, and a list the file gained that the driver does not name still collides by line position (Q915); `--managed-vars` reports the array so the suite reconciles the value the driver runs on. A list neither side touched is reused byte for byte and a list with only additions keeps its existing lines, so a merge does not rewrap 30 lines nobody changed. The rebuilt block is read back and required to round-trip to the entry set it was given; `gate-lists-check` is the backstop underneath that. It makes the local rebase trivial; it cannot stop a merge-queue eviction, because GitHub performs the queue's merge itself and never runs a per-clone driver. Installed by the one-time `make merge-driver`. Exercised by `git-merge-gate-lists-test.sh` under `make scripts-test`. |
| [git-merge-gate-lists-test.sh](ci/git-merge-gate-lists-test.sh) | Tests for the gate-list driver. Every resolution asserts two things, the merged entry set and that `make` still parses the result, because a correct-looking list with a dropped backslash breaks every build downstream and a set comparison alone would not see it; the variable is read back through make's own parser via a wrapper makefile, since the `make` shipped with macOS has no `--eval`. Also asserts the zero-churn property, after an earlier revision rewrapped a variable neither side had touched, and the refusals: a conflict outside the lists, and a side missing a managed variable. Every fixture is derived from `mk/gate-lists.mk` rather than restated, and the two lists are reconciled both ways, because a fixture naming its own variables asserts the shape it was written against: the driver spent #1603 onward refusing every merge of that file while this suite passed, its fixture still declaring the variable the file had dropped (Q915). Ends with a real `git rebase` through `.gitattributes`, on two branches each appending to the real file. Runs under `make scripts-test`. |
| [check-template-library.sh](ci/check-template-library.sh) | Reconcile the shipped runner template library (`deploy/templates/`) with the set CI exercises, both directions (Q554). A golden template is an implicit validation claim, so an entry no dogfood e2e overlay consumes fails the gate unless it is declared inert in the script with its reason, and an overlay that stops consuming the library fails it too. Also holds every patch against a `ClusterRunnerTemplate` to JSON 6902, because kustomize has no CRD schema and a strategic merge there silently replaces lists wholesale at exit 0 (measured, kustomize v5.8.1); and, when kubectl is on PATH, renders each overlay and fails on a load-bearing line its base declares and the render lost. Backs `make template-library-check` and the CI step of the same name; assertions in `check-template-library-test.sh` under `make scripts-test`. |
| [run-parallel.sh](ci/run-parallel.sh) | Run multiple commands in parallel with labeled, real-time output. Backs the fan-out in `make check`, `make status-gates` and `make scripts-test`. Every pid is waited, so one command failing never abandons its siblings, and each failure is summarised with its exit status. That status tells an assertion failure apart from a command the kernel killed (128+n; 137 is the OOM killer's signature) or one that was never found (127), a distinction five flakes in the Q703 family had to guess at. That status also sets the verdict: a signal death is summarised under `KILLED` rather than `FAILED` and exits with its own `128+n`, because it reached no verdict and is not a defect to go and read (Q837). Assertions in `run-parallel-test.sh` under `make scripts-test`. |
| [check-tool-pins.sh](ci/check-tool-pins.sh) | Assert every `.build/` tool rule declares the file carrying its version pin as a prerequisite (Q904). Q842 set the pattern and a Makefile comment stated it, but nothing held a rule to it: without such a prerequisite make treats an existing binary as up to date forever, so a bump serves the old tool against the new target. That is how a stale mdreflow met an unknown `--explain` flag and then reported four false reflow failures on a clean tree, and how cosign shipped with no prerequisite at all and served a stale verifier until Q857. Not [check-cosign-pin.sh](ci/check-cosign-pin.sh), which holds two version *strings* to each other across two files and never asks whether a rule fires on a bump. Rules come from `make -pnq`, the resolved database, so variable expansion, backslash continuations and the eight-target rule the Go tools share are make's answer rather than a regexp's. A tool binary is a `.build/` target that is not a prerequisite of another one, which is what separates the tools from the pin sentinels. Fails on a rule with no normal prerequisite, on one carrying only order-only prerequisites (those never make a target out of date, so the defect survives behind an apparent fix), and on a prerequisite that is neither tracked nor version-keyed. Version-keyed is measured rather than pattern-matched: the database is read again with every makefile `*_VERSION` variable overridden, and the path must move, so a `.build/x.stamp` touched once and never again fails. Refuses with rc 2 when the read yields no `.build/` rule, since a database it could not parse would otherwise report every rule pinned. Backs `make tool-pin-check`, in `make check` and the CI `shellcheck` job; both directions asserted by `check-tool-pins-test.sh` under `make scripts-test`. |

## `go/` — Go build, test, lint, vendor

Backs `make test` / `make test-race`. `RUN='TestName'` narrows to matching tests and **fails** when the regex selects none, since `go test -run` reports a green suite on a miss (Q680); assertions in `go-test-run-filter-test.sh` under `make scripts-test`. Owns the budget so it is one number rather than four, reports the package total against it on every run, and on a breach says the *suite* ran out of time: Go's timeout panic names whichever test held the wall, so the name moves between runs and sends readers after a bystander (Q166 spent two wrong hypotheses there, Q741). | [go-vet-tags.sh](go/go-vet-tags.sh) | Compile + vet the build-tagged (`integration`/`e2e`/`load`/`autoscaler`) Go files no other fast gate builds, and fail if a new tag appears that its list does not cover (Q404: a tagged-file compile break used to reach only CI's path-gated heavy tiers; both properties asserted by `go-vet-tags-test.sh` under `make scripts-test`). | [check-codegen-drift.sh](go/check-codegen-drift.sh) | Regenerate every registered module's CRD/RBAC/webhook manifests into a scratch tree and fail if a committed copy is stale — the GMC's ActionsGateway CRD embeds AGC types, so an edit in `cmd/agc/api` goes stale in the GMC manifest until someone runs the GMC's `manifests` target (Q440). | [check-v2-api-sync.sh](go/check-v2-api-sync.sh) | Fail when the v2alpha1 and v2beta1 API packages drift apart. Backs `make v2-api-sync-check`. `check-v2-api-sync-test.sh` runs under `make scripts-test` and is the permanent form of the invert-the-fix verification (Q374): a body divergence fails, the entitled differences (package clause, storage-version and deprecated-version markers) do not, and a stale exemption fails. |
| [check-test-cache-inputs.sh](go/check-test-cache-inputs.sh) | Entry point for the out-of-module test read checker below: an `exec` forwarding its arguments. It also brings the gate under the shell linter and the errexit prologue check. |
| [check-test-cache-inputs.py](go/check-test-cache-inputs.py) | Fail when a cached test reads a file resolving outside its package's **module** root (Q895). Go's test cache drops those `open`/`stat` events from the key, so the assertion replays a stale pass when only the external file changes: measured 2026-08-17 on the since-retired `pipedgate`, `make check` reported it `(cached)` and exited 0 while the package failed 5 assertions, as did CI, and the same shape left the root-`Dockerfile` runner-version lockstep gate green across a tag bump. A lexical sweep cannot tell a path that is read from one that is data, so exceptions are an `ALLOW` map carrying the reason rather than a pattern. Files behind `//go:build e2e` are skipped, since `ginkgo run` compiles with `go test -c` and execs the binary, consulting no test-result cache. The fix it points at is a symlink under the package's own `testdata/`. Backs `make test-cache-inputs-check`. |

Green: the same file reached through an in-module `testdata/` symlink, a `../` read that stays inside the module root, and an `//go:build integration` file. ## `fetch/` — the download / retry family

Three entry points by what they retry — an arbitrary command, a `curl`, a `docker pull` — plus the two pre-pull cachers built on the last.
Every heavy tier calls at least one, which is why `scripts/fetch/**` appears in the e2e, security-scan, manifest-validate and autoscaler-drift filters.

| Script | Purpose |
|---|---|
| [retry.sh](fetch/retry.sh) | Run an arbitrary command with bounded retries and linear backoff. Used by the publish workflow to absorb transient GHCR errors on idempotent push/sign steps, and by `trivy-scan.sh` to absorb a base-image pull denial during the image build (Q863). |
| [download-verified.sh](fetch/download-verified.sh) | `<url> <sha256> <output-path>`: download a pinned release asset, retrying any nonzero `curl` exit on exponential jittered backoff (`DOWNLOAD_RETRIES`/`DOWNLOAD_RETRY_DELAY`/`DOWNLOAD_RETRY_MAX_DELAY` env, default 5 retries, 5s doubling to a 60s cap, 135-202s), and write the output path only once the bytes match the digest. Used by every pinned-binary install: kind, shellcheck, kubeconform, polaris, syft, cosign. `download-verified-test.sh` holds both halves to that contract under `make scripts-test` (Q433, Q829): a mismatched digest leaves nothing at the output path and is not retried, a malformed or absent digest is rejected outright, no flag or environment variable skips verification, and, off a stubbed `curl`/`sleep` so nothing waits, a `curl: (22)` is retried rather than fatal and the schedule doubles, jitters and caps. |
| [pull-image-with-retry.sh](fetch/pull-image-with-retry.sh) | `docker pull <image-ref>` with bounded retries and exponential, jittered backoff (`PULL_RETRY_ATTEMPTS`/`PULL_RETRY_DELAY`/`PULL_RETRY_MAX_DELAY` env, default 6 attempts, 5s doubling to a 60s cap). Absorbs transient registry timeouts/429s in-step; the jitter keeps concurrent CI callers from retrying in lockstep (Q460). Used by the e2e, security-scan and publish workflows to pre-pull the buildkit builder and mirror the curl/Vault test images. The schedule *is* the fix, so `pull-image-with-retry-test.sh` asserts it under `make scripts-test`: exponential growth, jitter on every delay, and a cap, read off the arguments passed to a stubbed `sleep`, so none of it waits. |
| [prepull-image-cached.sh](fetch/prepull-image-cached.sh) | `<image-ref> <cache-dir> <local-tag>`: pre-pull one pinned image into the runner's Docker daemon (retried) and cache it as a tarball, exposing it under a local-only tag; a warm cache `docker load`s the tar without touching the registry. The single-image sibling of prepull-manifest-images.sh — the local tag exists because `docker load` cannot restore a manifest digest, so a digest-pinned ref would never resolve from the cache. Used by the security-scan trivy job's buildkit pre-pull. |
| [prepull-manifest-images.sh](fetch/prepull-manifest-images.sh) | `<name> <manifest-url> <cache-dir>`: extract the image refs a pinned Kubernetes manifest names, pre-pull them into the runner's Docker daemon (retried) and cache as a tarball + `images.txt`; on a warm cache `docker load`s the tar without touching the network. The shared pre-pull half of the e2e Calico/cert-manager/metrics-server caching pattern. |

Measured 2026-08-15 on `050f1e80e`, where all nine required workflows reported success and all nine had skipped their real job. The lanes also disagree, a `merge_group` run path-gating what the `push` lane runs outright, so it prefers a lane that ran in full instead of trusting list order. The gate list is derived from the repository's branch ruleset and each context resolved to the workflow declaring that job, never by name convention (`e2e-gate` lives in `e2e-test.yml`, so a stem-derived filename drops the e2e lane); a context that resolves to nothing is reported, never dropped. A skip is not a failure on its own but exits non-zero, pointing at `check-artifact-unchanged.sh` to prove the shipped surface is covered by an earlier full run. Both directions asserted by `check-gates-green-test.sh` under `make scripts-test`. |

## `dogfood/` — GKE dogfood tenant tooling

These drive a live, billable GKE cluster, so no gate ever executes one: they are run by hand or by the release gate.
What CI does run is their assertions: thirteen `*-test.sh` here run under `make scripts-test`, and so under `make check`, against stubbed `gcloud`/`kubectl`/`gh`.
That is deliberate, because every failure mode below is silent and costs money in one direction or the other.
The only CI reference to the group's files is `dockerfile-lint.yml`, over [runner/Dockerfile](dogfood/runner/Dockerfile).

The shared helpers sit in a nested [`lib/`](dogfood/lib/) rather than the tree-wide [`lib/`](#lib--sourced-helpers-no-entry-points) because every one of them reads or writes dogfood cluster state.
The five tests covering a `lib/` helper sit at the group root rather than beside their subject, since a sourced helper's behaviour is only reachable through a caller.

| [lib/quota.sh](dogfood/lib/quota.sh) | The global CPU-budget arithmetic the release gate reserves the e2e pool's capacity with (Q631). The gate's two legs draw on one project-wide `CPUS_ALL_REGIONS` limit: its deploy leg routes CI to GAG, whose `workers` pool autoscales out of the budget the e2e leg then needs 16 vCPU from, and the autoscaler refuses that scale-up as a bare `FailedScaleUp` naming no quota. Two `v1.3.0-rc.5` runs died there, after three wrong diagnoses chasing the family and regional quotas. Reads the limit live because a transcribed one ages: it was 32 until 2026-08-03 and is 64 now. Asserted by `quota-test.sh`. |
| [lib/progress.sh](dogfood/lib/progress.sh) | The release gate's phase event stream and the status renderer over it (Q615, Q616): one JSON line per transition, so a renderer can answer "where is it" at any moment without replaying the terminal. Same shape and the same reasons as the e2e suite's spec stream ([testing.md](../docs/development/testing.md#watching-an-e2e-run-in-progress)), where the stream is the contract, renderers read it, and nothing derives state by parsing human-readable output. |
| [lib/workers.sh](dogfood/lib/workers.sh) | Worker-pod occupancy probes, read by every script that scales the system pool down or deletes the cluster, and read the same way from here (Q434). Asserted by `workers-test.sh` in both directions, because both are silent: an unreachable cluster read as idle is the 82-node-hour incident, and a settled cluster read as busy bills forever. |

## `lib/` — sourced helpers, no entry points

Sourced across the tree, never executed, and never a gate of their own.
Callers set `REPO_ROOT` and have `set -euo pipefail` active before sourcing.
A helper only one group calls belongs in that group instead, which is why the dogfood cluster-state helpers live in [`dogfood/lib/`](#dogfood--gke-dogfood-tenant-tooling).

| Script | Purpose |
|---|---|
| [common.sh](lib/common.sh) | The tree-wide helpers: `require_cmd`, `step`/`die`/`gh_curl`, `workspace_modules`, `git_candidates`/`select_present_files`, and the throttle setup. |
| [chart-sync.sh](lib/chart-sync.sh) | The skeleton the three `manifest/sync-chart-{crds,rbac,webhook}.sh` generators had triplicated verbatim (Q370): a temp-file registry with a single EXIT-trap cleanup, so `--check` renders a candidate and diffs it without ever mutating the working tree, plus the `--check` / write / usage dispatch. The per-artifact render logic stays in each script, where it genuinely differs. |
| [merge-driver-common.sh](lib/merge-driver-common.sh) | The plumbing all three Markdown merge drivers share: argument handling, the per-clone `--install`, the conflict labels git only supplies from 2.44 on, and the one fallback path all uncertainty exits through. Three drivers over one copy is the point, since they must behave identically when they refuse and a second hand-maintained copy would drift. |
| [merge-keyed-records.awk](lib/merge-keyed-records.awk) | The set-semantics all three drivers merge by: a three-way merge of one block of keyed records, one per line. The table modes key on cell 1 alone so an escaped pipe in a later cell cannot shift the key (Q613/Q614 are the same class of defect elsewhere); `key_mode` picks how the key is read (the backlog anchor, a Markdown link target, or a roadmap bullet's `<!-- q:QN -->` annotation), and is the only file-specific knowledge here. Exit 2 means the merge is not certain and the caller falls back to conflict markers. |

## `updatecli/` — version-pin resolvers

Shell sources for the manifests under [`updatecli.d/`](../updatecli.d/), each printing one value with no trailing newline so updatecli uses it verbatim.
They cover the pins Dependabot cannot track: a version and its checksum held in a workflow env var or a script rather than in a package manifest.
Bumping the *tested* Kubernetes version is reviewed, so these open a PR and never auto-merge.

| Script | Purpose |
|---|---|
| [sha256-of-url.sh](updatecli/sha256-of-url.sh) | Hash the file at a URL directly, for an upstream that publishes no checksum file (shellcheck). When an upstream does publish a per-asset checksum, fetch that instead: it is cheaper and it matches the value a human would copy by hand. |
| [kind-linux-amd64-sha256.sh](updatecli/kind-linux-amd64-sha256.sh) | Print the upstream SHA-256 of the kind linux/amd64 binary for a given tag, from the release's published `kind-linux-amd64.sha256sum` asset, so `KIND_BINARY_SHA256` in `e2e-reusable.yml` stays in lockstep with `KIND_VERSION`. |
| [polaris-linux-amd64-sha256.sh](updatecli/polaris-linux-amd64-sha256.sh) | The same for polaris, keeping `POLARIS_SHA256` in lockstep with `POLARIS_VERSION` in `security-scan.yml`. polaris drops the leading `v` from its v10+ asset names, so the tag's `v` is stripped to build the filename matched in `checksums.txt`. |
| [syft-linux-amd64-sha256.sh](updatecli/syft-linux-amd64-sha256.sh) | The same for syft, keeping `SYFT_SHA256` in lockstep with `SYFT_VERSION` in both `publish.yml` and `security-scan.yml`. syft is a runtime tool download rather than an action ref, so nothing else bumps it: it used to ride the `syft-version` input on `anchore/sbom-action`, whose unretried installer is what Q806 replaced. The version is stripped of its leading `v` for both the asset name and the `syft_<version>_checksums.txt` filename. |
| [latest-envtest-version.sh](updatecli/latest-envtest-version.sh) | Print the latest stable envtest Kubernetes version as `1.<minor>.x`, resolved from the same controller-tools index `setup-envtest` reads, so the chosen version provably has published binaries and the integration tier cannot be bumped onto a minor with no envtest release. The envtest twin of `KIND_NODE_IMAGE`, which is bumped by hand because release notes are not a clean datasource. |
| [latest-cluster-autoscaler-patch.sh](updatecli/latest-cluster-autoscaler-patch.sh) | Print the newest cluster-autoscaler patch *within* the minor the pin already names, so the live-autoscaler drift gate tests the version it pins rather than waiting on the next kind minor (Q483). The minor is a floor and a ceiling: cluster-autoscaler ships one series per Kubernetes minor, so crossing it is a decision about the kind version and is made by hand in the kind bump PR. Resolved from the registry tag list, not the git tags, because a tag exists before its image can be pulled. `latest-cluster-autoscaler-patch-test.sh` pins that it never crosses the minor and never goes backwards. |

## Per-clone setup

The tracked git hooks live in [`.githooks/`](../.githooks/).
Install them with `make hooks` (or [dev/setup.sh](dev/setup.sh), which does it for you); the pre-commit hook runs a sub-second gate (gofmt on staged Go files, plus [check-em-dash.sh](docs/check-em-dash.sh) when Markdown is staged).
Bypass a single commit with `git commit --no-verify`.

The Markdown merge drivers are the other per-clone `git config`: `make merge-driver` (also run by [dev/setup.sh](dev/setup.sh)) installs all four.
The committed half is the `merge=` line each file carries in [`.gitattributes`](../.gitattributes); git refuses to let a tracked file supply the driver's command, so the config is opt-in per clone and the attributes are a no-op without it.
The backlog has no driver: one file per item means concurrent sessions touching different items touch different files, and two touching the same item have a real conflict that must not be resolved by ID behind anyone's back (Q889).
